# 한국어 형태소 분석기 후보 3종 비교 — 5지표 실측 (ADR-0028 §2)

> 실측 환경: Windows 11, Node 24 (Git Bash), 이 저장소의 `apps/api` 워크스페이스.
> 후보를 실제로 `npm install`하고 실제 문장으로 호출해 측정했다(추정치 아님).

## 후보

| 구분 | 패키지 | 방식 | 라이선스 |
|---|---|---|---|
| M1 후보 A(**채택**) | `garu-ko@0.9.18` | WASM(1.2MB 모델 + 412KB WASM 엔진, 모델 내장) | MIT |
| M1 후보 B | `kuromoji-ko@1.0.8` | 순수 TypeScript/JS(WASM도 아니고 네이티브도 아님 — mecab-ko-dic 이식) | Apache-2.0 |
| M2 후보 | `napi-mecab@0.1.1` | Node-API 네이티브 바인딩 + 별도 사전 다운로드(mecab-ko-dic) | MIT(사전은 별도 라이선스) |

## 5지표 실측 결과

| 지표 | garu-ko(M1, 채택) | kuromoji-ko | napi-mecab(M2) |
|---|---|---|---|
| ① 스팬 경계 품질(정성 — 아래 예시 참고) | "해외배송비"→`해외/배송비`(2-way, gazetteer 친화적) | "해외배송비"→`해외/배송/비`(3-way) | "해외배송비"→`해외/배송/비`(3-way) |
| ① 공개 벤치마크 F1 | **96.0%**(9k 골드셋, 공식 공개) | 미공개(mecab-ko-dic 학계 통용치 ~95~97%) | 미공개(동일 사전 기반) |
| ② gazetteer 재현율(가설 문장 10건 실측) | 10/10 — "해외"를 항상 독립 토큰으로 분리 | 10/10 | 10/10 |
| ③ 분석 지연 P50/P95(ms, 문장 10종 반복 200회) | 0.48 / 1.13 | **0.06 / 0.14**(최소) | 0.015 / 0.031(최속이나 네이티브) |
| ③ 최초 로드 시간(ms) | 109(WASM 초기화) | 1,068(gzip 사전 압축해제) | 1.5(prebuild 즉시) |
| ④ 설치 난이도 | `npm install` **1줄**로 끝. 추가 네트워크 호출 0회 | `npm install` **1줄**로 끝(사전이 패키지에 내장) | `npm install` + **별도 `npx napi-mecab-setup ko`** 필요(GitHub Releases에서 prebuild 23.78MB 추가 다운로드 — 폐쇄망에서 실패) |
| ④ 오프라인/폐쇄망 적합성 | 최적 — 설치 후 네트워크 0 | 최적 — 설치 후 네트워크 0 | 열등 — 설치 스크립트가 인터넷 필요(사전·바이너리를 미리 동봉하지 않으면 실패) |
| ④ 플랫폼 종속성 | 없음(WASM, 크로스 플랫폼) | 없음(순수 JS) | 있음(플랫폼별 prebuild, 없으면 node-gyp 컴파일 필요 — Python/빌드툴 요구) |
| ⑤ 라이선스 | MIT(모델 포함) | Apache-2.0(사전 포함) | MIT(단, mecab-ko-dic 사전은 별도 확인 필요) |
| ⑤ 설치 후 디스크 사용량 | **1.8MB** | 28MB | 109MB(ja+ko 사전·prebuild 포함) |

## 실측 예시(원문 그대로)

```
입력: "해외로 반품 보낼 수 있나요"
garu-ko      : 해외/NNG 로/JKB 반품/NNG 보내/VV ㄹ/ETM 수/NNB 있/VA 나요/EF
kuromoji-ko  : 해외/NNG 로/JKB 반품/NNG 보낼/VV+ETM 수/NNG 있/VV 나요/EC
napi-mecab   : 해외 로 반품 보낼 수 있 나요

입력: "해외배송비"
garu-ko      : 해외/NNG 배송비/NNG      ← 등록 키워드가 "배송비"라면 정확히 한 토큰으로 잡힌다
kuromoji-ko  : 해외/NNG 배송/NNG 비/NNG
napi-mecab   : 해외 배송 비
```

## 판단 — M1으로 `garu-ko`를 채택한다

- **④⑤(설치 난이도·배포 크기)에 실질 가중치를 크게 둔다는 ADR-0028의 지침**을 그대로 적용하면
  `napi-mecab`(M2)은 탈락한다 — 별도 네트워크 설치 스텝이 있어 구축형 폐쇄망 배포와 상충하고(J-10/
  ADR-0028이 가장 우려한 지점), 디스크 사용량도 60배 크다.
- `garu-ko`와 `kuromoji-ko`는 둘 다 "npm install 1줄로 끝, 네트워크 0, 크로스플랫폼"이라는
  이상적인 조건을 만족한다. 이 둘 사이에서는:
  - **`garu-ko`가 공개된 F1 96.0% 벤치마크를 갖고 있다**(다른 둘은 사전 자체의 학계 통용치에
    의존할 뿐 이 라이브러리·설정 조합으로 직접 측정된 공개 수치가 없다).
  - **`garu-ko`의 압축어 분리가 실측 예시에서 더 유용하다** — "해외배송비"를 `해외/배송비` 2-way로
    잘라 gazetteer 매칭("배송비"가 등록 키워드인 흔한 경우)에 유리하다. `kuromoji-ko`/`napi-mecab`은
    3-way(`해외/배송/비`)로 더 잘게 쪼개 후처리(재결합)가 필요할 수 있다.
  - `garu-ko`는 ADR-0028이 명시적으로 지정한 "M1(**WASM 배포본**) 우선" 문구와 정확히 일치하는
    유일한 후보다(`kuromoji-ko`는 WASM도 네이티브도 아닌 순수 JS라 성격이 다르다).
  - 지연(③)은 셋 다 50ms 예산(NFR-LP4) 대비 1~2자릿수 이상 여유가 있어 실질적 차이가 없다.
- **알려진 한계(반드시 인지할 것)**: `garu-ko`가 반환하는 `start`/`end`는 **어절 단위** 오프셋이라
  같은 어절 내 형태소가 좌표를 공유하며, 불규칙 활용(예: "보내"+"ㄹ"→표면 "보낼")에서는 형태소를
  이어붙여도 원문 부분 문자열과 다를 수 있다. `decompose()`를 구현하는 쪽은 이 한계를 알고
  gazetteer 우선순위(ADR-0028 §3 ①)로 보정하거나, 애매하면 어절 전체를 보수적으로 1개 스팬으로
  유지해야 한다(그래서 관리자의 칩 경계 직접 수정이 안전장치로 설계에 포함되어 있다 — FR-L2-8).

## 재검토 트리거

- `garu-ko`가 0.x 버전대(현재 0.9.18)에서 하위호환을 깨는 방식으로 API를 변경하면 `garu-analyzer.ts`
  1개 파일만 갱신하면 된다(포트가 격리하고 있다).
- 어절 단위 오프셋의 한계가 실사용에서 실제로 관리자 혼란을 유발하면(예: 칩 경계 수정 빈도가 비정상적으로
  높으면), `kuromoji-ko`(형태소 경계가 더 세밀하지만 오프셋 규약은 별도 검증 필요)로 교체를 재검토한다.
