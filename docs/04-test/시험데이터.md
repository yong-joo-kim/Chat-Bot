# 시험데이터 (샘플)

> 실제 대량 시험데이터는 `seed/`(Auto QA 컨벤션 참고)에 별도 관리하고, 여기서는 형식과 대표 샘플만 정의한다. **실 고객 대화 원문/PII는 절대 이 문서나 저장소에 포함하지 않는다.**

## 1. 의도(Intent) 샘플

```json
{
  "intentName": "배송조회",
  "examples": [
    "제 주문 어디까지 왔어요?",
    "배송 조회하고 싶어요",
    "택배 언제 도착하나요",
    "주문번호 12345 배송상태 알려줘"
  ]
}
```

## 2. 동음이의어/다의어 사전 샘플

| 단어 | 의미1 (컨텍스트) | 의미2 (컨텍스트) |
|---|---|---|
| 배 | 과일(주문/배송 문맥 아님) | 교통수단(예약 문맥) |
| 다리 | 신체부위(건강상담 챗봇) | 구조물(길찾기 챗봇) |

## 3. 컨텍스트(슬롯필링) 시나리오 샘플 — 커피 주문

```json
{
  "contextName": "coffee_order",
  "slots": [
    { "name": "menu", "prompt": "어떤 음료를 원하세요?", "example": "아메리카노" },
    { "name": "size", "prompt": "사이즈는요?", "example": "톨" },
    { "name": "temperature", "prompt": "따뜻한 걸로 드릴까요, 차갑게 드릴까요?", "example": "아이스" }
  ]
}
```

## 8. 챗봇 운영관리(No.1~4) 시드 데이터 — `apps/api/prisma/seed.ts`

> `docs/requirements/chatbot-operations.md` D-5(빈 상태 검증용 로그 0건 챗봇 포함) 권고를 반영해 **3트랙**으로 구성한다. 그룹/챗봇은 name·slug 기준 upsert(재실행해도 중복 생성되지 않음), 대화로그는 매 실행마다 재생성된다(`pnpm --filter @chat-bot/api prisma:seed`).

| 트랙 | 챗봇 | slug | 상태 | 소속 그룹 | 대화로그 | 검증 대상 |
|---|---|---|---|---|---|---|
| A | 샘플 고객지원 챗봇 | `sample-support-bot` | `ACTIVE` | 고객지원 그룹 | 100건(응답 90 / 미응답 10, sessionId 40종, "배송 조회" 12건·"환불 절차" 7건·공백정규화 1건·빈 문자열 1건 포함) | AC-2-1~2-4(응답률/미응답률/인기질문 정규화), D-1(A안, sessionId 기반 visitCount) |
| B | 빈 대시보드 챗봇 | `empty-dashboard-bot` | `DRAFT` | 고객지원 그룹 | 0건 | AC-2-5/AC-2-6(빈 상태), AC-4-10(DRAFT 임베드 주의문구) |
| C | 레거시 보관 챗봇 | `archived-legacy-bot` | `ARCHIVED` | 보관 그룹 | 20건(30일 이전, 응답률 75%, sessionId 일부 null) | AC-1-11(영구삭제 409), AC-1-12(편집 409), AC-2-10(보관본 대시보드 조회) |

추가로 "테스트 그룹"(챗봇 0개 유지)을 별도로 시드해 EX-1-4(빈 그룹 삭제 정상), AC-1-5(잔여 챗봇 그룹 삭제 거부)와 구분되는 "그룹 자체는 항상 삭제 가능한 빈 상태"를 상시 제공한다.

### 8.1 apps/web 컴포넌트/통합 테스트 픽스처

자동화된 컴포넌트 시험(`apps/web/src/**/*.spec.tsx`)은 위 시드를 그대로 DB에서 읽지 않고 `apps/web/src/test/fixtures.ts`의 순수 함수 픽스처(`makeGroup`/`makeChatbot`/`makeChatbotListItem`/`makeDashboardSummary`/`makeEmptyDashboardSummary`)를 사용한다. 수치는 위 표(트랙 A/B)와 정렬해 두었다 — 예: `makeDashboardSummary()`는 트랙 A의 "배송 조회 12건/환불 절차 7건" 상위질문을, `makeEmptyDashboardSummary()`는 트랙 B(로그 0건)를 그대로 재현한다. 시드 수치를 변경하면 이 픽스처도 함께 갱신해야 한다.

### 8.2 API 통합 테스트 데이터

`apps/api/src/integration/chatbot-operations.integration.spec.ts`는 seed에 의존하지 않고 매 케이스마다 임시 SQLite DB(`prisma db push`)에 그룹/챗봇을 직접 생성한다(`createGroup`/`createChatbot` 헬퍼). `ConversationLog`가 필요한 케이스(AC-1-11, AC-2-10)는 `PrismaService`를 통해 직접 1건 삽입한다. slug는 매번 `Date.now()` + 랜덤 접미사로 유일성을 보장한다.

## 9. 대화 설계(No.5~9) 시험 데이터

### 9.1 `apps/api/prisma/seed.ts`(NFR-M5) — 알려진 공백

`sample-support-bot`에 의도 5건(예문 포함, "빈예문의도" 1건은 EX-D-5용 예문 0개)/키워드 3건/동음이의어 1건("배")/컨텍스트 1건("커피주문")/노드 4건(START·NORMAL 2·FALLBACK)/FAQ 4종(카테고리별 1건 이상)이 있다. **단, 동음이의어 의미(`meanings[].intentId`)와 컨텍스트 슬롯(`slots[].keywordId`)이 실제 의도/키워드를 참조하는 조합은 시드에 없다** — frontend-implementer가 H2 수정 후 자체 보고한 미검증 지점과 동일 공백이다. 수동 확인이나 seed 확장이 필요하면 이 절을 갱신할 것.

### 9.2 API 통합 테스트(H2 검증) — 인라인 fixture로 공백 재현

위 공백은 seed를 건드리지 않고 `apps/api/src/integration/dialogue-design.integration.spec.ts`가 매 케이스마다 직접 만드는 조합으로 재현했다:

- `EX-R-2 / H2`: 의도를 생성 → `intentId`를 연결한 동음이의어(의미 2개, 그중 하나가 그 의도를 참조) 생성 → 의도 삭제 시도 → `409` 메시지에 "동음이의어" 포함 확인.
- `EX-R-3 / H2`: 키워드를 생성 → `type=KEYWORD` 슬롯(`keywordId`가 그 키워드를 참조)을 가진 컨텍스트 생성 → 키워드 삭제 시도 → `409` 메시지에 "컨텍스트" 포함 확인.

`apps/web/src/pages/dialogue/IntentsKeywordsPage.spec.tsx`는 서버 메시지를 그대로 `ApiError` mock으로 주입해 `resolveBlockedRefKind` 매핑과 배너 렌더링·링크 이동까지 프런트 측에서 재검증한다(`DeleteBlockedBanner.spec.tsx`는 순수 컴포넌트 단위로 3가지 kind를 전수 검증).

### 9.3 `packages/dialogue-engine` 성능 시험 규모(M4)

`resolver.performance.spec.ts`는 ADR-0008/FR-E-10이 명시한 설계 규모를 그대로 합성 생성한다 — 의도 1,000건×예문 20건(합 20,000예문), 키워드 50건, 노드 500건(전 의도 구간에 고르게 분산 참조 + FALLBACK 1건), FAQ 2,000건. 노드 매칭 히트/FAQ 매칭 히트/완전 폴백 3가지 경로를 섞은 100회 호출의 P95를 측정한다(2026-09-20 측정치: 인덱스 재사용 시 P95 수 ms대, 200ms 기준 대비 여유 큼).

### 9.4 `apps/web` 대화설계 화면 컴포넌트 시험 픽스처

의도/키워드/노드 목록 아이템은 각 스펙 파일 내부에 `IntentListItem`/`KeywordListItem`/`DialogNodeListItem` 최소 픽스처를 인라인으로 정의한다(`chatbot-operations` 그룹의 `test/fixtures.ts` 패턴과 달리 대화설계 쪽 리소스는 스펙별로 필요한 필드 조합이 크게 달라 공용 팩토리보다 지역 정의가 더 읽기 쉽다고 판단). 공용으로 재사용하는 것은 `makeChatbot`(`test/fixtures.ts`)뿐이다.
