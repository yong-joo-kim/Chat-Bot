### 1.2 이미 있는 것과 없는 것 (코드 확인)

#### 1.2.1 ★ "챗봇 삭제"의 실제 코드 경로 — 대화로그는 **현재 어떤 운영 경로로도 지워지지 않는다**

| 경로 | 코드 | 대화로그(`ConversationLog`)·미응답(`UnansweredQuestion`)에 일어나는 일 |
|---|---|---|
| **보관**(콘솔의 "삭제", `DELETE /chatbots/:id`) | `chatbots.service.ts` 266~279행 `archive()` — `status='ARCHIVED'`만 바꾼다 | **변화 없음.** 통계 API도 보관 챗봇을 허용한다(`stats.service.ts` 65·138행 주석 "ARCHIVED 챗봇도 조회를 허용한다"). 단 **챗봇 목록은 기본적으로 보관 챗봇을 숨긴다**(`chatbots.service.ts` 93~95행) |
| **영구삭제**(`POST /chatbots/:id/permanent-delete`) | `chatbots.service.ts` 282~375행. **291~328행이 하위 9종을 count하고 `conversationLogs`·`unansweredQuestions` 포함 0이 아니면 `409 CHATBOT_HAS_CHILDREN`** | **대화가 1턴이라도 있었던 챗봇은 영구삭제되지 않는다.** 342~366행의 "동반 삭제" 14테이블은 전부 **파생 데이터**(임베딩·RAG 호출로그·증강·분류기·TC·버전·예약)이며 `ConversationLog`는 **없다** |
| 그 밖의 삭제 호출 | 전수 검색 결과 `conversationLog.deleteMany`는 **`prisma/seed.ts` 153·229행뿐**(개발용 시드) | 운영 코드 경로 0건 |

→ **`stats-learning.md` 729행·`stats-learning-설계.md` 898행의 "ADR-0002(영구삭제 시 하위 데이터 제거)와 충돌" 서술은 사실과 다르다.** ADR-0002의 결정은 정반대다 — "암묵적 cascade 금지 · 하위 데이터가 있으면 409"(ADR-0002 17~22행)이고, 감수 비용으로 "**대화로그가 쌓인 챗봇은 사실상 영구 삭제가 불가능해진다. 의도된 것이며 사용자에게는 `ARCHIVED`가 최종 정리 수단이다**"(54행)를 명시했다. "하위 데이터 제거" 분류(ADR-0002 70·79행 갱신)는 **파생 테이블**(버전·예약)에만 적용됐다.

**따라서 "챗봇이 삭제되어도 누적 통계가 남는다"는 요구는 오늘 이미 데이터 차원에서는 성립한다.** 원천이 남아 있기 때문이다. 이 그룹의 실제 과제는 다음 네 가지다.

| # | 실제 공백 | 근거 |
|---|---|---|
| **G-1** | **그룹·전역 집계가 존재하지 않는다.** 통계 4개 엔드포인트 전부 `chatbotId` 필수·챗봇 스코프 | `stats.controller.ts` 22~44행 · `stats.service.ts` 74~77·144~147행 |
| **G-2** | **보관 챗봇이 "보이지 않는다".** 데이터는 있으나 목록 기본값에서 숨겨져 사용자가 합산할 방법이 없다 | `chatbots.service.ts` 93~95행 |
| **G-3** | ★ **그룹 이동이 과거 통계를 소급해서 옮긴다.** `ConversationLog`에 `groupId`가 없고(`schema.prisma` 369~406행) 그룹 소속은 `Chatbot.groupId` **현재값**뿐이다(35~36행). `moveGroup()`(`chatbots.service.ts` 204~221행)은 `groupId`만 갱신한다 → 조회 시점 조인으로 그룹 합계를 내면 **이동 전 그룹의 과거 누적이 줄어든다** | "그룹(서비스) 기준 누적 **유지**"와 직접 충돌하는 유일한 현재 경로 |
| **G-4** | **미래의 로그 삭제 경로에 대한 보호가 없다.** ADR-0002 54행이 예고한 "하위 데이터 함께 삭제" 플로우, No.45 보존기간 정책, 개인정보 파기 요청이 생기는 순간 원천이 사라지고 누적 통계도 함께 사라진다. 지금은 "아무도 지우지 않는다"는 **우연**에 기대고 있다 | ADR-0002 54행 · `stats-learning-설계.md` 904행(보존기간 정책 → No.45) |

**없다**: 그룹·전역 스코프 집계 API와 화면, 대화 당시 그룹 귀속 정보, 로그 삭제 경로를 막는 구조적 장치, 의도별 매칭 집계.

### 1.3 ★ 선결 쟁점 — "삭제된 챗봇의 누적"을 무엇으로 보장하는가

#### 1.3.1 후보 비교

| 후보 | 방식 | "삭제되어도 유지" 충족 | 비용·위험 |
|---|---|---|---|
| **A. 원천 로그 조회 + 로그 삭제 경로 봉인** ★ | 통합 통계는 `ConversationLog`를 **직접 집계**한다(No.14와 같은 방식). ADR-0002의 "대화로그가 있으면 영구삭제 409"를 **통계의 보존 보장으로 명문화**하고, `ConversationLog`·`UnansweredQuestion` 삭제 코드가 **0건임을 정적 검사로 단언**한다. 미래에 삭제 경로가 필요해지면 **대안 B의 스냅샷을 먼저 적재해야 한다**는 교체 지점을 문서·테스트로 고정 | **충족.** 사용자 관점의 "삭제" = 보관이고, 보관 챗봇의 로그는 그대로 집계된다. 영구삭제는 로그가 있으면 애초에 불가능하므로 사라질 원천이 없다 | **가장 낮음.** 신규 테이블 0 · 스케줄러 0 · 집계 정의 1벌(No.14 순수 함수 재사용). 대가: ① 대화가 있었던 챗봇은 **영원히 영구삭제 불가**(현행 그대로) ② 원천이 무기한 보관된다(개인정보 관점 — §1.4, No.45) ③ 데이터가 커지면 성능(재검토 트리거 J-12) |

#### 1.3.2 권장안 — **A**, 단 B를 "다음 단계의 유일한 삭제 경로"로 설계 고정

**근거**
1. **"충돌"이 존재하지 않는다**(§1.2.1). 원천이 구조적으로 보존되는 시스템에서 B·C는 **쓰기 주체 없는 구조**가 된다 — B의 롤업은 영구삭제가 로그를 지우기 전까지 한 행도 생기지 않고, C는 원천이 있는데 사본을 만든다. "쓰기 주체·수용기준 없는 구조는 만들지 않는다"(ADR-0004, ADR-0015 95행)에 어긋난다.
2. **A도 약속이 아니라 구조로 보장한다** — 로그 삭제 코드 0건 정적 검사(FR-I1-3)가 "누군가 편의상 `deleteMany`를 추가"하는 순간을 CI에서 잡는다. ADR-0002가 `onDelete: Restrict` 명시로 "리뷰 포인트"를 만든 것(29행)과 같은 방식이다.
3. **B는 제품 정책 결정이다** — "사용된 챗봇도 완전히 지울 수 있어야 한다"(구독형 해지·개인정보 파기·보관 챗봇 누적 정리)가 필요하면 B가 맞다. 그러나 이는 ADR-0002의 결정 변경 + 자산 9종 "함께 삭제" 플로우(ADR-0002 54행 예고) + 삭제 미리보기 UI를 수반하는 **별도 범위**다. PM이 원하면 이 그룹에 포함할 수 있게 §4.9에 개요를 남긴다(⚠ **P-2**).
4. **C는 성능 문제이지 보존 문제가 아니다** — 보존은 A가 해결하고, 성능은 ADR-0017의 재검토 트리거(로그 1,000만 행 · P95 미달)가 발동할 때 판단한다. `PollingLoop`이 생겨 "채울 주체가 없다"는 사유는 약해졌지만, 재계산 경로·DD-61 불일치·질문 순위 원천 의존이라는 **나머지 기각 사유는 그대로**다(J-12).

### 1.4 데이터 보존과 개인정보 — 이 그룹이 **악화시키지 않는** 선

| 관점 | 사실 | 이 그룹의 입장 |
|---|---|---|
| 원천의 성격 | `userMessage`/`botResponse`는 **금지어·PII 마스킹 후 값만** 저장된다(ADR-0013 §2 — 적재 1곳). 단 규칙 기반이라 **이름·주소는 탐지하지 못한다**(ADR-0013 §6) | 통합 통계는 **새 원문 저장소를 만들지 않는다**. 질문 순위는 이미 있는 마스킹 문자열을 조회 시점에 읽을 뿐(NFR-IS2) |
| 보존 기간 | `ConversationLog`에 보존기간·자동 정리가 **없다**(`stats-learning-설계.md` 904행 → No.45) | 대안 A는 이 상태를 **바꾸지 않는다**(악화도 개선도 아님). 보존기간 정책은 No.45 — 도입 시 **삭제 전에 롤업을 적재해야 한다**는 제약을 이 문서가 남긴다(FR-I1-4) |
| 파기 요구(정보주체 삭제권) | 방문자 식별자가 없어(ADR-0001, `stats-learning-설계.md` 899행) 특정인의 로그를 찾을 수단이 없다 | 범위 밖(No.45). 이 그룹은 식별자를 **추가하지 않는다** |
| 삭제된 챗봇의 질문 원문 | 대안 A: 보관 챗봇의 로그는 원문(마스킹본) 그대로 남으며 그룹 질문 순위에 **나타난다** | 보관 챗봇의 질문은 **개별 챗봇 통계 화면에서 이미 볼 수 있다**(`stats.service.ts` 330행 — 보관 허용). 합산 화면이 새 노출을 만들지 않는다. 단 PM이 "보관 챗봇 질문은 그룹 순위에서 제외"를 원하면 필터 기본값만 바꾼다(⚠ P-5) |
| 대안 B 채택 시 | 롤업에는 **수치만** — 질문 텍스트·세션 ID·의도 ID 원문을 넣지 않는다 | 삭제 = 원문 파기, 누적 = 수치 보존. 이 분리가 B의 존재 이유다(§4.9) |

### 1.5 목적

1. 관리자가 **그룹(서비스) 단위와 전체 단위**로 대화량·응답률·세션·응답 출처·채널·이용 시간대·질문 순위를 **한 화면에서** 본다.
2. 챗봇을 **보관(삭제)해도** 그룹 합계와 누적 KPI가 **줄어들지 않는다**. 보관 챗봇은 챗봇별 기여 표에 "보관됨"으로 남는다.
3. 챗봇을 다른 그룹으로 **옮겨도** 옮기기 전 그룹의 과거 누적이 **소급해 바뀌지 않는다**(⚠ P-3 확정 시).
4. 누적 통계를 지탱하는 원천 로그가 **어떤 코드 경로로도 조용히 사라지지 않는다**(구조적 보장).
5. 선행 그룹이 남긴 부채(KST 헬퍼 중복·`stats:read` 판단·의도별 통계)를 **이번에 정리**한다.
6. No.14 챗봇 스코프 통계·No.2 대시보드의 **동작·응답·수치를 한 글자도 바꾸지 않는다.**

## 2. 사용자 역할 및 시나리오

### 2.1 역할

`security-audit.md` §2.1의 역할 3종을 상속한다. **신규 권한 0종**(J-10 — `Permission` 15종 불변).

| 역할 | 이 그룹에서의 활동 | 권한 |
|---|---|---|
| **ADMIN** | 모든 조회 + (J-5 채택 시) 보관 그룹 확인 | `chatbot:read` |
| **EDITOR** | 모든 조회. 그룹 이동·보관 등 **기존 쓰기 동작의 통계 영향**을 확인 대화상자에서 안내받음 | `chatbot:read` |
| **VIEWER** | 모든 조회(이 그룹에는 쓰기 동작이 없다) | `chatbot:read` |
| 최종 사용자 | 영향 없음. 적재 경로에 필드 1개가 늘 뿐 응답 시간·내용 불변(NFR-IP4) | — |

### 2.2 사용자 시나리오

**S-1. 서비스 단위 월간 보고 (VIEWER · ★ 핵심)**
운영 모니터가 콘솔 홈에서 `전체` → `세무 서비스` 그룹을 선택한다. 누적 카드에 `누적 대화 128,420턴 · 응답률 91.2% · 누적 세션 31,044 · 운영 챗봇 3 / 보관 2 (2024-03-02부터)`가 보인다. 기간을 `월 · 최근 12개월`로 바꾸자 월별 추이 막대와 응답률 선이 나오고, 아래 **챗봇별 기여 표**에 `연말정산봇 62% · 부가세봇 28% · 종소세봇 7% · 2024 연말정산봇(보관됨, 2025-02-10) 3%`가 보인다.

**S-2. 챗봇을 보관해도 그룹 누적이 유지된다 (EDITOR · J-9)**
편집자가 `2024 연말정산봇`을 보관(콘솔의 "삭제")한다. 확인 대화상자에 **"보관해도 이 챗봇의 대화 기록은 그룹 통계에 계속 포함됩니다"** 가 표시된다. 보관 후 `세무 서비스`의 누적 대화 수는 **보관 전과 같다**. 챗봇별 기여 표에서 해당 행에 `보관됨` 배지가 붙는다.

**S-3. 챗봇을 다른 그룹으로 옮긴다 (EDITOR · J-4, ⚠ P-3)**
`부가세봇`을 `세무 서비스`에서 `사업자 서비스`로 옮긴다. 확인 대화상자에 **"이동 이후의 대화만 새 그룹에 집계됩니다. 이동 전 대화는 '세무 서비스' 통계에 남습니다"** 가 표시된다. 이동 후 `세무 서비스`의 지난달 수치는 **변하지 않는다**. `세무 서비스`의 챗봇별 기여 표에 `부가세봇 (현재: 사업자 서비스)`가 남고, `사업자 서비스`에는 이동일 이후 수치만 쌓인다.

**S-4. 빈 그룹을 정리한다 (EDITOR · J-5, ⚠ P-4)**
챗봇을 모두 옮긴 `2024 이벤트` 그룹을 삭제한다. 과거 대화 기록이 있으므로 **그룹은 목록에서 사라지지만 통계에는 `2024 이벤트(보관된 그룹)`으로 남는다**. 대화 기록이 한 번도 없던 그룹은 기존처럼 완전히 삭제된다.

**S-5. 전사 비교 (ADMIN · 전역 스코프)**
관리자가 `전체`를 선택한다. 그룹별 비교표에 그룹 5개(보관 그룹 1개 포함)의 기간 턴 수·응답률·세션·미응답 비율이 나오고, 응답률 낮은 순으로 정렬한다. 행을 누르면 그 그룹 스코프로 이동한다.

**S-6. 그룹 인기 질문 (EDITOR · J-9, ⚠ P-5)**
`세무 서비스`의 인기 질문 Top 10에서 `"연말정산 환급 언제 들어와요"`가 1위이며, 행에 이 질문이 가장 많이 들어온 챗봇이 표시된다. `보관 챗봇 포함` 토글을 끄면 현재 운영 중인 챗봇의 질문만 남는다. 후보 500건 초과로 근사일 때는 **"근사값"** 안내가 뜬다(No.14와 동일).

**S-7. 의도별 매칭 순위 (EDITOR · 챗봇 스코프, J-13)**
`연말정산봇` 통계 화면의 새 섹션 `의도별 매칭`에서 `환급일_문의 18.2% · 공제_항목 12.1% · … · 삭제된 의도(a1b2c3d4) 0.8%`를 본다. 의도 이름을 누르면 해당 의도 편집 화면으로 이동한다(삭제된 의도는 링크 없음).

**S-8. 오래 운영한 대형 그룹 (운영자 · 성능)**
로그 300만 행이 쌓인 그룹의 누적 카드가 2초 안에 뜬다. 5초 안에 집계가 끝나지 않으면 **옛 값을 보여 주지 않고** "지금은 통계를 불러올 수 없습니다. 기간을 줄이거나 잠시 후 다시 시도해 주세요"를 표시한다(ADR-0004 40행 규약 승계).

**S-9. 접근성**
누적 카드·추이 차트·분포는 **표 대체(데이터 표 보기)** 를 제공하고, 보관·이동 표시는 색이 아니라 **텍스트 배지**로 구분한다. 스코프 선택기는 키보드로 조작되며 선택 결과가 `aria-live`로 알려진다.

## 7. 수용기준 (AC)

### AC-I1. 누적 보존 · 봉인

- **AC-I1-1** ★ Given 그룹 G에 챗봇 A(로그 100턴)·B(로그 50턴), When A를 보관하면, Then G의 누적 턴 = **150 그대로**이고 기여 표에 A가 `보관됨`(보관일 포함)으로 남는다.
- **AC-I1-2** Given 보관된 A, When 영구삭제를 요청하면, Then 기존과 같이 `409 CHATBOT_HAS_CHILDREN`이고 안내에 통계 보존 문구가 포함된다. G의 누적은 불변.
- **AC-I1-3** ★ Given 저장소 전체, When 정적 검사를 돌리면, Then `apps/api/src`(테스트 제외)에서 `conversationLog`/`unansweredQuestion`의 삭제 호출·raw `DELETE`가 **0건**이다. 임의 파일에 `conversationLog.deleteMany`를 추가하면 검사가 **실패**한다.
- **AC-I1-4** Given `ACTIVE`·`DRAFT`·`ARCHIVED` 챗봇이 섞인 그룹, When 요약을 조회하면, Then 세 상태의 로그가 모두 합산된다.

### AC-I2. 지표 정의 일치

- **AC-I2-1** ★ Given 챗봇 1개뿐인 그룹, When 같은 기간·단위로 그룹 요약·분포와 챗봇 요약·분포를 조회하면, Then **모든 수치가 같다**(NFR-IM2).
- **AC-I2-2** Given 그룹 G의 챗봇 A·B, When G 요약을 조회하면, Then 턴·응답·미응답·차단 = A + B이고, 세션 = A 세션 + B 세션이다(챗봇 간 세션 비공유).
- **AC-I2-3** Given 자정을 넘긴 세션 1개(일 2개에 걸침), When 주 단위 그룹 요약을 조회하면, Then 그 주의 세션 수에 **1회만** 반영된다(DD-61).
- **AC-I2-4** Given 전역 스코프, When 요약을 조회하면, Then 모든 그룹(보관 그룹 포함) 합계와 같다.
- **AC-I2-5** Given 로그 0건 그룹, When 누적 KPI를 조회하면, Then 모든 수치 0, `firstDayBucket = null`, 응답률 0(오류 아님).
- **AC-I2-6** Given 기여 표, When 비중을 합산하면, Then 정확히 1이다(표시 반올림 제외).
- **AC-I2-7** Given 챗봇 250개 그룹, When 기여 표를 조회하면, Then 200행 + "기타 50개" 합산 행이며 총합이 그룹 요약과 같다.

### AC-I3. 그룹 귀속 (P-3 = 대화 당시 그룹)

- **AC-I3-1** ★ Given 챗봇 A가 그룹 G1에서 9/1~9/10 대화 100턴, 9/11 G2로 이동 후 20턴, When G1·G2의 9월 요약을 조회하면, Then **G1 = 100, G2 = 20**이고 이동 전후로 G1의 9/1~9/10 수치가 변하지 않는다.
- **AC-I3-2** Given 공개 대화 1턴, When 로그를 확인하면, Then `groupId` = 그 시점 챗봇의 `groupId`이고, 해당 턴 처리에 **추가 DB 조회가 없다**(쿼리 계측).
- **AC-I3-3** Given `groupId = ''` 행이 남은 상태, When 그룹 요약을 조회하면, Then `backfillPending: true`이고 화면에 정리 중 안내가 뜬다. 백필 후 `false`이며 수치가 증가한다.
- **AC-I3-4** Given 백필 스크립트를 두 번 실행, When 결과를 비교하면, Then 동일하다(멱등).

### AC-I4. 그룹 삭제 (P-4 = 보관)

- **AC-I4-1** Given 로그가 귀속된 빈 그룹 G1, When 삭제하면, Then `204`, 그룹 목록에서 사라지고 `archivedAt`이 설정되며, 통합 통계의 그룹 선택기에 **"보관된 그룹"** 으로 남아 과거 수치를 그대로 조회할 수 있다.
- **AC-I4-2** Given 로그가 없는 빈 그룹, When 삭제하면, Then 물리 삭제된다(현행).
- **AC-I4-3** Given 보관 그룹 G1, When 챗봇 생성·이동·복사의 대상으로 지정하면, Then `404`다.
- **AC-I4-4** Given 보관 챗봇만 남은 그룹, When 삭제하면, Then 현행 `409 GROUP_NOT_EMPTY`(판정 불변).

### AC-I5. 질문 순위 · 의도별

- **AC-I5-1** Given 그룹 G의 A·B에 같은 질문(공백 변형 포함), When 그룹 질문 순위를 조회하면, Then 1행으로 병합되고 최다 챗봇이 표시된다.
- **AC-I5-2** Given 보관 챗봇 C의 질문, When `includeArchivedChatbots=false`로 조회하면, Then C의 질문이 제외되고, 누적 KPI·요약은 **영향받지 않는다**.
- **AC-I5-3** Given 질문 종류가 500을 넘는 그룹, When 조회하면, Then `approximated: true`다.
- **AC-I5-4** Given 전화번호가 포함된 원 발화, When 그룹 질문 순위를 보면, Then 마스킹된 형태만 보인다(AC-P-9 승계).
- **AC-I5-5** Given 의도 X로 매칭된 30턴 후 X 삭제, When 의도별 통계를 조회하면, Then `deleted: true, name: null` 30턴 행이 있고 화면에 "삭제된 의도(ID 앞 8자리)"가 표시된다.
- **AC-I5-6** Given 의도 매칭 턴 70 · 비매칭 30, When 의도별 통계를 조회하면, Then 의도별 두 비율과 `unmatchedTurnCount = 30`이 반환된다.

### AC-I6. 비회귀 · 권한 · KST · 성능

- **AC-I6-1** ★ Given 이 그룹 적용 전후, When 기존 `/stats/dashboard|summary|distribution|questions` 테스트를 수정 없이 돌리면, Then 전부 통과한다.
- **AC-I6-2** Given VIEWER, When 통합 통계 6종을 호출하면, Then `200`이다. Given 비로그인, Then `401`.
- **AC-I6-3** Given `Permission` 유니온, When 개수를 세면, Then **15**다. `@Public()` 핸들러는 **6**이다.
- **AC-I6-4** Given `dashboard-period.ts`, When 파일을 검사하면, Then `toKstDateOnly`/`kstDateOnlyToUtc` 정의가 없고 `kst-date.ts`를 import한다. 기존 `dashboard-period.spec.ts`가 수정 없이 통과한다.
- **AC-I6-5** Given 임의 시각 1,000개(경계 포함), When `kst-date` 조합과 `toKstDayBucket`을 비교하면, Then 전부 같다.
- **AC-I6-6** Given NFR-IP1 기준 데이터, When 누적 KPI·요약·질문 순위를 측정하면, Then NFR-IP2 예산을 만족한다. 5초 초과를 주입하면 `503 AGGREGATION_TIMEOUT`이고 이전 값을 반환하지 않는다.
- **AC-I6-7** Given 그룹 스코프 세션 집계, When 쿼리 반환 행 수를 계측하면, Then 버킷 수 × 채널 수 이하다(세션 수 비례 아님, NFR-IP3).
- **AC-I6-8** Given 키보드만 사용, When 스코프·기간·토글·정렬을 조작하면, Then 마우스 없이 완료되고 axe 대비 위반 0건이다.
