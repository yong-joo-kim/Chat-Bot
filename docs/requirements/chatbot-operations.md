## 1. 배경 / 목적

### 1.1 배경
`개발명세서.md` §6-3에서 1차 개발 범위가 **기본기능 15개(No.1~15)** 전체로 확정되었다. 그중 이 문서가 다루는 **챗봇 운영관리 4종(No.1~4)** 은 다음 이유로 최초 구현 대상(첫 버티컬 슬라이스)으로 선정되었다.

- GPU 필요도 1(순수 CRUD/집계)로 `apps/ml-worker` 없이 `apps/api` 단독 처리 가능 (`개발명세서.md` §1 설계원칙).
- 다른 기능그룹(대화설계·품질·채널·통계)이 모두 `Chatbot` 엔터티에 종속되므로, 이 그룹이 **모든 후속 기능의 루트 엔터티**를 제공한다.
- 의존성이 가장 적어 `shared-types(zod) → Prisma → NestJS 모듈 → React 콘솔 → 테스트 자동화`로 이어지는 **전체 파이프라인 검증**에 적합하다.

### 1.2 목적
1. 챗봇 관리자가 다수의 챗봇을 **그룹(폴더) 단위로 생성·조회·복사·삭제**할 수 있게 한다.
2. 각 챗봇의 **운영 현황(접속수/응답률/미응답률/인기질문)** 을 한 화면에서 요약 확인하게 한다.
3. 챗봇의 **정체성 정보(이름/아바타/소개/고유 URL)** 와 **외형·배포 수단(스킨/임베드 코드)** 을 코드 수정 없이 설정하게 한다.

### 1.3 이 문서의 범위 경계
현재 DB에는 `ConversationLog`를 생성하는 경로(대화 처리 API)가 없다. 따라서 **No.2 대시보드는 "집계 조회 API + 화면"만 구현**하며, 데이터가 0건인 상태가 **정상 동작 시나리오**로 취급된다(§4.2, §7 AC-2-5 참고).

## 2. 사용자 역할 및 시나리오

### 2.1 역할 정의

| 역할 | 설명 | 이 그룹에서의 권한(Phase 1 목표) |
|---|---|---|
| 챗봇 관리자(Admin) | 챗봇을 생성·설정·배포하는 고객사 운영 담당자 | 전 기능 CRUD |
| 운영 모니터(Viewer) | 지표만 확인하는 보조 담당자 | 조회 전용(대시보드/리스트) |
| 최종 사용자(End User) | 임베드된 챗봇과 대화하는 웹 방문자 | 직접 접근 없음 — 스킨/임베드 결과물의 **소비자** |

> **주의**: 인증·RBAC은 No.12(회원·권한·보안 관리)의 범위이며 별도 Phase다. 이 그룹에서는 **권한 검사 훅이 삽입될 지점(컨트롤러 가드 위치)** 만 식별해 두고, 실제 역할 분기는 구현하지 않는다(§9 Out of scope).

### 2.2 사용자 시나리오

**S-1. 신규 챗봇 개설 (관리자)**
관리자가 콘솔에 접속해 좌측 그룹 트리에서 `+ 그룹 추가`로 "고객지원 그룹"을 만든다. 그룹을 선택한 상태에서 `+ 챗봇 만들기`를 눌러 이름("주문 상담봇")과 고유 URL(slug, `order-bot`)을 입력한다. 저장하면 챗봇이 `DRAFT` 상태로 생성되고, 바로 기본설정 화면으로 이동한다.

**S-2. 기존 챗봇 복제로 빠른 개설 (관리자)**
유사한 챗봇을 하나 더 만들기 위해 리스트에서 기존 챗봇의 `복사`를 누른다. 시스템은 이름에 `(사본)`, slug에 `-copy` 접미를 자동 부여하고 `DRAFT` 상태로 복제한다. 관리자는 기본설정에서 이름/slug만 실제 값으로 바꾼다.

**S-3. 운영 현황 확인 (관리자/운영 모니터)**
관리자가 챗봇을 선택하고 대시보드 탭을 연다. 기간 선택(오늘/최근 7일/최근 30일/직접 지정)에 따라 접속수, 응답률, 미응답률, 인기질문 TOP 5가 카드 형태로 표시된다. 미응답률이 높으면 향후 No.15(학습현황)로 이동해 보완한다.

**S-4. 신규 챗봇의 빈 대시보드 확인 (관리자)**
방금 만든 챗봇의 대시보드를 연다. 대화 이력이 없으므로 "아직 수집된 대화 데이터가 없습니다"라는 빈 상태 안내와 함께 모든 지표가 `0`으로 표시되고, 오류 화면이나 `NaN`은 나타나지 않는다.

**S-5. 브랜드에 맞춰 외형 변경 (관리자)**
스킨 설정에서 주 색상을 회사 브랜드 컬러로 바꾸고 헤더 문구를 "OO기업 고객센터"로 수정한다. 우측 실시간 미리보기에 즉시 반영된다. 색상 대비가 기준(4.5:1) 미만이면 경고 배지가 뜬다.

**S-6. 홈페이지에 붙이기 (관리자 → 웹개발자)**
임베드 탭에서 PC용/모바일용 스니펫을 각각 확인하고 `복사` 버튼으로 클립보드에 담아 사내 웹개발자에게 전달한다.

**S-7. 사용 종료 챗봇 정리 (관리자)**
더 이상 쓰지 않는 챗봇을 `보관(ARCHIVED)` 처리한다. 리스트 기본 필터에서 사라지지만 "보관됨" 필터로 다시 볼 수 있고, 누적 통계는 유지된다. 그룹을 지우려 하면 소속 챗봇이 남아 있어 삭제가 거부되고, 챗봇을 먼저 정리하라는 안내가 뜬다.

## 4. 기능별 요구사항

### 4.1 No.1 — 챗봇 리스트/그룹 관리

#### 4.1.1 그룹(ChatbotGroup) CRUD

| ID | 요구사항 |
|---|---|
| FR-1-1 | 그룹을 생성할 수 있다. 입력: `name`(필수, 1~100자), `description`(선택, 최대 500자). |
| FR-1-2 | 그룹 목록을 조회할 수 있다. 각 항목은 `id`, `name`, `description`, **소속 챗봇 수(`chatbotCount`)**, `createdAt`, `updatedAt`를 포함한다. 기본 정렬은 `createdAt` 오름차순. |
| FR-1-3 | 그룹 단건을 조회할 수 있다. |
| FR-1-4 | 그룹의 `name`/`description`을 수정할 수 있다(부분 수정, PATCH). |
| FR-1-5 | 그룹을 삭제할 수 있다. **소속 챗봇이 1건 이상이면 삭제를 거부**하고 `409`와 함께 잔여 챗봇 수를 안내한다(§8 EX-1-3). |
| FR-1-6 | 그룹명은 **전역 중복을 허용**한다(운영 편의). 단 동일 이름 그룹이 이미 있으면 UI에서 "같은 이름의 그룹이 있습니다" 안내 문구를 표시한다(차단은 아님). |
| FR-1-7 | 그룹을 복사할 수 있다. 새 그룹명은 `{원본명} (사본)`으로 자동 생성되며, **그룹에 속한 챗봇들도 함께 복제**된다(복제 규칙은 FR-1-13을 따른다). |

#### 4.1.2 챗봇(Chatbot) 리스트/CRUD

| ID | 요구사항 |
|---|---|
| FR-1-8 | 챗봇을 생성할 수 있다. 입력은 `CreateChatbotSchema`(`groupId`, `name`, `slug` 필수 / `avatarUrl`, `description` 선택)를 따른다. 생성 시 `status`는 항상 `DRAFT`, `skin`은 기본값(`primaryColor: #4F46E5`, `headerTitle: 챗봇 상담`)으로 초기화한다. |
| FR-1-9 | 챗봇 목록을 조회할 수 있다. 필터: `groupId`(선택), `status`(`DRAFT`/`ACTIVE`/`ARCHIVED`, 복수 선택 가능), `q`(이름·slug 부분 일치 검색). 정렬: `createdAt`/`updatedAt`/`name` × `asc`/`desc`(기본 `updatedAt desc`). |
| FR-1-10 | 목록 기본 필터는 `status != ARCHIVED`이며, 사용자가 "보관됨 포함" 토글로 확장할 수 있다. |
| FR-1-11 | 목록 각 행은 `아바타(또는 이니셜 대체)`, `이름`, `slug`, `상태 배지`, `소속 그룹명`, `수정일시`와 행 액션(설정/스킨·임베드/대시보드/복사/그룹 이동/삭제)을 제공한다. |
| FR-1-12 | 챗봇의 소속 그룹을 다른 그룹으로 이동할 수 있다(`groupId` 변경). 대상 그룹이 없으면 `404`. |
| FR-1-13 | 챗봇을 복사할 수 있다. 복제 규칙: `name` → `{원본명} (사본)`(100자 초과 시 말줄임 후 접미), `slug` → `{원본slug}-copy`(이미 존재하면 `-copy-2`, `-copy-3` … 순차 증가, 50자 초과 시 앞부분을 잘라 길이를 맞춤), `status` → `DRAFT`, `avatarUrl`/`description`/`skin` → 원본 값 그대로, `groupId` → 원본과 동일(요청에서 지정 시 지정 그룹). |
| FR-1-14 | **복제 범위 제한**: Phase 1의 복사는 `Chatbot` 레코드 자체(기본설정 + 스킨)만 대상으로 하며, 하위 리소스(의도/키워드/FAQ/대화노드/채널/대화로그)는 복제하지 않는다. UI는 복사 확인 모달에서 이 제한을 명시한다. |
| FR-1-15 | 챗봇 삭제는 **2단계**로 동작한다. (a) `삭제` = `status`를 `ARCHIVED`로 전환(되돌릴 수 있음), (b) `영구 삭제` = `ARCHIVED` 상태에서만 가능하며 확인 문구(챗봇 이름 타이핑) 입력 후 레코드 제거. |
| FR-1-16 | 영구 삭제 시 해당 챗봇에 연결된 `ConversationLog` 등 하위 레코드가 존재하면 `409`로 거부한다(참조 무결성 보호). 하위 데이터 일괄 삭제(cascade)는 이 Phase 범위 밖이다. |
| FR-1-17 | 챗봇 상태를 `DRAFT ↔ ACTIVE ↔ ARCHIVED`로 전환할 수 있다. 허용 전이는 `DRAFT→ACTIVE`, `ACTIVE→ARCHIVED`, `DRAFT→ARCHIVED`, `ARCHIVED→DRAFT`이며, `ARCHIVED→ACTIVE` 직접 전이는 금지한다(복구 후 재검수 강제). |
| FR-1-18 | `ARCHIVED` 상태 챗봇은 기본설정/스킨 수정 API가 `409`로 거부되고, UI의 편집 컨트롤은 비활성화 + 사유 안내를 표시한다. |

#### 4.1.3 화면 요구사항 (ui-designer 인계용)
- 좌측: 그룹 트리(그룹명 + 챗봇 수 배지), 상단: 검색/상태 필터/정렬, 본문: 챗봇 카드 또는 테이블, 우상단: `+ 챗봇 만들기`.
- 삭제/영구삭제/복사는 모달 확인 절차를 거치며, 모달은 포커스 트랩 + `Esc` 닫기 + 포커스 복귀를 보장한다(UIUX §3).
- 상태는 색상 배지 + **텍스트 레이블 병기**(색상 단독 전달 금지, UIUX §1).

### 4.2 No.2 — 대시보드

#### 4.2.1 집계 대상 및 정의

응답 스키마는 이미 정의된 `DashboardSummarySchema`(`packages/shared-types/src/stats.ts`)를 그대로 사용한다.

| ID | 지표 | 정의(Phase 1 확정 규칙) |
|---|---|---|
| FR-2-1 | `visitCount` (접속수) | 기간 내 해당 챗봇의 **고유 대화 세션 수**. 세션 식별자가 없으면 **`ConversationLog` 건수(대화 건수)** 를 대리 지표로 사용한다(§5.4 데이터 이슈 D-1 참고). 어떤 정의를 쓰든 UI 카드 하단에 산정 기준을 캡션으로 명시한다. |
| FR-2-2 | `responseRate` (응답률) | `isAnswered = true`인 로그 수 ÷ 전체 로그 수. 0~1 실수, **소수 넷째 자리 반올림**. |
| FR-2-3 | `noResponseRate` (미응답률) | `1 - responseRate`로 계산한다(별도 집계하지 않아 합이 항상 1이 되도록 보장). |
| FR-2-4 | `topQuestions` (인기질문) | 기간 내 `userMessage`를 **정규화**(앞뒤 공백 제거, 연속 공백 1칸 축약)한 값으로 그룹핑해 건수 내림차순 상위 N건. 기본 N=5, 쿼리로 1~10 지정 가능. 동률이면 최근 발생 시각이 늦은 것을 우선한다. 빈 문자열은 제외한다. |

| ID | 요구사항 |
|---|---|
| FR-2-5 | 대시보드는 **챗봇 단위**로 조회한다. 요청: `chatbotId`(필수), `from`/`to`(선택). |
| FR-2-6 | 기간 프리셋으로 `오늘`, `최근 7일`, `최근 30일`, `직접 지정`을 제공한다. 기본값은 **최근 7일**이다. |
| FR-2-7 | 기간 경계는 `Asia/Seoul` 기준 `from` 00:00:00.000 ~ `to` 23:59:59.999(포함)로 해석해 UTC로 변환 후 질의한다. 응답의 `periodStart`/`periodEnd`에는 실제 적용된 경계를 그대로 담아 반환한다. |
| FR-2-8 | `from > to`이거나 기간이 **366일을 초과**하면 `400`을 반환한다. |
| FR-2-9 | **빈 상태(로그 0건)** 에서도 `200`을 반환하며 `visitCount: 0`, `responseRate: 0`, `noResponseRate: 0`, `topQuestions: []`로 응답한다. 0으로 나누기, `NaN`, `null`을 반환해서는 안 된다. |
| FR-2-10 | 화면은 빈 상태일 때 지표 카드에 `0`(및 `0%`)을 표시하고, 인기질문 영역에는 "아직 수집된 대화 데이터가 없습니다. 챗봇을 배포하고 대화가 쌓이면 표시됩니다."라는 **빈 상태(Empty State) 안내와 다음 행동 링크**(임베드 설정 바로가기)를 제공한다. 오류 스타일(빨강)로 표현하지 않는다. |
| FR-2-11 | 존재하지 않는 `chatbotId`는 `404`를 반환한다. `ARCHIVED` 챗봇도 **대시보드 조회는 허용**한다(누적 지표 보존 목적). |
| FR-2-12 | 조회 중에는 카드별 스켈레톤을 표시하고, 완료 시 "조회 기간 · 집계 건수" 배지로 완료 상태를 구분 표시한다(UIUX §8). |
| FR-2-13 | 응답률/미응답률은 백분율 표기(소수 첫째 자리)로 화면에 표시하되, 색상만으로 좋고 나쁨을 전달하지 않고 수치 + 레이블을 함께 표기한다. |
| FR-2-14 | 대시보드 화면에 `새로고침` 버튼을 제공하며, 연타 시 중복 요청이 발생하지 않도록 진행 중 비활성화한다(UIUX §4). |

> **연계 메모**: 그룹 전체/전 챗봇 합산 대시보드, 시계열 추이 그래프, 일/주/월 드릴다운은 No.14(기본 통계)·No.29(통합 통계)의 범위로 이 Phase에서 제외한다(§9).

| NFR-S4 | 대시보드 응답에는 `userMessage` 원문이 인기질문 형태로 포함되므로, 원천 로그 저장 시점의 **PII 마스킹 전제**(`개발명세서.md` §5)를 문서로 명시하고, 마스킹은 대화 처리 Phase의 책임으로 둔다. |

| NFR-S6 | 삭제/영구삭제 등 파괴적 동작은 GET으로 노출하지 않는다. |

## 7. 수용기준 (Acceptance Criteria)

### AC-1. 챗봇 리스트/그룹 관리 (No.1)

- **AC-1-1** Given 그룹이 없는 상태, When 이름 "고객지원 그룹"으로 그룹을 생성하면, Then `201`과 함께 `id`/`createdAt`이 채워진 그룹이 반환되고 목록에 `chatbotCount: 0`으로 나타난다.
- **AC-1-2** Given 그룹이 존재, When `name: "주문봇"`, `slug: "order-bot"`으로 챗봇을 생성하면, Then `201`이 반환되고 `status`는 `DRAFT`, `skin`은 기본값(`#4F46E5`, `챗봇 상담`)으로 초기화된다.
- **AC-1-3** Given `slug: "order-bot"` 챗봇이 이미 존재, When 동일 slug로 다시 생성하면, Then `409`와 "이미 사용 중인 고유 URL입니다. 다른 값을 입력해 주세요." 메시지가 반환되고 신규 레코드는 생성되지 않는다.
- **AC-1-4** Given `slug: "Order_Bot!"`(대문자/특수문자), When 생성 요청하면, Then `409`가 아닌 `400`과 함께 `field: "slug"` 형식 오류가 반환된다.
- **AC-1-5** Given 챗봇 3개가 속한 그룹, When 그룹 삭제를 요청하면, Then `409`와 "소속 챗봇 3개를 먼저 이동하거나 삭제해 주세요."가 반환되고 그룹과 챗봇 모두 보존된다.
- **AC-1-6** Given 소속 챗봇이 0개인 빈 그룹, When 그룹 삭제를 요청하면, Then `204`가 반환되고 목록에서 제거된다.
- **AC-1-7** Given `slug: "order-bot"` 챗봇, When 복사를 요청하면, Then 새 챗봇의 `name`은 `주문봇 (사본)`, `slug`는 `order-bot-copy`, `status`는 `DRAFT`이고 `skin`은 원본과 동일하다. 원본은 변경되지 않는다.
- **AC-1-8** Given `order-bot-copy`가 이미 존재, When 같은 원본을 다시 복사하면, Then 새 slug는 `order-bot-copy-2`가 되고 `409`가 발생하지 않는다.
- **AC-1-9** Given 챗봇 3개가 속한 그룹, When 그룹 복사를 요청하면, Then 새 그룹이 생성되고 그 안에 3개 챗봇이 FR-1-13 규칙으로 복제되며, 각 복제본은 원본과 동일한 이름·소개·스킨 설정을 갖고 모두 `DRAFT` 상태다.
- **AC-1-10** Given `ACTIVE` 챗봇, When 삭제(보관)를 요청하면, Then `204` 후 `status`가 `ARCHIVED`로 바뀌고 기본 목록 필터에서 사라지며 "보관됨 포함" 토글 시 다시 보인다.
- **AC-1-11** Given `ARCHIVED` 챗봇에 `ConversationLog`가 1건 이상 존재, When 영구 삭제를 요청하면, Then `409`가 반환되고 레코드는 보존된다.
- **AC-1-12** Given `ARCHIVED` 챗봇, When 기본설정 또는 스킨 수정을 요청하면, Then `409`가 반환되고 UI 편집 컨트롤은 비활성 + 사유 안내가 표시된다.
- **AC-1-13** Given `ARCHIVED` 챗봇, When `ACTIVE`로 직접 전환을 요청하면, Then `400`이 반환된다. `DRAFT`로의 전환은 `200`으로 성공한다.
- **AC-1-14** Given 챗봇 30개, When `pageSize=20`으로 목록을 조회하면, Then `items` 20건, `total: 30`, `page: 1`이 반환되고 2페이지에 나머지 10건이 반환된다.
- **AC-1-15** Given 이름에 "주문"을 포함한 챗봇 2개, When `q=주문`으로 검색하면, Then 해당 2건만 반환된다.
- **AC-1-16** Given 존재하지 않는 `groupId`, When 챗봇 생성 또는 그룹 이동을 요청하면, Then `404`가 반환된다.

### AC-2. 대시보드 (No.2)

- **AC-2-1** Given 최근 7일 내 로그 100건(응답 90건, 미응답 10건), When 대시보드를 조회하면, Then `responseRate: 0.9`, `noResponseRate: 0.1`이 반환되고 두 값의 합은 정확히 `1`이다.
- **AC-2-2** Given 동일 질문 "배송 조회"가 12건, "환불 절차"가 7건 기록, When 대시보드를 조회하면, Then `topQuestions[0] = { question: "배송 조회", count: 12 }`, `topQuestions[1] = { question: "환불 절차", count: 7 }` 순으로 반환된다.
- **AC-2-3** Given 질문 종류가 20가지, When `topN` 미지정으로 조회하면, Then `topQuestions` 길이는 5다. `topN=10`이면 10이다.
- **AC-2-4** Given `" 배송  조회 "`와 `"배송 조회"`가 각각 기록, When 조회하면, Then 정규화되어 `"배송 조회"` 1개 항목에 합산된 count로 반환된다.
- **AC-2-5** Given `ConversationLog`가 0건인 신규 챗봇, When 대시보드를 조회하면, Then `200`과 함께 `visitCount: 0`, `responseRate: 0`, `noResponseRate: 0`, `topQuestions: []`가 반환되며 `NaN`/`null`/5xx가 발생하지 않는다.
- **AC-2-6** Given 위와 동일한 빈 상태, When 대시보드 화면을 열면, Then 지표 카드에 `0`/`0.0%`가 표시되고 인기질문 영역에 빈 상태 안내 문구와 임베드 설정 바로가기가 노출되며, 오류(빨강) 스타일이 아니다.
- **AC-2-7** Given 기간 미지정, When 조회하면, Then 최근 7일(`Asia/Seoul` 기준 오늘 23:59:59.999까지)이 적용되고 응답의 `periodStart`/`periodEnd`가 실제 적용 경계와 일치한다.
- **AC-2-8** Given `from`이 `to`보다 늦거나 기간이 367일, When 조회하면, Then `400`과 사유 메시지가 반환된다.
- **AC-2-9** Given 존재하지 않는 `chatbotId`, When 조회하면, Then `404`가 반환된다.
- **AC-2-10** Given `ARCHIVED` 챗봇에 과거 로그 존재, When 대시보드를 조회하면, Then `200`으로 과거 지표가 정상 반환된다.
- **AC-2-11** Given 대시보드 화면, When 조회가 진행 중이면, Then 카드 영역에 스켈레톤이 표시되고 완료 시 "조회 기간 · 집계 건수" 배지로 전환된다.
- **AC-2-12** Given 새로고침 버튼, When 빠르게 2회 클릭하면, Then 요청은 1회만 발생한다.

### AC-3. 챗봇 기본설정 (No.3)

- **AC-3-1** Given 챗봇 상세, When `name`만 변경해 PATCH하면, Then `200`과 함께 `name`·`updatedAt`만 변경되고 `slug`/`skin`/`status`는 보존된다.
- **AC-3-2** Given `name`을 빈 문자열로, When PATCH하면, Then `400`과 `field: "name"` 오류가 반환된다.
- **AC-3-3** Given `description`을 501자로, When PATCH하면, Then `400`이 반환되며, UI는 입력 중 501자 도달 시 잔여 글자 수 카운터로 초과 상태를 표시한다.
- **AC-3-4** Given `avatarUrl`에 `javascript:alert(1)` 입력, When PATCH하면, Then `400`이 반환된다.
- **AC-3-5** Given `slug`에 예약어 `admin` 입력, When PATCH하면, Then `400`과 "사용할 수 없는 예약어입니다." 메시지가 반환된다.
- **AC-3-6** Given slug 입력란, When 다른 챗봇이 이미 쓰는 값을 입력하면, Then 저장 전 400ms 이내 디바운스 후 "이미 사용 중" 상태가 아이콘 + 텍스트로 표시되고 저장 버튼이 비활성화된다.
- **AC-3-7** Given slug 변경 시도, When 저장을 누르면, Then 기존 임베드 코드 무효화 경고 모달이 먼저 표시되고, 사용자가 확인해야만 PATCH가 전송된다.
- **AC-3-8** Given 변경 사항이 있는 폼, When 다른 화면으로 이동하면, Then 저장되지 않은 변경 사항 확인이 표시된다.
- **AC-3-9** Given 저장 성공, When 응답을 받으면, Then 완료 토스트가 노출되고 화면의 공개 URL 미리보기가 새 slug로 갱신된다.

### AC-4. 스킨/임베드 설정 (No.4)

- **AC-4-1** Given 스킨 설정 화면, When `primaryColor`를 `#0F62FE`로 바꾸면, Then 저장 전에 미리보기 헤더 색상이 즉시 변경된다.
- **AC-4-2** Given `primaryColor`에 `#GGGGGG` 또는 `blue` 입력, When 저장하면, Then `400`과 형식 안내가 반환된다.
- **AC-4-3** Given `primaryColor`를 흰 텍스트 대비 4.5:1 미만인 밝은 색(예: `#FFF176`)으로 설정, When 값을 입력하면, Then 대비 경고 배지와 수치, 대안 안내가 표시되되 저장은 차단되지 않는다.
- **AC-4-4** Given `headerTitle`을 51자로, When 저장하면, Then `400`이 반환된다.
- **AC-4-5** Given 스킨을 저장 후 재조회, When 챗봇 단건을 조회하면, Then `skin`이 **객체 형태**(문자열 아님)로 반환되고 저장값과 일치한다.
- **AC-4-6** Given `기본값으로 되돌리기` 클릭 후 확인, When 저장하면, Then `skin`이 `{ primaryColor: "#4F46E5", headerTitle: "챗봇 상담" }`로 초기화되고 `logoUrl`은 제거된다.
- **AC-4-7** Given 임베드 탭, When 화면을 열면, Then PC용/모바일용 스니펫 2종과 공개 URL이 표시되고 각각 복사 버튼을 갖는다.
- **AC-4-8** Given 복사 버튼, When 클릭하면, Then 클립보드에 코드 전문이 담기고 "복사되었습니다" 피드백이 표시된다.
- **AC-4-9** Given `slug`를 `order-bot` → `order-bot-v2`로 변경, When 임베드 탭을 다시 열면, Then 스니펫의 식별자가 `order-bot-v2`로 갱신되어 있다.
- **AC-4-10** Given `DRAFT` 상태 챗봇, When 임베드 탭을 열면, Then 활성화 필요 주의 문구와 상태 전환 바로가기가 표시되고, 코드 확인·복사는 가능하다.
- **AC-4-11** Given `headerTitle`에 `<script>alert(1)</script>` 저장, When 미리보기·임베드 코드 영역이 렌더링되면, Then 스크립트가 실행되지 않고 문자 그대로 표시된다.

### AC-5. 공통/횡단

- **AC-5-1** 모든 엔드포인트 응답이 대응하는 zod 스키마 파싱을 통과한다(계약 테스트).
- **AC-5-2** 검증 오류 응답은 항상 `details[].field`를 포함해 UI가 필드 하단에 인라인 오류를 렌더링할 수 있다.
- **AC-5-3** 그룹 트리 → 리스트 → 설정 폼 → 저장까지 전 과정을 **마우스 없이 키보드만으로** 완료할 수 있다.
- **AC-5-4** axe 등 자동 접근성 스캔에서 대비 4.5:1 미만 요소 0건이다(`시험항목.md` TC-A2).
- **AC-5-5** 삭제/복사/영구삭제 확인 모달에서 `Esc`로 취소 시 아무 변경도 발생하지 않고 포커스가 트리거 버튼으로 복귀한다.

| EX-1-10 | 두 관리자가 동시에 같은 챗봇 수정 | Phase 1은 last-write-wins. 응답의 `updatedAt`으로 최신 상태를 화면에 반영 |
| EX-2-1 | **대화 로그 0건 상태의 대시보드** | `200` + 모든 지표 0 + `topQuestions: []` + 화면 빈 상태 안내(오류 아님) |
| EX-2-2 | 기간 내 로그는 있으나 전부 미응답 | `responseRate: 0`, `noResponseRate: 1` (스키마 범위 내 정상값) |
| EX-2-3 | `userMessage`가 공백/빈 문자열인 로그 | `topQuestions` 집계에서 제외. 단 `visitCount`/응답률 분모에는 포함 |
| EX-2-4 | 잘못된 기간(역전/366일 초과/파싱 불가) | `400` + 사유 |
| EX-2-5 | 집계 쿼리 타임아웃 | `503`(또는 `500`) + "잠시 후 다시 시도해 주세요" + 화면 재시도 버튼. 캐시된 이전 결과를 임의로 보여주지 않는다 |
| EX-3-1 | `avatarUrl`/`logoUrl`에 비허용 스킴 또는 잘못된 URL | `400` |
| EX-3-2 | 아바타 이미지 URL이 깨져 로드 실패 | 이니셜 대체 아바타로 폴백, 콘솔 오류로 화면이 깨지지 않음 |
| EX-3-3 | `slug` 변경 후 기존 임베드 코드가 동작하지 않음 | 변경 전 경고 모달로 사전 고지(FR-3-8). 리다이렉트/별칭 유지는 이 Phase 범위 밖 |
| EX-4-1 | DB의 `skin` JSON 문자열이 손상/파싱 실패 | 기본 스킨으로 폴백 + 서버 경고 로그, 사용자에게는 정상 화면 제공 |
| EX-4-2 | 클립보드 API 미지원/권한 거부 | 코드 영역 전체 선택 + "Ctrl+C로 복사해 주세요" 안내로 폴백 |
| EX-4-3 | 위젯 base URL 환경변수 미설정 | 서버 기동 시 설정 검증 실패로 조기 오류. 임베드 API는 `500` 대신 명확한 설정 오류 메시지 반환 |
| EX-X-1 | 관리자 로그인 세션 만료(No.12 도입 후) | `401` 수신 시 편집 중 내용을 로컬에 보존한 채 재로그인 유도. **이 Phase에서는 401 처리 훅 자리만 마련** |
| EX-X-2 | 금지어/비속어가 챗봇 이름·헤더 문구에 입력 | 이 Phase에서는 차단하지 않음. No.12 금지어 필터 도입 시 적용 지점(설정 저장 전 검증)으로 표시만 해 둔다 |
| EX-X-3 | 다국어 입력(영문/일문 등) 이름·소개 | 저장·표시 모두 정상 동작해야 한다(UTF-8). 단 **UI 레이블 다국어화는 범위 밖** |

## 9. Out of scope (이번 Phase 제외)

### 9.1 다른 기능그룹 — 별도 Phase
- **대화 설계(빌더) 그룹 No.5~9**: 대화 그래프(시나리오) 빌더, 의도(Intent)·키워드(Entity) 관리, 동음이의어/다의어 사전, 컨텍스트(멀티턴/슬롯필링), FAQ 관리 — 전부 별도 Phase. 본 Phase의 챗봇 복사는 이 하위 리소스를 복제하지 않는다(FR-1-14).
- **품질 관리 No.10**(응답 테스트/시뮬레이션), **관리/보안 No.12~13**(회원·권한·보안, 이력관리), **통계/분석 No.14~15**(기본 통계, 학습현황) — 별도 Phase.
- 확장기능/옵션(No.16~47) 전체.

### 9.2 실제 채널 연동 — No.11, 별도 Phase
- 카카오톡/라인/페이스북/네이버톡톡/앱/키오스크 등 **외부 채널 연동 및 Webhook 처리**는 No.11의 범위로 이번 Phase에서 제외한다.
- 본 Phase의 No.4는 **임베드 코드 문자열의 생성·표시·복사**까지만 다루며, `apps/widget` 스크립트의 실제 로딩·렌더링·대화 동작은 위젯 구현 Phase에서 검증한다(FR-4-15).

## 10. `기능요구사항.md` 갱신 제안

이번 분석에서 기준 목록(`docs/01-requirements/기능요구사항.md` §2)과 대조한 결과 **기능 항목의 추가·삭제는 불필요**하며, 아래 **설명 보강 2건 + 각주 1건**만 제안한다. 반영 여부는 PM 확인 후 결정한다.

| 대상 | 현재 문구 | 제안 |
|---|---|---|
| §2 No.1 기능 설명 | "다수 챗봇을 그룹(폴더)으로 생성·조회·복사·삭제" | "다수 챗봇을 그룹(폴더)으로 생성·조회·복사·삭제. **복사는 챗봇 단건/그룹 단위 모두 지원하며, 하위 대화설계 리소스 포함 여부(deep copy)는 Phase별로 구분**" — TC-01("그룹 복사 → 챗봇 3개 동일 설정")과 구현 범위의 정합성을 명확히 하기 위함 |

| §2 No.4 기능 설명 | "채팅창 테마 변경, PC/모바일 임베드 코드 제공" | 동일 + 비고 "**Phase 1 스킨 범위는 주색상/헤더문구/로고 3종**(`ChatbotSkinSchema`). 폰트·다크모드 등 고급 테마는 후속 확장" |
