### 1.2 원본 근거 — "무엇을 요구하는가"

**근거 2 — ROCHA 원 절차**(No.28 원문 "학습 완료된 챗봇을 지정 시각에 자동 반영" · `scheduled-deploy.md` 57행): 원본은 **운영본과 학습본이 동시에 존재**하고 "교체"를 예약한다. No.28은 두 벌이 없어서 이를 부분 충족(버전 예약 복원 — 준비 편집이 운영에 노출)했다(T-5).

#### 1.3.5 대화 엔진 — 동점 규칙이 `updatedAt`을 본다(C-1)

`rankNodes()` = `priority desc → 조건 수 desc → ALL 우선 → **updatedAt desc** → id asc`(`packages/dialogue-engine/src/node-matcher.ts` 84~104행). 라이브 번들은 행별 실제 `updatedAt`을, 스냅샷 번들은 전부 `capturedAt`(동일값)을 쓴다 → 운영 버전에서는 `updatedAt` 단계가 무력화되고 `id asc`가 승자를 정한다. **캡처 직전 초안 시뮬레이터에서 본 답과 운영 서빙 답이 동점 노드에서 다를 수 있다.** 엔진은 수정하지 않으므로(J-13) 해법은 **스냅샷에 항목별 `updatedAt`을 해시 밖 보조 필드로 담는 것**(업캐스터 — 과거 스냅샷은 `capturedAt` 폴백) 또는 **초안 시뮬레이터·TC와 운영이 같은 역직렬화 번들을 보게 하는 것**이다(architect — FR-EN2-4).

| 판정 | **1차 권고** — 카탈로그 비고·ADR-0032가 예고한 형태, 학습 루프·TC·통계가 자연스럽다. 대가: C-1·C-2·번들 소스(4건) | **기각(1차)** — 드리프트·ID 대응표·통계 분산. 공개 경로를 안 바꾸는 장점은 있으나 학습 루프가 깨진다 | **2차 권고** — (a) 위에 "버전 파일 내보내기 → 다른 서버 챗봇에 적재(초안으로)"를 얹는다. ADR-0037 적재기 + 차이 적용 + 대응표가 부품 |

**권고 요약**: (a)를 1차로, (c)를 2차(구축형 망분리 고객 요구 확인 시)로. (a)에서 가져온 버전은 **대상 서버의 초안**에 들어가므로 (c)는 (a)와 충돌하지 않고 위에 쌓인다.

### 1.6 ★ 선결 쟁점 3 — 승격 · 트래픽 전환 · 롤백 (P-2 · P-3 · P-7)

- **승격**(초안 → 스테이징): 초안을 캡처해 버전을 만들고(직전 버전과 해시 같으면 재사용) 스테이징 포인터를 옮긴다. **자산 테이블 쓰기 0**.
- **운영 전환**(스테이징 → 운영): 운영 포인터를 스테이징 버전으로 옮긴다. 새 캡처 없음.
- **전환 방식**: (a) 즉시만 (b) 즉시 + **예약**(No.28 포인터 전환 동작) (c) (b) + **비율 분할**(세션 고정 카나리/A·B) — 원문 동사는 "전환"이고 분할은 로그 귀속·통계 비교·세션 고정 규칙이 함께 필요하다 → **(b) 권고, 분할 2차**(로그 `servedVersionId`는 1차에 넣어 대비).
- **롤백**: 운영 포인터를 **직전 운영 버전**(전환 이력)으로 되돌린다 — 쓰기 1행, 즉시, 자산 무변경. **No.25 복원과 역할이 나뉜다**: 복원 = 초안의 시간축 되돌리기, 롤백 = 운영 포인터 되돌리기. 긴급 차단은 기존 WEB 채널 닫기가 그대로 최후 수단이다.

### 1.7 ★ 선결 쟁점 4 — 시뮬레이터 · TC · 검증 게이트 (P-5)

| 선택지 | 내용 | 판정 |
|---|---|---|
| 게이트 없음 | 시뮬레이터·TC를 환경별로 실행할 수 있게만 한다 | "배포 전 격리 검증"(원문) 강제력 없음 |
| **경고 게이트**(기본) + **챗봇별 차단 게이트 선택** ★ | 운영 전환 미리보기에 "대상 버전의 최근 TC 결과(세트·합격률·실행 시각)"를 표시하고 없거나 미달이면 경고 + 확인 요구. 챗봇 설정으로 **필수 TC 세트 + 최소 합격률**을 지정하면 미달 시 전환 거부(예약 전환 포함 — 실행 시 재확인) | **권고.** 규제 고객은 차단, 소규모 팀은 경고 |
| 항상 차단 | 모든 챗봇이 TC 통과 필수 | TC 세트가 없는 챗봇은 운영 전환 불가 — 도입 장벽 |

전환 **후** 자동 롤백은 하지 않는다(ADR-0032 대안표 98행 — 무인 롤백의 진동·오판 위험 판단 유지).

### 1.8 ★ 선결 쟁점 5 — 기존 데이터 이행과 하위 호환 (P-6)

- **기본 꺼짐.** 켜지 않은 챗봇은 공개 대화·시뮬레이터·TC·버전·예약·통계·상담·평가가 **바이트 단위로 동일**하고 공개 경로 추가 조회 0이다(FR-0-150).
- **켜기**: 현재 초안을 캡처(트리거 `ENV_INIT` — 해시 같으면 최신 버전 재사용)하고 **운영·스테이징 포인터를 그 버전으로** 설정한다 → 켜는 순간 운영 응답은 켜기 직전과 같다(C-1·C-2 해법 적용 전제). `DRAFT`(미공개) 챗봇도 켤 수 있다(공개 여부는 여전히 `status`·채널이 정한다).
- **끄기**: 미전환 초안 변경이 있으면 선택을 요구한다 — ① **운영 유지**(콘솔이 기존 복원 API로 초안을 운영 버전으로 되돌린 뒤 끔 — 복원 직전 백업이 초안 변경을 보존) ② **초안을 운영으로**(차이 미리보기 확인 후 끔 — 초안이 즉시 라이브). 권고 기본 = ①.
- 전환 이력·로그 `servedVersionId`·버전은 끈 뒤에도 남는다.

### 1.9 ★ 선결 쟁점 6 — 권한 · 감사 (P-4)

현재 버전 복원 = `dialogue:write` AND `chatbot:write`(EDITOR 가능 — ADR-0031 §7이 "사고 현장의 EDITOR가 즉시 롤백"을 이유로 `chatbot:restore` 신설을 기각). 운영 전환은 **"운영 사용자가 보는 답을 바꾸는"** 동작이라 성격이 다르다.

| 선택지 | 내용 | 판정 |
|---|---|---|
| (1) 기존 권한 재사용 | 스테이징·운영 전환 모두 `dialogue:write` AND `chatbot:write` | 편집자 = 배포자. 분리 요구가 없는 소규모 팀에 적합 |
| **(2) 신규 권한 1종(가칭 `chatbot:deploy`) — ADMIN 기본** ★ | 스테이징 승격 = 기존 권한(EDITOR 가능) · **운영 전환·운영 롤백·운영 전환 예약·환경 모드 켜기/끄기·게이트 설정** = 신규 권한 | **권고.** 원문의 "배포 전 격리 검증"은 편집과 배포의 분리가 전제. 긴급 차단은 EDITOR의 채널 닫기(`channel:write`)로 여전히 가능 |
| (3) 신규 권한 + 신규 역할 "배포 관리자" | 역할 5종 | 역할 추가는 사용자 관리 화면·권한 매트릭스 전체에 파급 — 요구 확인 후 |
| (4) 2인 승인(요청 → 승인) | 전환 요청·승인 상태 기계 | No.36/45 거버넌스와 함께(후속) |

감사: 승격·전환·롤백·예약 전환 실행·모드 켜기/끄기·게이트 설정 변경을 **모두 감사**한다(주체·챗봇·from/to 버전 번호·사유 메모 — 자산 본문 없음).

### 1.10 목적

1. 관리자가 **운영 사용자에게 보이지 않는 초안**에서 대화 자산을 고치고, 시뮬레이터·TC로 **스테이징 버전**을 시험한 뒤, 확인된 버전만 **운영으로 전환**한다.
2. 각 환경이 **지금 어떤 버전인지**가 콘솔·버전 목록·전환 이력에 명시된다(환경별 태깅).
3. 운영 전환은 **즉시 또는 예약**으로 하며, 문제가 있으면 **직전 운영 버전으로 즉시 되돌린다**.
4. 운영 응답은 **운영 버전만으로** 결정된다 — 초안 편집·삭제·재색인이 운영의 규칙·의미 매칭을 바꾸지 않는다.
5. 기능을 켜지 않은 챗봇은 **모든 동작이 바이트 단위로 동일**하고, 대화 엔진·ml-worker·위젯은 **수정하지 않는다**.

## 2. 사용자 역할 및 시나리오

### 2.1 역할

| 역할 | 이 그룹에서의 활동 | 권한(권고안 기준) |
|---|---|---|
| **ADMIN** | 모드 켜기/끄기 · 운영 전환·예약·롤백 · 게이트 설정 · 이하 전부 | 기존 + `chatbot:deploy`(신규) |
| **EDITOR** | 초안 편집 · 시뮬레이터/TC 환경 선택 · **초안 → 스테이징 승격** · 전환 미리보기 조회 · 긴급 시 WEB 채널 닫기 | `dialogue:write`·`chatbot:write`·`simulation:*`·`channel:write` |
| **VIEWER** | 환경 현황·전환 이력·버전 배지 조회 | `chatbot:read`·`dialogue:read` |

| 최종 사용자 | 변경 없음 — 운영 버전과 대화 | — |

### 2.2 사용자 시나리오

**S-1. 환경 분리 켜기 (ADMIN · ★)** 운영 중인 "고객센터 봇"(v42)에서 `환경 분리 사용`을 켠다. 확인 창에 "현재 상태를 v43으로 저장하고 운영·스테이징을 v43으로 지정합니다. 이후 편집은 운영에 바로 보이지 않습니다. 예약된 버전 복원 1건이 보류됩니다"가 나온다. 켠 직후 위젯 응답은 켜기 전과 같다.

**S-2. 운영에 보이지 않는 편집 (EDITOR · ★)** 편집자가 "환불 안내" FAQ 답변을 새 정책으로 고친다. 콘솔 상단에 "초안 · 운영(v43)과 다름 · 변경 3건" 배지가 보인다. 실제 위젯에서는 여전히 옛 답변이 나온다.

**S-3. 스테이징 승격과 시험 (EDITOR)** `스테이징으로 승격`을 누르면 v44가 만들어지고 스테이징 = v44가 된다. 시뮬레이터에서 대상 `스테이징(v44)`을 골라 대화하고, TC 세트 "회귀 120문장"을 대상 `스테이징`으로 실행해 합격 118/120을 얻는다.

**S-4. 운영 전환 (ADMIN · ★)** 전환 미리보기에 "v43 → v44 · FAQ 수정 1 · 노드 추가 2 · TC 회귀 120문장 98.3%(10분 전)"가 보인다. `지금 전환`을 누르면 다음 요청부터 모든 서버에서 v44가 응답한다. 전환 이력에 "09-25 14:02 v43 → v44 · 관리자 김○○ · 사유: 환불 정책 개정"이 남는다.

**S-5. 예약 전환 (ADMIN)** 정책 시행일에 맞춰 `예약 전환 10-01 00:00`을 건다. 그 사이 누군가 운영을 v45로 바꾸면 예약은 실행되지 않고 "확인 필요(운영 버전이 바뀜)"로 남는다.

**S-6. 롤백 (ADMIN · ★)** 전환 후 미응답이 늘자 `직전 운영 버전으로 되돌리기`를 누른다. 운영 = v43이 즉시 적용된다. 초안과 스테이징(v44)은 그대로라 편집자가 이어서 고친다.

**S-7. 차단 게이트 (ADMIN)** 챗봇 설정에서 "운영 전환 필수 TC = 회귀 120문장 · 최소 95%"를 켠다. 스테이징 v46의 최근 실행이 91%라 `지금 전환`이 비활성이고 "필수 시험 미달(91% < 95%)"이 표시된다.

**S-8. 학습현황과 환경 (EDITOR)** 학습현황에서 "주차 되나요?"를 `주차_안내`에 반영한다. 항목은 `반영 완료 · 운영 미반영` 배지를 달고, 운영 전환 후 배지가 사라진다. 그 사이 운영에서 같은 질문이 또 와도 "반영 후 재발생"으로 표시되지 않는다.

**S-9. 버전 복원의 의미 변화 (EDITOR)** 환경 모드 챗봇의 버전 탭에서 v40 복원을 누르면 "초안에만 적용됩니다. 운영(v44)은 바뀌지 않습니다"가 나온다.

**S-10. 끄기 (ADMIN)** `환경 분리 끄기`에서 초안 변경 5건이 있다고 나온다. 기본 선택 "운영(v44) 상태 유지 — 초안 변경은 백업 버전으로 보관"을 고르면 초안이 v44로 복원된 뒤 모드가 꺼지고, 이후 편집은 다시 즉시 반영된다.

### 4.11 구축형 / 구독형 적합도

- **구축형 ○** — 한 서버 안에서 논리 분리. 신규 인프라 0. **망분리된 개발/운영 서버를 따로 두는 고객**은 서버 간 이관(해석 (c))이 필요하며 2차다 — 1차 동안은 "운영 서버 한 대 안에서 초안/스테이징/운영"으로 운영한다.
- **구독형 ○** — 테넌트 인프라 변화 없음. 버전 번들 캐시 메모리 증가(챗봇당 최대 스테이징·운영 2벌)만 용량 산정에 반영.

## 7. 수용기준 (AC)

### AC-EN1. 범위 · 회귀 · 모드

- **AC-EN1-1** ★ Given 모드 꺼진 챗봇(기본), When 공개 대화·설정 조회·시뮬레이터·비교·TC·버전·예약·상담·평가 전 시험 세트를 실행, Then 결과가 도입 전과 바이트 단위로 같고 공개 대화 경로 DB 조회 수가 같으며 로그 `servedVersionId`는 null이다.
- **AC-EN1-2** ★ Given 운영 중 챗봇, When 모드 켜기, Then 버전 1개(또는 재사용)가 생기고 스테이징 = 운영 = 그 버전이며, 켜기 직전·직후 같은 TC 세트·같은 입력의 공개 응답이 **동일**하다(동점 포함).
- **AC-EN1-3** Given 활성 `RESTORE_VERSION` 예약이 있는 챗봇, When 모드 켜기, Then 예약이 `HELD(ENV_MODE_CHANGED)`다.
- **AC-EN1-4** Given 초안이 운영과 다른 챗봇, When "운영 유지"로 끄기, Then 초안 해시 = 운영 버전 해시 · `BEFORE_RESTORE` 백업 1건 · 모드 꺼짐 · 이후 편집이 즉시 공개에 반영된다.
- **AC-EN1-5** Given 같은 조건, When "초안을 운영으로"로 끄기, Then 공개 응답이 초안 기준이 되고 이력에 `DISABLE`이 남는다.
- **AC-EN1-6** Given `ARCHIVED` 챗봇, When 켜기, Then `409`.

### AC-EN2. 운영 서빙 격리

- **AC-EN2-1** ★ Given 모드 켜진 챗봇(운영 vP), When 초안에서 FAQ 답변 수정·노드 삭제·의도 예문 추가·답변 설정 변경·표시 설정(스킨) 변경, Then 공개 응답·`getConfig()`의 이름/아바타/스킨이 **변하지 않는다**(P-10 권고안 기준).
- **AC-EN2-2** ★ Given 운영 vP와 같은 버전 대상 시뮬레이터·TC, When 같은 입력 세트, Then 매칭 결과(노드·FAQ·의도·폴백·의미 점수 순위)가 **전부 같다**(동점 노드 픽스처 포함 — C-1).
- **AC-EN2-3** Given 토픽 T를 비활성화, When 운영 대화, Then 운영 버전에서도 T의 노드·의도·FAQ가 제외된다(환경 밖 즉시 반영).
- **AC-EN2-4** Given 설문 문구 수정, When 운영 대화, Then 수정이 즉시 반영된다(환경 밖) · 편집 화면에 안내가 있다.
- **AC-EN2-5** Given 전환 커밋, When 두 인스턴스에 연속 요청, Then 두 번째 요청부터 두 인스턴스 모두 새 버전으로 응답한다(`servedVersionId` 확인).
- **AC-EN2-6** Given 운영 번들 캐시 적중, Then NFR-ENP1 지연 기준을 만족한다(측정 기록).

### AC-EN3. 의미 매칭

- **AC-EN3-1** ★ Given 의미 매칭 켜진 챗봇 운영 vP, When 초안에서 FAQ X의 대체 질문을 바꾸고 FAQ Y를 삭제한 뒤 재색인 완료, Then 운영에서 X·Y의 의미 점수가 변경 전과 같다.
- **AC-EN3-2** Given 스테이징 승격 → 운영 전환, Then 추가 임베딩 호출 수가 0이다(초안 편집 시 이미 임베딩).
- **AC-EN3-3** Given 모드 꺼진 챗봇, Then 재색인 후 벡터 수·호출 수가 도입 전과 같다.

### AC-EN4. 승격 · 전환 · 롤백

- **AC-EN4-1** Given 초안 변경, When 스테이징 승격, Then 새 버전 생성 · 스테이징 = 그 버전 · 운영 불변 · 감사 1건.
- **AC-EN4-2** Given 변경 없는 초안, When 승격, Then 기존 버전 재사용(새 행 0).
- **AC-EN4-3** ★ Given 미리보기 이후 다른 관리자가 운영을 전환, When 이전 미리보기로 전환 요청, Then `409 ENV_POINTER_STALE` · 포인터 불변.
- **AC-EN4-4** Given 스테이징도 이력도 아닌 버전, When 운영 전환, Then `409 ENV_TARGET_NOT_STAGING`.
- **AC-EN4-5** ★ Given 전환 후, When 롤백, Then 운영 = 직전 운영 버전 · 초안·스테이징 불변 · 자산 테이블 쓰기 0 · 이력 `ROLLBACK`.
- **AC-EN4-6** Given 동시 전환 요청 2건(같은 기대값), Then 1건만 성공, 다른 1건 `409`.
- **AC-EN4-7** Given 포인터·이력 참조 버전, When 수동 삭제·보존 정리, Then `409 VERSION_REFERENCED_BY_ENVIRONMENT` · 정리 대상 제외.
- **AC-EN4-8** Given 버전 목록, Then 운영·스테이징·운영 이력 배지가 텍스트로 표시되고 라벨은 그대로다.

### AC-EN5. 예약 전환

- **AC-EN5-1** ★ Given `SWITCH_PROD_VERSION` 예약, When 실행 시각 도달 · 운영 = 기대값, Then 전환 성공 · 감사 주체 = 예약자 · 이력 `SCHEDULED`.
- **AC-EN5-2** Given 예약 후 운영이 수동 전환됨, When 실행, Then `FAILED(STATE_CHANGED)` · 포인터 불변 · 후속 예약 `HELD`.
- **AC-EN5-3** Given 차단 게이트 · 실행 시 최근 TC 미달, Then `FAILED(GATE_NOT_PASSED)`(재시도 없음).
- **AC-EN5-4** Given 예약자 권한 상실, Then `FAILED(CREATOR_NOT_AUTHORIZED)`.
- **AC-EN5-5** Given 2인스턴스, Then 전환 1회만 실행(기존 CAS 선점).

### AC-EN6. 시뮬레이터 · TC · 게이트

- **AC-EN6-1** Given 시뮬레이터 대상 = 운영, Then 공개 대화와 같은 결과 · 로그 적재 0.
- **AC-EN6-2** Given 대상 = 스테이징에서 오버레이 요청, Then `400`(오버레이는 초안 대상 전용).
- **AC-EN6-3** Given TC 대상 = 버전, Then 실행 행에 대상 종류·버전 id·해시가 기록되고 기대값 판정이 그 버전 번들로 이뤄진다.
- **AC-EN6-4** ★ Given 차단 게이트(세트 S · 95%) · 대상 버전의 24시간 내 최근 실행 91%, When 전환, Then `409 ENV_GATE_NOT_PASSED` · 미리보기에 사유 표시.
- **AC-EN6-5** Given 경고 게이트 · TC 실행 없음, When 전환, Then 경고 확인(`acknowledgeWarnings`) 후 성공.
- **AC-EN6-6** Given 차단 게이트, When 롤백, Then 게이트 경고만 표시되고 성공한다.

### AC-EN7. 버전 · 학습 · 평가 · 로그

- **AC-EN7-1** Given 모드 켜진 챗봇, When 버전 복원, Then 초안만 변경 · 공개 응답 불변 · 확인 문구가 "초안에만 적용"이다.
- **AC-EN7-2** Given 운영 턴, Then 로그 `servedVersionId` = 운영 버전 id · 보류 RAG 턴도 같다.
- **AC-EN7-3** Given 학습현황 반영 후 전환 전, Then 항목에 "운영 미반영" · 그 사이 재유입은 "반영 후 재발생"으로 표시되지 않는다 · 전환 후 배지 해제.
- **AC-EN7-4** Given 초안에서 삭제된 FAQ로 답한 운영 턴의 👎, Then 큐·평가 화면에 "초안에서 삭제됨".
- **AC-EN7-5** Given 상담 힌트, Then 운영 버전 번들 기준 후보가 제시된다.

### AC-EN8. 권한 · 감사 · 봉인

- **AC-EN8-1** ★ Given EDITOR, When 운영 전환·롤백·전환 예약·모드 변경·게이트 설정, Then `403` · 스테이징 승격은 성공(P-4 (2) 기준).
- **AC-EN8-2** Given 각 쓰기 동작, Then 감사 1건(본문 없음 · from/to 번호).
- **AC-EN8-3** ★ Given 저장소 전체, When `environment-sealing.spec.ts`, Then FR-EN9-3 단언 전부 통과(역검증 포함) · `@Public()` 8 · 엔진 패키지 변경 0.
- **AC-EN8-4** Given 공개 요청(임의 헤더·쿼리), Then 초안·스테이징 번들로 응답하는 경로가 없다.
