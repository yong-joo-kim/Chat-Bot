### 1.2 원본 근거 — "무엇을 요구하는가"

**근거 1 — 카탈로그 원문**(`기능요구사항.md` 95행):
> "채널별 리치 메시지 컴포넌트 | **카카오톡 바로연결버튼·캐러셀 등 채널 고유 UI 컴포넌트를 대화그래프 아웃풋에서 선택 가능** | GPU 1 | ○ | ○ | 카카오 i 오픈빌더 벤치마킹. **5번(대화그래프 아웃풋 12종 이상)을 채널별로 특화하는 개념**"

→ 요구는 셋이다: ① **대화그래프 아웃풋에서 고를 수 있는** 새 표현(편집기 선택지) ② 그 표현이 **채널마다 다르게** 나간다(채널 특화) ③ 예시 2개 = **바로연결 버튼 · 캐러셀**.

**근거 2 — 예시 2개는 사실 "채널 중립"이다**: 캐러셀(카드 여러 장 가로 넘김)과 바로연결 버튼(답 아래 빠른 선택 칩)은 카카오톡뿐 아니라 라인·페이스북 메신저·네이버 톡톡·웹 챗 위젯 **모두에 있는 일반 개념**이다(⚠ 조사 한계 — 기억 기반). 즉 원문의 두 예시는 **WEB 위젯에서도 그대로 구현할 수 있고**, 카카오 전용이 아니다. → **판단 J-1**: "채널 고유"의 실체는 **컴포넌트 자체가 아니라 채널마다 다른 한계(몇 장까지 · 몇 글자까지 · 어떤 버튼 동작까지)와 못 그릴 때의 대체 방식**이다. 이것은 **능력표 + 강등 규칙**으로 표현된다.

**근거 3 — 채널 현실(코드)**: 8개 배포 채널 중 **WEB 1개만 종단 구현**이고 나머지 7개는 "설정만 저장"(§1.3.1). No.42가 외부 채널 실연동을 2차로 미뤘다. → 1차에서 **실제로 사용자가 보는 곳은 WEB 위젯뿐**이고, 다른 채널은 **콘솔 미리보기(가정치)** 로만 확인할 수 있다.

### 1.4 ★ 선결 쟁점 1 — 1차 범위 (P-1)

| 선택지 | 내용 | 사용자가 실제로 보는 곳 | 외부 전제 | 판정 |
|---|---|---|---|---|
| **(a) 채널 중립 컴포넌트 + 능력표 + 강등** ★ | 캐러셀·바로연결을 **WEB 위젯에서 실제로 렌더**. 8개 채널 능력표(WEB 실측 · 카카오 **가정치** · 나머지 보수 기본값)와 강등 규칙 정의. 콘솔·시뮬레이션에서 "카카오톡에서는(예상) 이렇게 보임" 미리보기 | WEB 위젯 + 콘솔 미리보기 | 없음 | **권고** — 원문 예시 2개(바로연결·캐러셀)를 **실제 화면에서** 쓸 수 있고, 카카오 계정이 생기면 능력표 한 행과 어댑터만 바꾸면 된다 |
| (b) (a) + **카카오 전용 컴포넌트 모델링** | "상담원 연결 버튼·채널 추가 버튼·공유 버튼" 같은 **카카오에만 있는 버튼 동작**을 편집기에서 고를 수 있게 저장. WEB에서는 항상 강등(텍스트·일반 버튼) | WEB에선 강등된 모습만 | 없음 | 비권고 — **아무도 원형을 볼 수 없는 데이터**가 쌓인다. 규격 미확인(조사 한계)이라 실연동 때 **다시 고칠 가능성이 크다**. 구버전 위젯이 모르는 버튼 동작을 받으면 "메시지 버튼"으로 오인하는 위험(`output-view.ts` 23~31행 — 모르는 action은 MESSAGE 분기로 떨어짐)까지 새로 막아야 한다 |
| (c) (a) + **카카오 실연동** | 오픈빌더 스킬 서버로 실제 카카오톡에 캐러셀 발송 | 실제 카카오톡 | 카카오 비즈 채널·오픈빌더 계정·심사 · **공개 HTTPS 수신 주소**(`@Public()` +1) · 자격증명 저장 ADR · **No.42 2차(공개 파이프라인 채널 매개변수화) 선행** | 1차 불가 — No.42가 같은 이유로 2차로 미룬 전제가 하나도 없다(`omnichannel-inbox.md` §9 619행) |

→ **판단 J-1**: **(a)**. 사용자가 "카카오 미연동"을 알고도 도입을 택한 취지는 "카카오톡처럼 풍부한 응답을 우리 챗봇에서도"로 해석하며, 그것은 **WEB에서 실제로 전달 가능**하다. 카카오 고유성은 **능력표의 한 행(가정치)** 으로 먼저 담아 두고, 실연동(2차)에서 **실측치로 교체**한다.

### 1.9 목적

1. 운영자가 대화그래프에서 **캐러셀과 바로연결 버튼**을 골라, 웹 위젯 사용자가 **여러 선택지를 한눈에 보고 한 번에 고르게** 한다.
2. 같은 응답이 **다른 채널에서는 어떻게 보일지**를 저장 전에 미리 보고(가정치 표시 포함), 못 그리는 채널에서는 **정보가 사라지지 않고** 더 단순한 모습으로 전달된다.
3. 새 컴포넌트도 **금지어 필터·대화 로그·참조 보호·스냅샷·자산 이전**을 기존 아웃풋과 똑같이 받는다.
4. 이미지·링크 주소는 **https + 피싱 형식 차단**을 기본으로 한다.
5. 새 컴포넌트를 쓰지 않는 챗봇·구버전 위젯은 **동작이 바이트 단위로 동일**하다.

## 2. 사용자 역할 및 시나리오

### 2.1 역할

| 역할 | 이 그룹에서의 활동 | 권한(권고안 기준) |
|---|---|---|
| **EDITOR / ADMIN** | 캐러셀·바로연결 작성 · 채널별 미리보기 · 허용 도메인 목록 관리 | 기존 대화노드 편집 권한 · `chatbot:write` |
| **VIEWER** | 노드 상세·미리보기 **조회만** | 기존 조회 권한 |
| **AGENT** | 변경 없음(대화 보기·인박스 타임라인에 캐러셀이 **요약 텍스트**로 보임) | 기존 |
| **최종 사용자** | 웹 위젯에서 캐러셀을 넘겨 보고, 바로연결 칩으로 빠르게 선택 | — |

### 2.2 사용자 시나리오

**S-1. 요금제 비교 캐러셀 (EDITOR · ★)** 통신사 챗봇 운영자가 "요금제 추천" 노드에 캐러셀을 추가하고 카드 3장(요금제 이름·월 요금·이미지·"자세히 보기"(링크)·"이걸로 상담"(노드 이동))을 만든다. 사용자는 위젯에서 카드를 옆으로 넘기며 비교하고 "이걸로 상담"을 누른다.

**S-2. 바로연결 칩 (EDITOR · ★)** "배송 조회" 답변 뒤에 버튼 아웃풋을 추가하고 표시 방식을 **바로연결**로 고른다. 사용자에게는 답 아래 작은 칩 "(반품 문의) (교환 문의) (처음으로)"가 보이고, 칩을 누르거나 직접 글을 입력하면 칩이 사라진다.

**S-3. 키보드·화면낭독 사용자 (최종 사용자 · ★)** 화면낭독기 사용자가 캐러셀에 도착하면 "요금제 카드 3개, 3개 중 1번째"를 듣고, Tab으로 카드 안 버튼과 "다음 카드" 버튼을 차례로 이동한다. 카드가 저절로 넘어가지 않는다.

**S-4. 채널별 미리보기 (EDITOR · ★)** 카카오톡 계약을 앞둔 운영자가 미리보기를 **카카오톡(예상)** 으로 바꾸자 "가정치입니다 — 실제 카카오 규격 확인 전" 라벨과 함께 카드 버튼 5개 중 3개만 보이는 모습이 나온다. **텍스트만 채널**로 바꾸면 "1) 요금제 A … 자세히: https://…" 목록으로 보인다.

**S-5. 시뮬레이션 채널 (EDITOR · No.42 연계)** 통합 인박스의 시험 고객에게 가상 채널 "카카오톡"으로 "요금제 추천"을 넣으면, 스레드 기록 옆 미리보기에 강등된 모습과 "바뀐 점 2건"이 보인다(예상 라벨).

**S-6. 구버전 위젯 (최종 사용자 · ★)** 고객사가 몇 달 전 복사해 둔 위젯 스크립트를 쓰는 사이트에서도 캐러셀 응답은 **카드 3개가 세로로** 보이고, 바로연결은 일반 버튼으로 보인다(빈 말풍선 없음).

**S-7. 피싱 링크 차단 (EDITOR · ★)** 운영자가 실수로 `https://bank.example.com@phish.example.net/login`을 카드 링크에 붙여 넣자 "주소에 '@'가 포함된 형식은 쓸 수 없습니다(다른 사이트로 보내는 속임수에 쓰입니다)"로 저장이 거부된다. `http://`로 시작하는 이미지 주소는 "https 주소만 쓸 수 있습니다"로 거부된다.

**S-8. 금지어 (★)** 캐러셀 카드 설명에 `{api.memo}` 치환값이 들어가고, 그 값에 금지어가 섞여 있다. 사용자에게는 마스킹된 문구로 보인다(기존 카드와 같은 규칙).

**S-9. 기능 미사용 챗봇 (★)** 새 컴포넌트를 한 번도 쓰지 않은 챗봇은 대화 응답·로그·통계·스냅샷 해시가 이전과 **바이트 단위로 같다**.

**S-10. 폐쇄망 고객 (운영자)** 인터넷이 막힌 구축형 고객은 사내 이미지 서버(`https://img.intra.example`)를 허용 도메인 목록에 넣고 그 주소만 쓴다. 목록 밖 도메인은 저장 시 거부된다.

## 7. 수용기준 (AC)

### AC-RM1. 범위 · 회귀

- **AC-RM1-1** Given 새 컴포넌트를 쓰지 않는 챗봇과 `rich-v1`을 보내지 않는 요청, When 기존 시나리오 전체를 실행하면, Then 공개 응답·로그·통계 결과가 도입 전과 **바이트 동일**하고 기존 시험이 FR-0-201 목록 외 수정 없이 통과한다.
- **AC-RM1-2** Given 도입 전 캡처한 버전 스냅샷 픽스처, When `contentHash`를 다시 계산하면, Then **도입 전 골든 해시와 같다**(`BUTTON` 페이로드에 `display` 키가 생기지 않는다).
- **AC-RM1-3** Given 엔진 빌드, When 엔진 표면 골든 시험을 돌리면, Then 파일 목록·export 심볼이 **불변**이다.
- **AC-RM1-4** Then `@Public()` 8 · `EgressExitId` 6 · 신규 권한 0 · 백그라운드 루프 추가 0(정적 검사).

### AC-RM2. 캐러셀 · 바로연결 저장 · 실행

- **AC-RM2-1** Given 카드 1장 또는 11장 캐러셀, When 저장하면, Then `400 VALIDATION_FAILED`(카드 2~10장). 카드 버튼 4개도 거부.
- **AC-RM2-2** Given 캐러셀 카드 버튼 NODE가 노드 X를 가리킴, When 노드 X를 삭제하면, Then 기존 CARD 버튼과 같은 `409` 참조 보호가 동작하고 참조 위치(`outputs.i.payload.cards.j.buttons.k.value`)가 보고된다.
- **AC-RM2-3** Given 바로연결에 LINK 버튼 · 또는 바로연결 뒤에 다른 표시 아웃풋, When 저장하면, Then 거부된다(FR-RM2-2·3).
- **AC-RM2-4** ★ Given `{api.*}` 치환이 일어나는 턴(v2 `API_CONDITION` 성공 분기 뒤)의 바로연결 BUTTON과 캐러셀, When 대화하면, Then 응답에 **`display: 'QUICK_REPLY'`가 보존**되고 캐러셀 카드 제목·설명·라벨만 치환되며 URL·버튼 값은 치환되지 않는다(재조립 경로 포함 — `resumeAfterApiCall`).
- **AC-RM2-5** Given 치환 후 모든 카드 제목이 빈 문자열, Then 캐러셀 아웃풋이 제거되고 `API_VALUE_DROPPED` trace가 남는다.
- **AC-RM2-6** Given 기존 엔진 시험 전체, Then 수정 없이 통과한다.

### AC-RM3. 능력표 · 강등

- **AC-RM3-1** Given 캐러셀 3장, When `rich-v1`을 선언한 WEB 요청이면 Then 원형 그대로 · 선언하지 않은 요청이면 Then **CARD 3개**로 도착한다(빈 말풍선 0).
- **AC-RM3-2** Given 카카오톡(가정치) 프로필, When 카드 버튼 5개짜리 카드를 강등하면, Then 앞 3개만 남고 `changes`에 `BUTTONS_TRUNCATED`가 있다.
- **AC-RM3-3** Given 텍스트만 프로필, When 캐러셀(링크 버튼 포함)을 강등하면, Then "1) 제목 — 설명 … / 라벨: https://…" 텍스트가 되고 NODE 버튼은 `ACTION_LOST`로 보고된다.
- **AC-RM3-4** Given 기존 6종 아웃풋, When 텍스트 강등하면, Then 문구가 도입 전과 같다(`[카드] 제목` 등).
- **AC-RM3-5** Then `WebChannelAdapter`에 자체 지원 타입 목록 리터럴이 없고 능력표에서 파생된다(정적 검사).

### AC-RM4. 콘솔 · 시뮬레이션

- **AC-RM4-1** Given 캐러셀 노드, When 미리보기를 `카카오톡(예상)`으로 바꾸면, Then 강등된 모습과 **"예상 모습" 라벨**이 보인다.
- **AC-RM4-2** Given No.42 시험 고객 · 가상 채널 KAKAOTALK, When 캐러셀 노드를 시뮬레이션하면, Then `degradePreview`가 `{ channelType: 'KAKAOTALK', source: 'ASSUMED', outputs, changes }`이고 스레드 기록은 원형 요약 텍스트다. 가상 채널 WEB이면 `changes`가 빈 목록.
- **AC-RM4-3** Given 응답 테스트 시뮬레이터, Then 캐러셀·바로연결이 위젯과 같은 모습으로 렌더된다.
- **AC-RM4-4** VIEWER는 미리보기를 볼 수 있고 저장·허용 도메인 목록 변경은 불가(`403`).

### AC-RM5. 주소 안전

- **AC-RM5-1** Given 캐러셀 이미지 `http://…` 또는 링크 `https://a.example@b.example/`, When 저장하면, Then 거부된다. 기존 `CARD`의 `http` 이미지는 **계속 저장 가능**하다(하위 호환).
- **AC-RM5-2** Given 허용 도메인 목록 `[img.intra.example]`, When 목록 밖 호스트 이미지를 저장하면, Then 거부 · 목록 비우면 허용.
- **AC-RM5-3** Given 퓨니코드 호스트, Then 저장은 되고 경고가 표시된다.
- **AC-RM5-4** Given 위젯, Then 캐러셀 링크는 `rel="noopener noreferrer"` · 이미지 `referrerpolicy="no-referrer"` · 서버를 우회해 주입된 비 https 주소는 렌더하지 않는다.
- **AC-RM5-5** Given 허용 도메인 목록 변경, Then 감사로그 1건(전후 값).

### AC-RM6. 금지어 · 로그

- **AC-RM6-1** ★ Given 캐러셀 카드 제목·설명·버튼 라벨·안내 문구에 금지어, When 공개 대화하면, Then **모두 마스킹**되어 나간다.
- **AC-RM6-2** Given 캐러셀만 있는 턴, Then 대화 로그 `botResponse`가 `[캐러셀] 제목1 · 제목2 …`이다(빈 문자열 아님). 바로연결은 `[바로연결] …`.
- **AC-RM6-3** Given 칩 클릭(MESSAGE·NODE), Then 로그 `inputKind`가 `BUTTON_MESSAGE｜BUTTON_NODE`이고 질문 순위·미응답 수집 동작이 기존 버튼 턴과 같다.

### AC-RM7. 위젯 · 접근성

- **AC-RM7-1** Given 캐러셀 5장, Then 모든 카드가 DOM에 있고 각 카드 `aria-label`이 "5개 중 K번째: 제목" 형식 · 이전/다음 버튼이 `<button>`이며 끝에서 비활성.
- **AC-RM7-2** Given 키보드만 사용, Then Tab으로 카드 버튼·이전/다음에 도달하고 Enter/Space로 동작하며 자동 넘김이 없다.
- **AC-RM7-3** Given 바로연결 표시 뒤 사용자가 직접 입력해 전송, Then 칩 묶음이 `hidden`이 되고 새 DOM 노드가 추가되지 않으며, 포커스가 칩에 있었다면 입력창으로 이동한다.
- **AC-RM7-4** Given 이미지 로드 실패, Then 대체 텍스트로 교체되고 레이아웃이 무너지지 않는다.
- **AC-RM7-5** Given 위젯 빌드, Then gzip 100KB 이내이고 증가분 ≤ 6KB가 보고된다.
- **AC-RM7-6** Given 요청 본문, Then `features`에 `rich-v1`이 포함된다(총 3개).

### 11.1 AskUserQuestion용 쉬운 문구(핵심 4건)

**Q1. 1차에서 어디까지 만들까요?** (지금 실제로 연결된 채널은 웹 하나뿐이고, 카카오톡은 아직 연결 전입니다)
- ① **웹 챗봇에서 캐러셀·바로연결을 실제로 쓰고, 카카오톡 등에서는 "이렇게 보일 것"을 추정 미리보기로 보여 주기 (추천)**
- ② ①에 더해, 카카오에만 있는 버튼(상담원 연결·채널 추가·공유)도 미리 만들어 저장만 해 두기 — 웹에선 일반 버튼·글로 바뀌어 보임
- ③ 카카오톡 실제 연결까지 포함 — 카카오 계정·심사·외부에서 접속 가능한 서버 주소가 먼저 필요

**Q2. 어떤 모양을 새로 넣을까요?**
- ① **캐러셀(카드 여러 장을 옆으로 넘겨 보기) + 바로연결 버튼(답 아래 빠른 선택 버튼) (추천)**
- ② ①에 목록형 카드(제목·설명이 줄지어 나오는 목록)도 추가
- ③ ②에 상품 카드(가격 표시)와 전화 걸기·공유·상담원 연결 버튼까지 추가

**Q3. 다른 채널에서는 어떻게 보이게 할까요?**
- ① **채널마다 보여 줄 수 있는 것을 표로 정해 두고, 못 보여 주는 건 자동으로 단순하게(카드 → 글 목록 등) 바꾸기. 편집 화면에서 채널별 미리보기, 저장 때 경고만 (추천)**
- ② 웹만 정하고, 다른 채널은 "글자만 나오는 모습" 한 가지로만 미리보기
- ③ ①에 더해, 관리자가 채널마다 대신 보낼 응답을 직접 따로 입력

**Q4. 카드에 넣는 이미지·링크 주소는 어떻게 받을까요?**
- ① **지금처럼 인터넷 주소(https)를 입력하되, 다른 사이트로 속여 보내는 주소 형식은 막고, 원하면 허용할 사이트 목록을 지정 (추천)**
- ② 허용할 사이트 목록을 반드시 먼저 등록해야 사용 가능
- ③ ①에 더해, 이미지 파일을 직접 올려 우리 서버에 보관(보관 공간·외부 공개 주소 추가 필요 — 준비 작업 큼)
