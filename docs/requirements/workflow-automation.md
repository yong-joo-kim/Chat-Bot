### 1.2 원본 근거 — "무엇을 요구하는가"

**근거 1 — 카탈로그 원문**(`기능요구사항.md` 90행):
> "업무 자동화 워크플로우 커넥터 | **대화 중 트리거된 이벤트**를 **사내 업무자동화 도구(Power Automate류)와 연결**해 **승인·티켓생성 등 후속 처리를 자동 실행** | GPU 2 | ○ | ○ | Copilot Studio 벤치마킹. 39번(커넥터 허브)이 '데이터 연동'이라면 이건 '**액션 자동 실행**' 계층"

→ 요구는 셋이다: ① **트리거 = 대화 중 이벤트** ② **연결 대상 = 사내 업무 자동화 도구**(특정 제품이 아니라 "Power Automate**류**") ③ **후속 처리의 자동 실행**(승인·티켓 생성은 **받는 쪽 도구가** 수행 — 이 시스템은 "일을 넘기는 것"까지).

**근거 2 — "자동 실행"의 주체**: 결재 승인·티켓 생성의 **업무 로직은 고객의 업무 도구 안에 있다**(Power Automate 흐름·ITSM 규칙). 이 챗봇이 그 로직을 다시 만들 이유가 없다(=내장 액션 최소화, J-6). 챗봇의 책임은 **"정확히 한 번 의미로, 안전하게, 추적 가능하게 넘기기"** 다 — 이것이 No.26(같은 턴 조회)에 없는 것(재시도·멱등·이력)이다.

| **C-6** | 익명 공개 대화가 **외부 업무 시스템에 쓰기**를 일으킨다(티켓 폭탄·결재 스팸) — No.26 J-7이 "원격 수정 트리거는 조회보다 위험 등급이 다르다"로 기록 | **세션·대상 단위 발송 상한**(DB 기준 — 인스턴스 무관) · 대상별 사용 여부 · 일시 정지 · 받는 쪽 멱등키(FR-WF5-8) |

| **C-8** | 로그 적재·감사는 fire-and-forget/커밋 후 best-effort(기존 규약) | 이벤트 발송함 적재도 **원천 트랜잭션에 끼우지 않고 커밋 후 적재**(봉인된 쓰기 파일 변경 최소) — 서버 강제 종료 시 극소 유실 창을 **명시**(J-8 · NFR-WFR2) |

**없다**: 발송 대상 레지스트리 · 워크플로우 아웃풋 · 이벤트 구독 · 발송함·재시도·실패 보관 · HMAC 서명 · 멱등키 · 실행 이력·재발송·정지 · 테스트 발송 · 6번째 출구 · 외부 알림 경로 전반.

### 1.8 ★ 선결 쟁점 5 — 보내는 데이터와 보안 (P-6 · P-7)

- **기본 = 최소**: 이벤트 종류 · 발생 시각 · 챗봇 id/이름 · 채널 · **`sessionRef`**(가명 — `sessionId` 원값은 보내지 않음) · 원천 참조 id(메시지·상담·설문 응답·평가) · 이벤트별 **수치·열거값**(종료 사유·메시지 수·척도 점수 등).
- **노드 바인딩 값**(폼 슬롯)은 **기본 `maskPii()` 후 송신**, 대상 단위 **"원문 개인정보 전송 허용"**(ADMIN · 대상 이름 재입력 · 감사)만 원문 — **No.26 `allowRawPersonalData`와 같은 규약**(ADR-0013 5번째 적용 지점).
- **대화 본문(사용자 발화·봇 답변)·설문 자유 텍스트·상담 메시지는 1차 페이로드에 넣지 않는다**(P-6 (b)). "대화 발췌 첨부"는 2차(거버넌스 모드 ON에서는 금지 옵션과 함께).
- **서명 비밀·헤더 토큰·비밀 주소 = 환경변수 참조**(`WORKFLOW_SECRET__<REF>` — DB·로그·응답·스냅샷에 값 0 · No.26 J-3 선례).
- **출구 게이트 편입**(C-1): 모드 ON에서 대상 저장 시 호스트 검사(`400 EGRESS_HOST_NOT_ALLOWED` 재사용) · 발송 직전 재검사(차단 = 재시도 없는 영구 실패 `EGRESS_BLOCKED`) · 리다이렉트 불추종 · DNS 후 주소 검사·절대 차단 대역·사설 대역 허용 목록(ADR-0034 §4 전부).
- **거버넌스 상호작용**: 발송함 본문 = 일시 보관(성공 즉시 소거 · 실패는 기본 7일 뒤 소거) · 암호화 ON이면 봉투 암호화 · 이력 메타데이터는 `CALL_LOGS` 보존기간으로 행 삭제.

### 1.9 선결 쟁점 6 — 버전 · 환경 · 하위 호환 (P-10)

- **노드 아웃풋**(`WORKFLOW` — `targetId` 참조) = 대화 자산이므로 **스냅샷·환경 포인터에 자동 포함**(별도 작업 0). 운영 버전이 가리키는 노드에 있어야 운영에서 발송된다.
- **발송 대상**(전역) = `ApiConnection`처럼 **스냅샷 밖**. 복원·운영 전환 시 대상이 없거나 꺼져 있으면 **경고(차단 아님)** · 실행 시 `SKIPPED(TARGET_UNAVAILABLE)` 기록.
- **이벤트 구독**(챗봇 운영 설정) = **환경 밖 — 저장 즉시 운영 반영**(설문·상담 설정과 같은 J-15 규약) + 편집 화면 안내.
- **기능을 쓰지 않는 설치·챗봇은 바이트 단위로 동일**: `WORKFLOW` 아웃풋이 없는 번들 = 엔진 결과 키 부재 · 구독 없는 챗봇 = 구독 캐시 조회 1회 외 추가 DB 조회 0 · 발송 루프는 빈 발송함 폴링 1쿼리/주기뿐.

### 1.10 목적

1. 관리자가 대화그래프에 **"업무 요청 보내기"** 를 넣어, 폼으로 모은 값을 사내 업무 도구(결재·티켓)로 **자동 전달**할 수 있다.
2. 상담 시작·종료, 설문 완료, 부정 평가, 연속 미응답 같은 **대화 이벤트를 구독**해 업무 도구·메신저로 알릴 수 있다.
3. 전달은 **대화 응답을 늦추지 않고**, 받는 쪽 장애 시 **재시도**하며, **서명·멱등키**로 받는 쪽이 진위와 중복을 판단할 수 있다.
4. 모든 발송은 **실행 이력**으로 추적되고, 실패는 콘솔에서 보이며 **재발송·일시 정지**할 수 있다.
5. 새 출구는 **No.45 출구 게이트와 No.26 SSRF 방어**를 그대로 받고, 기능을 쓰지 않는 설치는 **동작이 바이트 단위로 동일**하다.

### 1.12 전체 흐름 (이 문서가 만드는 것)

```
■ 발송 대상 등록 (ADMIN · security:write · 설정 > 업무 자동화 > 발송 대상)
  이름 · 주소(https) · 인증(없음/헤더 키/Bearer/Basic) · 서명(HMAC 켜기) · secretRef · 비밀 주소 ref(선택)
  타임아웃 · 최대 재시도 · 원문 개인정보 허용(재입력 확인) · 사용 여부
  → 모드 ON: 호스트 ∈ DATA_EGRESS_ALLOWED_HOSTS 검사 · [테스트 발송] 샘플 봉투 1건

■ 명시 트리거 (EDITOR · dialogue:write · 대화그래프 노드 편집)
  노드 아웃풋 "업무 요청 보내기" = 대상 선택 · 동작 키(예: leave.request) · 필드 [이름 ← 상수 | 폼 슬롯]
  엔진: executeOutputs → 바인딩 해석 → result.workflowEvents[] (사용자 출력 없음 · 비종결)
  공개 대화 ④.6 뒤: 발송함 적재(await, 세션 상한 확인) → 응답은 노드 문구 그대로

■ 암묵 트리거 (EDITOR · chatbot:write · 챗봇 > 업무 자동화 > 이벤트 구독)
  [상담 시작] [상담 종료] [설문 완료] [부정 평가] [연속 미응답 N회] × 대상 선택 × 사용 여부
  원천 커밋 후 → 구독 캐시 확인 → 발송함 적재(유일 키로 중복 차단)

■ 발송 루프 (PollingLoop 5초 · 행 선점 CAS · 인스턴스 여럿 안전)
  PENDING & nextAttemptAt ≤ now → 선점 → EgressGuard → SSRF(DNS·주소 고정) → POST
     헤더: Content-Type · X-Chatbot-Event · X-Chatbot-Delivery(멱등키) · X-Chatbot-Signature(t=,v1=)
  2xx → SUCCEEDED(본문 소거)      408/429/5xx/시간초과/네트워크 → 재시도 예약(백오프 · Retry-After 상한)
  기타 4xx · 차단 · 비밀 없음     → FAILED(재시도 안 함 · 본문 N일 보관 → 소거)
  최대 시도 초과                  → FAILED

■ 운영 (콘솔)
  실행 이력(필터: 대상·챗봇·이벤트·상태·기간) · 재발송 · 취소 · 대상/구독 일시 정지(보류 → 재개 → 만료)
  경고 배지(대상 연속 실패 · 실패 보관 N건) · 요약(발생·성공·실패·건너뜀·P95 지연)

■ 봉인 (CI 정적 검사)
  발송 파일 ∈ 출구 레지스트리(6클래스) · 가드가 송신보다 앞 · 비밀 읽기 1파일 · 엔진 I/O 0
  WORKFLOW 없는 번들 결과 불변 · 이력·로그에 본문·비밀·sessionId 0 · @Public() 8 · 위젯·ml-worker 변경 0
```

### 2.2 사용자 시나리오

**S-1. 휴가 신청 결재 (EDITOR · ★)** 인사 챗봇의 "휴가 신청" 노드에 폼(시작일·종료일·사유)을 두고, 폼 완료 노드에 **업무 요청 보내기**(대상 "그룹웨어 결재 흐름", 동작 키 `leave.request`, 필드 `start ← 슬롯 시작일`, `end ← 슬롯 종료일`, `reason ← 슬롯 사유`)와 텍스트 "결재 요청을 올렸어요. 결과는 메일로 안내됩니다."를 둔다. 직원이 폼을 채우면 응답은 즉시 나오고, 몇 초 뒤 Power Automate 흐름이 결재를 시작한다.

**S-2. 발송 대상 등록 (ADMIN · ★)** `설정 > 업무 자동화 > 발송 대상`에서 "그룹웨어 결재 흐름"을 추가한다. 주소는 흐름이 발급한 HTTP 트리거 주소라 **주소 자체가 비밀**이므로, 호스트만 입력하고 "비밀 주소 참조 = `GW_LEAVE`"를 지정한다. 운영자가 서버에 `WORKFLOW_SECRET__GW_LEAVE=<전체 주소>`를 넣고 재기동하자 상태가 "설정됨"이 된다. [테스트 발송]을 누르면 `"test": true` 봉투가 가고 "성공(HTTP 202 · 412ms)"이 표시된다.

**S-3. 상담 종료 알림 (EDITOR)** `챗봇 > 업무 자동화 > 이벤트 구독`에서 "상담 종료 → Teams 상담팀 채널"을 켠다. 상담원이 상담을 끝내면 Teams에 "상담 종료 · 사유: 상담원이 종료 · 사용자 메시지 7 · 상담원 메시지 5 · 대화 참조 a1b2c3"이 올라온다(대화 본문은 없다).

**S-4. 연속 미응답 → 상담원 호출 (EDITOR)** "연속 미응답 3회 → 상담원 메신저 봇"을 구독한다. 한 방문자가 세 번 연속 답을 못 받자 메신저에 "대화 참조 d4e5f6 — 연속 미응답 3회"가 오고, 상담원이 콘솔 모니터링에서 같은 참조를 찾아 개입한다. 같은 세션에서 4·5회째 미응답은 다시 알리지 않는다(세션당 1회).

**S-5. 받는 쪽 장애 (ADMIN · ★)** ITSM 점검으로 티켓 대상이 1시간 동안 503을 준다. 발송은 30초 → 2분 → 10분 → 30분 간격으로 재시도되고, 콘솔 대상 목록에 "연속 실패 12건 — 재시도 대기" 경고가 뜬다. 점검이 끝나자 대기 중이던 요청이 순서대로 성공한다. 받는 쪽은 `X-Chatbot-Delivery`로 앞서 처리된(응답만 유실된) 건을 걸러낸다.

**S-6. 일시 정지 (ADMIN)** 결재 흐름을 교체하는 동안 대상을 **일시 정지**한다. 그동안 들어온 요청은 "보류"로 쌓이고, 재개하면 발송된다. 24시간을 넘긴 보류 건은 "만료"로 끝나고 이력에 남는다.

**S-7. 실패 재발송 (EDITOR)** 필드 이름이 틀려 받는 쪽이 400을 준 건 5개가 "실패"로 남았다. 흐름을 고친 뒤 이력에서 5건을 골라 **재발송**한다(같은 멱등키 — 받는 쪽이 이미 처리했다면 중복 제거된다). 실패 본문은 7일이 지나면 소거되어 재발송할 수 없다고 안내된다.

**S-8. 부정 평가 → 품질 티켓 (EDITOR)** "부정 평가 → 품질 개선 티켓"을 구독한다. 👎가 눌리면 티켓에 "메시지 참조 · 매칭 대상(FAQ #123) · 챗봇"이 들어간다. 사용자 발화 본문은 가지 않으며, 담당자는 콘솔 학습현황 큐에서 원문(마스킹본)을 본다.

**S-9. 티켓 폭탄 방지 (★)** 익명 사용자가 "장애 신고" 폼을 20번 반복 제출한다. 처음 3건만 발송되고 나머지는 이력에 "건너뜀(발송 상한)"으로 남는다. 사용자 화면의 봇 답변은 매번 같다.

**S-10. 기능 미사용 고객 (★)** 발송 대상을 하나도 만들지 않은 설치는 모든 화면·API·통계·대화 응답이 이전과 같다. 발송 루프는 빈 발송함을 5초마다 1번 확인할 뿐이다.

**S-11. 거버넌스 모드 (운영자)** `DATA_GOVERNANCE_MODE=ON` 설치에서 허용 목록에 없는 `hooks.partner.com`으로 대상을 저장하려 하자 "외부 전송 허용 목록에 없는 호스트입니다(서버 설정 필요)"로 거부된다. 데이터 지도에는 "업무 자동화 웹훅 · 대상 2개(허용 2 · 차단 0) · 폼 값(대상별 마스킹)"이 표시된다.

## 3. 공통 기능 요구사항 (FR-0)

선행 18개 그룹의 FR-0-1~171을 **상속**한다.

| ID | 요구사항 | 비고 |

### 4.12 GPU 필요도 재확인 — J-22

신규 연산 = JSON 조립 · HMAC-SHA256(발송 1건 1회) · HTTP 송신 · DB 발송함 선점/갱신 · 마스킹(정규식). 모델·학습·추론·임베딩 호출 0. 카탈로그의 2는 "워크플로우 엔진·LLM 요약" 같은 부가 기능을 가정한 값으로 보이며, 1차 범위에서는 **No.26(GPU 1)과 같은 등급 → 1로 하향 제안**(P-12). 2차에 "상담 요약을 페이로드에 첨부"(생성형)를 넣으면 그 기능만 옵션 AI로 별도 평가.

### 4.13 이 그룹이 **하지 않는** 것 (범위 요약)

| NFR-WFR1 | 전달 의미 = **최소 1회**(at-least-once). 임대 회수·응답 유실로 같은 `deliveryId`가 2번 이상 갈 수 있으며, 받는 쪽 중복 제거를 **연동 가이드에 명시**한다. "정확히 1회"는 약속하지 않는다. |
| NFR-WFR2 | **적재 유실 창**: 원천 커밋 후 적재 전 프로세스가 죽으면 그 이벤트는 유실된다(감사 기록과 같은 수용 — C-8). 적재 실패는 경고 로그 + 요약 통계 "적재 실패" 계수로 관측한다. |
| NFR-WFR3 | 재기동·다중 인스턴스에서 같은 행을 **동시에** 두 인스턴스가 발송하지 않는다(선점 CAS) — 2인스턴스 동시 `tick()` 시험. |
| NFR-WFR4 | 받는 쪽 장시간 장애에도 발송함이 무한히 늘지 않는다: 최대 시도·보류 만료·실패 본문 소거로 **본문 보관은 유한**, 이력 행은 `CALL_LOGS` 보존 정책을 따른다. |

### 6.3 보안 / 개인정보 (NFR-WFS)

| ID | 요구사항 |
|---|---|
| NFR-WFS1 | 비밀 값은 읽기 1파일 밖으로 문자열로 나가지 않는다 — 가짜 비밀 전수 grep 시험(로그·응답·DB·이력·감사). |
| NFR-WFS2 | 페이로드 기본 = 메타데이터 + 마스킹된 바인딩 값. 사용자 발화·자유 텍스트·상담 메시지·`sessionId` 원값 0(정적·동적 검사). |
| NFR-WFS3 | SSRF: ADR-0034 §4 방어 층 전부 · 절대 차단 대역은 어떤 설정으로도 열 수 없다 · DNS 재바인딩 시험 · 리다이렉트 불추종. |
| NFR-WFS4 | 서명: HMAC-SHA256 · 타임스탬프 포함(재생 공격 완화) · 비밀 최소 길이 32바이트(미만이면 대상 상태 "비밀 약함" 경고 — 기동 실패 아님). |
| NFR-WFS5 | 공개 익명 입력이 발송 **대상·주소·헤더**를 정할 수 없다 — 대상은 ADMIN 등록, 노드는 대상 id 참조, 값은 필드 **값**으로만 들어간다(JSON 직렬화 — 인젝션 없음). |
| NFR-WFS6 | 받는 쪽 응답 본문은 저장·로그하지 않는다(개인정보·토큰 반사 방지). |
| NFR-WFS7 | 원문 개인정보 허용 대상은 콘솔·데이터 지도·노드 편집기에서 **항상 표시**된다. |

## 7. 수용기준 (AC)

### AC-WF1. 범위 · 회귀

- **AC-WF1-1** ★ Given 대상 0개 · 구독 0개, When 전 시험 세트(공개 대화·설정·통계·상담·설문·평가·버전·환경·예약·거버넌스)를 실행, Then 결과·응답 바이트·공개 경로 DB 조회 수가 도입 전과 같다.
- **AC-WF1-2** ★ Given `WORKFLOW`가 없는 번들, When 엔진 스위트·TC 대량 실행, Then 도입 전과 바이트 동일(기존 spec 무수정).
- **AC-WF1-3** Given 저장소 전체, When `workflow-sealing.spec.ts`·`governance-sealing.spec.ts`·`legacy-api-sealing.spec.ts`, Then 전부 통과(역검증 포함) · `@Public()` 8 · 위젯·ml-worker 변경 0.

### AC-WF2. 명시 트리거

- **AC-WF2-1** ★ Given 폼(시작일·사유) 완료 노드에 `WORKFLOW`(필드 2개 SLOT) + TEXT, When 공개 대화로 폼 완료, Then 응답 출력 = TEXT만 · 발송함 1행(`PENDING`, 필드 이름 2개) · 응답 스키마 불변.
- **AC-WF2-2** Given 같은 노드에서 `WORKFLOW` 제거, Then 사용자 출력이 AC-WF2-1과 **바이트 동일**.
- **AC-WF2-3** Given SLOT 바인딩인데 버튼 진입(폼 완료 없음), Then 발송함 `SKIPPED(BINDING_MISSING)` · 발송 0.
- **AC-WF2-4** ★ Given 전화번호가 든 슬롯 · 원문 허용 꺼짐, When 발송, Then 수신 본문의 값이 마스킹 결과이고 이력 `personalDataMasked=true`. 원문 허용 켜진 대상은 원문.
- **AC-WF2-5** Given 시뮬레이터(실호출 조건 충족 여부 무관)·비교·TC, Then 발송 0(전송 목 호출 0) · 시뮬레이터 결과에 "모의" 표시.
- **AC-WF2-6** ★ Given 노드 A = [`WORKFLOW`#1, `API_CONDITION`] · 성공 분기 노드 B = [`WORKFLOW`#2, TEXT], When 실제 API 성공, Then 발송함 2행(#1·#2) · API 실패 분기·폴백 동봉본에서도 #1이 유지된다.
- **AC-WF2-7** Given 존재하지 않는 `targetId`로 노드 저장, Then `400 WORKFLOW_OUTPUT_INVALID`. 꺼진 대상은 저장 허용 + 설계 점검 경고.
- **AC-WF2-8** Given 입구 금지어 BLOCK·상담 중·서빙 버전 없음 턴, Then 발송함 적재 0.

### AC-WF3. 이벤트 구독

- **AC-WF3-1** ★ Given "상담 종료" 구독, When 상담원 종료와 정리 루프 시간 종료가 **동시에** 같은 상담을 끝내려 함, Then 발송함 1행(유일 키) · 페이로드에 종료 사유·메시지 수 · 텍스트 본문 0.
- **AC-WF3-2** Given "설문 완료" 구독, When 같은 세션이 설문을 두 번 완료, Then 2행(응답 id별) · 두 번째 `data.isDuplicate=true`. 구조 답 옵션 꺼짐이면 답 값 없음.
- **AC-WF3-3** Given "부정 평가" 구독, When 👎 → 👍 → 👎(변경 창 안), Then 발송함 1행(첫 선점만).
- **AC-WF3-4** ★ Given "연속 미응답 3회" 구독, When 한 세션에서 미응답 5회 연속, Then 1행(3회째) · 다른 세션은 별도 · 구독 없는 챗봇의 미응답 턴 추가 조회 0.
- **AC-WF3-5** Given 구독 저장, Then 다음 원천 이벤트부터 즉시 반영(환경 모드 챗봇 포함) · 캐시 무효화.
- **AC-WF3-6** Given 적재 중 DB 오류 주입, Then 상담 종료·설문 적재·평가 응답은 정상 · 경고 로그(본문 없음).

### AC-WF4. 발송 · 재시도 · 멱등

- **AC-WF4-1** ★ Given 받는 쪽 503 2회 후 200, When 발송 `tick()`을 시각 주입하며 반복, Then 시도 3회 · 간격이 백오프 표를 따름 · `SUCCEEDED` · 본문 소거 · 3회 모두 **같은 `X-Chatbot-Delivery`**.
- **AC-WF4-2** Given 400 응답, Then 즉시 `FAILED` · 재시도 없음 · 본문 보관(7일).
- **AC-WF4-3** Given 429 + `Retry-After: 120`, Then 다음 시도 = 120초 뒤(상한 안). `Retry-After: 99999` → 상한 2시간.
- **AC-WF4-4** ★ Given 2인스턴스(같은 DB), When 동시에 `tick()`, Then 각 행은 한 인스턴스만 발송(전송 목 호출 수 = 행 수).
- **AC-WF4-5** Given `SENDING` 중 프로세스 종료(임대 만료 시뮬레이션), Then 다음 `tick()`이 회수해 재발송 · 같은 `deliveryId`.
- **AC-WF4-6** ★ Given 서명 켜짐, Then 수신 헤더 `X-Chatbot-Signature`의 `v1`이 `HMAC(secret, t + "." + 원시 본문)`과 일치(단위 시험 — 연동 가이드 예시 코드로 검증).
- **AC-WF4-7** Given 세션 상한 3/10분, When 같은 세션이 폼 5회 제출, Then 3건 `PENDING` · 2건 `SKIPPED(RATE_LIMITED)` · 봇 응답 5회 동일.
- **AC-WF4-8** Given 비밀 주소 대상 · 환경변수 주소 호스트 ≠ 기준 주소 호스트, Then `FAILED(TARGET_HOST_MISMATCH)` · 송신 0.
- **AC-WF4-9** Given 비밀 미설정, Then `FAILED(SECRET_MISSING)` · 대상 목록 "미설정" · 참조 노드/구독 경고 배지.

### AC-WF5. 출구 · 방어 · 거버넌스

- **AC-WF5-1** ★ Given 모드 ON · 허용 목록 밖 호스트, When 대상 저장, Then `400 EGRESS_HOST_NOT_ALLOWED`. 저장된 대상의 호스트를 목록에서 뺀 뒤 발송, Then 송신 0 · `FAILED(EGRESS_BLOCKED)` · 재시도 없음.
- **AC-WF5-2** ★ Given 대상 호스트가 DNS로 `127.0.0.1`·`169.254.169.254`로 해석, Then 송신 0 · `FAILED(BLOCKED_ADDRESS)` — 사설 허용 목록에 넣어도 절대 차단 대역은 열리지 않는다.
- **AC-WF5-3** Given 3xx 응답, Then 따라가지 않음 · `FAILED(REDIRECT_NOT_ALLOWED)`.
- **AC-WF5-4** Given 데이터 지도, Then 출구 6클래스 · "업무 자동화 웹훅" 행에 대상 수·허용/차단·원문 허용 수 표시.
- **AC-WF5-5** Given 거버넌스 암호화 ON, Then 발송함 본문 DB 원시 값이 `enc:v1:` 봉투 · 발송 본문은 평문 JSON(복호화 후).
- **AC-WF5-6** Given `CALL_LOGS` 보존 30일 · 31일 전 종단 이력, When 파기 잡, Then 이력 행 삭제 · 대기·재시도 행 유지.

### AC-WF6. 운영

- **AC-WF6-1** ★ Given `FAILED` 5건(본문 있음), When 재발송, Then 5건 `PENDING` · `deliveryId` 불변 · 감사 1건. 본문 소거 건 포함 시 `409 WORKFLOW_RUN_NOT_RETRYABLE`(해당 id 목록).
- **AC-WF6-2** Given 대상 정지, When 이벤트 3건 발생, Then 3건 `HELD` · 재개 시 `PENDING` · 24시간 경과분은 `EXPIRED`(본문 소거).
- **AC-WF6-3** Given 연속 실패 10회, Then 대상 경고 배지 · 챗봇 목록 "확인 필요" · 성공 1회로 해제 · 자동 정지 없음.
- **AC-WF6-4** Given 이력 조회, Then 필드 **이름만** 보이고 값·본문·`sessionId` 없음.
- **AC-WF6-5** Given 테스트 발송, Then 1회 · `test:true` · 결과 안내 · 이력 `TEST` · 분당 6회째 `429`.
- **AC-WF6-6** Given 참조 중인 대상 삭제, Then `409 WORKFLOW_TARGET_IN_USE`(참조 노드·구독 목록).

### AC-WF7. 권한 · 감사 · 버전

- **AC-WF7-1** ★ Given EDITOR, When 대상 생성·원문 허용·테스트 발송, Then `403`. 구독·노드 편집·재발송은 허용. VIEWER는 조회만. AGENT는 전부 `403`.
- **AC-WF7-2** Given 선택 목록 응답, Then 주소·secretRef 필드가 없다.
- **AC-WF7-3** Given 대상·구독 변경, Then 감사 1건씩(비밀 값 0) · 발송 1건마다 감사 0.
- **AC-WF7-4** Given `WORKFLOW` 있는 버전 복원·운영 전환 · 대상 삭제됨, Then 경고(차단 아님) · 운영 대화에서 `SKIPPED(TARGET_UNAVAILABLE)`.
- **AC-WF7-5** Given 환경 모드 챗봇 · 초안에만 `WORKFLOW` 추가, Then 운영 대화는 발송 0(운영 버전 번들 기준).
