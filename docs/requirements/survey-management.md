#### 1.3.2 엔진 통합 — 정지점(ADR-0034) 재사용 vs 세션형 + 사후 적재

| 기준 | 정지점 재사용(설문 시작·매 응답마다 정지 → DB 확인 → 재진입) | **세션형 + 결과에 설문 이벤트 동봉 → API 계층 사후 적재** ★ |
|---|---|---|
| 정지가 필요한가 | 정지점은 "**호출 결과에 따라 다음 출력이 달라질 때**"를 위한 장치다(ADR-0034 근거 99행). 설문의 다음 출력(다음 문항·재질문·완료 문구)은 **입력과 설문 정의만으로 결정**된다 | 엔진이 출력을 끝까지 결정하고, DB는 **기록만** 한다 — 기록 결과가 출력을 바꾸지 않는다 |
| DB 판단이 필요한 유일한 지점 | "이 세션이 이미 완료했나"(중복) — 서버 조회 없이 봉투 기록으로 UX를 막고, 서버는 **적재 시 중복 표시**로 통계에서 걸러 낸다(§1.3.3). 출력이 서버 판정을 기다릴 필요가 없다 | 같음 |
| 턴당 정지 1회 규약과의 충돌 | API 분기 대상 노드의 `SURVEY`는 **두 번째 정지**가 되어 실행 불가(`apiCallsRemaining = 0` 재진입, `api-call.ts` 223행) | 정지 없음 → API 분기 노드에서도 설문 시작 가능(EX-SV-18) |
| 소비자 영향 | 공개·시뮬레이터·비교·TC 4곳에 설문용 완결 헬퍼 추가 | 결과의 선택 필드(`surveyEvents`)를 **무시하면 저장만 안 될 뿐 출력은 같다** — TC·비교·시뮬레이터는 무시(저장 0이 기본값) |
| 엔진 수정량 | 정지 분기 + 재진입 함수 + 폴백 동봉 | 세션 모듈(순수) + 결과 필드 + 상태 필드 — **컨텍스트 폼과 같은 모양** |
| 판정 | 기각 | **채택 권고**(architect 확정 사항 — J-4) |

### 1.5 목적

1. 관리자가 **챗봇별로 설문을 만들고**(단일/다중 선택·척도·자유 텍스트), 대화 노드에서 **호출**해 최종 사용자가 **대화 창 안에서** 답하게 한다(카탈로그 "대화 중 설문조사 생성·호출").
2. 응답은 **문항 단위로 즉시** 서버에 남아, 완료하지 않은 사용자의 **어디서 멈췄는지**까지 참여 통계로 볼 수 있다(카탈로그 "응답결과·참여통계").
3. 설문 진행 상태는 클라이언트 봉투에 두되, **응답 값·완료 판정·중복 판정의 근거는 서버**에 둔다 — 봉투 무서명(ADR-0009)이 응답 데이터의 신뢰를 깨지 않는다.
4. 자유 텍스트는 **마스킹 후에만** 저장되고, 응답은 어떤 운영 경로로도 **조용히 사라지지 않는다**(ADR-0033 봉인 확장).
5. **공개 표면·위젯·엔진 계약을 늘리지 않는다** — `@Public()` 6개 · 위젯 변경 0 · 엔진 I/O 0 · 봉투 버전 1 유지.
6. 설문이 없는 챗봇에서 대화·시뮬레이션·TC·통계·버전·예약 배포의 동작이 **바이트 단위로 동일**하다.

### 2.2 사용자 시나리오

**S-1. 설문 응답 (최종 사용자 · ★ 핵심)**
배송 조회 대화 끝에 "배송이 완료되었어요." 다음 줄로 "배송은 만족스러우셨나요? 30초면 끝나요." + **1/3** "배송 속도는 어떠셨나요?" + 버튼 `1점`~`5점`, `그만하기`가 나온다. `4점`을 누르면 **2/3** "좋았던 점을 골라 주세요(여러 개면 번호를 쉼표로 입력해 주세요 — 예: 1,3)" + 번호가 붙은 선택지 버튼이 나온다. "1,3"을 입력하면 **3/3** 자유 텍스트 문항과 `건너뛰기` 버튼. "포장이 꼼꼼했어요"를 보내면 "소중한 의견 감사합니다!" 뒤에 `추가문의_안내` 노드의 출력이 이어진다.

**S-2. 잘못된 답 (최종 사용자)**
척도 문항에서 "괜찮았어요"를 입력 → "1~5 사이의 숫자로 답해 주세요. (예: 4)"로 **같은 문항을 다시** 묻는다. 두 번 더 틀리면 "입력 횟수를 초과해 설문을 마칠게요. 궁금한 점을 입력해 주세요."로 끝난다(이탈 사유 `RETRY_EXCEEDED`).

**S-3. 중간에 그만두기 · 다른 질문 (최종 사용자)**
2/3 문항에서 "그만"을 입력하면 "설문을 마칠게요. 참여해 주셔서 감사합니다."(이탈 `CANCELLED`, Q1 응답은 남는다). 대신 앞 메시지의 `상담원 연결`(노드 버튼)을 누르면 설문이 끝나고 상담원 안내가 바로 나온다(`SWITCHED`).

**S-4. 방치 후 돌아오기 (최종 사용자)**
Q2에서 40분간 자리를 비운 뒤(타임아웃 30분) "환불 방법 알려줘"를 입력 → "설문 참여 시간이 지나 설문을 마쳤어요." 1줄 뒤 **이번 입력은 일반 대화로 처리**되어 환불 안내가 나온다. 20분 뒤였다면 "환불 방법 알려줘"는 Q2의 답으로 판정되어 재질문이 나온다.

**S-5. 이미 참여함 (최종 사용자)**
같은 탭에서 다시 배송 조회를 끝까지 진행 → "배송이 완료되었어요." 뒤에 설문 대신 아무것도 추가되지 않는다(노드의 다른 출력이 있으므로). 설문 아웃풋만 있는 노드였다면 "이미 설문에 참여해 주셨어요. 감사합니다."가 나온다.

**S-6. 설문 만들기 (EDITOR)**
챗봇 상세 > 설문관리 > `설문 추가`. 문항을 추가하고 유형별 입력(선택지 목록·척도 종류·최대 글자)을 채운 뒤 `미리보기`로 위젯에 나갈 모양(문항 문구 + 버튼)을 확인한다. `오픈`을 누르면 "문항이 1개 이상이어야 합니다" 같은 검증을 통과해야 한다.

**S-7. 노드에 연결 (EDITOR)**
노드 편집 > 아웃풋 추가 > `설문` → **설문 선택기**(이 챗봇의 설문 목록: 이름·상태·문항 수) → `완료 후 이동 노드`(선택). 설계 점검이 "설문 뒤의 아웃풋 1개는 설문이 시작되면 실행되지 않습니다"(WARNING)를 보여 준다.

**S-8. 응답이 달린 설문 수정 (EDITOR · J-8)**
Q2에 선택지 "가격"을 추가하려고 저장 → `409` "응답이 있는 설문은 문항 구성을 바꿀 수 없습니다. 문구 수정만 가능합니다. 구성을 바꾸려면 `복제`로 새 설문을 만드세요." `복제`하면 "배송 만족도 (사본)"이 DRAFT로 생기고, 노드 연결은 사용자가 바꾼다. 선택지 "기사님 친절"을 "기사님 응대"로 고치는 것은 허용되며 "문구를 바꾸면 이전 응답과 의미가 달라질 수 있습니다" 배너가 뜬다.

**S-9. 참여 통계 (VIEWER · J-13)**
설문 결과 > 요약: 기간 09/25~10/24(노출일 기준) · 노출 1,240 · 시작 610(참여율 49.2%) · 완료 512(완료율 41.4%) · 중도 이탈 88(중도 이탈률 14.8%) · 진행 중 10 · 중복 완료 7(제외됨). 문항별: Q1 평균 4.1점 · 분포 막대 + 표 · Q2 도달 571 · "속도" 62%(복수 응답 — 합계 100% 초과) · Q3 응답 203 · 건너뜀 309 · 응답 목록(마스킹 — "배송 기사님 010-****-5678 친절" 형태). "자유 응답의 이름·주소는 자동으로 가려지지 않을 수 있습니다" 안내.

**S-10. CSV (VIEWER · J-16)**
`응답 내려받기` → 기간 필수 → `survey-배송만족도-responses-20250925-20251024.csv`: 응답 번호 · 노출 일시(KST) · 상태 · 채널 · 완료 일시 · Q1 · Q2 · Q3 열. `sessionId` 열은 없다. 10,000건 초과면 최신 10,000건 + "기간을 좁혀 다시 내려받으세요" 안내.

**S-11. 시뮬레이터 (EDITOR/VIEWER · J-17)**
시뮬레이터에서 S-1을 재현하면 결과 패널에 `설문 단계: 2/3 · 판정 성공(선택 1,3) · 저장되지 않음`이 보인다. 설문이 DRAFT라 "지금은 참여할 수 있는 설문이 없어요"가 나오면 `설문 미리보기` 토글을 켜고 다시 실행한다.

**S-12. 접근성 (최종 사용자 · EDITOR)**
스크린리더 사용자는 문항 번호("2/3")와 문항 문구를 먼저 듣고, 버튼은 `1점 매우 불만족`처럼 **텍스트 라벨**로 듣는다(별 기호 단독 금지). 편집기의 문항·선택지 순서는 위/아래 버튼으로 바꾼다(드래그 단독 금지). 통계 차트는 같은 값의 **표**를 함께 제공한다.

| FR-SV2-6 | **복제**(`POST …/surveys/:surveyId/copy`): 정의만 복사, 이름 "… (사본)"(충돌 시 번호), 상태 `DRAFT`, 문항·선택지 **키를 새로 발급**, 응답·노드 참조는 복사하지 않는다. |
| FR-SV2-7 | **삭제**: 노드가 참조 중이면 `409 SURVEY_IN_USE`(참조 노드 최대 5건 — 노드명), **응답 행(노출 포함) 1건 이상이면 `409 SURVEY_HAS_RESPONSES`**("마감하면 더 이상 응답을 받지 않습니다" 안내). 둘 다 없을 때만 물리 삭제. ⚠ 스냅샷 안의 참조는 삭제를 막지 않는다(J-9). |
| FR-SV2-8 | **감사**: `AuditTargetType`에 `Survey`를 추가하고 생성·수정·삭제(`CREATE`/`UPDATE`/`DELETE`)·상태 변경(`STATUS_CHANGE`)·복제(`COPY`)를 기록한다. 화이트리스트: `name`·`status`·`activeFrom`·`activeTo`·`questionCount`·`structureVersion`·`sessionTimeoutMinutes`. **문항 문구·선택지·안내 문구 본문은 기록하지 않는다**(개수·버전만 — `outputs`를 화이트리스트에서 뺀 선례 `audit-snapshot.ts` 39행). |
| FR-SV2-9 | 설문 정의는 **대화 번들에 포함**한다(번들 캐시 무효화 = 설문 쓰기 시 — 기존 자산 쓰기와 같은 경로). 번들 스키마의 설문 필드는 **선택(기본 `[]`)** 이다(FR-SV10-2). |
| FR-SV2-10 | 목록 응답에 설문별 **상태·기간·문항 수·참조 노드 수·최근 30일 노출/완료 수**를 담는다(통계 요약 쿼리 재사용, N+1 금지). |

### 4.3 `SURVEY` v2 아웃풋 · 설계 점검 · 참조 무결성 — J-18 · J-20

```
SURVEY v2 = {
  version: 2,
  surveyId: uuid,              // 같은 챗봇의 Survey
  onCompleteNodeId?: uuid      // 완료 직후 이어서 실행할 노드(선택) — 이탈·건너뜀에는 쓰지 않는다
}
```

| ID | 요구사항 |
|---|---|
| FR-SV3-1 | 저장 시 서버 검증: `surveyId`가 **같은 챗봇의 설문**(없으면 `404 INVALID_REFERENCE` + `details`) · `onCompleteNodeId` 존재. 설문 상태는 저장을 막지 않는다(DRAFT 설문을 미리 연결 가능). |
| FR-SV3-2 | **참조 무결성 편입(J-20)**: `onCompleteNodeId`를 `getOutgoingNodeRefs()`(`design-validator.ts` 9~30행)의 신규 분류 `surveyTargets`로 넣어 ① 노드 저장 검증 ② 노드 삭제 `409 NODE_IN_USE` ③ 들어오는 참조·고아 판정·흐름 요약 ④ 스냅샷 무결성 경고 4곳에 반영한다. 노드 → 설문 참조는 설문 삭제 409(FR-SV2-7)와 스냅샷 경고(FR-SV10-1)에 반영한다. |
| FR-SV3-3 | 설계 점검 신규 항목: ① `SURVEY` 뒤에 아웃풋이 있음(WARNING — "설문이 시작되면 실행되지 않습니다") ② 한 노드에 `SURVEY` 2개 이상 또는 `SURVEY`+`CONTEXT_FORM`(ERROR — 첫 종결자만 의미) ③ 참조 설문이 `DRAFT`/`CLOSED`/기간 종료(WARNING) ④ 노드 출력이 `SURVEY`뿐(INFO — "설문을 진행할 수 없을 때 고정 안내 문구가 나갑니다") ⑤ v1 형식(WARNING — FR-SV1-4) ⑥ 참조 설문의 문항 0개(ERROR). |
| FR-SV3-4 | 노드 아웃풋 상한 10개(`dialogue.ts` 824행)는 불변. v2 `SURVEY`는 노드 복사 시 그대로 복사한다. |

### 4.4 대화 실행 (엔진 — 순수) — J-3 · J-4 · J-7 · J-10 · J-19

#### 4.4.1 시작 · 건너뜀

| ID | 요구사항 |
|---|---|
| FR-SV4-1 | `executeOutputs`가 v2 `SURVEY`를 만나면 **참여 가능 판정**(순수): ① 번들에 설문 존재 ② `status = OPEN` ③ `activeFrom ≤ now < activeTo`(지정된 쪽만) ④ 봉투 `completedSurveyIds`에 없음 ⑤ 문항 ≥1. 옵션 `surveyPreview = true`(시뮬레이터 토글·TC·비교)면 ②③을 무시한다(J-17). |
| FR-SV4-2 | **참여 가능 → 시작**: 그때까지의 출력 뒤에 `introMessage`(있으면) + 첫 문항 출력을 붙이고, 다음 상태에 `surveySession`을 만들고, `surveyEvents`에 `EXPOSED`를 넣고 **실행을 멈춘다**(뒤 아웃풋 미실행 — `CONTEXT_FORM` 종결 규약, `outputs.ts` 148~162행). 진행 중 컨텍스트 세션이 있으면 **취소 + 전환 고지**(`SESSION_SWITCH_MESSAGE` `constants.ts` 20행 재사용). |
| FR-SV4-3 | **참여 불가 → 건너뜀**: 트레이스 `SURVEY_SKIPPED`(사유 `NOT_FOUND`·`NOT_OPEN`·`OUT_OF_PERIOD`·`ALREADY_RESPONDED`·`EMPTY`)를 남기고 **다음 아웃풋을 계속 실행**한다(`SURVEY`는 시작될 때만 종결자). 노드 출력이 결국 0건이면 기존 기본 폴백 대신 **설문 고정 문구**: `ALREADY_RESPONDED` → "이미 설문에 참여해 주셨어요. 감사합니다." · 그 외 → "지금은 참여할 수 있는 설문이 없어요." |
| FR-SV4-4 | 트레이스 `SURVEY_SKIPPED`는 `judgeAnswered`의 폴백 코드(`conversation-log.ts` 5행)에 **넣지 않는다** — 설문 미진행은 학습 공백이 아니다. |

### 4.5 응답 적재 (API 계층) · 위변조 방어 — J-3 · J-10 · J-11

| ID | 요구사항 |
|---|---|
| FR-SV5-1 | 공개 대화 파이프라인에서 결과에 `surveyEvents`가 있으면 **엔진(및 API 완결) 직후 · 출구 필터 전**에 `SurveyResponseService.apply()`를 **await**한다(설문 턴만 — 순서 보장·중복 흡수). 적재 실패는 대화 응답을 실패시키지 않는다(예외 삼킴 + 내용 없는 경고 로그 — `record()` 99~103행 규약). |
| FR-SV5-2 | `EXPOSED` → 응답 행 생성: `chatbotId` · `surveyId` · `structureVersion` · `sessionId` · `channelType` · **`groupId` 스냅샷**(요청 처리 중 이미 가진 챗봇 행 — 추가 조회 0, ADR-0033 §4) · `startedAt`(엔진이 정한 값) · `exposedNodeId` · `conversationLogId`(이번 턴 `messageId`) · `dayBucket`(KST, 노출 시점 확정·불변) · 상태 `EXPOSED`. 같은 쓰기 키의 행이 이미 있으면 무시(리플레이). |
| FR-SV5-3 | `ANSWERED`/`SKIPPED` → **쓰기 가드**: ① 쓰기 키 `(chatbotId, sessionId, surveyId, startedAt)`의 행 존재 ② 상태가 `EXPOSED`/`IN_PROGRESS` ③ 구조 버전 일치 ④ 문항 인덱스 < 문항 수 & **이미 적재된 마지막 인덱스보다 큼** ⑤ `(응답 행, 문항 키)` 미적재. 하나라도 불충족이면 **조용히 무시**(카운터·경고 로그 — 값 없음). 통과하면 답 행 적재 + 응답 행 `IN_PROGRESS`·`lastInteractedAt`·`lastAnsweredIndex` 갱신(첫 답이면 `firstAnsweredAt`). |
| FR-SV5-4 | `COMPLETED` → 응답 행 `COMPLETED`·`completedAt`. **서버가 필수 문항 답 행 존재를 재확인**해 누락 수를 `missingRequiredCount`로 남긴다(정상 경로 = 0). 같은 `(chatbotId, sessionId, surveyId)`에 **이미 완료된 행이 있으면 `isDuplicate = true`**. |
| FR-SV5-5 | `ABANDONED` → 응답 행 `ABANDONED`·`endReason`·`endedAt`. 무응답 이탈(탭 닫기·방치)은 **행을 바꾸지 않고** 조회 시점에 판정한다(FR-SV6-3). |

## 7. 수용기준 (AC)

### AC-SV1. 범위 · 호환 · 참조 무결성

- **AC-SV1-1** ★ Given v1 `SURVEY`(`surveyId: 'post-shipping-satisfaction'`) 노드, When 공개 대화·시뮬레이터로 매칭시키면, Then 결과는 No.27 이전과 **바이트 단위로 같다**(`unsupportedOutputs`에 `SURVEY` + 안내 문구 폴백) — 같은 문자열 키의 설문이 있어도 연결되지 않는다.
- **AC-SV1-2** Given v1 payload, When 노드 생성·수정 API로 저장하면, Then `400 SURVEY_OUTPUT_LEGACY_FORMAT`이다. 노드 복사는 v1 `SURVEY`를 제외하고 안내를 담는다.
- **AC-SV1-3** Given v1 `SURVEY` 노드, When 설계 점검을 돌리면, Then 미지원 INFO와 전환 WARNING이 **둘 다** 있다(`design-validator.ts` 교체 회귀).
- **AC-SV1-4** Given 설문 아웃풋이 없는 챗봇, When 기존 엔진·대화·통계·검증·버전 스위트를 돌리면, Then FR-0-107 예외 목록 외에는 **수정 없이 전부 통과**한다.
- **AC-SV1-5** Given 다른 챗봇의 설문 id를 가진 v2 `SURVEY`, When 저장하면, Then `404 INVALID_REFERENCE`다.
- **AC-SV1-6** Given 노드 B가 `onCompleteNodeId`로만 참조됨, When B 삭제 요청·흐름 요약을 보면, Then `409 NODE_IN_USE`이고 B는 고아가 아니다.
- **AC-SV1-7** Given 노드가 참조 중인 설문 / 응답(노출 포함)이 있는 설문, When 삭제하면, Then 각각 `409 SURVEY_IN_USE` / `409 SURVEY_HAS_RESPONSES`이고 DB 변경 0이다.

### AC-SV2. 대화 진행

- **AC-SV2-1** ★ Given S-1 설문(OPEN), When 노드를 매칭시키면, Then **한 응답에** 앞 출력 + 소개 + "1/3" 문항 + `1점`~`5점`·`그만하기` 버튼이 있고, 설문 뒤 아웃풋은 **출력되지 않으며**, 다음 상태에 `surveySession`(문항 인덱스 0)이 있고 **응답 값 필드가 없다**.
- **AC-SV2-2** Given 1/3 진행 중, When `4점` → "1,3" → "포장이 꼼꼼했어요"를 보내면, Then 완료 문구 + `onCompleteNodeId` 노드 출력이 나오고, `completedSurveyIds`에 설문 id가 있으며, `surveySession`이 null이다.
- **AC-SV2-3** Given 척도 문항, When "괜찮았어요"를 3번 보내면, Then 1·2번째는 같은 문항 재질문, 3번째는 종료 안내 + `ABANDONED(RETRY_EXCEEDED)`다.
- **AC-SV2-4** Given 다중 선택(1~3개), When "1, 2, 3, 4" / "5" / "포장,속도"를 보내면, Then 각각 재질문(최대 초과) / 재질문(범위 밖) / 성공(키 2개)이다.
- **AC-SV2-5** Given 선택 문항, When `건너뛰기`를 누르면 `SKIPPED`로 다음 문항, 필수 문항이면 재질문이다.
- **AC-SV2-6** Given 진행 중, When "그만" / 이전 메시지의 `NODE` 버튼을 보내면, Then `CANCELLED` 종료 안내 / `SWITCHED` 후 버튼 노드 출력이다.
- **AC-SV2-7** ★ Given 타임아웃 30분 설문 진행 중, When 31분 뒤 "환불 방법 알려줘"를 보내면, Then 종료 안내 1줄 **+ 환불 노드 출력**이 한 응답에 있고 `ABANDONED(TIMEOUT)`다. 29분 뒤면 설문 판정(재질문)이다.
- **AC-SV2-8** Given `completedSurveyIds`에 설문 id가 있는 봉투, When 같은 노드를 매칭시키면, Then 설문이 시작되지 않고 다른 아웃풋이 실행된다. 노드 출력이 설문뿐이면 "이미 설문에 참여해 주셨어요. 감사합니다."다.
- **AC-SV2-9** Given 설문 `DRAFT`/`CLOSED`/기간 밖, When 공개 대화로 매칭시키면, Then 설문이 시작되지 않고(트레이스 `SURVEY_SKIPPED`) 로그 `isAnswered`는 설문 때문에 false가 되지 않는다.
- **AC-SV2-10** Given 진행 중 관리자가 설문을 마감(또는 응답 전 구조 변경), When 다음 턴을 보내면, Then 종료 안내 + 이번 입력은 일반 대화로 처리된다.
- **AC-SV2-11** Given 진행 중 컨텍스트 폼이 있는 봉투, When 버튼으로 설문 노드에 들어가면, Then 전환 고지 + 설문 시작이고 컨텍스트 세션은 취소된다. 두 세션이 동시에 `IN_PROGRESS`인 봉투는 생기지 않는다.

- **AC-SV2-13** Given 선택지 8개 단일 선택, When 문항을 출력하면, Then 선택지 버튼이 5·3 두 블록이고 8개 모두 버튼이 있다(`slice(0,5)` 결함 비재현).
- **AC-SV2-14** Given 설문 진행 중 입구 금지어 BLOCK 입력, When 보내면, Then 금지어 안내가 나오고 봉투가 그대로이며 같은 문항이 유지된다.

### AC-SV3. 적재 · 위변조 · 중복

- **AC-SV3-1** ★ Given S-1을 완주한 세션, When DB를 보면, Then 응답 행 1(`COMPLETED`·`missingRequiredCount=0`·`groupId`·`dayBucket` 채워짐) + 답 행(Q1 정수 4 · Q2 선택지 키 2개 · Q3 마스킹 텍스트)이다.

- **AC-SV3-4** Given 같은 요청(봉투+답)을 2회 전송, When DB를 보면, Then 답 행 1건이다.
- **AC-SV3-5** ★ Given 완료 후 봉투에서 `completedSurveyIds`를 지우고 다시 완주, When 통계를 보면, Then 두 번째 응답 행은 `isDuplicate=true`이고 완료 수는 1이다(`includeDuplicates=true`면 2).
- **AC-SV3-6** Given 답 행 쓰기 실패(DB 오류 주입), When 턴을 보내면, Then 사용자 응답은 정상이고 서버 로그에 응답 값이 없다.
- **AC-SV3-7** Given 설문 응답 턴 3개, When `ConversationLog`를 보면, Then 3행 모두 `surveyTurn=true`이고 노출 턴은 false다. 미응답 큐에 설문 턴이 **적재되지 않았다**.
- **AC-SV3-8** ★ Given 100명이 척도 문항에 "5"를 입력, When 챗봇 스코프·그룹 스코프 질문 순위를 보면, Then "5"가 **나타나지 않는다**. 턴 수·세션 수·응답률은 설문 턴을 포함한 값이다.
- **AC-SV3-9** Given RAG 설정이 켜진 챗봇, When 설문 진행 중 턴·설문 고정 문구 턴을 보내면, Then RAG 호출 0건이다.

### AC-SV6. 시뮬레이션 · TC · 버전 · 봉인

- **AC-SV6-1** ★ Given VIEWER가 시뮬레이터로 설문 완주, When DB를 보면, Then 응답·답 행 **0건**이고 결과 패널에 `저장되지 않음`이 있다.

- **AC-SV6-3** ★ Given 설문 3턴 TC(설문 CLOSED), When 서로 다른 날짜에 2회 실행하면, Then 둘 다 설문이 진행되고 **응답 해시가 동일**하며 응답 행 0건이다.
- **AC-SV6-4** Given 설문을 참조하는 버전 v8과 설문 삭제(노드 참조 제거 후), When v8 복원 미리보기를 하면, Then 경고 `SURVEY_MISSING`이고 blocker가 아니다. 복원 후 해당 노드는 설문을 건너뛴다.
- **AC-SV6-5** Given 스냅샷 캡처, When 페이로드를 검사하면, Then 설문 정의가 없다. 스냅샷에서 hydrate한 번들로 복원 검증이 통과한다(설문 필드 선택).
- **AC-SV6-6** Given 응답이 있는 챗봇, When 영구삭제하면, Then `409 CHATBOT_HAS_CHILDREN`에 `설문 응답`이 포함된다.
- **AC-SV6-7** Given 저장소 전체, When `survey-sealing.spec.ts`를 돌리면, Then NFR-SVS3의 9단언이 통과한다(역검증 픽스처 포함).

### AC-SV7. 접근성 · 콘솔

- **AC-SV7-1** Given 키보드만 사용, When 설문을 만들고 문항 순서를 바꾸고 오픈하고 노드에 연결하면, Then 마우스 없이 완료된다.
- **AC-SV7-2** Given 신규 화면 3종(설문 목록·편집기·결과), When axe를 돌리면, Then 대비 위반 0건이다. 차트마다 표가 있다.
- **AC-SV7-3** Given 위젯 스크린리더, When 척도 문항이 도착하면, Then "n/N"·문항 문구·`1점 매우 불만족` 순으로 읽힌다(ui-designer 기준 확정 후).
