## 1. 배경 / 목적

### 1.1 근거

### 1.3 목적

1. 기존 10분 프리셋(`customer-onprem-10m`)을 **보존**하면서 신규 기능을 보여 줄 수 있게 한다.

## 3. 사용자 시나리오

### 3.1 역할

DT-1 §2.1과 같다(시연 진행자 · 개발자 · 고객 관람자 · 시연 계정 5종). 추가: **시연 계정은 그대로**(새 계정 0).

### 3.2 시나리오

**S-DX-1 (풀 투어 · 3050 노트북 · 플래그 전부)**: 진행자가 `pnpm demo -- --preset customer-onprem-full --with-voice-input --with-local-llm`을 실행한다. 사전 점검이 DT-1 항목에 더해 음성 의존성·STT 모델 캐시·CUDA DLL 경로·한국어 합성 음성·Ollama 모델·가짜 마이크 동작을 확인한다. 준비 단계에서 로컬 생성 결과 1건을 미리 만들어 두고(실패 시 대체용), Ollama 모델을 내린 뒤 음성 인식 프로세스(GPU)를 띄운다. 공연은 DT-1 7장면 → ⑧ 음성(합성 음성 파일을 가짜 마이크로 재생 → 입력창에 글자가 채워짐 → 전송 → 답 듣기) → ⑨ 선제 안내 → (음성 프로세스 종료·VRAM 회수 확인) → ⑩ 엣지 추론(사내 소형 모델이 예문 후보를 만들고 사람이 고름) → 끝. 자막에는 "합성 음성 · 가짜 마이크" · "이 노트북 GPU(RTX 3050) 사용 · 동작 확인 수준" 이 공개된다.

**S-DX-2 (풀 투어 · GPU 없는 노트북 · 플래그 없음)**: 같은 프리셋을 플래그 없이 실행한다. ⑧은 콘솔 음성 구역·답변 듣기·데이터 지도 `speech` 절만 보이고, 음성 입력 단계는 "이 PC 구성에서는 음성 인식 모델을 띄우지 않았습니다"로 생략된다. ⑩은 구간째 생략되고 끝 장면 로드맵에 1줄로 안내된다. "GPU 없이 CPU로" 배지가 공연 전체에서 유지된다.

**S-DX-3 (무인 점검 · 개발자)**: `pnpm demo:check -- --preset customer-onprem-full --with-voice-input`. 가짜 마이크로 녹음 → 서버 STT → 입력창 글자가 기대 문장과 대략 일치(FR-DX4-6) → 전송 → 기대 의도 답 → `speech` 키 존재 → 엑셀 내보내기 파일 수신·행 수 확인 → 선제 말풍선 표시·클릭 집계 증가를 검증한다. 음성 모델이 없는 PC는 `--voice-mock-check`로 **파이프만**(위젯 → API → 모의 공급자) 점검하고 보고서에 "모의 인식 — STT 미검증"을 기록한다.

**S-DX-4 (10분 시연 · 변경 없음)**: `pnpm demo`는 DT-1 정의 그대로 돈다. 끝 장면 로드맵만 No.32가 "구현됨 — 확장판에서 시연"으로 바뀌어 있다.

**S-DX-5 (실패 중 시연)**: ⑧에서 STT가 15초 안에 답하지 않는다. 하네스는 그 단계를 실패로 기록하고 "음성 인식이 지연되어 글자로 입력합니다" 자막과 함께 같은 문장을 타이핑해 대화를 이어 간다(FR-DX4-9).

### 5.3 한계

1. **가짜 오디오 파일은 브라우저 기동 인자**라 한 실행(한 영속 컨텍스트) 동안 **한 파일**만 쓸 수 있다 → 음성 문장 1개(FR-DX4-4). 문장 2개가 필요하면 브라우저 재기동(영상이 갈라짐 — 비권고).
2. 녹음을 시작할 때마다 파일이 처음부터 재생되는지, 이어서 재생되는지 **미확인** → 녹음은 공연 중 1회(무인 점검도 1회)를 기본으로 한다.
3. 녹음 길이는 하네스가 클릭으로 정한다 — 파일보다 짧으면 문장이 잘리고, `%noloop` 없이 길면 반복 재생이 섞여 "반복 고리 축약" 후처리에 걸린다 → `%noloop` 필수 + 녹음 = 파일 길이 + 0.8~1.2초(제안).
4. 관객은 가짜 마이크 소리를 듣지 못한다(FR-DX4-8 보완안). 영상·GIF에는 어떤 소리도 담기지 않는다.
5. 합성 음성은 화자·잡음 다양성이 없어 **실제 사용자 음성보다 낙관적**이다(STT 보고서 §5) — 시연 결과로 인식 품질을 말하지 않는다.
6. 기기 안 한국어 음성(듣기)은 PC·브라우저마다 다르다(자동배포 §5.14-8 ⑤) — 헤드리스 Edge의 `speechSynthesis` 음성 목록은 미확인.

### 6.1 동시 적재 조합(시연 구성 — 임베딩은 항상 CPU)

### 6.2 순차 적재 지점(요구사항)

| 시점 | 동작 | 이유 |
|---|---|---|
| 준비 P3 이전(`--with-local-llm`) | 로컬 생성 사전 1회 → Ollama 언로드 → VRAM 회수 확인 | 공연 중 대체 결과 확보 + STT와 겹치지 않게 |
| 준비 P3(`--with-voice-input`) | STT 프로세스 기동·예열(turbo 약 5.6~7.2초 — 보고서 §4.1) | 공연 시간 밖 |
| 공연 ⑧·⑨ | STT 상주 · Ollama 미적재 | 조합 ① |
| ⑩ 시작 직전 | **STT 프로세스 종료 → VRAM 회수 조건 대기(상한 제안 15초 · 미실측)** → 생성 자식 기동 → 첫 요청이 Ollama 모델 적재(시간 **미실측**) | 조합 ⑤ 회피 |
| ⑩ 종료 | Ollama 언로드 · 생성 자식 종료 | 정리 |

- 구간 순서는 **⑧ → ⑨ → ⑩ → 끝**으로 고정한다(정의 검사로 강제 — ⑩ 뒤에 STT 장면 금지).
- VRAM 관찰은 보고서에만 쓰고 합격 판정에 쓰지 않는다(FR-0-352).
- STT를 CPU(조합 ③)로 정하면 ⑩ 직전 STT 종료는 VRAM 이유가 아니라 RAM 여유 이유로만 유지한다(architect 판단 — 기본은 같은 절차).

1. **실행 실측 0** — 셸을 실행하지 못했다. §8.1 예산·준비 시간·VRAM 회수 시간·Ollama 첫 적재 시간은 **제안·미실측**이다. 인용 수치는 `stt-3050-dongjak-hwakin.md`(STT VRAM·지연·적재)·`ollama-dev-pipeline-validation.md`(VRAM 관찰·20건 약 13초 — API 경유 아님)·`실기동확인.md`(KURE·Edge) 출처 그대로다.

3. **제품 경로 미확인** — 브라우저 `MediaRecorder` 산출물(webm/opus)을 서버 PyAV가 실제로 디코딩하는지(No.32 3050 확인에서 미수행), 증강 공급자를 챗봇별로 고를 수 있는지(FR-DX3-5 — 전역으로 추정), 콘솔 음성·선제 구역의 정확한 경로·버튼 문구, Ollama 언로드 API 사용 가능 여부는 코드를 끝까지 따라가지 않았다.
