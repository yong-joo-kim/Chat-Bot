## 0. 쉬운 말 요약 — 왜 필요한가, 무엇이 달라지나, 안 해도 되는 경우

### 0.1 한 줄 요약

**"챗봇 창에 마이크 버튼과 '듣기' 버튼을 달아, 말로 묻고 소리로 답을 듣게 한다. 말한 내용은 우리 서버가 글자로 바꾸되 목소리는 저장하지 않고, 답을 읽어 주는 목소리는 사용자 기기(브라우저)에 들어 있는 한국어 음성을 쓴다."** 전화 상담(콜봇)이나 끊김 없는 실시간 대화는 범위 밖이다. "감정 톤"은 "AI가 사용자 기분을 읽는 것"이 아니라 **"사과할 때는 조금 느리고 낮게, 인사할 때는 조금 밝게"처럼 답의 종류에 맞춰 읽는 빠르기·높낮이·크기를 고르는 규칙**이다. 기기마다 목소리가 다르고, 한국어 음성이 없는 기기에서는 듣기 버튼이 꺼진 채 안내가 나온다. **읽는 것은 봇의 답뿐이다** — "금지어가 포함돼 있어요", "잠시 답변을 준비하지 못했어요", "문서에서 찾아보고 있어요" 같은 시스템 안내 문구는 화면에만 보이고 소리로 읽지 않는다.

### 0.5 이 기능 없이 충분한 경우 (정직하게)

- **고객사가 웹 챗봇을 주로 PC에서 쓰고, 음성 요구가 접근성 대응 수준이면** — 기기의 스크린리더와 휴대폰 키보드 받아쓰기가 상당 부분을 대신한다. 위젯은 이미 레이블·`aria-live`를 지키고 있다.
- **실제 수요가 "전화 상담 자동화(콜봇)"라면** — 규모 A는 그 요구를 채우지 못한다.
- **운영 GPU 서버(L40S) 접근 담당자가 없는 지금** — 3050에서 "동작 확인"까지는 되지만 "고객에게 켜도 되는 인식 정확도인가"는 판정할 수 없다(No.17과 같은 상황 — **고객 개통은 운영 실측 후**).

PM은 2026-10-01 규모 A를 결정했다(P-1). 공공·연금 기관처럼 고령 사용자와 접근성 요구가 큰 고객, "목소리를 밖으로 보내지 않는 음성 챗봇"을 제안해야 하는 구축형 영업에서 가치가 있다.

### 1.7 ★ "감정 톤"의 정의 (확정 — P-4)

**정의**: 감정 톤 = **"봇 답변을 브라우저 음성으로 읽을 때의 빠르기(rate)·높낮이(pitch)·크기(volume)를, 답변의 종류와 관리자 지정에 따라 규칙으로 고르는 것"**. 사용자의 감정은 판정하지 않으며, 답변의 **글자 내용은 바꾸지 않는다.** 판정 모델 **0건**.

| 입력(무엇을 보고) | 출처 | 예 |
|---|---|---|
| ① 챗봇 기본 말투 | 관리자 설정 | "차분함"(기본) |
| ② 노드별 말투 지정(선택) | **음성 설정에서 관리자가 대화 노드를 골라 붙인 말투 꼬리표**(노드 출력 필드가 아님 — H-2) | 인사 노드 = "밝게" |
| ③ 응답 종류 신호(서버가 이미 아는 것) | 턴 결과 | 폴백·미응답 안내 = "사과" · No.36 "안전 문구로 대체" = "차분함"(고정) |

**우선순위**: 안전 문구(No.36 대체) 고정 > ② 노드별 지정 > ③ 응답 종류 규칙 > ① 기본. **말투 결정은 서버**가 하고(위젯은 응답 종류를 모른다 — `conversation.ts` 320~344행), 결과 말투 이름을 `speech` 키에 싣는다(FR-VO4-1).

> **[2026-10-01 환류 정정]** 초안 ③의 "상담 연결 안내 = 차분함"은 **삭제**했다 — 상담 연결 관련 문구는 봇 답변 경로가 아니라 상담 경로(상담원·상담 시스템 메시지)로 나가며 읽기 대상이 아니다(J-8 · H-4). "오류 안내 = 사과"도 **삭제**했다 — 일시 장애 문구는 시스템 안내라 읽지 않는다(H-3). 금지어 안내·외부 RAG 대기 문구도 같은 이유로 말투 대상이 아니다.

**출력(어떻게 반영)**: 말투 이름(닫힌 목록 4종 — 차분함·밝게·사과·안내, 이름은 ui-designer) → **고정 대응표**(공유 타입 상수 — 코드 분기 아님) → `SpeechSynthesisUtterance`의 `rate`·`pitch`·`volume`. 관리자 빠르기 배율(0.8~1.2)을 `rate`에 곱한다. 대응표 초안(**제안 · 미청취**, 확정은 ui-designer가 실제 기기 청취 후):

| 말투 | rate(× 관리자 배율) | pitch | volume |
|---|---|---|---|
| 차분함(기본) | 0.95 | 0.95 | 1.0 |
| 밝게 | 1.05 | 1.1 | 1.0 |
| 사과 | 0.9 | 0.9 | 0.9 |
| 안내 | 1.0 | 1.0 | 1.0 |

> ⚠ **정직한 한계(원문 요구와의 차이)**: 카탈로그 원문은 **"감정 톤 반영 자연스러운 음성 응대"** 다. P-3(브라우저 내장 음성) 결정으로 이 제품이 줄 수 있는 감정 톤은 **빠르기·높낮이·크기를 조금 바꾸는 수준**이며, 원문이 기대하는 "감정이 실린 목소리(스타일·억양 표현)"는 **채우지 못한다**. 또한 ① 기기 음성에 따라 `pitch`·`volume`을 **무시**할 수 있고(**확인 필요**) ② 목소리 자체가 기기마다 달라 **같은 말투도 기기마다 다르게 들린다**. 따라서 수용기준은 "위젯이 말투에 맞는 매개변수를 넘겼는가"까지만 자동 검증하고, **"듣기에 감정이 느껴지는가"는 합격 기준이 아니다**(§8 AC-VO3). 감정 표현이 강한 음성이 필요해지면 서버 사내 합성(말투 제어 모델) 또는 클라우드 음성을 다시 검토한다(§10 재검토 트리거).

### 1.8 목적

1. 웹 위젯에서 **말로 묻고(확인 후 전송) 소리로 듣는** 최소 음성 경험을 제공한다.
2. 대화 처리 구조(엔진·로그·마스킹·규칙·통계·상담)를 **바꾸지 않는다.**
3. **음성 원본을 저장·디스크 기록·외부 전송하지 않는다.**
4. STT는 3050 경량 경로와 L40S 운영 경로를 **설정만으로** 고르게 하고, 3050 결과는 "동작 확인"으로만 남긴다.
5. 공개 GPU 경로(음성 인식 1개)를 **남용·폭주로부터 보호**한다.
6. 답변 읽기는 **서버 자원 0**으로 사용자 기기에서 처리하되, 답 글자가 기기 밖으로 나가지 않게 한다(기기 안 음성만).
7. 실시간 스트리밍·전화·감정 판정·서버 합성은 **재검토 트리거와 함께** 범위 밖으로 둔다.

### 2.2 사용자 시나리오

**S-1 (최종 사용자 — 음성 질문)**: 휴대폰에서 챗봇 창을 연다 → 입력창 옆 마이크 버튼을 누른다 → 처음이면 브라우저 마이크 권한 창이 뜬다(위젯 첫 사용 고지 문구는 법무 확인 후 도입 — P-13) → "듣고 있어요 · 남은 시간 28초" 표시를 보며 "카드 분실 신고는 어떻게 해요"라고 말하고 다시 버튼을 누른다 → "글자로 바꾸는 중" → 입력창에 "카드 분실 신고는 어떻게 해요"가 채워지고 포커스가 입력창으로 간다 → 사용자가 확인하고 전송 → 이후는 지금과 똑같다.

**S-2 (최종 사용자 — 답변 듣기)**: 답변 옆 "듣기" 버튼을 누른다 → 기기의 한국어 음성으로 읽어 준다 → 다시 누르면 멈춘다. 외부 RAG 답이면 대기 문구("문서에서 찾아보고 있어요")에는 듣기 버튼이 없고, 최종 답이 표시된 뒤에 그 답에 듣기 버튼이 생긴다.

**S-3 (최종 사용자 — 자동 읽기)**: 위젯 머리의 "답변 소리로 듣기" 토글을 켠다(기본 꺼짐) → 이후 새 봇 답변이 도착할 때마다 자동으로 읽는다 → 사용자가 녹음을 시작하거나 입력을 시작하면 읽기를 멈춘다. 토글 상태는 탭 세션 동안 기억한다. 금지어 안내·일시 장애·답변 대기 같은 시스템 안내는 화면 글자로만 보이고 읽지 않는다(H-3 · EX-VO-25).

**S-4 (최종 사용자 — 한국어 음성이 없는 기기)**: 한국어 기기 음성이 없는 PC에서 챗봇을 연다 → 듣기 버튼과 자동 읽기 토글이 **비활성**으로 보이고 "이 기기에는 한국어 읽기 음성이 없어 소리로 들려드릴 수 없어요"가 글자로 안내된다(문구·위치는 ui-designer) → 글자 대화와 마이크 입력은 그대로 쓸 수 있다.

**S-5 (관리자 — 설정)**: 콘솔 챗봇 설정 › "음성"에서 음성 입력·듣기를 켠다 → 빠르기를 정한다 → 기본 말투 "차분함", 폴백(미응답) 말투 "사과"를 확인한다 → "들어보기"에 문장을 넣어 말투별로 들어 본다(**관리자 자기 브라우저의 기기 음성으로 재생 — 서버 호출 0**, "사용자 기기마다 목소리가 다르고, 말투는 빠르기·높낮이·크기만 바뀝니다" 안내) → 저장.

**S-6 (서버 음성 인식 꺼짐)**: 서버 음성 인식 스위치가 꺼져 있거나 음성 인식 프로세스가 내려가 있으면 → 위젯에 마이크 버튼이 **나타나지 않는다**(공개 설정 결과로 판단). **듣기는 서버 자원을 쓰지 않으므로 챗봇 듣기 설정만으로 동작한다.** 기동 중 장애가 나면 마이크를 누른 순간 "지금은 음성 입력을 쓸 수 없어요. 글자로 입력해 주세요"가 뜨고 입력창은 그대로 쓸 수 있다.

**S-7 (혼잡)**: 동시 인식 요청이 상한을 넘으면 → 대기열에 쌓지 않고 즉시 "음성 인식이 잠시 붐벼요. 글자로 입력하거나 잠시 뒤 다시 시도해 주세요".

**S-8 (시연 — 3050 노트북)**: 개발자가 3050 노트북에서 경량 STT 구성으로 S-1~S-5를 보여 준다. 시연 자료에는 "동작 확인용 — 인식 정확도·속도 판단 근거 아님 · 읽기 목소리는 시연 기기 음성"이 붙는다.

**S-9 (상담 중)**: 상담원이 개입한 대화(No.24)에서 사용자가 음성으로 입력하면 → 인식 글자가 상담원에게 글자로 간다. 듣기는 **봇 답변에만** 붙는다(상담원 메시지 제외 — J-8).

### 4.2 음성 인식 서버 (FR-VO2)

| ID | 요구사항 |
|---|---|
| FR-VO2-1 | 공개 **음성 인식 엔드포인트**(`POST /public/chatbots/:slug/speech/transcriptions`)는 **세션 헤더(`x-cb-session-id`)와 오디오 본문(녹음 바이트 그대로)** 을 받아 `{ text, durationMs, empty? }`를 돌려준다. **`durationMs`는 디코딩된 녹음 길이(ms)이며 서버 처리 시간이 아니다**(처리 시간은 내부 정보 — H-9). 기존 공개 가드(요청 한도 → Origin)를 거치고 **전용 요청 한도 버킷**을 쓴다(대화 `ip`·`session` 버킷 비소비 — No.44·35 선례). **이 그룹이 추가하는 유일한 공개 엔드포인트**다(`@Public()` 10번째) |
| FR-VO2-2 | **챗봇 조건 [2026-10-01 환류 H-1 정정]**: 챗봇이 공개 상태 · WEB 채널 활성 · 챗봇 음성 입력 켜짐 · 서버 음성 인식 스위치 켜짐 · **세션 헤더가 있고 형식(UUID)이 맞을 때만** 처리한다. 아니면 존재 탐지가 안 되는 일관된 응답(챗봇·음성 상태 불일치는 전부 같은 `503 SPEECH_UNAVAILABLE` · 세션 헤더 누락·형식 불량은 `400`). **세션과 챗봇의 결합("세션이 그 챗봇 것인가")은 검증하지 않는다** — 대화 세션은 위젯이 만든 값이고 서버에 세션 목록이 없어 검증할 원천이 없다(ADR-0009). 대신 **IP 축·세션 축 전용 요청 한도 · 동시 처리 상한 즉시 거절 · 크기·길이·업로드 수신 시간 상한 · Origin 검사**로 통제한다(PM 대체 통제 수용 · 서명 토큰 1차 미도입 · 남은 위험 R-13). 원안: "세션이 그 챗봇 것일 때만 처리한다" |
| FR-VO2-3 | **입력 검사**: 오디오 크기 상한(권고 1MB — architect) · 길이 상한(30초 + 여유) · 형식 판별은 확장자·헤더가 아니라 **내용 디코딩 결과**로. 디코딩 실패·상한 초과는 4xx + 위젯 안내 |
| FR-VO2-4 | **처리 순서**: 디코딩 → 표본화율 통일(모델 요구값) → **무음 구간 제거(VAD)** → 말소리가 없으면 STT를 부르지 않고 `empty: true` → STT(언어 = **`ko` 고정** — 자동 언어 감지 사용 안 함) → 결과 앞뒤 공백·반복 정리 → **숫자 표기 정규화**(한글로 적힌 숫자열을 아라비아 숫자로 — 설계: API 후처리 · 규칙 목록은 ml-engineer · P-16) |
| FR-VO2-5 | STT 추론은 **ml-worker의 음성 인식 프로세스**(새 역할 `speech`)에서 한다. 임베딩 프로세스(대화 경로)와 **같은 프로세스에 올리지 않는다**(J-9). API는 STT Provider 포트(`mock` · `local` · `cloud`(자리만))로 부른다(J-10) |
| FR-VO2-6 | **동시 처리 상한**: 동시 인식 수를 제한하고, 넘으면 **즉시 거절**(503 계열 + "붐벼요" 안내). 무기한 대기열 금지(설계: API·ml-worker 양쪽 비대기 상한) |
| FR-VO2-7 | **시간 제한**: API → ml-worker 인식 요청 제한(권고 10초 — architect). 초과 시 위젯 안내 · ml-worker 쪽 시간 제한은 API보다 짧게(No.37 P-9 원칙) |
| FR-VO2-8 | 인식 요청은 **대화 로그·미응답 수집·통계 대화 수에 아무것도 남기지 않는다**(사용자가 전송해야 대화가 된다). 남는 것은 일별 숫자(FR-VO5-5)뿐 |
| FR-VO2-9 | 인식 결과에서 **금지어·개인정보를 이 단계에서 걸러 내지 않는다** — 사용자 본인에게만 보이고, 전송 시 기존 대화 경로가 처리한다. 결과를 로그·감사에 남기지 않는다(FR-0-324와 같은 수준) |
| FR-VO2-10 | 알려진 엉뚱한 출력(무음에서 지어낸 상투 문장 등) 대응: VAD + 사용자 확인(P-2)을 기본으로 하고, 상투 문장 목록 필터를 둘지는 ml-engineer가 3050 동작 확인 결과를 보고 제안(**미실측**) |

### 4.3 답변 읽기 — 브라우저 내장 음성 (FR-VO3)

| ID | 요구사항 |
|---|---|
| FR-VO3-1 | 공개 설정 `voice.tts`가 참이고(챗봇 듣기 켜짐 — **서버 음성 인식 스위치와 무관**) 그 봇 답변 응답에 `speech` 키가 있으면 **봇 답변 응답마다 1개의 "듣기" 버튼**을 둔다(재생 중에는 "멈추기" · 응답 하나가 여러 말풍선(캐러셀·버튼)으로 그려져도 읽기 단위는 응답 — H-6 정정, 원안 "말풍선마다"). 외부 RAG 보류 답변은 폴링으로 최종 답(+`speech`)이 도착한 뒤 활성화한다. `speech` 키가 없는 메시지(사용자·상담원 메시지, 시스템 안내 등)에는 버튼을 두지 않는다. **[환류 H-3 확인] 시스템 안내 = 금지어 안내 · 일시 장애 안내 · 외부 RAG 대기 문구 등 처리 상태를 알리는 제품 고정 문구** — 서버가 `speech`를 붙이지 않으므로 버튼이 없다(원문 유지) |
| FR-VO3-2 | **기기 음성 판별**: 위젯은 `window.speechSynthesis`가 있고 `getVoices()` 중 **언어가 `ko`로 시작하고 `localService === true`인 음성**이 1개 이상 있을 때만 읽기를 쓸 수 있다고 본다. 음성 목록이 늦게 채워지는 브라우저를 위해 `voiceschanged`를 기다리되 상한(권고 2초 — architect) 후 판정한다. **조건 불충족 시 듣기 버튼과 자동 읽기 토글을 비활성(`aria-disabled`)으로 두고 이유를 글자로 안내**한다("이 기기에는 한국어 읽기 음성이 없어 소리로 들려드릴 수 없어요" — 문구 ui-designer). `speechSynthesis` 자체가 없으면 같은 안내 |
| FR-VO3-3 | **음성 선택**: 조건을 만족하는 기기 음성 중 `default`가 참인 것 → 없으면 첫 번째. 관리자가 특정 목소리를 지정하는 기능은 두지 않는다(기기마다 목록이 달라 지정이 의미 없음) |
| FR-VO3-4 | **읽을 글자는 서버가 준 `speech.text`만** 쓴다(위젯이 출력 목록에서 직접 만들지 않음 — 화면 표시와 서버 규칙의 일치를 서버가 보장). 위젯은 이 글자를 **기기 음성 외 어디로도 보내지 않는다** |
| FR-VO3-5 | 긴 글자는 위젯이 **문장 단위로 나눠** 차례로 `speak()`한다(일부 브라우저의 긴 발화 중단 문제 대응 — **확인 필요**). 서버는 `speech.text`를 상한(권고 2,000자)으로 자르고 "나머지는 화면에서 확인해 주세요"로 끝맺는다(FR-VO4-1) |
| FR-VO3-6 | **자동 읽기**: 위젯 토글(기본 꺼짐 · 사용자 조작으로만 켜짐 · 탭 세션 동안 기억 — P-8). 켜져 있으면 새 봇 답변(`speech` 키가 있는 응답) 도착 시 자동 재생. 사용자가 녹음을 시작하거나 입력하거나 창을 닫으면 즉시 멈춘다. 관리자는 이 토글을 보일지 말지만 정한다(기본값을 "켬"으로 바꾸는 설정은 두지 않음 — NFR-VOA2). 사용자 조작 없이 첫 재생을 막는 브라우저(예: iOS Safari — **확인 필요**)를 위해 토글을 켜는 조작 시점에 재생 권한을 확보하는 방식은 frontend-implementer가 정한다 |
| FR-VO3-7 | **정지·겹침 방지**: 멈추기·녹음 시작·입력 시작·창 닫기·새 답 읽기 시작 전에 `speechSynthesis.cancel()`로 진행 중 읽기를 끊는다. 한 번에 한 답만 읽는다 |
| FR-VO3-8 | 읽기 실패(`error` 이벤트 · 음성 사라짐) 시 위젯은 "지금은 소리로 들려드릴 수 없어요"를 글자로 보이고 답변 글자는 그대로 둔다. 자동 읽기가 켜져 있어도 실패를 연속으로 재시도하지 않는다 |
| FR-VO3-9 | **서버 합성·합성 공개 API·합성 오디오 전송·합성 캐시는 두지 않는다**(P-3 · P-11 해당 없음). 읽기 재생 횟수는 1차에 **서버로 보내지 않는다**(공개 수집 경로가 추가로 필요해지므로 — 필요하면 2차에서 기존 공개 수집 엔드포인트 재사용 여부를 architect가 검토) |

### 4.4 읽기용 글자 · 감정 톤 — 서버 (FR-VO4)

| ID | 요구사항 |
|---|---|
| FR-VO4-1 | 챗봇 듣기가 켜져 있고(위젯 기능 선언 `speech-v1` — 듣기 켜진 챗봇에서만 위젯이 싣는다) **WEB 채널의 봇 답변**이면, 서버는 공개 메시지 응답과 보류 답변 폴링 응답에 선택 키 **`speech: { text, tone }`** 를 붙인다(메시지 단위 · 응답의 마지막 키). **[환류 H-3 — 봇 답변의 범위]** 봇 답변 = 그 질문에 대해 챗봇이 내놓은 답 — 정상 답(대화 노드 출력) · 폴백(미응답) 안내 · 외부 RAG 최종 답과 그 실패 시 폴백 문구 · **No.36 "안전 문구로 대체"**(관리자가 규칙마다 쓴 대체 답 — 입구·출구 모두). **금지어 안내 · 일시 장애 안내 · 외부 RAG 대기 문구 같은 시스템 안내에는 붙이지 않는다**(듣기가 켜져 있어도 응답 바이트가 듣기 꺼짐과 같다). 듣기 꺼짐·사용자 메시지·상담원 메시지(상담 중 응답 · 봇 답 앞에 붙어 나오는 상담원 미전달 메시지 포함)·다른 채널이면 **키 없음(바이트 동일)**. `speech`는 저장하지 않는다(로그·스냅샷·감사 0) |
| FR-VO4-2 | `speech.text`는 **같은 응답에서 화면에 보내는 봇 출력 목록**(외부 RAG 답은 No.36 출구 가림 이후)으로 만든다 — 사용자가 화면에서 본 것과 같은 내용이고, 화면에서 가려진 것은 소리로도 가려진다. 변환 규칙: 글자 = 그대로 · 카드/캐러셀 = 제목·설명 · 버튼·바로연결 = "선택지: A, B, C" · 링크 = 라벨만(주소 읽지 않음) · 이미지 = 대체 글자가 있으면 그것 · 전화 걸기 = "전화 연결 버튼이 있습니다" · 일시정지(PAUSE) = 문장 끊김. 설계: No.46 텍스트 강등 함수는 `[카드]` 접두·링크 주소를 실어 **재사용하지 않고 같은 분기 구조의 별도 함수**로 만든다(설계서 DD-126) |
| FR-VO4-3 | **읽기 정리(서버 보장)**: **가림 표시(`[카드번호]` → "카드번호 가림")** · URL 제거 · 이모지 제거 · 장식 기호 제거는 반드시 서버에서 처리한다. 숫자·금액·날짜·전화번호의 읽는 방식은 기기 음성마다 다르므로 **1차는 최소 규칙**(예: 전화번호 하이픈 사이 쉼)만 두고, 추가 규칙은 3050 시연 기기 청취 결과를 보고 architect·ui-designer가 정한다 |
| FR-VO4-4 | **말투 선택**(§1.7 · 환류 H-3·H-4 정정): 우선순위 = No.36 안전 문구 대체 시 "차분함" 고정 > 노드별 말투 꼬리표 > 응답 종류 규칙(폴백·미응답 = "사과" · 관리자가 바꿀 수 있음) > 챗봇 기본 말투(정상 답). 결과를 `speech.tone`(닫힌 목록 이름)으로 싣는다. 원안의 "상담 연결 안내 = 차분함"(봇 답변 경로에 없음 — H-4)과 "오류 안내 = 사과"(시스템 안내라 읽지 않음 — H-3)는 삭제했다 |
| FR-VO4-5 | 말투 목록은 **닫힌 목록 4종**(차분함·밝게·사과·안내 — 이름은 ui-designer). 말투 → `rate`·`pitch`·`volume` 대응은 **공유 타입의 고정 대응표**(§1.7 초안 — 값은 ui-designer 청취 후 확정)로 두고 위젯이 그대로 적용한다. 관리자 빠르기 배율은 공개 설정 `voice.rate`로 내려 `rate`에 곱한다. 값 범위는 안전 구간으로 제한(권고 rate 0.7~1.3 · pitch 0.8~1.2 · volume 0.8~1.0) |
| FR-VO4-6 | **노드별 말투 꼬리표 [환류 H-2 정정]**: 관리자가 **음성 설정 구역에서 대화 노드를 골라** 말투를 붙인다(노드 편집기의 출력 필드가 아님 — 응답 1건 = 말투 1개라 출력 단위 지정은 의미가 없다). 꼬리표는 음성 설정에 저장되며 **버전 스냅샷·버전 해시·환경 분리(No.25·40) 밖**이다(저장 즉시 운영 반영 · 복원 대상 아님 · 노드 출력 스키마 변경 0 → 꼬리표가 없을 때 바이트 동일). 원안: "대화 노드 출력의 선택 필드 · 스냅샷 포함 권고" |
| FR-VO4-7 | 말투는 **글자 내용을 바꾸지 않는다** · 사용자 감정을 판정하지 않는다 · 판정 모델 0(P-4) |

### 4.9 GPU 재확인

| 구성 | 실제 연산(서버) | 기준표 구간 | 비고 |
|---|---|---|---|
| 규모 A · 등급 0~1 | 소형 STT 추론(요청마다) | 4~5 | 동시 사용자 소수 · 동작 확인만 · 읽기 서버 0 |
| 규모 A · 운영 | 대형 STT · 동시 처리 | 6 | 사용자 수에 비례해 GPU 필요 |
| (참고) 규모 B 스트리밍 | 연결 동안 GPU 점유 | 7 | 범위 밖 |
| (참고) 규모 C 전화 | B + 상시 동시 통화 | 7~8 | 범위 밖 |

→ **결정(P-12): 카탈로그 6 유지 + 각주**("서버 모델은 STT 1종 — 소형이면 CPU로도 성립(동시 소수) · 동시 사용자가 늘면 GPU 필요 · 답변 읽기는 사용자 브라우저(서버 GPU 0) · 실시간 스트리밍·전화는 범위 밖 · 장비 등급표 No.37"). P-3으로 서버 합성이 빠져 실제 부담은 6의 하단이지만, 운영 동시성 기준으로 6을 유지한다. **구축형 △ → ○**(각주: "규모 A는 공개 STT 모델로 사내 처리 · 읽기는 기기 안 음성") · **구독형 ○ 유지**(각주: "클라우드 음성 API는 음성 원본이 벤더로 나간다 — 1차 미구현 · 거버넌스 모드 기본 차단").
