## 0. 쉬운 말 요약 — 왜 필요한가, 무엇이 달라지나, 안 해도 되는 경우

### 0.1 한 줄 요약

**"영업 담당이 노트북에서 명령 하나만 치면, 사내 서버처럼 챗봇 시스템 전체가 켜지고, 시연용 데이터가 깨끗한 별도 DB에 준비되고, 10분짜리 7개 장면이 자막과 함께 자동으로 진행되며, 끝나면 화면 캡처·영상·결과 보고서가 남고 모든 프로세스가 정리되는 도구"** 다. 같은 도구를 사람 없이 빠르게 돌리면 "7개 장면이 지금 코드에서 실제로 동작하는가"를 확인하는 **종단 점검**도 된다. 제품 코드는 한 줄도 바꾸지 않고, 이미 있는 화면과 API를 바깥에서 **사용만** 한다.

### 0.5 이 도구 없이 충분한 경우 (정직하게)

- **시연이 분기에 한두 번이고, 개발자가 매번 동행할 수 있는 경우** — 손으로 띄우는 절차서(체크리스트) 1장이 더 싸다. 단 이번 PM 확정(10분 · 7개 · 구축형 고객 상용화 시연)은 반복 시연을 전제로 한다.
- **녹화 영상 한 편으로 충분한 경우** — 한 번 손으로 녹화해 돌려 보는 방식. 단 코드가 바뀌면 영상이 낡고, 고객이 "지금 이 자리에서 다시"를 요청하면 대응할 수 없다.

### 1.9 목적

1. 구축형 고객에게 **10분 안에 7개 핵심 가치**를 같은 품질로 반복 시연한다.
2. 시연 준비·실행·정리를 **명령 1번**으로 묶고, 개발 PC 데이터를 **오염하지 않는다**.
3. 같은 시나리오를 **무인으로 빠르게** 돌려 7개 장면이 현재 코드에서 동작하는지 확인한다(로컬 — CI는 범위 밖).
4. 연출과 사실을 구분한다 — 모형·사전 준비·시연용 설정값을 **숨기지 않는다**.
5. 제품 코드를 **바꾸지 않는다**.

## 2. 사용자 역할 및 시나리오

### 2.1 역할

| 역할 | 하는 일 |
|---|---|
| **시연 진행자**(영업·PM) | 명령 실행 · 준비 완료 확인 · 공연 시작 · 필요 시 일시정지/건너뛰기 · 끝나면 보고서 전달 |
| **개발자** | 무인 모드 실행 · 실패 단계 분석 · 시나리오 정의 수정 · 리허설로 G1 후보 고정 |
| **고객 관람자** | 화면·자막을 본다 · 보고서를 받는다 |
| (하네스 안의) 시연 계정 | ADMIN1(요청자) · ADMIN2(승인자) · EDITOR · AGENT(상담원) · VIEWER(선택) |

### 2.2 사용자 시나리오

**S-1 (고객 시연 — 보이는 모드)**: 진행자가 고객사 회의실에서 노트북(네트워크 분리 상태 — P-8)으로 명령 1번을 실행한다. 사전 점검이 포트·모델 캐시·Edge·`.venv`를 확인하고, 준비 단계가 새 실행 폴더에 격리 DB를 만들고 서버 4~5개를 띄우고 데모 데이터를 넣고 예열한다(수 분 — 고객 도착 전). 터미널에 "시연 준비 완료 · 엔터를 누르면 시작"이 뜬다. 엔터 → 브라우저 창(큰 화면)이 열리고 10분 동안 7개 장면이 자막과 함께 진행된다. 고객 질문이 나오면 진행자가 일시정지 키를 누르고, 다시 누르면 이어진다. 시간이 밀리면 하네스가 "건너뛰기 가능" 단계를 자동으로 생략한다. 끝나면 로드맵 화면이 나오고, 진행자가 종료 키를 누르면 모든 프로세스가 정리되고 보고서 폴더가 열린다.

**S-2 (개발 점검 — 무인 모드)**: 개발자가 기능 그룹을 완료한 뒤 무인 모드를 실행한다. 자막·녹화 없이 최대 속도로 7개 장면을 돌리고, 각 단계의 기대 결과(예: 의미 매칭 후 위젯 답 = "배송조회" 노드 문구)를 검증한다. ③단계 4번에서 실패하면 "S3-04 통계 반영 확인 실패 — 기대 응답률 증가, 실제 변화 없음" + 화면 + API 응답 + 서버 로그 마지막 200줄 + "`--from S3-04`로 재개" 안내가 보고서 맨 위에 나온다.

**S-3 (리허설)**: 진행자가 보이는 모드를 혼자 1회 돌려 보고서의 "단계별 예산 대비 실측" 표를 본다. ④의 G1 후보 중 어색한 것이 있으면 개발자가 시나리오 정의의 "승인할 후보 목록"을 고친다.

**S-4 (실패 중 시연)**: 공연 중 ⑦에서 ml-worker가 응답하지 않는다. 하네스는 그 단계를 "실패"로 기록하고 자막에 "이 장면은 준비된 결과로 대신 보여 드립니다"를 띄운 뒤 미리 완료한 분석 결과 화면으로 넘어간다(정직성 — 보고서에도 기록). 끝까지 진행한다.

**S-5 (중단)**: 진행자가 공연 중 Ctrl+C를 누른다. 하네스는 브라우저·서버 프로세스 트리를 모두 종료하고, 그때까지의 보고서를 "중단됨"으로 저장한다. 다음 실행 때 남은 프로세스(이전 실행의 PID 파일 기준)가 있으면 먼저 정리한다.

### 4.4 공연 — 시나리오 실행 (FR-DH4)

| ID | 요구사항 |
|---|---|
| FR-DH4-1 | 시나리오는 **선언형 정의**(§5.1.2)로 둔다 — 단계 ID(`S<구간>-<번호>`) · 제목 · 나레이션 문장 · 예산(초) · 구동 방식(API/UI) · 동작 · 기대 결과(검증) · 캡처 지시 · 핵심 장면 여부 · 건너뛰기 가능 여부 · 실패 시 대체 |
| FR-DH4-2 | §2.3 표의 7개 구간 + 시작·끝을 구현한다. 각 구간의 **핵심 장면은 반드시 캡처**한다 |
| FR-DH4-3 | **검증**: 각 단계는 기대 결과를 API 응답 또는 화면 요소로 확인한다(예: ①의 켠 후 답 = 배송조회 노드 문구 포함 · ③ 응답률 분모 증가 · ④ 실행 상태 완료·실패 0 · ⑤ 운영 버전 포인터 변경 후 롤백으로 원복 · ⑥ 저장본에 `[주민등록번호]`·`[카드번호]` 표식 · ⑦ 반영 후 의도 예문 수 증가). 검증 실패 = 단계 실패 |
| FR-DH4-4 | UI 조작은 **접근성 이름(역할·레이블·표시 문구) 기반**으로 대상을 찾는다(CSS 구조 의존 최소). 선택자는 시나리오 정의 한곳에 모은다 |
| FR-DH4-5 | **고정 지연 금지** — 비동기 결과는 조건 대기(`waitFor` 규약)로 기다리고, 단계별 상한(권고: 위젯 봇 답 10초 · 상담 메시지 15초 · 검증 실행 60초 · 묶음 분석 120초 · 예약 실행 = 예약 시각 + 폴링 주기 + 30초)을 넘으면 실패. **보이는 모드의 "사람 속도"는 대기와 별개로** 단계 사이 최소 표시 시간(권고 1.5~3초)과 타이핑 속도(권고 1글자 60~90ms)로만 만든다 |
| FR-DH4-6 | 두 브라우저 컨텍스트(예: 위젯 / 상담 콘솔, ADMIN1 / ADMIN2)를 **한 화면에 나란히** 보여 주는 배치를 지원한다(visible — 창 2개 배치 또는 합성 캡처 — architect) |
| FR-DH4-7 | **시간 관리**(visible): 구간마다 누적 지연을 계산해 예산 초과가 예상되면 건너뛰기 가능 단계를 §2.3 순서로 생략하고 자막 없이 넘어간다(생략 사실은 보고서에). 핵심 장면은 생략하지 않는다 |
| FR-DH4-8 | **실패 후 계속**(visible): 단계가 실패하면 그 구간의 "실패 시 대체"(사전 준비 결과 화면 등)로 넘어가 자막에 "준비된 결과로 대신 보여 드립니다"를 표시하고 공연을 계속한다. headless는 기본 "실패 시 해당 구간 중단 · 다음 구간 계속"(`--fail-fast`로 즉시 중단) |
| FR-DH4-9 | ⑥의 개인정보 예시는 **형식만 맞는 가짜 값**(시험데이터 문서에 고정)을 쓴다. 위험 질문 예시는 고객 앞에서 불편하지 않은 분류(권고: "의료 조언" — 예: "이 약을 두 배로 먹어도 되나요?" → "의사·약사와 상담" 안내)를 기본으로 하고, 위기·자해 분류는 쓰지 않는다(P-6) |
| FR-DH4-10 | 위젯 화면에서는 사용자가 친 원문이 그대로 보인다(정상 동작). ⑥ 나레이션은 "가림은 **저장되는 기록과 관리자 화면**에 적용"이라고 말한다 — 입력창에서 가려진다고 말하지 않는다 |
| FR-DH4-11 | ④ 예문 늘리기는 G1 규칙 기반 출력 중 **리허설로 고정한 후보만** 승인한다 · 나레이션은 "규칙으로 만든 후보를 사람이 골라 반영" — AI가 만든 문장이라고 말하지 않는다 |

### 11.1 AskUserQuestion용 쉬운 문구(8건)

**Q1. 시연 도구를 어떤 방식으로 돌릴 수 있게 할까요?**
- ① **사람이 보며 진행하는 '보이는 시연'(자막·녹화)과, 사람 없이 빠르게 돌려 고장 여부만 확인하는 '무인 점검' 둘 다 (추천)** — 같은 시나리오를 공유해 추가 비용이 작고, 시연 전날 고장을 미리 잡을 수 있습니다
- ② 보이는 시연만
- ③ 무인 점검만

**Q2. 화면을 자동으로 조작하는 도구는 무엇을 쓸까요?**
- ① **Playwright라는 자동화 도구를 시연 도구에만 넣고, 브라우저는 이 PC에 이미 있는 Edge를 사용 (추천)** — 별도 브라우저를 내려받거나 폐쇄망에 반입할 필요가 없고, 제품 코드에는 아무것도 추가되지 않습니다
- ② 같은 도구 + 전용 브라우저를 따로 내려받아 사용 — 폐쇄망 PC에는 수백 MB를 따로 옮겨야 합니다
- ③ 도구 없이 서버 호출로만 진행하고 화면 캡처는 사람이 — '자동 시연'이 되지 않습니다

**Q3. 시연 장면을 어떤 형태로 남길까요?**
- ① **핵심 장면 사진 + 시연 전체 녹화 영상 + 자막 파일, 움직이는 그림(GIF)은 핵심 장면 2~4개만 (추천)**
- ② 핵심 장면 사진만
- ③ 전체를 움직이는 그림(GIF)으로 — 파일이 매우 커집니다

**Q4. 결과 보고서는 어떤 형식으로 만들까요?**
- ① **고객에게 그대로 줄 수 있는 웹 문서 1개(인터넷 없이 열림) + 개발자용 요약 문서 + 나중 자동화용 데이터 파일 (추천)**
- ② 개발자용 요약 문서만
- ③ 웹 문서만

**Q5. '예약 배포'(정해진 시각에 운영 챗봇 자동 교체)는 10분 안에 어떻게 보여 줄까요?** (제품 규칙상 예약은 최소 5분 뒤로만 잡을 수 있습니다)
- ① **시연 시작 전에 미리 예약해 두고, 해당 장면 도중 실제로 실행되는 모습을 보여 줌. 시간이 어긋나면 '이미 실행된 예약 기록'으로 대신하고 자막으로 알림 (추천)**
- ② 시연용으로 서버 시계를 앞당겨 바로 실행 — 화면에 나오는 시각이 실제와 달라집니다
- ③ 예약을 만드는 화면만 보여 줌

**Q6. 개인정보·안전 장면과 발화 묶음 분석 장면은 어디까지 보여 줄까요?**
- ① **개인정보: 주민번호·카드번호를 넣은 질문이 저장 기록에서 가려진 모습 + 위험 질문(예: 약 복용 질문)에 안전 문구가 나가는 모습. 묶음 분석: 파일 올리기는 실시간, 분석 결과는 같은 파일로 미리 돌려 둔 것 사용(자막으로 알림) (추천)** — 가짜 서버 없이 10분 안에 안정적으로 끝납니다
- ② ①에 더해, 문서 검색 AI 답 속 번호가 가려지는 모습까지 — 시연용 가짜 문서 검색 서버가 필요하고 자막에 '모형'이라고 표시합니다. 묶음 분석도 시연 중 실제로 기다림(수십 초)

**Q7. 이 도구를 자동 시험(CI)이나 회귀 점검에도 쓸까요?**
- ① **이번엔 개발 PC에서 명령으로 돌리는 것까지. 나중에 CI에 붙일 수 있도록 결과 형식만 맞춰 두고, 기능 개발이 끝날 때마다 무인 점검 1회를 권장 (추천)**
- ② 지금 바로 기존 자동 시험 묶음에 넣기
- ③ 시연 전용으로만 쓰기

**Q8. '사내 설치 · 데이터가 밖으로 안 나감'을 얼마나 강하게 보여 줄까요?** (점검 중 관리 화면의 글꼴을 인터넷(Google)에서 받아 오는 부분을 발견했습니다)
- ① 보고서에 '외부로 보내는 곳 점검표'를 넣고, 글꼴 문제는 별도 결함으로 등록해 사내 글꼴로 교체
- ② **①에 더해, 시연 노트북의 네트워크를 실제로 끊은 채로 전 과정을 진행 (추천)** — 고객에게 가장 강한 증거입니다
- ③ 따로 언급하지 않음
