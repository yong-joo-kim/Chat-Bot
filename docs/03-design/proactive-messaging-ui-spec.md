## 0. 전제와 연계 확인

- 설계서 §1.1에 따라 이번 범위에서 **빠진 것**: `HOST_SIGNAL`(사이트 신호) 트리거 · `UNANSWERED_STREAK`(연속 미응답) 트리거와 대화 창 안 제안 표식(FR-PA3-8) · 스크롤/이탈 트리거 · 시뮬레이터 제안(FR-PA9-5) · 규칙 조건 종류를 고르는 실질적 라디오 그룹(1종뿐이므로 고정 텍스트로 대체). 이 화면 설계서는 이 항목들의 **UI를 만들지 않는다**(빈 자리·비활성 옵션도 두지 않는다 — 나중에 트리거가 추가되면 이 문서와 화면을 함께 갱신).
- 설계서 §13 인계표의 권고를 그대로 따른다: 콘솔 위치는 **새 최상위 탭이 아니라** `apps/web/src/pages/chatbot-detail/ChannelsTab.tsx`의 **WEB 채널 카드 안** 섹션(Q-1 기본값 — `TabNav.spec.tsx` 기대값 변경 0, X-8 발생 안 함).
- `apps/web/src/pages/dialogue/components/ButtonItemEditor.tsx`(리치 메시지·설문 버튼 편집에서 이미 쓰는 공용 컴포넌트)를 **그대로 재사용**할 수 있는지 확인했다 — `{label, action: 'NODE'|'MESSAGE'|'LINK', value}` 구조가 `ProactiveButtonSchema`와 동일하다. 다만 현재 `label`의 `maxLength`가 `40`으로 하드코딩돼 있어(21행) 선제 버튼 라벨 상한(20자, FR-PA1-5)과 다르다 → **컴포넌트에 선택 prop `labelMaxLength?: number`(기본 40) 추가**를 frontend-implementer에게 요청한다(기존 소비자는 무변경 · 이 그룹에서만 `20` 전달). 그 외(NODE는 `ResourcePickerField`로 켜진 노드 검색 선택, LINK 인라인 오류)는 수정 없이 그대로 쓴다.
- `apps/web/src/pages/dialogue/NodesListPage.tsx`의 삭제 확인 흐름(`ConfirmDialog` + `deleteTarget`/`deleteBlocked` state, 426~450행)에 **차단하지 않는 경고**를 추가로 얹는다(기존 `DeleteBlockedBanner`는 차단 시에만 뜨는 컴포넌트라 재사용하지 않고 새 컴포넌트 `ProactiveRuleRefWarning`을 만든다 — §3.6).
- 위젯 쪽은 `apps/widget/src/ui/launcher.ts`(런처 DOM) · `apps/widget/src/ui/panel.ts`(`#cb-status` 패널 안 알림 영역, 56~58행) 구조를 확인했다 — 말풍선은 **패널과 무관하게 런처 형제 요소**로 새로 만들고, 패널 안 `#cb-status`는 건드리지 않는다(설계서 §6.4).

## 3. 화면별 설계

## 3.1 PA-C1 — 선제 안내 섹션 진입점 (WEB `ChannelCard` 안)

### 목적
운영자가 채널 탭에서 WEB 카드를 열면 선제 안내 기능이 있다는 것을 알고, 켜져 있는지·규칙이 몇 개인지 한눈에 보고 펼칠 수 있다.

### 배치
`ChannelCard.tsx`(§0 확인)의 `channel-card-actions` 줄(129~143행)에 **새 버튼 1개**를 추가한다 — 기존 "설정 열기/닫기"·"삽입 코드"·"삭제" 버튼과 나란히, WEB 타입일 때만:

```tsx
{item.type === 'WEB' && (
  <button type="button" className="btn btn-secondary" aria-expanded={proactiveExpanded}
          onClick={() => setProactiveExpanded(v => !v)}>
    {proactiveExpanded ? '선제 안내 닫기' : '선제 안내'}
  </button>
)}
```

- 버튼 옆에 **요약 배지**(펼치지 않아도 보임): 스위치 꺼짐이면 "꺼짐"(중립), 켜짐이면 "켜짐 · 규칙 N개 켜짐"(성공색+텍스트).
- 펼치면 `ProactiveSection`을 카드 하단(기존 `WebChannelForm` 펼침 영역과 독립적으로, 둘 다 동시에 펼 수 있음)에 렌더.
- 최초 펼침 시 `proactiveApi.getOverview(chatbotId)` 1회 호출(캐시 없음 — "저장하면 다음 조회부터 반영" 안내와 일치).

### 상태별 UI

| 상태 | UI |
|---|---|
| 로딩(최초 펼침 직후) | `SkeletonCard` 1개(설정 영역) + `SkeletonRow` 3개(목록 영역) |
| 오류(조회 실패) | `ErrorState`(재시도 버튼) — 카드의 다른 영역(설정 폼·삭제 등)은 정상 동작 |
| 빈 상태(규칙 0개, 스위치 무관) | `EmptyState`: "아직 선제 안내 규칙이 없습니다" + "규칙 추가" 버튼(설정 스위치는 규칙 유무와 별개로 항상 보임) |
| 성공 | §3.2·§3.3 |
| `channel:read`만 있는 사용자 | 섹션은 보이되 스위치·상한·간격 입력·"규칙 추가"·수정·삭제·켜기/끄기·이동 버튼이 전부 `disabled` + `aria-disabled` + 툴팁 "편집 권한이 없습니다"(AC-PA8-5) — 통계 보기는 가능(`channel:read`) |
| 서버 전체 스위치 꺼짐(`serverEnabled: false`) | 섹션 상단에 안내 배너: "서버 설정에서 선제 안내 기능이 꺼져 있습니다 — 규칙을 만들어도 방문자에게 표시되지 않습니다." 입력은 막지 않음(콘솔 편집은 계속 가능 — 설계서 §3.5) |
| 런처 숨김(WEB `showLauncher=false`) | 배너: "이 챗봇은 런처가 숨겨져 있어 선제 안내가 표시되지 않습니다."(EX-PA-7) |
| 챗봇 비공개·WEB 채널 꺼짐 | 배너: "챗봇이 공개되지 않았거나 웹 채널이 꺼져 있어 방문자에게 표시되지 않습니다." |
| 보관됨(`ARCHIVED`) | 섹션 전체 읽기 전용(기존 `isArchived` 규약과 동일 — 편집 버튼 숨김) |

## 3.2 PA-C2 — 선제 안내 설정 (섹션 상단)

### 레이아웃

```
┌─ 선제 안내 ──────────────────────────────────────────────┐
│ (서버에서 꺼짐 배너 — 해당 시)                              │
│ (런처 숨김 / 비공개 배너 — 해당 시)                          │
│                                                            │
│ 선제 안내 사용    [○──] 꺼짐                                │
│                                                            │
│ 세션당 최대 표시 수   [1] (1~3)                             │
│ 안내 사이 최소 간격   [60 ]초 (30~600)                      │
│ 메시지를 보낸 뒤 조용한 시간 [300]초 (60~1800)               │
│                                                            │
│ ⓘ 저장하면 방문자의 다음 페이지 이동부터 반영됩니다.          │
│   이미 떠 있는 안내는 그 페이지에서 그대로 보입니다.          │
│                                                            │
│                                              [저장]         │
└────────────────────────────────────────────────────────────┘
```

- 스위치는 `ChannelToggle`(기존 채널 켜기/끄기 토글 컴포넌트)과 같은 시각 스타일을 재사용하되, **별도 저장 버튼**을 둔다(즉시 토글이 아님 — 숫자 필드와 한 번에 검증·저장, `ProactiveSettingsInputSchema` 전체 교체).
- 숫자 입력 3개는 `type="number"` + `min`/`max`(HTML5) + 저장 시 서버 재검증. 슬라이더는 쓰지 않는다(범위가 좁고 정수 입력이 더 정확 — UIUX §6 슬라이더 규칙은 "쓸 때"의 제약이라 여기서는 해당 없음).
- 값이 바뀌지 않았으면 저장해도 감사 기록 없음(설계서 §12.1) — 화면 동작 차이는 없음(사용자에게는 "저장됨" 토스트만).

### 필드-오류 매핑 (PA-C2)

| 필드 | 오류 조건 | 인라인 메시지 |
|---|---|---|
| 세션당 최대 표시 수 | 1~3 범위 밖 | "1~3 사이의 숫자를 입력하세요." |
| 안내 사이 최소 간격 | 30~600 범위 밖 | "30~600초 사이로 입력하세요." |
| 조용한 시간 | 60~1800 범위 밖 | "60~1800초 사이로 입력하세요." |
| (전체) | 저장 API 403(`channel:read`만) | 폼 자체가 `disabled`라 도달 불가 — 방어적으로 토스트 "편집 권한이 없습니다" |

### 목적

### 레이아웃

```
┌─ 미리보기 ───────────────────────────────────┐
│ [데스크톱] [휴대폰]                             │

│  │                          │                   │
│  │ [배송 조회하기]           │                   │
│  │ [안내 닫기 ×] [이번 방문 동안 안내 끄기]        │

```

- 챗봇 스킨 색(주 색상)을 배경/버튼에 그대로 적용(챗봇 상세의 스킨 설정값 재사용 — API 재호출 없이 이미 로드된 챗봇 스킨 값 사용).

## 3.7 PA-C7 — 삽입 코드 안내

섹션 상단(설정 위 또는 바로 아래) 고정 배너:

```

```

- 콘솔이 **기존 삽입 코드 문자열에 `data-proactive="on"` 속성을 끼워 예시로만 보여준다**(서버 `embed-code.service.ts` 변경 0 — 설계서 §13). 실제 발급 코드 화면은 기존 `/chatbots/:chatbotId/skin?section=embed`로 링크만 건다.
- "위젯 로드 후에만 인식됩니다" 같은 신호 함수 안내는 **넣지 않는다**(P-2 축소로 `HOST_SIGNAL` 자체가 이번 범위 밖 — EX-PA-13 관련 문구도 생략).

## 3.8 PA-C8 — 노드 삭제 확인 — 선제 안내 경고 (`NodesListPage`)

### 목적
편집자가 노드를 삭제하기 전에, 그 노드를 가리키는 선제 안내 규칙이 있다는 것을 알린다(EX-PA-4·R-9) — **삭제를 막지 않는 비차단 경고**.

### 배치

`NodesListPage.tsx`의 `ConfirmDialog`(426~450행) 안, 기존 `deleteBlocked && <DeleteBlockedBanner .../>` **바로 위**에 새 컴포넌트를 추가한다:

```tsx
<ConfirmDialog isOpen={Boolean(deleteTarget)} title={msg.deleteTitle}
  description={deleteTarget ? msg.deleteDesc(deleteTarget.name) : ''}
  confirmLabel={MESSAGES.common.delete} danger
  onConfirm={handleDeleteConfirm} onCancel={...}>
  {deleteTarget && (
    <ProactiveRuleRefWarning chatbotId={chatbot.id} nodeId={deleteTarget.id} />
  )}
  {deleteBlocked && <DeleteBlockedBanner .../>}
</ConfirmDialog>
```

- `ProactiveRuleRefWarning`은 `deleteTarget`이 바뀔 때 **`channel:read` 권한이 있을 때만** `proactiveApi.getOverview(chatbotId)`를 호출해 `findProactiveRulesReferencingNode(rules, nodeId)`(공유 순수 함수, §0 확인)로 계산한다.
  - 참조 0건 또는 `channel:read` 없음 또는 조회 실패 → **아무것도 렌더하지 않는다**(경고 없음 · 삭제 흐름 그대로 — 비차단 원칙, R-9).
  - 참조 N건(N≥1) → 확인 창 본문에 경고 박스: "ⓘ 이 노드를 가리키는 선제 안내 {N}개({이름1, 이름2, …})가 더 이상 표시되지 않습니다. 삭제할 수는 있지만, 필요하면 먼저 해당 규칙을 수정하세요."
  - 이 경고는 **확인 창 본문**(스크린 리더가 다이얼로그를 열자마자 읽는 위치)에 두고, "삭제" 버튼 활성 상태·클릭 동작에는 영향을 주지 않는다.

### 상태별 UI

| 상태 | UI |
|---|---|
| 로딩 중 | 경고 영역에 아무것도 표시하지 않음(깜빡임 방지 — 짧은 지연이라 스피너 생략) |
| 조회 실패 | 조용히 생략(비차단이므로 오류를 사용자에게 보이지 않음, R-9) |
| 참조 0건 | 렌더 없음 |
| 참조 N건 | 경고 박스(위) |

## 4. 위젯 — 런처 옆 말풍선 (PA-W1)

### 목적
방문자가 규칙 조건(페이지 머묾)을 만족하면 런처 옆에 짧은 제안이 뜬다. 대화 창은 자동으로 열리지 않고, 포커스·스크롤을 건드리지 않는다.

### 다크 패턴 금지 원칙(FR-0-247 — 화면 설계 원칙으로 명시)

이 말풍선을 설계·구현할 때 다음을 **구조적으로 불가능**하게 만든다(선택 옵션이 아니라 애초에 만들 수 있는 입력 항목 자체를 두지 않는다):

1. **가짜 상담원 말투 금지** — 사람 이름·사진·"입력 중…" 표시를 넣지 않는다. 표식은 항상 "챗봇 이름" 또는 "챗봇 안내"라는 정직한 텍스트다.
2. **가짜 긴급성 금지** — 카운트다운, "N명이 보고 있어요", "지금만" 같은 문구를 넣을 수 있는 필드가 없다(문구는 관리자가 쓰는 자유 텍스트이지만 저장 시 용도 확인 문구로 "도움 안내 한정"을 계속 상기시킨다).
3. **가짜 배지 금지** — 읽지 않은 메시지 수, 런처 배지 카운트를 선제 안내가 만들지 않는다.
4. **닫기 버튼 숨기기·작게 하기 금지** — "안내 닫기"는 다른 버튼과 **동일한 크기(44×44px 이상)·동일한 명도 대비**로, 항상 보이는 위치에 둔다. "이번 방문 동안 안내 끄기"도 닫기와 **동등한 노출**(같은 줄 또는 바로 아래, 같은 시각적 비중)로 둔다 — 하나를 흐리게 하거나 작게 만들지 않는다.
5. **닫을 때 되묻기 금지** — 닫기·끄기를 누르면 "정말 닫으시겠어요?" 같은 재확인 없이 즉시 닫힌다.
6. **소리·진동 금지**.

### 레이아웃(ASCII — 데스크톱, 런처 오른쪽 하단 기준)

```
                              ┌───────────────────────────┐
                              │ 챗봇 안내                    │
                              │ 주문·배송 조회를 도와드릴까요? │
                              │                              │
                              │ [배송 조회하기]                │
                              │                              │
                              │ [안내 닫기 ×]  [이번 방문 동안  │
                              │                 안내 끄기]     │
                              └───────────────────────────┘
                                          (●) ← 런처(cb-launcher)
```

- `launcherPosition: 'LEFT'`면 말풍선도 왼쪽 정렬로 대칭 이동(§6.1 제약 ⑧ — `applySkin()` 앞당김으로 위치 정보를 먼저 확보).
- 휴대폰(`data-mode="mobile"` ∧ 규칙 `devices`에 `MOBILE` 포함)은 화면 하단 폭 전체에 가깝게, **최대 높이는 뷰포트의 40%**(본문을 가리지 않도록 — FR-PA3-9)로 제한하고 내용이 넘치면 말풍선 내부 스크롤.

### 컴포넌트 분해 (`apps/widget/src/ui/proactive-bubble.ts`)

| 요소 | 구현 | 접근성 |
|---|---|---|
| 컨테이너 | `<div id="cb-pa-bubble" hidden>` — Shadow DOM 안, 런처의 형제(앞) | 표시 전 `hidden` — DOM에는 미리 존재(깜빡임 없는 등장을 위해) |
| 표식 | `<span>챗봇 안내</span>`(또는 챗봇 이름) | 텍스트 — 색상 단독 아님(NFR-PAA5) |
| 문구 | `<p>` `textContent`만(HTML 해석 0, AC-PA7-3) | — |
| 버튼(0~3) | `<button>`(NODE/MESSAGE) 또는 `<a target="_blank" rel="noopener noreferrer">`(LINK) | 44×44px 이상 · 텍스트 이름 |
| 버튼 0개 규칙 | 문구 영역 전체가 `<button>`("대화 열기") | FR-PA1-7 · NFR-PAA3 |
| 닫기 | `<button aria-label="안내 닫기">×</button>` | 텍스트 이름 "안내 닫기"(아이콘만 아님) |

| 패널 밖 알림 영역 | `<div id="cb-pa-status" role="status" aria-live="polite" class="cb-sr-only">` | 표시 시 "챗봇 안내: {문구}" 1회 기록(NFR-PAA2) — 패널 안 `#cb-status`와 별개 |

### 접근성 결정 — 핵심 요약

| 요구 | 결정 |
|---|---|
| **자동 포커스 이동 금지** | 말풍선 표시 함수는 `.focus()`를 호출하지 않는다(PA-18 봉인 — `.focus(` 호출은 닫기/Esc 처리 함수 안에만 존재). `document.activeElement`·스크롤 위치가 표시 전후 동일해야 한다(AC-PA3-5). |
| **`aria-live` 정중 공지** | `role="status"`(암묵적 `aria-live="polite"`)인 **패널 밖 전용 영역**에 "챗봇 안내: {문구}" 텍스트를 **표시 시 1회만** 써넣는다. 같은 말풍선이 떠 있는 동안 재기록하지 않는다(AC-PA8-2). 이 영역은 패널 안 `role="log"` 메시지 목록과 별개라 대화 로그를 어지럽히지 않는다. |
| **키보드로 인지·닫기·클릭** | 탭 순서: 런처 바로 앞(DOM 순서 — 런처를 찾아가다 자연히 말풍선을 먼저 만난다). 말풍선 안에서는 버튼 → 닫기 → 끄기 순으로 Tab 이동. Enter/Space로 모두 실행. 말풍선 안에 포커스가 있을 때 **Esc = 안내 닫기 → 포커스는 런처로**(AC-PA8-1). 마우스로 닫아도 포커스가 말풍선 안이었다면 런처로 이동(포커스 유실 방지). |
| **포커스 표시** | 모든 버튼에 `:focus-visible` 아웃라인(런처와 동일한 스타일 — `styles.ts` 기존 `.cb-launcher:focus-visible` 규칙 재사용). |
| **자동 사라짐 없음** | 시간 제한으로 사라지지 않는다(FR-PA3-6) — 스크린 리더 사용자가 자기 속도로 읽을 시간을 보장. |
| **움직임 최소화** | 등장 시 짧은 페이드 1회만, `prefers-reduced-motion: reduce`면 애니메이션 없음(AC-PA3-9). 깜빡임·반복 애니메이션 없음. |
| **명도 대비** | 텍스트 4.5:1 · 버튼 테두리 등 비텍스트 3:1(NFR-PAA5) — 챗봇 스킨 색을 쓰되 대비 기준 미달 시 텍스트색을 자동 보정(콘솔 스킨 설정의 기존 대비 검사 로직 재사용 여부는 frontend-implementer 확인). |

## 5. 사용자 인터랙션 흐름 종합

### 5.1 운영자 — 규칙 생성 → 저장 → 통계 확인 (S-1)

```
채널 탭 진입 → WEB 카드 "선제 안내" 열기
  → 최초 조회(로딩 스켈레톤) → 성공(설정 폼 + 빈 규칙 목록)
  → "규칙 추가" → 모달 열림
    → 이름·조건(포함경로·머문시간)·문구·버튼 입력
    → "이 주소에서 맞나요?" 도구로 자체 검증(선택)
    → [미리보기] → 데스크톱/휴대폰 탭 전환 확인 → 모달로 복귀
    → 용도 확인 체크(빠짐없이) → [저장]
      성공 → 토스트 "저장했습니다" + 목록에 새 행(켜짐=꺼짐 상태로 시작)
      실패(검증) → 필드 아래 인라인 오류 + 첫 오류 필드로 포커스 이동
  → 목록에서 켜짐 토글 → 켜진 규칙 1/10
  → (다음 날) "통계 보기" → 기간 선택 → 표+그래프 확인
```

### 5.2 방문자 — 말풍선 표시 → 클릭 (S-2)

```
/order/123 페이지 진입(삽입 코드에 data-proactive="on")
  → 위젯이 조용히 규칙 조회(요청 1건, 로딩 UI 없음 — 방문자에게 보이지 않음)
  → 30초 경과(탭이 보이는 동안만) → 게이트 통과
  → 말풍선 표시(포커스·스크롤 불변) + 패널 밖 알림 1회
  ├ [배송 조회하기] 클릭 → 패널 열림(런처 위치에서 성장 애니메이션 — 기존 패널 열기와 동일) → 인사말(있다면) → 버튼 턴 결과
  ├ [안내 닫기] 클릭 또는 Esc → 사라짐 → 포커스 런처 → 이 페이지·세션에서 재표시 없음
  └ [이번 방문 동안 안내 끄기] → 사라짐 → 이 탭의 모든 선제 안내 중지
```

### 5.3 오류·억제 경로

| 상황 | 사용자에게 보이는 것 |
|---|---|
| 규칙 조회 네트워크 오류 | 아무것도 보이지 않음(현행 동작과 동일 — 오류 UI 없음, EX-PA-1) |
| 대화 패널이 이미 열려 있음 | 말풍선 뜨지 않음(조건은 다음 틱에도 계속 확인 — 패널을 닫으면 다시 뜰 수 있음) |
| 상담원 연결 중 | 말풍선·연속 미응답 제안(범위 밖) 모두 억제 |
| 서버에서 규칙이 꺼지거나 노드가 삭제됨(표시 중) | 이미 뜬 말풍선은 유지, 버튼을 누르면 엔진이 폴백 응답(콘솔에는 미리 "연결 대상 없음" 경고가 있었어야 함 — §3.8) |
| `channel:read`만 있는 콘솔 사용자가 편집 시도 | 컨트롤이 `disabled`라 애초에 시도 불가, API 직접 호출 시 403 토스트 |

### 8.3 `UIUX_준수기준.md` 갱신 제안(요구사항 §10 대응 — 이 설계서에서 반영은 하지 않는다, system-architect/오케스트레이터 승인 후 별도 편집)

`§8 로딩/상태 피드백` 아래(또는 새 `§11 일시적 안내(말풍선·배너)` 절)에 다음 패턴 추가를 제안한다:

> **선제 안내 말풍선(사용자 조작 없이 나타나는 제안)**: 조건이 맞아 화면에 스스로 나타나는 요소(팝업이 아닌 보조 말풍선)는 ① 키보드 포커스·스크롤 위치를 바꾸지 않는다 ② `role="status"`(polite)인 전용 알림 영역에서 등장을 **1회만** 알린다(대화 로그 등 다른 `aria-live` 영역과 공유하지 않는다) ③ 자동으로 사라지지 않는다(사용자가 직접 닫을 때까지) ④ 닫기 버튼과 "다시 보지 않기류" 버튼은 서로 동등한 크기·대비로 노출한다(하나를 숨기거나 작게 하지 않는다) ⑤ 가짜 사람·가짜 긴급성·가짜 배지·소리·되묻기 확인창을 두지 않는다.

이 제안 문구는 ADR-0045 §12 갱신 각주(요구사항 §10 표)와 함께 별도 커밋(④ 콘솔·문서)에서 반영한다.

## 9. 반응형 고려사항

### 9.1 콘솔(관리자 화면)

- 규칙 목록 표는 데스크톱 기준(§3.3). 태블릿 이하 폭에서는 "최근 7일" 4개 숫자 열을 접어(아이콘 없이 "최근 7일 ▾" 펼침 토글) 가로 스크롤을 줄인다(기존 채널 카드 그리드의 반응형 규칙과 동일 — 카드가 세로로 쌓임).
- 규칙 편집 모달은 좁은 화면에서 섹션 순서(조건 → 문구 → 버튼 → 기기 → 기간/시간대 → 용도 확인)를 **세로 1열**로 유지(레이아웃 단만 바뀜, 필드 그룹 순서는 불변).
- 미리보기 탭(데스크톱/휴대폰)은 좁은 화면에서도 그대로 2탭 유지(둘 다 근사 렌더일 뿐 실제 뷰포트 크기와 무관).

### 9.2 위젯(방문자 화면)

- 데스크톱: 말풍선 최대 너비 320px 근처(런처 위치 기준 좌/우 대칭), 문구·버튼 세로 배치.
- 휴대폰(`data-mode="mobile"`): 규칙의 `devices`에 `MOBILE`이 없으면 **애초에 표시 안 함**(요구사항 기본값 — 규칙별 선택, 전역 기본 꺼짐). 켠 규칙만 화면 하단 폭 대부분을 쓰는 카드형으로 표시하고 최대 높이는 뷰포트 40%로 제한, 넘치면 내부 스크롤(§4 레이아웃 참고). 가상 키보드가 열려 있으면(호스트 입력 요소 포커스 추정) 표시를 미룬다(FR-PA3-9·K-10).
- 전체 화면 모드(`/c/:slug`, `data-fullscreen="true"`)에는 말풍선이 없다(EX-PA-8 — 이미 창이 열려 있음).

## 10. Out of scope(이번 화면 설계에 포함하지 않음)

요구사항 §9·설계서 §22와 동일하게, 아래는 **화면도 자리도 만들지 않는다**(2차 트리거가 추가되면 이 문서를 갱신):

- 규칙 다국어 문구 · A/B 시험 · 그룹/전역 통계 합산
- 규칙 복사(챗봇 복사·토픽 분리 시 자동 복사)
- 며칠 동안 닫음 기억(`localStorage`) 옵션 — 이번은 탭 세션만
- 시뮬레이터(No.10)에서 선제 안내 확인

## 13. 사용자 확인이 필요한 화면 세부사항

아래는 **기본값으로 화면을 만들어도 되는** 항목이다(설계서 §21 Q-1~Q-4와 같은 결). 이견이 있을 때만 조정한다.

| # | 항목 | 이 문서의 기본값 | 대안 |
|---|---|---|---|
| U-1 | 규칙 목록의 "최근 7일" 열 표시 방식 | 숫자 4개를 한 열에 슬래시로 나열(§3.3) | 열 4개로 분리(가로 폭 넓어짐) |
| U-2 | 트리거 "종류" 필드 | 고정 텍스트(§3.4) | 라디오 1개(선택 여지 없음에도 형식 통일 우선 시) |
| U-3 | 통계 그래프 종류 | 막대 그래프(표시/클릭/닫기/끄기 4계열) | 선 그래프(일별 추이 강조 시) |
| U-4 | 휴대폰 말풍선 최대 높이 | 뷰포트 40% | 고정 px(예: 240px) |
| U-5 | 복제(§3.3) 시 이름 접미사 | "(복사본)" | "(사본)"(다른 화면 관례와 통일할지 — `NodesListPage`는 "(사본)" 사용, 이 문서는 §11 인계 시 통일 검토 필요로 표시) |

> **U-5는 특히 확인 필요**: `handleCopy`(NodesListPage.tsx 149행)는 노드 복사 접미사로 "(사본)"을 쓴다. 이 문서 초안은 표기 일관성을 위해 규칙 복제에도 **"(사본)"으로 통일**을 권장하며, 위 §3.3·§12.1 예시 문구의 "(복사본)"은 frontend-implementer 구현 시 "(사본)"으로 맞춰도 된다(문서상 표기 차이일 뿐 기능 차이 없음).
