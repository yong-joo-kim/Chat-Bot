## 0. 전제와 코드 확인 결과

1. **용어 원칙(DC-15 · FR-DC6-6)**: 화면에 보이는 모든 문자열에 "토픽·군집·클러스터·임베딩·벡터"를 쓰지 않는다. 대신 **묶음**(비슷한 말끼리 모은 것) · **문장 분석**(임베딩) · **챗봇 대조** · **학습 후보** · **미분류**를 쓴다. 예외는 도움말 한 문장뿐이다(`MESSAGES.utteranceAnalysis.clusterHelp` — "비슷한 말끼리 모은 것입니다. 챗봇의 '토픽' 설정과는 관계없습니다"). 이 문서의 산문에서는 설명을 위해 기술 용어를 쓰지만, **§ 문구 상자 안의 문자열이 실제 화면 문구**다.
2. **확인한 기존 코드**(`apps/web/src`):
   - 챗봇 상세 최상위 탭은 `pages/chatbot-detail/TabNav.tsx`에 이미 13개다. **탭을 더 늘리지 않는다**(§1.2 근거).
   - 통계 탭의 셸 `pages/stats/StatsShell.tsx`는 서브내비 3개(`기본 통계`·`학습현황`·`외부 연동 로그`)를 가로 스트립으로 렌더하며 권한별로 링크를 숨긴다(`can('dialogue:read')` 등). 이 문서는 여기에 4번째 링크를 추가한다.
   - 라우트는 `App.tsx`의 `/chatbots/:chatbotId/stats/*` 하위 중첩 라우트(`learning`, `api-calls`)다.
   - 재사용 컴포넌트가 이미 있다: `Modal`/`ConfirmDialog`(`components/Modal.tsx`, 기본 포커스 "취소"), `AsyncJobProgress`(`live={false}` 옵션), `FileUploadField`, `ResourcePickerField`('intent' 검색), `Pagination`, `EmptyState`, `ErrorState`, `SkeletonRow/SkeletonCard`, `InlineFieldError`, `SeverityBadge`(ERROR/WARNING/INFO — 색+아이콘+글자), `ProposalContainer`(제안-자산 분리 셸), `AutoSnapshotNotice`, `GovernanceViewAuditBanner`, `RequirePermission`/`ForbiddenState`, `useToast`, `KebabMenu`, `MultiSelectDropdown`, `useAnnouncedTransition`(kb-crawling 전용 훅), `KbFeatureOffState`(기능 꺼짐 화면 선례), `TestRunProgressBar`(진행 막대 선례).
   - 사용자 정보에 `user.governanceModeOn`이 있다(`useAuth()`) — 거버넌스 모드 안내 조건으로 쓴다.
   - 학습현황의 반영 완료 문구는 `MESSAGES.learning.resolveSuccessImmediate`/`resolveSuccessQueued`를 `appliedImmediately` 응답값으로 분기한다(FR-L3-6/K-4). 이 문서도 같은 상수를 재사용하고 새 문장을 만들지 않는다.
   - 버전 자동 캡처 트리거 라벨은 `constants/messages.ts`에 `BEFORE_AUGMENT_ACCEPT: '자동 · 증강 승인 직전'` 형식이다.
3. **이 문서가 다루지 않는 것**: 내부 대화 기록 입력(규모 B) · 음성 파일 · 자동 의도/노드/FAQ 생성 · 여러 챗봇 합친 분석 · 분석 간 비교(설계서 요구사항 §9).

### 1.2 메뉴 위치 판단

| 안 | 판정 |
|---|---|
| A. `TabNav` 최상위 탭 14번째로 추가 | **기각** — 이미 13개이고 `TabNav.spec.tsx` 기대값 변경이 생긴다. 사용 빈도가 낮은 도구(파일 분석)라 1급 목적지 자격이 약하다 |
| B. 설계서 §17 제안 경로 `/chatbots/:chatbotId/utterance-analyses`(탭 신설) | 위와 같은 이유로 기각 |
| **C. 통계 탭 서브내비 4번째 항목**(`stats/utterance-analyses`) | **채택** — 설계서가 말한 "챗봇 메뉴의 학습 영역('학습현황' 옆)"을 문자 그대로 만족한다. 학습현황과 같은 "학습 데이터를 만드는 근거 자료" 성격이며 `StatsShell`은 이미 권한별 링크 숨김을 구현하고 있다 |

- 서브내비 순서: `기본 통계 | 학습현황 | 외부 연동 로그 | 발화 묶음 분석`.
- **표시 조건**: `can('dialogue:read')` **그리고** 기능이 켜져 있을 때. 기능 꺼짐(`UTTERANCE_ANALYSIS_ENABLED=false`)은 `GET …/capability`가 `404`로 알려 준다(설계서 §12) → 링크를 **숨긴다**. capability 조회는 링크 자체를 그리는 작은 컴포넌트(`UtteranceAnalysisNavLink`)가 1회 수행하며 `StatsShell`의 다른 상태·`ChatbotDetailContext`는 건드리지 않는다. 404가 아닌 실패(네트워크 등)는 링크를 **보이고** 페이지에서 오류를 처리한다(숨겨서 기능을 못 찾게 만들지 않는다).
- 통계 탭 배지 없음(진행 중 알림 배지를 만들지 않는다 — 분석은 사용자가 화면에 머물지 않아도 되는 드문 작업이라 상시 배지 비용이 크다).
- 직접 URL 접근 시 기능이 꺼져 있으면 UA-1이 `KbFeatureOffState`와 같은 **기능 꺼짐 화면**을 보인다(§3.5).

### 2.3 폴링 규약(공통)

| 화면 | 대상 | 간격 | 멈춤 조건 |
|---|---|---|---|
| UA-1 | 목록(현재 페이지) — 목록에 `QUEUED`/`RUNNING` 행이 있을 때만 | 5초 | 진행 행이 없어지면 · 탭이 숨겨지면(`document.hidden`) 일시 정지 |
| UA-3(처리 중) | 상세 | 2초 | `SUCCEEDED`/`FAILED`/`CANCELLED` 도달 · 화면 이탈 |
| 공통 | 연속 실패 30초 | — | "연결이 원활하지 않습니다. 잠시 뒤 다시 시도합니다" 배너(UIUX §8), 재시도는 계속하되 간격을 10초로 늘림 |

- 폴링 갱신은 스크롤 위치·포커스·펼침 상태·입력 중인 값을 유지한다(UIUX §8 실시간 갱신). 새 상태 변화의 낭독은 **상태 단어가 바뀔 때만 1회**(§5.2).

| 5 | **대표 키워드 수** | 숫자 입력 | 1~20 · 기본 10 | `keywordCount` | |
| 6 | **키워드는 명사만 사용** | 체크박스 | 기본 켬 | `nounsOnly` | |
| 7 | **챗봇 대조** | 체크박스 + 하위(대조 대상 라디오 · 기준 점수 숫자) | 기본 켬 · 대상 기본 "운영 중인 답변" · 기준 비움 | `probe.enabled` · `probe.target`(`SERVING`/`DRAFT`) · `probe.scoreThreshold`(입력 0~100 → 0~1로 변환, 비움=`null`) | 대상 라디오는 `envModeEnabled`일 때만 표시. 꺼진 환경에서는 "현재 챗봇 답변과 비교합니다" 글자만. 대조를 끄면 하위 입력을 `disabled`로 두되 값은 유지 |
| (+) | 묶음 이름 제안(선택, 8번째) | 체크박스 | 기본 끔 · `nameSuggestAvailable`일 때만 표시 | `nameSuggest` | 서버가 꺼져 있으면 컨트롤을 렌더하지 않고 `false`로 보낸다(AC-DC6-1) |

- 조건은 `conditions`라는 멀티파트 필드에 **JSON 문자열**로 담아 파일과 함께 `POST`한다(설계서 §11).
- 기본값(10/5/10/명사만 켬/대조 켬/대상 운영/이름 제안 끔)은 **운영 권장값**이다. UIUX §6의 "기본값 임의 사전 선택 금지"는 개인정보성 값(성별 등)에 관한 규칙이라 운영 권장값에는 적용하지 않지만, 각 필드 아래에 "(권장 N)"을 글자로 밝혀 "왜 이 값인지" 알 수 있게 한다.

### 4.4 검증·사전 유효성 (UIUX §7 — 제출 시점 표시, 입력 중 팝업 없음)

| 검사 | 시점 | 결과 |
|---|---|---|
| 확장자·크기(`.xlsx`/`.csv`, ≤ 최대 크기) | 파일 선택 즉시(클라이언트, `FileUploadField` 기존 동작) | 파일 필드 아래 글자 오류. 파일 반영 안 함 |
| 서버 미리보기(`POST …/preview`) | 파일 선택 직후 **자동**(입력 중 팝업 아님, 결과 표만) | 표 또는 오류(§4.5) |
| 숫자 범위(3·4·5 및 기준 점수) | **"분석 시작" 제출 시** 필드별 인라인 오류(`InlineFieldError`) + 첫 오류 필드로 포커스 | "목표 묶음 수는 2 이상 50 이하의 숫자로 입력해 주세요." (필드마다 범위 문구) · 기준 점수 "0 이상 100 이하의 숫자로 입력하거나 비워 주세요." |
| 발화 부족 | 미리보기 표시 뒤·최소 발화 수 변경 시 **클라이언트에서 즉시 재계산**(서버 규칙: 분석할 발화 ≥ 최소 발화 수 × 2) | 표 아래 정보 문구 "분석할 발화가 {valid}개라 '묶음 최소 발화 수'를 {floor(valid/2)} 이하로 줄여야 합니다" + 제출 시 최소 발화 수 필드 인라인 오류 + "분석 시작"은 눌러도 이 오류로 이어짐(비활성화하지 않고 이유를 글자로 알린다) |
| 파일 없음 | 제출 시 | 파일 필드 오류 "발화 파일을 선택해 주세요." |

- 최소 발화 수를 바꿔도 **파일을 다시 올려 미리보기를 재호출하지 않는다** — 발화 부족 판정은 이미 받은 `validCount`로 클라이언트가 재계산한다(서버가 요청 시 최종 재검증, 설계서 §7.4 ⑦). 미리보기 API의 선택 쿼리 `minClusterSize`는 **최초 호출 시 현재 입력값**만 전달한다.
- 파일을 다른 파일로 바꾸거나 지우면 검사 결과·오류를 초기화한다.

## 5. 화면 UA-3 — 결과 상세

### 5.1 목적 · 구조

한 분석의 진행 상황과 결과를 보고, 결과를 엑셀로 받거나 **고른 발화만 확인 화면을 거쳐** 의도 예문으로 넣고, 분석을 취소·삭제한다. 상태에 따라 본문이 달라진다.

```
통계 > 발화 묶음 분석 > 3월_VOC.xlsx
[머리]      파일 이름 · 상태 글자 · 요청자 · 요청 일시 · 소요 시간 · 보존 만료일
            [엑셀로 받기](완료만) [분석 취소](처리 중만) [삭제](종결만)
[본문 분기]  QUEUED/RUNNING → §5.2 진행   |  FAILED/CANCELLED → §5.3   |  SUCCEEDED → §5.4~5.7
```

머리 정보: 파일 이름(마스킹·절단된 저장값, 사람 이름이 남을 수 있음은 설계서 K-2) · `AnalysisStatusText` · 요청자 이메일 · 요청·완료 시각 · 소요 시간 `durationMs`(있을 때, "3분 12초") · `RetentionExpiryText`.

### 5.2 처리 중(`QUEUED` · `RUNNING`)

```
분석이 진행 중입니다                    이 화면을 닫아도 분석은 서버에서 계속됩니다.
────────────────────────────────────────────────────────────
 ✔ 1. 파일 확인과 개인정보 가리기 — 완료
 ● 2. 문장 분석 — 진행 중
 ○ 3. 비슷한 말끼리 묶기 — 대기 중
 ○ 4. 대표 키워드 뽑기 — 대기 중
 ○ 5. 챗봇 대조 — 대기 중                 ← 대조를 끈 분석이면 이 줄 없음
 ○ 6. 이름 제안 — 대기 중                 ← 이름 제안을 켠 분석만
 ○ 7. 결과 저장 — 대기 중
 전체 진행률 ▓▓▓▓▓░░░░░ 42%
                                                    [분석 취소]
```

- 단계 ↔ `stage` 대응: 1=요청 처리에서 이미 끝난 단계(항상 "완료") · 2=`EMBEDDING` · 3=`CLUSTERING` · 4=`KEYWORDS` · 5=`PROBING` · 6=`NAMING` · 7=`SAVING`. `QUEUED`이면 1만 "완료", 나머지 "대기 중".
- 각 줄은 **글자로 상태를 밝힌다**("완료"/"진행 중"/"대기 중"). 기호(`✔ ● ○`)는 `aria-hidden`이며 색만으로 구분하지 않는다. 목록은 `<ol>`이고 진행 중 줄은 `aria-current="step"`.
- 진행 막대는 `AsyncJobProgress`를 **`live={false}`**로 쓰고(`<progress value max=100>`) 옆에 글자 "{n}%"를 항상 표시. 진행률 숫자가 바뀔 때마다 스크린리더가 다시 읽지 않도록 한다.
- **단계가 바뀔 때만** 별도 `role="status"` 영역에 1회 낭독: "문장 분석에서 묶기 단계로 넘어갔습니다"(`useAnnouncedTransition` 일반화 · 최초 마운트 낭독 없음 · 완료/오류/취소로 바뀔 때도 1회 "분석이 끝났습니다"/"분석 중 오류가 났습니다"/"분석이 취소되었습니다").
- 2초 폴링(`GET …/:analysisId`). 처리 중 응답의 `clusters`는 `[]`이므로 결과 영역은 그리지 않는다.
- **동시 1건 안내**: 진행 화면 하단 작은 글자 "분석은 서버 전체에서 한 번에 1건만 처리합니다. 이 분석이 끝난 뒤 다음 분석을 시작할 수 있습니다."
- **취소**: "분석 취소"(쓰기 권한 · 처리 중만) → `ConfirmDialog`(§5.8). 저장 단계(`SAVING`)에서 눌러 `409`가 오면 "이미 끝났거나 저장 중이라 취소할 수 없습니다. 잠시 뒤 결과를 확인해 주세요."로 알리고 상세를 즉시 재조회.
- 폴링 지연·실패: §2.3 배너 규칙. 장시간(예: 30분 이상 `RUNNING`)이라도 클라이언트가 임의로 종료 처리하지 않는다 — 서버가 상태를 확정한다(재시작 시 서버가 `FAILED`로 정리, 설계서 §8.4). 대신 **경과 시간 글자**("시작한 지 12분 지났습니다")를 표시해 정체를 알 수 있게 한다.
- 로딩(최초): 머리는 스켈레톤(`SkeletonCard`) · `aria-busy`.

### 5.4 완료(`SUCCEEDED`) — 상단 영역

배치 순서(위 → 아래):

1. **요약 줄**(4~5개 수치 카드, 글자 레이블 필수): "분석한 발화 {validCount}개 · 묶음 {m}개 · 미분류 {u}개 · 학습 후보 {k}개(대조한 경우) · 이미 넣은 예문 {a}개".
2. **안내 배너들**(정적):
   - `maskNotice`(정보)
   - `notIntentNotice`(정보)

3. **알림 목록**(`AnalysisNoticeList` — 해당하는 것만 각각 정보/주의 배너, 글자):

| 원인 | 문구 |
|---|---|
| `TARGET_REDUCED` | "발화 수에 맞춰 목표 묶음 수를 줄여서 분석했습니다." |
| `FEWER_THAN_TARGET` | "묶음이 목표({target}개)보다 적은 {m}개로 나왔습니다. 비슷한 말이 많거나 발화가 적을 때 이렇게 됩니다." |

- **번호**: 발화 수 많은 순, **미분류는 마지막 행**(`unassigned=true`) — 번호 칸에 숫자 대신 "미분류"라고만 적는다("11" 표시 안 함). 행 머리 셀(`<th scope="row">`)은 이름.
- **이름**: `displayName`(관리자 수정 > 자동 이름). 미분류는 수정 불가(버튼 없음). 도움말(`▸ 미분류란?` 툴팁 대신 표 아래 설명 문단): "어느 묶음에도 넣기 어려웠거나, 발화 수가 '묶음 최소 발화 수'보다 적은 묶음에 속한 문장들입니다. 미분류도 발화를 보고 예문으로 넣을 수 있습니다."
- **이름 바꾸기**(쓰기 권한): 버튼 클릭 → 이름 칸이 텍스트 입력으로 바뀜(레이블 sr-only "{번호}번 묶음 이름", 최대 40자 글자수 "12/40" 실시간, 붙여넣기 제한 없음) · [저장] [자동 이름으로 되돌리기](`customName=null`) [취소]. Enter=저장, Esc=취소. 저장/취소 후 **포커스를 "이름 바꾸기" 버튼으로 복귀**. 오류: `BANNED_WORD_BLOCKED` → 입력 아래 "이름에 사용할 수 없는 표현이 들어 있습니다. 다른 말로 바꿔 주세요." · `VALIDATION_FAILED` → "이름은 1자 이상 40자 이하로 입력해 주세요." 성공 → 토스트 없이 행 갱신 + 상태 영역 낭독 "묶음 이름을 바꿨습니다"(이름 변경은 자산이 아니라 메모라 강한 알림 불필요). 감사·스냅샷 없음(설계서 §15.6)이라 "감사 기록" 고지는 하지 않는다.
- **AI 제안**(`AiNameSuggestionChip`): `suggestedName`이 있고 `customName`과 같지 않을 때만 이름 아래 한 줄로 표시. **글자 표식 "AI 제안 — 확인 필요"**를 앞에 붙이고 점선 테두리·옅은 주의색(제안 시각 언어, UIUX §1)으로 분리해 확정된 이름과 구분한다. "이 이름 사용" 버튼은 `customName`으로 저장(그 시점에 서버가 다시 검사). 제안 없음/실패면 이 줄 자체가 없고 대신 위 알림이 있다. **이름 제안 기능이 꺼져 있으면(`nameSuggest.status=OFF`) AI 제안 관련 UI(줄·안내)를 전혀 그리지 않는다** — 빈 열이나 "제안 없음" 문구도 만들지 않는다(AC-DC6-1).
- **대표 키워드**: `keywords[].term`을 쉼표로 이은 글자(최대 `keywordCount`). 키워드가 0개인 묶음은 "(뽑힌 키워드 없음)". 점수·횟수는 화면에 숫자로 늘어놓지 않고 키워드 칩의 `title`/sr-only로 "포함된 발화 {count}개"만 제공.
- **발화(발생 합)**: "380 (1,204)" — 앞은 서로 다른 발화 수, 괄호는 발생 횟수 합. 열 머리 sr 설명 "서로 다른 문장 수(괄호: 발생 횟수를 합친 수)".
- **학습 후보 비율**: `candidateRatio` 있으면 "72% (274/380)"(글자), 대조를 끈/실패한 분석이면 "—" + 열 머리에 "(대조 안 함)" 보조. 값이 높을수록 색을 진하게 하는 등 **색 단독 표시를 하지 않는다**(숫자가 본문).
- **대표 발화 3개**: 행 펼침 버튼(`aria-expanded`, 레이블 "{번호}번 묶음 대표 발화 보기")으로 아래 하위 행에 `representatives[].text`를 목록으로. 미분류는 발생 횟수 순 대표(서버 결정).
- **발화 보기**: 클릭 시 발화 표 필터에 그 묶음을 설정하고(쿼리스트링 `cluster=`) 발화 표 머리로 포커스를 이동한다(스크롤 이동 후 발화 표 제목 `tabindex="-1"`에 포커스).
- 묶음이 0개(`NO_CLUSTER`)면 표에는 미분류 1행만 있다.
- 상태: 묶음 표는 상세 응답에 동봉(≤51행)이므로 별도 로딩 상태 없음. `staleModel`·notices는 위 알림으로.

**선택 규칙**(`SelectionBar`)

- 한 번에 최대 **50개**(`UTTERANCE_ANALYSIS_LIMITS.applyMaxUtterances`). 50개에 도달하면 나머지 체크박스는 `aria-disabled` + sr-only 이유 "한 번에 50개까지 고를 수 있습니다" + 선택 바에 "최대 50개까지 골랐습니다" 글자.
- 선택 불가: `applied != null`(이미 반영) · `hasBannedWord`(서버가 항상 제외하므로 화면도 선택을 막는다 — §12 조정 2).
- 머리 체크박스: "이 페이지에서 선택 가능한 발화 모두 선택"(선택 가능한 것만, 남은 자리(50 − 현재 선택) 내에서 앞에서부터). 일부만 선택되면 `indeterminate`. 선택 후 상태영역 낭독 "이 페이지에서 8개를 선택했습니다. 전체 선택 12개".
- 선택 수 글자 "12개 선택됨 — 최대 50개"는 `role="status"`(polite)에 두되 **선택 변경이 멈춘 뒤 500ms 디바운스로 1회** 낭독. 0개면 "선택한 발화가 없습니다".
- "선택 모두 해제" 버튼. 선택은 **페이지·필터가 바뀌어도 유지**하고 분석 이탈 시 폐기한다.
- 키보드: Tab으로 필터 → 선택 바 → 표 머리 체크박스 → 각 행 체크박스 순서. **Space**로 체크 토글. 표 행 사이는 Tab으로 이동(방향키 그리드 모델은 쓰지 않는다 — 단순 표 + 체크박스).
- "선택한 발화를 의도 예문으로 넣기" 버튼은 선택이 0개면 `aria-disabled` + 이유 글자 "넣을 발화를 먼저 골라 주세요". 클릭 시 §5.7 대화상자를 연다.

### 5.7 예문으로 넣기 대화상자 (`ApplyToIntentDialog`) — 미리보기 → 확정 → 결과

`Modal`(큰 크기) 하나 안에서 3단계를 전환한다. 단계가 바뀔 때마다 **단계 제목에 포커스**를 옮기고(`tabindex="-1"`), 대화상자 상단에 "1/3 대상 고르기 · 2/3 확인 · 3/3 결과"를 글자로 밝힌다(진행 표시를 본문보다 먼저 배치, UIUX §4의 취지). Esc/✕로 닫을 수 있으나 **요청이 진행 중일 때는 닫기 비활성**. 대화상자를 닫으면 포커스를 "선택한 발화를 의도 예문으로 넣기" 버튼으로 복귀한다.

**단계 1 — 넣을 곳 고르기**

```
예문으로 넣기 — 1/3 넣을 곳 고르기
선택한 발화 12개를 의도의 예문으로 넣습니다. (한 번에 최대 50개)
넣을 곳 (필수)
 ( ) 이미 있는 의도에 넣기      [ 의도 검색_______ ▾ ]   ← 이 라디오를 고르면 활성(ResourcePickerField 'intent')
 ( ) 새 의도를 만들어 넣기      [ 새 의도 이름________ ] 0/100   ← 이 라디오를 고르면 활성
 ⓘ 새 의도는 특정 분류 없이 만들어집니다. 분류는 넣은 뒤 의도 화면에서 바꿀 수 있습니다.
                                              [취소]  [미리보기]
```

- 라디오는 **사전 선택하지 않는다**(UIUX §6). 제출 시 미선택이면 라디오 그룹 아래 "넣을 곳을 골라 주세요." 인라인 오류.
- 기존 의도: `ResourcePickerField`(type `intent`, 레이블 "의도 검색", 필수) — 선택 안 하면 "넣을 의도를 골라 주세요."
- 새 의도: 텍스트 입력(레이블 "새 의도 이름", 필수, 1~100자 글자수 실시간). 이미 같은 이름이 있으면 서버가 `EXISTING_BY_NAME`으로 알려 준다(다음 단계에서 안내).
- 각주: DC-15 때문에 이 문구에도 "토픽"을 쓰지 않는다 → 실제 문구는 "새 의도는 특정 분류 없이 만들어집니다. 분류는 넣은 뒤 의도 화면에서 바꿀 수 있습니다."
- [미리보기] → `POST …/apply/preview` → 스피너("확인하는 중입니다") → 단계 2. 오류 처리: `404 NOT_FOUND`(의도 삭제됨, EX-DC-10) → 단계 1로 남아 라디오·선택기 아래 "의도가 없습니다. 다른 의도를 골라 주세요."(선택기를 비움) · `409 INVALID_STATUS_TRANSITION` → "분석이 완료된 상태에서만 넣을 수 있습니다." · `409 CHATBOT_ARCHIVED` → "보관된 챗봇에는 넣을 수 없습니다." · 그 외 대화상자 상단 오류 배너.

**단계 2 — 확인 (반드시 거친다)**

```
예문으로 넣기 — 2/3 확인
넣을 곳: 기존 의도 '해지문의'에 넣습니다.        ← resolution 문구 §아래
[환경 분리 모드] ⚠ 이 챗봇은 환경 분리 모드입니다. 예문은 "초안"에만 들어가며, 운영에는 스테이징 승격과
                  운영 전환을 거쳐야 나갑니다.                                  ← draftOnly
넣는 문장 7개   →  넣은 뒤 이 의도의 예문은 총 58개가 됩니다.
 ▸ (스크롤 목록) 1. 환불 어떻게 받아요
                 2. [전화번호]로 해지해 주세요  ⓘ 개인정보 가림 표시가 들어간 문장입니다 — 필요하면 의도 화면에서 다듬으세요
                 …
빠지는 문장 3개  (아래 이유로 넣을 수 없습니다)
 <table caption="빠지는 문장과 이유">
  문장                     이유
  진짜 화나네 *****         금지어가 들어 있는 문장입니다
  (201자 문장…)             200자를 넘는 문장입니다
  위약금 얼마예요           다른 의도 '위약금'에 같은 예문이 이미 있습니다
 ⚠ 이 의도를 쓰는 대화상자가 없습니다 — 예문을 넣어도 대화에는 아직 연결되지 않습니다.   ← linkedNodeCount === 0
 ⓘ 저장하면 바로 이 의도에 들어갑니다. 저장 직전 상태는 자동으로 버전 이력에 남습니다.   ← draftOnly=false
                                       [뒤로]  [예문 7개 넣기]
```

`target.resolution` 문구:

| 값 | 문구 |
|---|---|
| `EXISTING` | "넣을 곳: 이미 있는 의도 '{이름}'에 넣습니다." |
| `NEW` | "넣을 곳: 새 의도 '{이름}'을 만들어 넣습니다." + (`linkedNodeCount === null`) "새 의도는 아직 어떤 대화상자와도 연결되어 있지 않습니다. 넣은 뒤 대화설계에서 연결해 주세요." |
| `EXISTING_BY_NAME` | 주의 배너 "같은 이름의 의도 '{이름}'이 이미 있어, 새로 만들지 않고 그 의도에 넣습니다." |

제외 사유 코드 → 문구(`UtteranceApplyExcludeReason`):

| 코드 | 문구 |
|---|---|
| `NOT_FOUND` | "이 분석에 없는 발화입니다." |
| `ALREADY_APPLIED` | "이미 의도에 넣은 발화입니다." |
| `BANNED_WORD` | "금지어가 들어 있는 문장입니다." |
| `TOO_LONG` | "200자를 넘는 문장입니다." |
| `DUPLICATE_IN_TARGET` | "이 의도에 같은 예문이 이미 있습니다." |
| `DUPLICATE_IN_OTHER_INTENT` | "다른 의도 '{conflictIntentName}'에 같은 예문이 이미 있습니다." |
| `TARGET_LIMIT` | "의도 하나에 넣을 수 있는 예문 수(500개)를 넘어 넣을 수 없습니다." |

- 경고 `MASK_TOKEN`: 해당 문장 아래 "개인정보 가림 표시가 들어간 문장입니다 — 필요하면 의도 화면에서 다듬으세요."(포함은 되지만 경고).
- **넣는 문장이 0개**면 [예문 0개 넣기]를 `aria-disabled`로 두고 "넣을 수 있는 문장이 없습니다. 뒤로 가서 선택을 바꿔 주세요." 글자를 연결. [뒤로]는 항상 가능(선택은 유지).
- 확정 버튼 레이블은 **동사형 + 개수**("예문 7개 넣기"). 확정 시 버튼 `disabled` + 스피너("넣는 중…"), 연타 방지(UIUX §4). 기본 포커스는 [뒤로]가 아니라 **단계 2 제목**이며, 파괴적 동작은 아니므로 `ConfirmDialog`의 "취소 기본 포커스" 규약과 달리 확정 버튼에 초기 포커스를 두지 않는다(실수 방지).
- 미리보기 이후 상태가 바뀌었을 수 있으므로 서버는 확정 시 계획을 다시 계산한다(설계서 §15.3 ①). 결과가 확인 화면과 다를 수 있음을 결과 화면이 정직하게 보여 준다.

**단계 3 — 결과 (건별 부분 성공 표시)**

```
예문으로 넣기 — 3/3 결과                 (role="status" 영역)
 반영 완료 — 다음 대화부터 적용됩니다.          ← appliedImmediately=true (MESSAGES.learning.resolveSuccessImmediate)
 (draftOnly면 "초안에 넣었습니다. 운영에는 스테이징 승격·운영 전환을 거쳐 나갑니다.")
 (appliedImmediately=false면 MESSAGES.learning.resolveSuccessQueued)
 넣은 문장 6개 · 빠진 문장 3개 · 실패한 문장 1개
 [새 의도 '환불문의'를 만들었습니다]   ← created=true
 (AutoSnapshotNotice: 자동 저장된 버전 안내 + 보기 링크 / 실패 안내)
 ⚠ 이 의도를 쓰는 대화상자가 없습니다 …   ← linkedNodeCount===0
 실패한 문장 표(caption "넣지 못한 문장"): 문장 | 이유 — failed[].code/message (예: "의도 하나에 넣을 수 있는 예문 수를 넘었습니다")
 빠진 문장 표(단계 2 표와 같은 이유 문구)
                                                         [닫기]
```

- 넣은 수 0(전부 제외/실패)이면 제목 "넣은 예문이 없습니다"(정보/주의 톤) — 성공 문구를 보이지 않는다.
- 문구는 `appliedImmediately` 응답값으로만 분기한다(`MESSAGES.learning` 상수 재사용). 새 자유 문장을 만들지 않는다(K-4).
- 실패 표의 문장 본문은 응답에 `utteranceId`만 있으므로 **미리보기 응답의 `included[].text`를 id로 매핑**해 보여 준다(`textById`).
- [닫기] 시: 성공·제외(이미 반영 포함)된 발화는 선택에서 제거하고 **실패한 발화는 선택 유지**(재시도 가능), 발화 표·묶음 표·상세 요약의 "넣은 예문" 수를 재조회(`GET` 상세 + 발화 목록). 표에는 해당 발화에 "반영됨 — 의도명"이 나타난다.
- `POST …/apply`가 통째로 실패(네트워크·5xx)하면 대화상자 안에 오류 배너 "요청이 실패했습니다. 이미 일부가 들어갔을 수 있으니 발화 목록에서 '반영됨' 표시를 확인해 주세요." + [다시 확인](발화 목록 재조회) · [닫기].

### 6.1 데이터 지도 "업로드 발화 분석" 절

기존 `DataGovernanceMapPage`(`/settings/data-governance/map`)의 `kbSources`·`proactive` 절 선례에 맞춰 **`GovernanceMapResponse.utteranceAnalysis` 키가 있을 때만**(분석 1건 이상) 절 하나를 추가한다. 키가 없으면 절을 그리지 않는다.

### 6.2 다른 라벨 상수(frontend-implementer 작업)

- 버전 자동 캡처 트리거 라벨: `BEFORE_UTTERANCE_APPLY` → **"자동 · 발화 묶음 반영 직전"**(기존 라벨 형식 `자동 · … 직전`을 따른다 — 설계서 §21.3의 "발화 묶음 반영 직전(자동)" 표기와 어순만 다름, §12 조정 5). 버전 목록 필터 그룹은 자동(`AUTO`).
- 감사로그 대상 유형 라벨: `UtteranceAnalysis` → **"발화 묶음 분석"**. `AuditTargetType` 라벨 매핑(컴파일 강제 Record)에 키를 추가하지 않으면 빌드가 깨진다.
- `MESSAGES.utteranceAnalysis` 네임스페이스 신설(위 문구 전부 + 상태·오류·사유 라벨). 화면 문자열에 금지 용어("토픽·군집·클러스터·임베딩·벡터")가 없는지 확인하는 vitest를 추가하고 `clusterHelp` 1개만 허용 목록에 둔다(DC-15).

## 7. 사용자 인터랙션 흐름 종합 (제출 → 로딩 → 결과, 오류 포함)

```
[UA-1] 진입 → capability·목록 로딩 → (빈/오류/성공)
   └ [새 분석] (쓰기 · 서버 여유 · 보관 여유일 때만 활성)
[UA-2] 양식 받기 → 발화 붙여 넣기(외부) → 파일 선택
```

### 9.1 스크린리더 · 접근성 세부

1. **표**: 모든 표에 `<caption>`, `<th scope="col|row">`. 발화 표 행 체크박스는 `aria-labelledby`(같은 행 발화 셀). 열 머리에 보조 설명이 필요한 "점수"·"발화(발생 합)"는 sr-only 설명 텍스트를 함께 둔다.
2. **낭독 예산**(반복 낭독 방지): 낭독 영역(`role="status"`)은 화면당 다음 3개만 둔다 — ① 진행 단계 전환(처리 중 화면) ② 선택 수(디바운스 후) ③ 필터 결과 개수(로딩 완료 후). 진행률 %·폴링 갱신·이름 수정 성공은 각각 다른 방식(비낭독/1회)으로 처리한다.
3. **포커스 관리**: 페이지 이동 시 제목 `h1`에 포커스(`tabindex="-1"`). "발화 보기" 클릭 → 발화 표 제목으로 포커스. 대화상자 닫기 → 트리거 복귀. 삭제 성공으로 행이 사라지면 표 캡션으로 포커스.
4. **색 비의존**: 상태(대기/진행/완료/오류/취소)·단계(완료/진행 중/대기)·배지 4종·필터 상태 모두 글자로 표기. 학습 후보 비율에 색 농도를 쓰지 않는다.
5. **키보드 완결성**: 파일 선택→조건→제출, 필터→행 선택→대화상자→확정, 이름 편집이 모두 마우스 없이 가능해야 한다(NFR-DCA2). 파일 선택은 `FileUploadField`의 `<label htmlFor>` + 숨김 input 방식을 그대로 쓰며 드래그앤드롭은 보조로만 제공한다.
6. **오류 문구**: 원인 + 해결 방법을 함께 쓴다(§8.2). 기술 용어·코드명·서버 원문 메시지를 노출하지 않는다.

## 10. 반응형 고려사항

1. **기본 규칙**: 기존 관리자 콘솔의 브레이크포인트·간격 규칙을 따른다(새 브레이크포인트 정의 없음). 콘솔은 데스크톱 우선이며 태블릿·모바일에서도 **모든 기능이 동작**해야 한다(터치 44×44px).
2. **서브내비**: 항목이 4개로 늘어 가로 폭이 부족해지면 기존 `stats-subnav`의 줄바꿈/가로 스크롤 규칙을 그대로 쓴다(현재 항목 표시가 잘리지 않게). 링크 문구 "발화 묶음 분석"은 줄이지 않는다.
3. **UA-1 표**: 좁은 화면(< 768px)에서는 표를 **카드 목록**으로 재구성한다 — 카드마다 "파일 이름 · 상태 글자 · 요청 일시 · 발화/묶음/학습 후보/반영 수(레이블 포함 2열) · 보존 만료일" + "결과 보기"·"삭제" 버튼(44×44px, 세로 배치). 읽기 순서: 파일 이름 → 상태 → 수치 → 만료 → 버튼.
4. **UA-2**: 단일 열. 조건 필드는 세로 스택, 숫자 입력 폭은 전체 너비, 검사 결과 표는 2열(레이블/값) 유지. "분석 시작"·"취소" 버튼은 전체 너비 세로 스택(주 버튼이 위).
5. **UA-3 묶음 표·발화 표**: 열이 많으므로 **가로 스크롤 컨테이너 + 표 머리 sticky**(`validation-regression-ui-spec.md` §8 규칙 재사용, 카드형으로 재구성하지 않음 — 열 대응관계 유지가 확인·선택에 필수). 스크롤 컨테이너에 `tabindex="0"`·`role="region"`·`aria-label`("발화 목록, 가로로 스크롤할 수 있습니다")를 준다. 발화·선택 열은 왼쪽 고정(sticky) 검토.
6. **선택 바**: 좁은 화면에서 "12개 선택됨"과 버튼이 줄바꿈되며 버튼 44×44px 유지. 하단 고정(fixed) 바는 쓰지 않는다(확대·포커스 가림 방지) — 표 위에 정적 배치.
7. **대화상자**: 기존 `Modal` 규칙(좁은 화면 전체 폭, 내부 스크롤, 포커스 트랩)을 상속한다. 확인 화면의 "넣는 문장"·"빠지는 문장" 목록은 각각 최대 높이 + 내부 스크롤(키보드로 스크롤 가능하도록 `tabindex="0"` 영역).
8. **처리 중 화면**: 단계 목록은 세로 그대로, 진행 막대는 전체 폭, 취소 버튼은 막대 아래로 내려도 44×44px 유지.
9. **확대(200%)·가로 스크롤 금지 영역**: 폼·안내 배너·머리 정보는 확대 시 가로 스크롤이 생기지 않고 줄바꿈되어야 한다(표만 예외).
