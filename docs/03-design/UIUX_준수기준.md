# UI/UX 준수 기준 (챗봇 위젯 + 관리자 콘솔)

> 출처: `디지털 정부서비스 UIUX 가이드라인(2025.08)`, `디지털 정부 서비스 UIUX 가이드라인 자체 검증 체크리스트(2024.11)` — `docs/00-source/` 참고.
> 두 문서는 정부 디지털서비스 전반의 **일반 UI/UX·접근성 표준**이며, 챗봇을 직접 다루는 섹션은 없음("챗봇"은 문의채널 예시로 4회 언급). 아래는 그중 (a) **챗봇 위젯**(대화 입력창/메시지/버튼)과 (b) **관리자 콘솔**(챗봇 제작·설정·통계 화면)에 실제 적용되는 규칙만 추린 것.

## 1. 색상/명도 대비
- 텍스트-배경 명도 대비 최소 4.5:1(권장 7:1), 아이콘/버튼 테두리 등 비텍스트 요소는 3:1 이상.
- 위험(빨강)/주의(노랑)/성공(초록)/안내(파랑) 색상 의미 체계를 고정하고, **색상만으로 정보를 전달하지 않음**(밑줄·아이콘 병행). → (a) 챗봇 오류/성공 배지, (b) 관리자 폼 검증 상태 배지.
- 입력창 placeholder 텍스트색과 실제 입력값 텍스트색 간 대비 3:1 이상. → (a) 챗봇 입력창 "메시지를 입력하세요".
- **제안-자산의 시각적 분리**: 관리자 승인을 거쳐야 확정되는 항목(제안·초안·대기 상태)과 이미 확정된 자산(운영 데이터)은 같은 목록에 상태 컬럼만 다르게 표시하지 않고 **서로 다른 컨테이너**(배경색·테두리 스타일 차등 — 예: 제안은 옅은 주의색 배경 + 점선 테두리, 자산은 기본 배경 + 실선 테두리)로 분리해 렌더한다. 제안 컨테이너에는 "승인 전까지 반영되지 않습니다" 류의 안내를 상시 노출하고, 자산으로의 승격은 제안 컨테이너 안의 **단일 진입점 버튼**을 통해서만 이뤄지게 한다(자산 쪽에서 제안을 끌어오는 대응 버튼을 두지 않음 — 흐름의 방향성을 구조로 강제한다). 색상은 여기서도 단독으로 의미를 전달하지 않으며, 컨테이너 헤더에 "제안(승인 전)" 같은 텍스트 라벨을 반드시 병기한다. → (b) 예문 증강 제안 목록·미응답 요소분해 엔티티 등록 대기열(`learning-augmentation-ui-spec.md` §2).

## 2. 타이포그래피/가독성
- 본문 기본 글자 크기 16~17px 이상, 여러 줄 텍스트 행간은 글자 크기의 1.5배 이상.
- 인라인 링크는 본문과 동일한 글자 크기 유지.

## 3. 키보드 접근성/포커스 순서 — (a)+(b) 공통 최우선
- 모든 대화형 요소(버튼/링크/입력/셀렉트/체크박스)는 Tab 순차 진입, Shift+Tab 역순 진입 보장.
- 마우스 클릭과 키보드 Enter/Space 두 방식 모두 동일 동작을 실행해야 함. 셀렉트 확장 시 Esc로 닫히고 포커스가 컨테이너로 복귀.
- 검증 필요: 챗봇 입력창 → 전송버튼 탭 이동, 관리자 폼 필드 간 이동.
- **정렬 가능한 표의 헤더**는 클릭 가능한 텍스트가 아니라 `<button>`으로 제공하고(Tab 진입·Enter/Space 실행), 현재 정렬 상태를 헤더 셀의 `aria-sort`(`ascending`/`descending`/`none`)로 알린다. 정렬 변경 결과는 표 본문이 조용히 바뀌는 대신 `aria-live="polite"` 영역으로도 안내한다(색상만으로 정렬 방향을 표시하지 않음 — §1과 동일 원칙). → (b) 여러 스코프(챗봇/그룹/전역)를 한 표에서 비교하는 기여 표(`integrated-stats-ui-spec.md` §2 `SortableBreakdownTable`).

## 4. 버튼 — (a) 챗봇 전송 버튼에 핵심
- 텍스트 레이블은 동사형("전송", "닫기" 등).
- 더블클릭/연타 시 중복 실행(중복 전송) 방지 로직 필수.
- 반응 영역: 마우스 상호작용 17×17px, 터치 상호작용 44×44px 이상. → (b) 모바일 반응형 관리자 화면에도 적용.
- **대화형 설문 문항 표시 원칙**: 대화창 안에서 여러 턴에 걸쳐 문항을 묻는 설문(예: 만족도 조사)의 매 문항은 진행 표시("n/N")를 문항 문구보다 **먼저** 노출해 스크린리더가 "몇 번째 문항인지"를 먼저 듣게 한다. 선택형 응답 버튼은 별 기호 등 **기호만으로 의미를 전달하지 않고** 항상 텍스트 라벨을 함께 표시한다(예: "1점 매우 불만족", 양 끝 값에는 라벨을 병기). 응답 버튼이 5개를 넘으면 5개 단위로 블록을 나눠 전부 노출한다(일부 선택지가 잘려 사라지지 않게). 모든 문항에는 대화를 중단할 수 있는 "그만하기" 버튼을 상시 제공한다. → (a) 챗봇 위젯의 대화 내 설문 진행(`survey-management-ui-spec.md` §3.10).

## 5. 텍스트 입력 필드/텍스트 영역 — (a) 챗봇 메시지 입력창에 핵심
- 레이블 필수 제공(플레이스홀더를 레이블 대체 수단으로 쓰지 말 것).
- 입력 길이를 예측할 수 없는 경우 필드 폭은 컨테이너 전체 너비 사용.
- 복사/붙여넣기 제한 금지.
- 글자 수 제한 시 "최대 글자 수 + 남은 글자 수"를 실시간 갱신 표시.
- 텍스트 영역은 내용 초과 시 세로 스크롤 생성, 마우스 휠/방향키로 스크롤 가능해야 함.

## 6. 폼 컨트롤(셀렉트/체크박스/라디오/날짜) — (b) 관리자 콘솔 폼에 핵심
- 단일 선택=라디오/셀렉트, 다중 선택=체크박스로 용도 구분, 옵션 20개 초과 시 셀렉트 대신 다른 UI 권장.
- 셀렉트: 값 변경만으로 폼 자동 제출 금지, 방향키로 옵션 탐색 가능.
- 체크박스: 기본 가나다순 정렬, 수직 배치.
- 필수/선택 입력 항목을 명확히 구분 표시(일관된 방식, 예: 별표).
- 기본값(성별/생년월일 등) 임의 사전 선택 금지.
- **슬라이더(`type="range"`)**: 정밀한 수치 조정이 필요한 슬라이더는 **같은 값을 표시·수정할 수 있는 숫자 입력 필드를 항상 함께 제공**한다(슬라이더 단독 제공 금지 — 마우스 드래그로는 정밀 입력이 어렵고 스크린리더 사용자에게도 대체 입력 수단이 필요하다). 슬라이더의 현재 값은 텍스트로 상시 노출하며, 방향키(←/→, Home/End)로 조작 가능해야 한다. → (b) 챗봇별 매칭 임계값 슬라이더(`nlu-rag-answering-ui-spec.md` §4.1.1).

## 7. 오류 메시지/유효성 검증 피드백 — (a)(b) 공통 핵심
- 오류는 구체적 원인 + 해결 방법을 함께 안내(예: 입력 필드 하단 인라인 오류).
- 입력 중/포커스 이동만으로 오류 팝업을 띄우지 않고, 제출 시점 등 적절한 타이밍에 표시.
- 제출 전 가능한 범위에서 사전 유효성 검사 수행.

## 8. 로딩/상태 피드백 — (a)(b) 공통
- 데이터 로딩 중: 스켈레톤/스피너/영역 흐림효과 중 1가지 이상으로 "조회 중" 상태 명시.
- 완료 시 결과 개수·적용 조건 배지 등으로 "완료" 상태 구분 표시. → (b) 관리자 콘솔 필터링/정렬/테이블 조회, (a) 챗봇 "응답 생성 중" 상태에도 응용.
- 파일 업로드 중 스피너, 실패 시 구체적 오류 메시지 필수.
- **비동기 답변 대기 패턴**: 서버가 즉시 결과를 반환하지 못하고 백그라운드에서 계속 처리하는 경우(예: 외부 시스템 연동 응답 대기), 대기 상태는 **(1) 시각적 진행 표시**와 **(2) `aria-live`/`role="status"` 텍스트 안내**를 함께 제공한다. 애니메이션만으로 상태를 전달하지 않는다. 다른 입력을 차단하지 않는 것을 기본으로 하며, **상한 대기시간을 두고 초과 시 "지금은 처리하지 못했습니다" 류의 정리 문구로 상태를 명확히 종료**한다(무한 로딩 금지). → (a) 챗봇 위젯의 문서 기반 답변 대기(`nlu-rag-answering-ui-spec.md` §4.4), (b) 관리자 콘솔의 예문 증강 생성·분류기 재학습 진행 표시(`learning-augmentation-ui-spec.md` §3 `AsyncJobProgress`).
- **여러 원천(스코프)을 합산해 보여주는 화면의 부분 정정 상태**: 백엔드가 아직 일부 원본 데이터를 새 집계 기준으로 옮기지 못한 상태(예: 마이그레이션 직후 백필 대기)에서는, 화면에 **수치가 실제보다 적게 보일 수 있음을 조용히 넘어가지 않고** 상시 배너로 원인과 "자동으로 해소된다"는 전망을 함께 안내한다(빈 데이터처럼 보이게 두지 않음). → (b) 관리자 콘솔 통합 통계의 `backfillPending` 안내(`integrated-stats-ui-spec.md` §2 `BackfillPendingBanner`).

## 9. 내비게이션 — (b) 관리자 콘솔에 핵심
- 건너뛰기 링크(본문 바로가기) 제공, 페이지 최초 Tab 시 노출.
- 브레드크럼/사이드메뉴 링크는 href 기반 키보드 접근 보장.
- 페이지네이션: 현재 페이지는 색상만이 아닌 밑줄(대비 3:1)+형태로 구분.

## 10. 범위 제외 (해당없음)
지도, 동영상 플레이어, 인쇄 레이아웃, 공식 배너/운영기관 식별자, 방문·검색·로그인·신청 등 정부 "서비스 패턴"은 원문서에 독립 섹션으로 존재하나 챗봇 위젯/관리자 콘솔의 일반 UI 요구와 직접 관련이 없어 제외.
