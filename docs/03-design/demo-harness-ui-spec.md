## 0. 전제와 판단 요약

1. **이 화면들은 제품이 아니라 시연 도구의 화면이다.** 사람이 클릭해 조작하지 않고(자동 진행), 진행자는 **터미널**에서 키로 제어한다(설계 §4.4). 그래서 `UIUX_준수기준.md`를 "그대로 전부"가 아니라 **화면 성격별로 적용 범위를 나누어** 적용한다(§10). 어긋나게 조정한 곳은 §10.2에 모아 이유와 보완 수단을 적었다.
2. **프로젝터 가독성이 제품 기준보다 우선한다.** 큰 화면은 뒤에서 읽으므로 본문 16~17px 기준(§2)을 **무대 화면에서는 상향**한다(자막 24px 이상은 NFR-DHA1, 이 문서는 무대 전체 최소 글자 크기도 정한다).
3. **연출이 사실을 앞지르지 않는다(R-1 · FR-0-316).** 모든 화면에 "무엇이 실제이고 무엇이 미리 준비·모형·대체인가"를 **글자로** 드러내는 자리를 둔다(자막 띠의 `시연 안내` 줄 · 시작 카드의 증거 구분 열 · 보고서 정직성 표기 · 로드맵의 점선 컨테이너).
4. **색만으로 상태를 전달하지 않는다.** 모든 상태(통과/실패/건너뜀/대체/지연)는 **글자 라벨 + 모양**을 반드시 가지며 색은 보조다. 터미널은 색이 아예 없어도 같은 정보가 나오게 대괄호 라벨(`[통과]`)을 쓴다.
5. **외부 자원 0.** 하네스가 만드는 모든 HTML은 외부 CSS·JS·글꼴·이미지 요청이 없다. 글꼴은 **시스템 글꼴만**(Google Fonts 금지 — DHX-1과 같은 이유). 그래서 제품 콘솔과 글꼴이 약간 다를 수 있다.
6. **기호 사용 규칙**: 단계 제목·자막·터미널 문구에 **원문자(①)·화살표(→)·ⓘ·박스 드로잉 문자를 쓰지 않는다**(Windows 한국어 콘솔에서 폭이 모호해 표가 깨진다 — §9.1). 장면 번호는 `장면 3/7`처럼 글자로 쓴다. 설계서 §10·요구사항의 `①~⑦`는 문서 표기일 뿐 화면에 그대로 옮기지 않는다.

### 2.2 무대 크기 단위 `--u`

무대 안의 모든 크기는 **1920x1080 기준 px 값**으로 적고, 실제 크기는 `값 x --u`로 환산한다.

- `--u = min(100vw, 100vh x 16/9) / 1920` (16:9 비율을 지키고 남는 쪽은 `#111827`로 레터박스)
- 1920x1080 → `--u = 1` · 1600x900 → 0.833 · **1280x720 → 0.667**
- 무대 최소 지원은 **1280x720**. 이보다 작은 `--viewport`는 사전 점검 오류(`--viewport` 값 검사)로 막는다.
- 무대 페이지는 **스크롤바 0**(`overflow: hidden`)이다. 내용이 넘치면 줄이는 규칙(§3.3)으로 해결하지 스크롤로 해결하지 않는다.

아래 표의 "1920 기준" 값에 0.667을 곱한 값이 1280x720에서의 실제 크기다.

### 2.3 상태 어휘와 모양 (모든 화면 공통)

| 건너뜀 | `건너뜀` + 사유(`시간 부족` `진행자 선택` `옵션` `선행 실패` `브라우저 없음`) | `SKIPPED` | 마름모 + 겹화살표 | `[건너뜀]` |

- 모양은 **인라인 SVG 또는 CSS 도형**으로 만든다(글꼴 의존 기호 금지 — 폐쇄망 PC 글꼴에 없을 수 있음). 장식 모양은 `aria-hidden="true"`이고 **글자 라벨이 항상 함께** 있다.
- 실패 종류 한글명: `PREFLIGHT` 사전 점검 · `BUILD` 빌드 · `BOOT` 서버 기동 · `DATA` 데이터 준비 · `ACTION` 화면 동작 · `TIMEOUT` 대기 시간 초과 · `VERIFY` 결과 불일치 · `SELECTOR` 화면 요소를 찾지 못함(선택자 갱신 필요) · `TEARDOWN` 정리.
- 전체 결과(보고서 머리): `PASSED` 모두 통과 · `FAILED` 일부 실패 · `ABORTED` 중단됨 · `PREPARE_FAILED` 준비 실패(공연 못 함).

|---|---|

| 일시정지 | 무대: 타이머 정지 + `잠시 멈춤` 칩. 일시정지 시간은 예산 계산에서 제외하고 보고서에 `일시정지 m:ss`로 따로 적는다 |

| 수치 정직성 | 시간·지연 수치 옆에는 항상 장비·일자·커밋(보고서 머리). 영업용 성능 주장 문구 금지(FR-0-317) |

### 2.5 문구 원칙 (쉬운 한국어)

- 고객 눈에 보이는 문구는 **짧은 문장 · 존댓말(~합니다/~입니다) · 전문 용어 풀어쓰기**: `임베딩` 대신 `문장 분석`, `폴백` 대신 `답하지 못함`, `거버넌스` 대신 `데이터 통제`, `마스킹` 대신 `가림`.
- 숫자 약어·기능 번호(`No.17`)는 고객 화면에서 **작은 보조 글자**로만 쓴다(진행자 대조용).
- 약속하지 않는다: `곧` `조만간` `출시 예정` `~보다 N배 빠르다` 같은 표현 금지(FR-DH10-2 · FR-0-317).
- 오류·경고는 **무엇이 · 왜 · 어떻게 고치나** 3요소(UIUX §7). 터미널(§9)과 보고서 실패 카드(§8.4)에 적용.

## 3. 무대 페이지 (`/stage`)

### 3.1 목적 · 진입 · 구성

- **목적**: 장면 전체를 한 장의 문서에서 진행해 **영상 1개 · 자막 1개**로 남긴다(설계 DHD-4). 고객은 이 화면만 본다.
- **진입**: 하네스가 Edge를 열면 `/stage#ready`가 먼저 열린다. 진행자가 엔터를 누르면 T0에 `ready`가 풀리고 장면이 시작된다. 끝나면 마무리 카드(`/system?phase=end`)에 머문다.

| 영역 | 1920x1080 | 1280x720 | 비고 |
|---|---|---|---|
| 상단 바 | 높이 80 · 좌우 패딩 32 | 53 | 진행 막대(높이 8)는 바 맨 아래에 붙음 |

| 레이아웃 | 구성(1920 / 1280) | 쓰는 구간 |
|---|---|---|
| `card` | 본문 영역 전체에 카드 1장(`/system` `/roadmap`)을 `iframe`이 아니라 **같은 문서의 콘텐츠로** 채움. **상단 바·자막 띠는 유지**(설계서의 "전체 화면" 표현을 "본문 영역 전체"로 정정 — §13 A-3) | 시작 · 마무리 |

**1280x720의 `split`(중요 — 제품 콘솔은 폭 1024px 미만에서 태블릿 배치로 바뀐다)**
- 제품 콘솔은 폭 **1024px 이상에서 데스크톱 배치**(`global.css` 분기 1024/640). 1280x720의 오른쪽 폭은 실제로 약 820px뿐이라 그대로 두면 장면마다 레이아웃이 달라진다.
- 따라서 1280x720의 `split`에서는 **관리자 화면 `iframe`의 논리 폭을 1024px로 고정하고 `transform: scale(0.8)`로 축소**해 오른쪽 칸(약 820)에 맞춘다. 고객 화면은 폭 400 고정(실제 약 400)이며 축소하지 않는다. `console` 레이아웃은 폭 1264 ≥ 1024라 **축소하지 않는다**.
- 이때 제품 콘솔 글자는 16px x 0.8 = **약 12.8px**로 보인다 — 제품 화면은 우리가 바꿀 수 없으므로 이는 §10.2의 조정 항목이다. **프로젝터 시연은 1920x1080을 권고**하고, 1280x720은 저해상도 프로젝터·리허설 캡처용이다.
- 1920x1080에서는 오른쪽 폭 1136 ≥ 1024라 **축소 없음**(`--u`만 1.0).
- `transform`이 걸린 `iframe` 안의 Playwright 클릭·`frameLocator`는 문제없다고 알려져 있으나 **이 PC에서 확인하지 못했다** → UX-3(§12)에서 설계서 §21.2 확인 6에 이어 확인한다.

## 4. 자막 띠

### 4.1 구성과 위치

- `<div data-demo-harness="caption" aria-hidden="true">`(설계서 §8.4) — 무대 최상위에 **한 번만** 두는 하네스 전용 요소. **본문과 겹치지 않는 하단 예약 행**(§3.1)이라 `position: absolute` 덮어쓰기가 아니다.
- 내부 3줄 고정 구조(위 -> 아래):
  1. **배지 줄**(0~2개): 구축형 강조점 배지(§4.4). 없으면 비움(높이 유지).
  2. **본문 줄**(1~2줄): 나레이션.
  3. **시연 안내 줄**(0~1줄): 정직성 문구. 왼쪽에 칩 `시연 안내`(테두리 `#fcd34d` · 글자 `#fcd34d` 28 / 19) + 문구(`#fcd34d`).
- 높이 188(1920) / 125(1280). 줄 수가 모자라도 높이는 고정.
- 영상에는 **번인**(화면 그대로 녹화)되고, 접근 가능한 텍스트 대안으로 **WebVTT 파일**을 따로 만든다(§4.5). `aria-hidden`은 무대가 사람이 조작·낭독하는 화면이 아니라 자동 진행 화면이라서이며, 대안(VTT · 보고서)이 있다(§10.2 조정 U-2).

### 4.3 표시 시간 · 상태 · VTT 동기화

**표시 시간 규칙**
- **읽기 시간 R = max(2.0초, 글자 수 x 0.12초)**(본문+안내 글자 합 · 80자면 9.6초).
- 자막은 **단계 시작 0.3초 뒤**(전환 완료 후) 나타나 **다음 자막이 나타날 때까지** 유지한다(빈 시간 없음). 단계 실제 소요 < R이면 **남은 읽기 시간만큼 화면을 유지**(dwell — 설계 §11.2의 최소 2초 보장을 R로 일반화).
- **정의 검사(추가)**: 모든 자막이 있는 단계에서 `R <= 단계 예산 - 1초`. 위반하면 문구를 줄이거나 예산을 늘린다(설계서 §9.1 정의 검사에 1항목 추가 — §13 A-1).
- 자막이 없는 단계(S3-01 API 단계 등)는 **직전 자막을 그대로 유지**한다.
- 일시정지 중에는 자막·R 타이머 모두 정지.

**자막 상태**

| 상태 | 표시 |
|---|---|
| 표시 중 | 3줄 구조(§4.1) |
| 자막 없음(대기·헤드리스·정리) | 빈 띠(배경 유지) |
| 일시정지 | 중앙 `잠시 멈춤 — 진행자가 설명하는 중입니다` |
| 대체 화면 · 실패 | 안내 줄에 고정 문구(§3.4). 본문 줄은 해당 단계 본문 대신 `fallback.caption` |
| 무인 점검 | **자막 주입 안 함**(설계 §8.4). 나레이션 로그만 |

**WebVTT 동기화**(`video/show.vtt`)
- 헤더 `WEBVTT` + `Kind: captions` + `Language: ko`. 큐 ID = 단계 ID. 시각은 **영상(녹화) 기준 실시간**(일시정지 시간 포함 — 영상은 멈추지 않고 계속 녹화되므로). 대기 화면(`#ready`)이 영상 앞부분에 들어가므로 **큐 시각 = 화면에 실제로 표시된 시각 - 녹화 시작 시각**으로 계산(설계 §15 "녹화 시작 지연 보정").
- 큐는 **겹치지 않고**, 각 큐 >= 2.0초, 큐 사이 간격 0(자막이 이어지므로). 일시정지는 `잠시 멈춤` 큐로 기록.
- 큐 텍스트 = 본문 줄 + (있으면) `[시연 안내] ` 접두 줄(ASCII 접두 — 플레이어 글꼴 의존 회피). 줄 수 <= 3.
- 구간 시작마다 `NOTE 장면 3/7 통계와 대시보드` 블록. 배지는 `NOTE 배지: 사내 설치, CPU 동작`으로 기록(영상에는 보이나 큐에는 안 넣음).
- 보고서의 `<video>`에서 영상에 이미 자막이 번인되어 있으므로 `<track kind="captions" srclang="ko">`는 **`default` 속성 없이** 붙인다(기본 켜면 자막이 겹쳐 두 번 보임 — 필요할 때 사용자가 켬).

## 5. 고객사 모형 홈페이지 '가온마켓' (`/site`)

### 5.1 목적 · 원칙

- **목적**: 위젯이 실제 고객사 홈페이지에 **한 줄 스니펫으로 임베드된 모습**을 보여 주는 가상 쇼핑몰. 무대 왼쪽 `iframe`에 들어간다(장면 1·2·5·6). 챗봇별로 `?bot=<slug>`만 다르다(A 고객센터 · B 운영 통제 데모).
- **가상임을 숨기지 않는다**: 페이지 최상단 고정 띠와 하단 푸터에 글자로 명시한다(§5.2). 실제 쇼핑몰로 보이게 꾸미지 않는다.
- **금지(FR-0-316 · NFR-DHS)**: 실제 기업·브랜드의 이름·로고·상징색·상품 사진·문구 모방 · 실제 사업자번호·주소·전화번호 · 개인정보(이름·이메일·계좌) · 외부 이미지·글꼴·스크립트 · 외부로 나가는 링크 · 자동 재생/자동 넘김(캐러셀 금지 — UIUX §3).
- 모형의 **상호작용 요소는 없다**(메뉴·상품은 글자일 뿐, 링크처럼 보이게 하지도 않는다 — 가짜 `href="#"` 금지). 챗봇 위젯만 상호작용 대상이다.

| **움직임** | 없음(자동 재생·슬라이드·마우스 오버 효과 없음). 선제 말풍선(No.35)은 데이터상 규칙 0개라 나타나지 않음 |

## 7. 시작 / 마무리 카드 (`/system`, `/system?phase=end`)

### 7.1 목적

- **시작 카드(S0-01, 15초)**: "이 PC 한 대에서 전부 · GPU 없이 CPU · 외부 송신 0 · 감사·보존" 구축형 구성을 **하네스가 확인한 사실**로 보인다. 말(주장)이 아니라 **확인 값**이 증거다.

|---|---|---|
| 확인됨 | 칩 `확인됨`(원형 체크) | `장치: cpu` |
| 확인 못함 | 칩 `확인 못함`(물음표 모양) + 이유 한 줄 | 네트워크 점검 시간 초과: `인터넷 연결을 확인하지 못했습니다` |
| 주의(조건 불일치) | 칩 `주의`(삼각형) + 사실 문구 | 네트워크 `열림`: `이번 시연은 인터넷이 연결된 상태입니다. 서버는 외부로 보내지 않도록 설정되어 있습니다` |
| 해당 없음/생략 | 칩 `이번에는 생략`(마름모) | 데이터 지도 단계가 시간 부족으로 생략되면 카드 4~6 설명줄만 남음 |
| 측정 실패 | 지연 수치 자리에 `측정하지 못했습니다` | ml-worker 실측 실패(EX-DH-4/5) |

- 카드 표시 값에 **빈 값이 생기지 않는다** — 값이 없으면 항상 `확인 못함` 계열 문구.
- **시연용 설정 알림 줄**(`바뀐 설정이 있을 때만`): 하단 점선 `시연 안내` 줄 — `이 노트북 CPU에 맞춰 문장 분석 대기 시간을 600ms로 늘렸습니다`(설계 §14). 값이 기본이면 줄 자체를 숨김(자리는 비움).
- 시작 카드 시간 예산: 15초 안에 읽도록 카드 3개의 값만 크게, 나머지는 보조. 읽기 R(§4.3)은 자막 기준이며 카드는 자막이 맡는 설명과 겹치지 않게 **카드 글자는 값 위주**로 간결하게.

### 7.4 마무리 요약 (`?phase=end`)

```
+---------------------------------------------------------------------------------+
|  마무리 · 오늘 확인하신 구축형 구성                                                |
+--------------------------+--------------------------+---------------------------+
| 사내에서 전부 동작        | CPU로 동작                | 서버는 외부로 보내지 않음   |
|  이번 시연: 장면 N개 통과  |  분석 장치 cpu            |  외부 주소 설정 0개         |
|  (건너뜀 K개, 대체 M개)   |  지연 P95 142ms           |  네트워크 차단됨            |
+--------------------------+--------------------------+---------------------------+
| 브라우저(화면) 쪽 참고:  시연 중 외부 주소로 나가려던 요청 2건을 막았습니다.        |
|  자세한 내용은 시연 보고서에 있습니다.                                              |  <- 건수 0이면 이 줄 숨김
+---------------------------------------------------------------------------------+
| 시연 보고서는 시연이 끝난 뒤 전달해 드립니다.                                       |
+---------------------------------------------------------------------------------+
```

- **브라우저 차단 건수 줄**(`browserBlockedRequests` 합계 > 0일 때만): `관리 화면이 외부 주소로 보내려던 요청 N건을 시연 도구가 막았습니다. 서버가 외부로 보낸 것은 없습니다.` — 호스트 이름은 무대에 쓰지 않고(고객 혼란 최소) 보고서에 싣는다. 설계 §12 "DHX-1 수정 전엔 서버는 외부로 보내지 않는다까지만 말한다"를 **글자 크기 동등**하게 같은 화면에 둔다(숨기지 않음). 이 줄을 무대에 보일지는 **PM 결정 사항**(§14 Q-U1, 기본안 = 보인다).
- 통과/건너뜀/대체 개수는 이 시점의 실제 집계(`result.json`의 `steps`)이며 **100%가 아니면 그대로 표시**(실패 단계 개수 포함 시 `보여 드리지 못한 장면 K개`).
- 진행자가 `q`를 누르면 `정리 중` 상태로 바뀐다(§3.4).

### 7.5 접근성

`<main>` + `h1` + 카드마다 `<section aria-labelledby>` · 정의 목록 `<dl>` · 대비 11:1 이상(밝은 카드 위 `#1f2937`) · 상태는 칩 글자+모양 · 색만으로 `확인됨`/`주의`를 구분하지 않음(§2.3) · 터치 요소 없음.

**G. 시연용 설정 공개표 · 단건 지연** — 표: `설정 이름 · 시연 값 · 기본값 · 바꾼 이유`(기본값과 다른 것만 + `AUGMENTATION_PROVIDER` 같은 명시 항목은 `기본과 같음`으로 표기). 단건 지연 실측: `표본 20 · P50 NNms · P95 NNms · 결정 값 300ms(실측)/수동 지정` + 장비·일자·커밋(FR-0-317). **측정이 여러 라운드였으면**(모델 적재 직후 P95 > 200ms면 최대 3라운드 재측정 — 설계 §14) 그 아래 작은 표 `라운드 · P50 · P95`를 모든 라운드에 대해 싣고 마지막 행에 `결정에 쓴 라운드` 글자를 붙인다(색 비의존). 1라운드로 끝났으면 표 없이 위 한 줄만. 표 캡션 `단건 지연 측정 라운드`. 영업용 성능 주장 금지 문구 한 줄.

**H. 외부 송신 점검표** — 설계 §13.2의 8칸을 그대로 표로: `칸 · 항목 · 상태 · 근거`. 상태 어휘 고정: `미설정`(원형 체크) · `루프백(이 PC 안)`(원형 체크) · `꺼짐` · `차단함(N건)`(삼각형) · `열림`(삼각형, 네트워크 칸) · `확인 못함`(물음표). 서버 칸과 **브라우저 칸을 분리**(서버 0건 / 브라우저 N건 호스트 목록). 브라우저 칸은 `fonts.googleapis.com ×N` 식으로 호스트·횟수·최초 단계 ID. 맨 아래 주의 한 줄 고정: `API는 같은 네트워크의 다른 PC에서도 접속할 수 있습니다(제품 동작) — 시연 PC의 네트워크를 차단하세요`. 고객판에도 포함(호스트 목록 포함 — 숨기지 않는 것이 기본안).

**I. 정직성 표기** — `honesty[]`를 종류별 소제목(`모형` · `미리 준비한 결과` · `시연용 설정` · `대체 화면` · `건너뜀` · `시연용 과거 데이터`) 아래 목록으로: `S7-02 · 미리 같은 파일로 실행해 둔 분석 결과를 보여 드렸습니다`. 종류가 비면 `해당 없음`(이 절은 항상 보인다). **모형 서버 0건**이면 `모형 서버를 쓰지 않았습니다`를 명시. 과거 데이터는 `시연용 과거 대화 기록 N건(그래프용)`.

**J. 개선 후보(내부판만)** — 설계 §21.3 `DHX-*` 중 이번 실행에서 **관측된 것**만(예: 브라우저 차단 기록에 Google Fonts -> `DHX-1 관리 콘솔 외부 글꼴 요청`) + `SELECTOR` 실패 단계 + `대체 화면` 발생 단계. 형식: ID · 한 줄 설명 · 근거 링크(단계 ID/점검표 칸) · `별도 결함으로 등록 필요`. 후보가 없으면 `이번 실행에서 관측된 개선 후보가 없습니다`.

**K. 로드맵** — §6.3과 같은 6행 표(`기능 · 상태 · 이유`) + 고정 문구 `출시 일정·성능을 약속하지 않습니다`.

**L. 부록 LLM** — 무인 점검 `--appendix-llm`일 때만: `동작 확인`(결과 문장 수·소요 시간). **품질·합격 판정 문구 금지**(FR-0-318). 없으면 절 숨김.

**M. 알려진 한계** — 설계서 §21.5 고정 문구 목록(브라우저 백그라운드 통신 감시 밖 · 화면 그리기 GPU 가능 · API 모든 인터페이스 바인드 · 스키마 밖 `process.env` 비밀의 `.env` 잔존 가능성 · HF 캐시 잠금 파일 · 준비 단계 보정이 감사 로그 2행·임베딩 캐시를 남김 · 시간 수치는 이 노트북 기준 추정·실측이며 영업 수치 아님) + `정직성: 연출·사전 준비는 §10에 모두 공개`.

- 4요소 라벨 **고정 문구**: `무엇이 실패했나` · `기대값 / 실제값` · `왜 그럴 수 있나`(실패 종류별 기본 원인 문장 — 모르면 `원인을 특정하지 못했습니다. 로그를 확인하세요`) · `어떻게 하나`.

- 로그 `<details open>`(실패 카드는 기본 펼침 — 접힌 `details`는 인쇄되지 않으므로). 로그 블록은 `max-height: 320px` + `overflow: auto` + `tabindex="0"` + `role="region"` + `aria-label` (키보드로 스크롤 가능). 비밀 값은 이미 제거됨(§17.3 `redact`).

### 8.7 다크/라이트

- `<meta name="color-scheme" content="light dark">` + CSS `color-scheme: light dark`. 기본 **자동**(OS 설정 `prefers-color-scheme`). 상단 라디오 `테마: 자동 / 밝게 / 어둡게`는 **스크립트 없이** `:has(input[value=...]:checked)` 선택자로 토큰 값을 바꾼다(라벨 필수 · 키보드 화살표 선택). 브라우저가 `:has`를 지원하지 않으면 라디오가 효과를 못 낸다 -> **자동(OS 설정)은 항상 동작**하므로 기능 손실은 없다(Edge 154는 지원, 폴백은 UX-5에서 확인).
- 두 테마 모두 **본문 4.5:1 이상**(실제 값은 §2.1 표 — 본문 14.7:1 / 다크 #f3f4f6 on #111827 약 16:1). 상태 칩은 테마별 색 쌍을 따로 정의(§2.1)하고 **글자·모양은 동일**.
- 이미지(캡처)는 테마와 무관하게 원본 그대로(밝은 제품 화면이 어두운 문서 위에 놓임 — 이미지 테두리 `1px #6b7280`로 윤곽 유지).

### 9.1 공통 규칙 (Windows PowerShell 5.1/7 · Git Bash · 한글 폭)

| 규칙 | 내용 |

| **시간** | `HH:mm:ss`(시각) · `m:ss`(구간 시간) — 무대·보고서와 같은 표기 |
| **줄 길이 · 소음** | 한 단계 = 한 줄 원칙. 상세는 `--verbose`. 경고·오류만 여러 줄 |
| **비밀** | 계정 비밀번호는 **준비 완료 요약에만 1회** 출력하고 그 외 어디에도(로그·보고서·재출력) 없음(NFR-DHS3). 요약 아래에 `화면 공유 전에 이 터미널을 가리세요` 안내 |
| **오류 3요소** | 모든 `[오류]`/`[주의]`는 `무엇이 / 왜 / 어떻게` 3줄(UIUX §7) — §9.5 |

- 단계 줄 형식: `[n/6] 이름 ...(점선으로 폭 채움)... 상태 (소요)` — 상태 어휘 `완료` `진행` `대기` `생략` `실패`(대괄호 아님, 줄 끝 글자) · 하위 결과 줄은 들여쓰기 + `[통과]`/`[주의]`/`[오류]`.
- **긴 대기(이력 예약 약 6분)** 안내: `남은 시간 약 m분 s초 (추정)` 한 줄을 TTY는 **같은 줄을 갱신**, 비TTY는 **15초마다 새 줄**. 상한 시간을 같이 적는다(`상한 5분 후 경고`) — 무한 대기 인상 금지(UIUX §8 비동기 대기).
- 준비 총 소요 예상은 시작 시 한 줄(`준비에는 약 6분이 걸립니다 — 고객 도착 전에 시작하세요`).

### 9.4 공연 중 표시 (보이는 시연)

진행자 시선용이라 **짧게 · 안정적 위치**. TTY는 상태 영역을 제자리 갱신, 비TTY는 변화가 있을 때만 새 줄.

```
 장면 3/7 통계와 대시보드    단계 S3-02 대시보드  [진행]
 남은 시간 05:42   경과 04:18   일시정지 00:00   일정 정상
 다음: S3-03 응답 출처 분포 (15초)    건너뛸 수 있는 단계: S3-04
 키: Enter 없음 | Space 일시정지  n 건너뛰기  s 다음 장면  q 종료
--------------------------------------------------------------------------
14:36:02 [통과]  S3-01 반영 확인 (00:04)
14:36:24 [지연]  S3-02 대시보드 예산 00:20 -> 00:26 (+00:06)
14:36:24 [건너뜀] S3-04 통합 통계 · 시간 부족으로 자동 생략
14:36:40 [주의]  S5 예약 실행까지 남은 시간 약 1분 40초
```

- 상단 4줄(고정 영역) + 구분선 + 이벤트 로그(최근 10줄, 시각 접두).
- **상태 줄 문구**: `일정 정상` / `일정 지연 +0:08` / `일정 지연 +0:25 · 자동 생략 N개` / `일시정지 중` / `예정 시간 초과 +0:12`. **색 없이** 글자로 구분.
- **남은 시간 경고(`[주의]`)**: ① 누적 지연 20초 이상 최초 1회 ② 핵심 단계만 남아 더 줄일 수 없음 ③ 예약 실행(C-2) 임박 ④ 총 남은 시간 60초 / 30초 시점 ⑤ 일시정지 5분 초과(`계속 멈춰 있습니다`). 같은 경고를 반복하지 않는다(한 번만).
- **키 안내 줄**은 항상 상단에 보여(진행자가 외우지 않아도 됨) 모드에 따라 키/줄 명령 문구로 바뀐다. 핵심 단계에서 `n`을 눌렀을 때: `[정보] 핵심 장면은 건너뛸 수 없습니다 (S3-02)` 1줄(무시).
- **엔터 대기 외의 확인**: `q` 누르면 `[확인] 시연을 종료하고 정리할까요? y = 종료 / 그 외 = 계속` 한 줄 -> `y`면 정리 시작(종료 코드 130).
- **종료 직전**(마무리 화면 유지 중): `시연이 끝났습니다. q를 누르면 정리하고 보고서 폴더를 엽니다.`
