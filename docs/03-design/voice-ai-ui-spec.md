## 3. 콘솔 화면별 설계

## 3.1 VO-C1 — 음성 섹션 진입점 (WEB `ChannelCard` 안)

### 목적
관리자가 채널 탭에서 WEB 카드를 열면 음성 기능이 있다는 것을 알고, 켜져 있는지 한눈에 보고 펼칠 수 있다.

### 배치
`ChannelCard.tsx`의 `channel-card-actions` 줄에 **새 버튼 1개**(WEB 타입일 때만) — 기존 "선제 안내"·"설정 열기"·"삽입 코드"와 나란히:

```
[설정 열기] [선제 안내] [음성] [삽입 코드] [삭제]
                         └ 요약 배지: "입력 꺼짐 · 듣기 꺼짐"
```

- 버튼 이름은 `음성`(펼치면 `음성 닫기`) · `aria-expanded` · **펼침 상태는 선제 안내·웹 채널 설정 폼과 독립**(셋 다 동시에 펼 수 있다).
- 최초 펼침 시 `voiceApi.getOverview(chatbotId)` 1회 호출(캐시 없음).

### 상태별 UI

| 상태 | UI |
|---|---|
| 로딩(최초 펼침 직후) | 서버 상태 자리 `SkeletonRow` 1 + 설정 자리 `SkeletonCard` 1 + 숫자 표 자리 `SkeletonRow` 3 |
| 조회 실패 | `ErrorState`(재시도 버튼) — 카드의 다른 영역은 정상 동작 |
| 행 없음(설정을 한 번도 저장하지 않음) | **오류·빈 상태가 아니다** — 기본값(전부 꺼짐 · 속도 1.00 · 기본 말투 차분함 · 미응답 말투 사과 · 자동 읽기 토글 노출 켜짐 · 노드 지정 0)이 채워진 폼을 그대로 보인다. `updatedAt = null`이면 "아직 저장한 적이 없습니다" 한 줄 |
| 성공 | §3.2~§3.7 |
| `channel:read`만 있는 사용자 | 폼은 보이되 스위치·속도·말투·노드 추가/삭제·**저장**이 전부 `aria-disabled` + 이유("편집 권한이 없습니다") · 들어보기·숫자 조회는 가능 |
| 보관됨(`ARCHIVED`) | 섹션 전체 읽기 전용(편집 버튼 숨김 — 기존 `isArchived` 규약) |
| 웹 채널 꺼짐 · 챗봇 비공개(`context`) | 배너 §3.2 ③ |

## 3.2 VO-C2 — 상태 배너 묶음 (섹션 상단)

위에서 아래 순서로 **해당하는 것만** 쌓는다. 각 배너는 아이콘(`aria-hidden`) + 굵은 제목 + 설명 + (필요 시) 해결 방법. 섹션이 열릴 때 1회 렌더되며 `aria-live`로 낭독하지 않는다(정적 정보).

### ① 서버 음성 인식 상태 (`VoiceServerStatus` — `enabled` · `provider` · `inputAvailable` · `reason?`)

| 조건 | 배너(색+텍스트) | 문구 |
|---|---|---|
| `inputAvailable = true` ∧ `provider = local` | 성공 "● 사용 가능" | "음성 인식 서버를 사용할 수 있습니다." |
| `inputAvailable = true` ∧ `provider = mock` | 주의 "⚠ 모의 인식" | "시험용 모의 인식으로 동작 중입니다. 실제 음성 인식이 아니며 고정된 결과가 나옵니다. 방문자에게 공개하는 챗봇에서는 켜지 마세요. (운영 환경에서는 이 상태로 서버가 시작되지 않습니다.)" |
| `reason = SERVER_DISABLED` | 중립 "○ 꺼짐" | "서버에서 음성 인식이 꺼져 있습니다. 켜기 전에는 음성 입력을 쓸 수 없습니다. 답변 듣기는 영향을 받지 않습니다." |
| `reason = NOT_CONFIGURED` | 주의 "⚠ 설정 필요" | "음성 인식 서버 주소가 설정되지 않았습니다. 서버 관리자에게 설정을 요청하세요. 답변 듣기는 영향을 받지 않습니다." |
| `reason = PROVIDER_UNAVAILABLE` | 주의 "⚠ 사용 불가" | "음성 인식 서버가 지금 사용할 수 없는 상태입니다. 서버가 꺼져 있거나 응답이 없는 경우, 또는 운영 환경에서 시험용 구성으로 실행 중인 경우입니다. 서버 관리자에게 확인을 요청하세요. 답변 듣기는 영향을 받지 않습니다." |

- **원인을 더 쪼개 보여 주지 않는다**(설계 DD-135 ③ · `VoiceServerStatusSchema` — 운영 mock 차단도 `PROVIDER_UNAVAILABLE`로 수렴, 세부는 서버 경고 로그) · 모델 이름·장치·주소는 어떤 배너에도 싣지 않는다(§12 F-5).
- **음성 입력이 이미 켜져 있는데 서버가 사용 불가**이면 위 배너 아래 한 줄을 더한다: "이 챗봇의 음성 입력은 켜져 있지만 서버 상태 때문에 방문자 화면에 말하기 버튼이 나타나지 않습니다."

### ② 개통 전 법무 확인 경고 (`VoiceLegalNotice` — 상시 · 닫기 없음)

> "⚠ 법무 확인 전입니다. 음성 처리 첫 사용 안내 문구와 음성 원본의 법적 성격은 법무 확인이 끝나기 전이라 방문자 화면에 안내 문구가 나오지 않습니다. 고객 서비스에서 음성 입력을 켜기 전에 개통 전 점검표(법무 확인 2건 포함)를 완료하세요."

- 위치: 서버 상태 배너 바로 아래 **그리고** 음성 입력 스위치 설명 안에서 한 번 더 `aria-describedby`로 연결한다(§3.3).
- 코드로 켜기를 막지 않는다(DD-133 · K-13 — 운영 절차 게이트). 이 경고는 **정보 전달 수단**이지 확인 체크박스·차단 장치가 아니다(가짜 게이트를 만들지 않는다).
- 점검표 출처 표기: "개통 전 점검표: 운영 문서(`자동배포.md` §5.8 · 설계서 §17.5 OC-1~OC-8)" — 링크가 아니라 **이름만** 적는다(문서가 콘솔 밖에 있다).

### ③ 맥락 배너 (`context`)

| 조건 | 문구 |
|---|---|
| `webChannelEnabled = false` | "이 챗봇은 웹 채널이 꺼져 있어 방문자에게 표시되지 않습니다." |
| `chatbotStatus`가 공개 아님 | "챗봇이 공개되지 않아 방문자에게 표시되지 않습니다." |
| WEB 런처 숨김 상태는 이 화면에서 다루지 않는다 | (음성은 대화 창 안 기능이라 런처와 무관) |

## 3.4 VO-C4 — 말투 설정

### 레이아웃

```
── 말투 ──
기본 말투 *  (답변하는 대부분의 경우에 적용됩니다)
  (●) 차분함   조금 천천히, 조금 낮게 읽습니다
  ( ) 밝게     조금 빠르게, 조금 높게 읽습니다
  ( ) 사과     천천히, 낮고 조금 작게 읽습니다
  ( ) 안내     기기 기본 빠르기와 높낮이로 읽습니다

미응답(폴백) 안내 말투 *  (챗봇이 답을 찾지 못했을 때의 안내에 적용됩니다)
  ( ) 차분함  ( ) 밝게  (●) 사과 (기본)  ( ) 안내

ⓘ 안전 문구로 대체된 답변은 항상 "차분함"으로 읽으며 바꿀 수 없습니다.
ⓘ 말투는 글자 내용을 바꾸지 않고 빠르기·높낮이·크기만 조금 바꿉니다.
   기기 음성에 따라 높낮이·크기가 반영되지 않을 수 있습니다.
```

- 라디오 그룹 2개는 각각 `fieldset/legend`(UIUX §6 단일 선택 = 라디오). 필수 표시 `*`. 기본 선택값(기본 말투 = 차분함 · 미응답 말투 = 사과)은 **서버 내장 기본값**을 보인 것이며 항목 옆에 "(기본)"을 병기한다.
- 지정 가능한 응답 종류는 **미응답 1종뿐**이다(설계 §4.1 `VoiceToneByKindSchema` strict — `BLOCKED`·`ERROR` 등은 H-3으로 삭제). 금지어 안내·일시 장애·답변 대기는 읽지 않으므로 말투 항목을 만들지 않는다.
- 우선순위 안내(접이식 "말투가 정해지는 순서" — 기본은 닫힘, `aria-expanded`): ① 안전 문구 대체 = 차분함(고정) ② 노드별 지정 ③ 미응답 말투 ④ 기본 말투.

### 3.4.1 말투 안내 표 (읽기 전용 — `VoiceToneGuideTable`)

각 라디오 설명의 한 줄은 아래 표의 "느낌" 열을 그대로 쓴다(표는 접이식 "말투 값 보기"로 두고 기본은 닫는다 — 관리자 대부분에게 숫자는 불필요하다).

| 이름(식별자) | 느낌(화면 설명) | rate | pitch | volume | 상태 |
|---|---|---|---|---|---|
| 차분함(`CALM`) | 조금 천천히, 조금 낮게 | 0.95 | 0.95 | 1.0 | **제안값 — 실제 기기 청취 후 확정** |
| 밝게(`BRIGHT`) | 조금 빠르게, 조금 높게 | 1.05 | 1.10 | 1.0 | **제안값 — 실제 기기 청취 후 확정** |
| 사과(`APOLOGETIC`) | 천천히, 낮고 조금 작게 | 0.90 | 0.90 | 0.9 | **제안값 — 실제 기기 청취 후 확정** |
| 안내(`INFORMATIVE`) | 기기 기본값 그대로 | 1.00 | 1.00 | 1.0 | **제안값 — 실제 기기 청취 후 확정** |

- 값의 출처는 설계서 §4.2 `SPEECH_TONE_PARAMS`(초안) · 요구사항 §1.7 표다. 이 문서는 **소리를 들어 보지 않았으므로 확정하지 않았다**. 확정 절차와 책임은 §15 U-1.
- **표는 코드의 `SPEECH_TONE_PARAMS`를 그대로 읽어 렌더한다**(화면 문구에 숫자를 따로 적지 않는다 — 값이 바뀌어도 표가 어긋나지 않게). 단 "느낌" 열 문구는 사람이 쓴 것이라 **값을 확정·변경할 때 함께 재검토한다**(§15 U-1 체크리스트).
- 표 머리 아래 상시 문구: "제안값입니다. 실제 기기에서 들어 보고 확정하기 전까지 바뀔 수 있습니다."
- 실제로 적용되는 속도는 **말투 rate × 읽기 속도 배율**이며 안전 구간(rate 0.7~1.3 · pitch 0.8~1.2 · volume 0.8~1.0)으로 제한된다 — 표 아래 한 줄로 알린다.

## 3.5 VO-C5 — 노드별 말투 지정

### 목적

### 레이아웃

```
── 노드별 말투 (0/200) ──
ⓘ 지정한 노드가 답으로 나갈 때 그 말투를 씁니다. 안전 문구로 대체된 답변에는 적용되지 않습니다.
ⓘ 대화 이동으로 거쳐 가는 노드가 아니라 마지막으로 답이 된 노드에만 적용됩니다.
ⓘ 이 지정은 버전 기록·운영 전환 대상이 아닙니다. 저장하면 곧바로 반영되며 버전을 복원해도 돌아가지 않습니다.

노드 선택 [노드 이름 검색 ▾________]  말투 [밝게 ▾]  [추가]

노드                 말투        상태                      
인사                 [밝게 ▾]    —                         [삭제]
환불 안내 (삭제됨)    [안내 ▾]    ⚠ 노드를 찾을 수 없음 — 적용되지 않음   [삭제]
```

### 컴포넌트·바인딩

| 요소 | 규칙 |
|---|---|
| 노드 선택 | `ResourcePickerField`(검색형) — 이 챗봇의 **초안 노드**만 · 이미 지정한 노드는 후보에서 제외 · 노드 이름은 조회 시점 이름(`nodeName`) |
| 말투 | `<select>` 4옵션(`SPEECH_TONES` 순서 — 차분함·밝게·사과·안내) · 행마다 레이블 "{노드 이름} 말투"(시각적으로는 열 머리, 스크린리더용 `aria-label`) |
| 추가 | "추가" 버튼(노드 미선택이면 `aria-disabled` + 이유) · 200개 도달 시 `aria-disabled` + "노드별 말투는 최대 200개까지 지정할 수 있습니다." |
| 삭제 | 행마다 "삭제" 버튼 — 확인 창 없이 목록에서 제거(**저장 전까지 서버에 반영되지 않는다** — 전체 교체 PUT이므로 저장 버튼이 확정 지점) · 삭제 후 포커스는 다음 행의 삭제 버튼, 없으면 "노드 선택" 필드 |
| 없는 노드(`nodeMissing`) | `VoiceNodeMissingBadge` + 행 유지(자동 삭제하지 않는다 — 설계 §10.1: 노드 삭제는 막지 않고 런타임이 무시) |
| 빈 상태 | "지정한 노드가 없습니다. 모든 답은 기본 말투(또는 미응답 말투)로 읽힙니다." |

### 오류 매핑

| 오류 | 표시 |
|---|---|
| 저장 시 `400 INVALID_REFERENCE`(다른 챗봇·없는 노드 id) | 해당 행에 인라인 "이 챗봇의 노드가 아닙니다. 노드를 다시 선택하세요." + 첫 오류 행으로 포커스 이동 |

## 3.6 VO-C6 — 들어보기

### 목적
관리자가 입력한 문장을 고른 말투·읽기 속도로 **자기 브라우저의 기기 안 한국어 음성**으로 재생해 본다. **서버 호출 0 · 감사 0 · 입력 문장 저장 0**(FR-VO5-3 · AC-VO4-3). 방문자 기기에서는 다르게 들릴 수 있다는 점을 숨기지 않는다.

### 레이아웃

```
── 들어보기 ──
ⓘ 이 브라우저에서 재생합니다. 입력한 문장은 서버로 보내지 않으며 저장되지 않습니다.
ⓘ 방문자 기기마다 목소리가 다르고, 말투는 빠르기·높낮이·크기만 바뀝니다.
이 브라우저에서 쓸 수 있는 기기 안 한국어 음성: 2개

들어볼 문장 (최대 200자) *
[안녕하세요. 무엇을 도와드릴까요?                         ]  남은 글자 187자
말투  (●) 차분함  ( ) 밝게  ( ) 사과  ( ) 안내
읽기 속도: 위 폼의 값(1.00배)을 씁니다. (저장하지 않은 값도 반영됩니다)

[▶ 들어보기]     (재생 중이면 [■ 멈추기])
(읽기 불가 시) ⓘ 이 브라우저에는 기기 안 한국어 음성이 없어 들어볼 수 없습니다. ...
```

### 상태별 UI

| 상태 | UI |
|---|---|
| 음성 목록 확인 중(최대 2초 — `SPEECH_LIMITS.voicesWaitMs`) | "기기 음성을 확인하고 있습니다…" · 버튼 `aria-disabled` |
| 사용 가능(N ≥ 1) | "이 브라우저에서 쓸 수 있는 기기 안 한국어 음성: N개"(`isLocalKoreanVoice` 개수 — 정보 표시만 · FR-VO5-4) · 버튼 활성 |
| 사용 불가(N = 0 또는 `speechSynthesis` 없음) | 개수 "0개" + 버튼 `aria-disabled` + 이유 "이 브라우저에는 기기 안 한국어 음성이 없어 들어볼 수 없습니다. 온라인 음성(글자를 외부로 보내는 음성)은 쓰지 않습니다. 다른 브라우저나 기기에서 확인하세요." |
| 재생 중 | 버튼 텍스트 `들어보기 → 멈추기`(같은 노드 · `aria-pressed` 쓰지 않고 이름 변경) · 끝나면 자동 복귀 |
| 재생 오류 | 버튼 아래 인라인 "재생하지 못했습니다. 다시 시도하세요."(재시도 자동 반복 0) |
| 문장이 비어 있음 | 버튼 `aria-disabled` + 이유 "들어볼 문장을 입력하세요." |
| 문장 200자 초과 | 입력 `maxLength`로 막고 남은 글자 상시(§5 규칙) |

### 규칙

- 재생 인자는 위젯과 **같은 함수**로 만든다: `computeUtteranceParams(선택한 말투, 폼의 현재 읽기 속도)` · `selectLocalKoreanVoice()` · `splitForSpeech()` · `lang` = 선택 음성의 `lang`.
- 말투를 바꾸면 재생 중인 소리는 즉시 멈추고(`cancel()`) 다시 누르게 한다(자동 재생 금지 — 조작 없이 소리가 나지 않는다).
- 섹션을 접거나 화면을 떠나면 재생을 멈춘다(`cancel()`).
- **이 영역은 `fetch`·`XMLHttpRequest`·`sendBeacon`·스토리지 기록을 하지 않는다**(정적 검사 대상 — 위젯 VO-9와 같은 원칙을 콘솔 들어보기에도 적용하도록 test-automation에 제안).
- 첫 재생 전에 소리가 나는 것을 알리는 문구는 두지 않는다 — 버튼을 누른 사용자의 명시 조작이므로 별도 확인 창은 불필요하다.

## 3.7 VO-C7 — 일별 인식 숫자

### 목적
음성 입력이 실제로 쓰이는지, 실패·혼잡이 늘지 않는지 숫자로 본다. **목소리·글자·세션은 저장하지 않고 일별 건수만 센다**(P-15). 읽기(듣기) 횟수는 집계하지 않는다(FR-VO3-9).

### 레이아웃

```
── 인식 숫자 ──
기간 [시작 2026-09-25] ~ [끝 2026-10-01]  [조회]   (기본 최근 7일 · 최대 90일)
ⓘ 숫자만 기록합니다. 목소리와 인식된 글자는 저장하지 않습니다. 답변 듣기 횟수는 집계하지 않습니다.

날짜        요청   성공   말소리 없음   형식 오류   실패   혼잡
2026-10-01   42     37       3          1        1     0
...
합계        310    280      15          6        5     4
요청 = 성공 + 말소리 없음 + 형식 오류 + 실패 + 혼잡. 시각은 한국 시간(KST) 기준입니다.
ⓘ 혼잡·형식 오류가 평소보다 갑자기 늘면 서버 관리자에게 알려 주세요.
```

### 컴포넌트·바인딩

| 요소 | 데이터(`VoiceStatsResponse`) | 규칙 |
|---|---|---|
| 기간 입력 | `from`·`to`(`type="date"`) | 기본 최근 7일 · 90일 초과·시작>끝이면 인라인 오류 "기간은 최대 90일이며 시작일이 끝일보다 앞서야 합니다." · 조회 버튼을 눌렀을 때만 요청(입력 중 자동 조회 없음) |
| 표 | `daily[]`(0인 날도 채워져 옴) | 열 머리 `<th scope="col">` · 정렬 기능 없음(날짜 오름/내림 고정 최신 위) · 숫자는 오른쪽 정렬 · **그래프 없음**(표가 원천 — UIUX §8의 "그래프 단독 금지"를 구조로 회피하고 새 번들을 늘리지 않는다 · 필요하면 §15 U-5) |

| 열 설명 | — | 각 열 머리에 짧은 설명 툴팁이 아니라 **표 아래 상시 설명 목록**(툴팁은 터치·스크린리더 접근성이 나쁘다): 성공=글자로 바꾼 횟수 · 말소리 없음=무음이라 글자가 없던 횟수 · 형식 오류=읽을 수 없거나 너무 긴 녹음 · 실패=서버 오류·시간 초과 · 혼잡=동시 처리 한도 초과로 거절 |

## 3.8 VO-C8 — 데이터 지도: 음성 카드 · 출구 행 (`/settings/data-governance/map`)

### 목적
`security:read` 사용자가 **음성 원본이 어디로 가고 무엇이 저장되지 않는지**를 지도에서 확인한다(FR-VO6-2 · AC-VO4-5). 콘솔에서 바꿀 수 있는 값은 없다.

### 표시 조건
- **음성 카드**: 지도 응답에 선택 키 `speech`가 있을 때만(서버 음성 인식이 켜져 있거나 음성 입력·듣기를 켠 챗봇이 1곳 이상일 때) — 기본 설치의 지도 화면은 바뀌지 않는다.
- **출구 표의 음성 행**: `exits[]`에 `SPEECH_LOCAL`이 있을 때만(서버 음성 인식 켜짐 ∧ 공급자 `local`).
- 출구 표 제목의 숫자는 **응답 행 수로 계산**한다(하드코딩 "출구 5종" 금지 — C-7).

### 레이아웃

```
├─ 음성(눌러서 말하기 · 답변 듣기) ───────────────────────────────┤
│ 서버 음성 인식: 켜짐 · 방식: 사내 음성 인식(local)                   │   ← provider=mock이면 "모의 인식(실제 인식 아님)" ⚠
│ 음성 입력을 켠 챗봇 3개 · 답변 듣기를 켠 챗봇 5개                     │
│ 음성 원본: 저장 0 · 디스크 기록 0 · 사내 음성 인식 프로세스로만 전송 · 가림 불가 │
│ 인식된 글자: 사용자가 전송할 때만 대화 기록으로 저장(기존 마스킹 적용)    │
│ 답변 읽기: 사용자 기기 안에서 처리(기기 안 음성만) · 서버 전송 0         │
│ 기록하는 숫자: 챗봇·일별 인식 횟수만                                  │
│ ⓘ 음성은 개인정보를 가릴 수 없어 저장하지 않는 것이 유일한 보호 수단입니다.│
└──────────────────────────────────────────────────────────────┘

외부 전송(출구 N종 + 레거시 연결)
출구            대상 호스트        송신 데이터      마스킹  판정   차단(24h)
음성 인식(ml-worker)  ml-worker.internal  음성 원본(⚠가림 불가)  안 함  ● 허용   0
⚠ 음성 인식: 음성 원본이 음성 인식 프로세스(허용 호스트 ml-worker.internal)로 전송됩니다. 저장하지 않습니다.
```

### 필드 바인딩(`speech?` → 화면)

| 응답 필드 | 화면 |
|---|---|
| `serverEnabled` · `provider` | "서버 음성 인식: 켜짐/꺼짐 · 방식: 사내 음성 인식(local) / 모의 인식(실제 인식 아님)" — `mock`은 주의색+텍스트 |
| `chatbotsInputEnabled` · `chatbotsTtsEnabled` | "음성 입력을 켠 챗봇 N개 · 답변 듣기를 켠 챗봇 M개" |

모바일(≤768px): 카드 세로 스택 · 출구 표는 카드 리스트(기존 선례).

## 4.2 VO-W1 — 말하기 버튼 · 상태 줄 · 인식 중

### 목적
눌러서 말하고(최대 30초) 인식된 글자를 **입력창에 채워** 사용자가 확인·수정한 뒤 직접 전송하게 한다. 자동 전송은 없다.

### 레이아웃(데스크톱 패널 하단)

```
┌─ 입력 영역 ─────────────────────────────────────────────┐
│ ● 듣고 있어요 · 남은 시간 28초                    [취소]    │  ← 상태 줄(녹음·인식·오류 때만 보임)
│ 메시지를 입력하세요(레이블)                                 │
│ [카드 분실 신고는 어떻게 해요_________________________]     │  ← textarea#cb-input
│ 남은 글자 972자                                           │
│ [말하기 끝내기]                              [전송]        │  ← 마이크 · 전송(둘 다 44px 이상)
└────────────────────────────────────────────────────────┘
```

- 탭 순서: 입력창 → **말하기** → (상태 줄이 보일 때 **취소**는 말하기 앞이 아니라 상태 줄이 DOM상 입력창 앞이므로 입력창 앞) → 전송. 취소 버튼이 입력창 앞에 놓이는 것이 어색하지 않도록 **상태 줄은 입력 폼 맨 위**에 두고 그 안에 취소 버튼을 둔다(녹음 중에 가장 먼저 Tab이 닿는 곳 = 취소).
- 마이크 버튼과 전송 버튼은 같은 줄, 좁은 폭에서는 두 버튼이 각각 줄 너비의 절반을 쓰는 2열(§10).
- 마이크 버튼 설명(`aria-describedby`, `.cb-sr-only`): "눌러서 말하면 글자로 바꿔 입력창에 넣어 줘요. 최대 30초까지 말할 수 있어요."

### 4.2.1 녹음 상태기계(UI 관점 — 로직은 설계서 §9.3 `core/speech-capture.ts`)

| 상태 | 말하기 버튼 | 상태 줄 | 취소 버튼 | 입력창·전송 |
|---|---|---|---|---|
| **IDLE(대기)** | 활성 · 텍스트 "말하기" | 비움(숨김) | 없음 | 정상 |
| **REQUESTING(마이크 준비)** | `aria-disabled` · "마이크 준비 중…" | "마이크를 준비하고 있어요" | 없음 | 정상 |
| **RECORDING(녹음 중)** | **활성** · "말하기 끝내기"(누르면 종료 → UPLOADING) · 시각적으로 구분(진한 테두리 + 채움 + `●`) | "● 듣고 있어요 · 남은 시간 N초"(매초 글자만 갱신 — 라이브 영역 아님) | **보임**("취소" — Esc와 동일 · 터치용) | 입력창 정상 입력 가능 · 전송은 정상 · 듣기 버튼 `aria-disabled` |
| **UPLOADING(인식 중)** | `aria-disabled` · "글자로 바꾸는 중…" | "글자로 바꾸는 중이에요" + 진행 표시(회전 또는 `…`) | **보임**("취소" — 요청 중단 · 결과 버림) | 정상 |
| **FAILED(실패 — 복구 가능 · `503 SPEECH_UNAVAILABLE`·`503 SPEECH_BUSY`·시간 초과 포함)** | 활성 · "다시 말하기" | 오류 문구(§8) — **자동으로 사라지지 않음**(다음 조작 또는 입력 시작까지 유지) | 없음 | 정상 |
| **BLOCKED(권한 거부 · 사이트 정책 막힘 — 이 페이지에서 재시도 불가)** | `aria-disabled` · "말하기" | 이유 문구 상시(§8) | 없음 | 정상 |
| **(마이크 제거)** — **`403`만**(위젯 분류 `DISABLED` · `ORIGIN_NOT_ALLOWED`) — `503 SPEECH_UNAVAILABLE`은 제거하지 않고 FAILED(2026-10-01 구현 반영) | 버튼 DOM 제거 · **포커스가 버튼에 있었으면 입력창으로 이동** | 안내 문구 유지 | 없음 | 정상 |

- **글자 + 아이콘 + 라이브**(FR-VO1-3): 녹음 중은 `●`(aria-hidden) + 글자 + 버튼 형태 변화 3가지로 동시에 알린다 — 색만으로 구분하지 않는다. 라이브 안내는 `#cb-status`(polite)로 **시작 1회 · 남은 10초 1회 · 종료/결과 1회**만 낭독한다(매초 낭독 금지 — 상태 줄 글자는 라이브 영역이 아님).
- 인식 결과 반영: UPLOADING → 성공 시 입력창 **기존 글자 뒤에 공백 1개 + 인식 글자를 이어 붙이고**(덮어쓰기 없음) 포커스를 입력창 끝으로 옮긴다 → IDLE. 상태 줄에 "글자로 바꿨어요. 내용을 확인하고 고친 뒤 전송해 주세요."를 표시하고 같은 문구를 `#cb-status`로 1회 낭독한다. **전송은 사용자가 직접**(Enter 또는 전송 버튼).
- 글자가 길어 1,000자를 넘으면 남은 글자 영역(`#cb-remaining`)이 **"N자 초과 · 줄여 주세요"**(문구 제안 — 코드 리뷰 L-5 · §8.1 `over(n)`)로 바뀌고 전송이 `aria-disabled`가 된다(음수 표시 대신 — 위젯 공통 입력창 규칙이며 음성 전용 UI는 추가 0).
- 무음(`empty`): 입력창은 그대로, 상태 줄 "말소리가 들리지 않았어요. 다시 말씀해 주세요." → **FAILED와 같은 형태**(버튼 "다시 말하기") · 포커스는 말하기 버튼.
- 자동 종료 안내: 30초 도달 또는 녹음 용량 상한(1MB) 도달 시 UPLOADING으로 넘어가며 상태 줄 첫 문구에 "30초가 되어 녹음을 마쳤어요."(또는 용량 문구)를 한 번 붙였다가 "글자로 바꾸는 중이에요"로 바뀐다.
- **포커스 규칙**: 말하기 버튼을 눌러 시작 → 포커스는 **말하기 버튼에 그대로**(이름만 "말하기 끝내기"로 바뀐다 — 같은 노드). 취소·종료·실패 후 포커스 = 말하기 버튼. 성공 후 = 입력창. 버튼이 제거되는 경우 = 입력창. 포커스를 잃어 `body`로 가는 경우가 없어야 한다.
- 중복 실행 방지(UIUX §4): REQUESTING·UPLOADING 동안 말하기 버튼을 눌러도 아무 일도 없고(`aria-disabled`), 같은 틱의 연타는 상태기계가 무시한다.

### 4.2.2 키보드·터치 종료 수단 요약

| 동작 | 마우스·터치 | 키보드 |
|---|---|---|
| 시작 | 말하기 | 말하기에 Tab → Enter/Space |
| 종료(인식으로) | 말하기 끝내기 | 같은 버튼 Enter/Space |
| 취소(버림) | 상태 줄의 **취소**(휴대폰엔 Esc가 없으므로 필수) | **Esc**(아래 규칙) 또는 취소에 Tab → Enter |
| 인식 중 취소 | 상태 줄의 취소 | Esc 또는 취소 |

### 4.2.3 Esc 규칙 — 패널 닫기와의 우선순위 (§12 F-1)

- **RECORDING·UPLOADING·REQUESTING 중에는 Esc가 음성만 취소**하고 패널은 **닫히지 않는다**(`stopPropagation` — 패널의 Esc 닫기 처리보다 먼저 동작해야 한다: 패널 루트에 캡처 단계 `keydown` 리스너를 두거나 `panel.ts` 핸들러에 조건을 추가 — 방식은 frontend-implementer). **[구현 확정]** `panel.ts`의 `setEscapeGuard(fn)` — 기존 `keydown` 핸들러가 Esc에서 가드가 참이면 닫기를 건너뛴다(새 캡처 리스너 0 · 가드는 마이크가 조립될 때만 설정 → 음성이 꺼진 위젯의 Esc 동작 불변). 취소 직후 `#cb-status`로 "녹음을 취소했어요."를 1회 낭독하고 포커스는 말하기 버튼.
- 그 밖의 상태(IDLE·FAILED·BLOCKED)에서 Esc는 지금처럼 패널을 닫는다.
- 패널을 닫으면(버튼·Esc·런처) 녹음·인식은 **조용히 취소**된다(마이크 트랙 즉시 닫힘 · 요청 중단 · 결과 버림 — EX-VO-11).
- 탭이 숨겨지거나 화면이 꺼지면 녹음 중이던 것은 취소되고, 돌아왔을 때 상태 줄에 "녹음이 중단됐어요. 다시 말씀해 주세요."(EX-VO-18 · FAILED).

### 4.2.4 시간 제한(무한 대기 금지 — UIUX §8)
인식 요청에는 위젯 쪽 상한을 둔다. 상한을 넘으면 요청을 중단하고 FAILED("음성을 글자로 바꾸지 못했어요…")로 정리한다. 상한 **15초**(서버 인식 제한 10초 + 업로드 여유 — 2026-10-01 설계서 §9.3에 반영 · 상수 `SPEECH_LIMITS.uploadDeadlineMs`).

### 4.2.5 첫 사용 고지 자리(VO-W4 — **미구현**, 법무 확인 전)

- 녹음 시작 직전 단일 호출 지점 `ensureSpeechNoticeAcknowledged()`를 그대로 두고, **1차는 즉시 통과**한다. 따라서 **현재 화면에는 고지가 나타나지 않으며 임시 문구도 넣지 않는다**(법무 미확인 문구를 화면에 올리지 않는다).
- 법무가 필요하다고 판정해 구현을 요청할 때를 대비한 **자리 설계만** 남긴다:

```
(말하기 누름 → 고지 미확인 시)  상태 줄 위치에 인라인 안내 블록(모달 아님 — 패널이 비모달 dialog)
┌────────────────────────────────────────────┐
│ {법무 확정 문구가 들어갈 자리}                   │
│ [확인하고 말하기]  [취소]                       │
└────────────────────────────────────────────┘
```
  - 모달·전체 화면 덮개를 쓰지 않는다. 블록이 열리면 포커스는 "확인하고 말하기"로 이동하고, 취소·Esc는 닫고 포커스를 말하기 버튼으로 돌린다. "다시 보지 않기" 같은 기억 방식(탭 세션 vs 영구)은 **법무 결정 후에** 정한다.
  - 문구·필요성·기억 방식 = §15 U-2(법무). 이 블록은 **코드로 만들지 않는다**.

## 4.3 VO-W2 — 답변별 듣기 버튼

### 목적
봇 답변을 사용자 기기의 한국어 음성으로 듣는다. **응답마다 1개**이고 `speech` 키가 있는 응답에만 생긴다(H-6 · FR-VO3-1).

### 배치·구성

```
봇  카드 분실 신고는 고객센터 …           ← 말풍선(들)
    [듣기]   [도움이 됐어요] [도움이 안 됐어요]   ← 응답의 마지막 말풍선 아래 한 줄
```

- 위치: 그 **응답의 마지막 말풍선 아래 행동 줄**. 답변 평가 막대가 있으면 **같은 줄 앞쪽**(좁으면 줄바꿈 — `flex-wrap`). 평가 막대의 `role="group"`(`답변 평가`)에 **넣지 않는다**(의미가 다르다) — 구조는 frontend-implementer가 정한다(행동 줄 래퍼를 새로 만들거나 막대의 형제로 둔다).
- **버튼이 생기지 않는 메시지**: 사용자 메시지 · 상담원 메시지 · 서버 시스템 안내(금지어 안내·일시 장애·답변 대기 문구) · 위젯 자체 안내·오류 문구 — 위젯은 **`speech` 키 유무만 본다**(응답 종류를 해석하지 않는다).
- 외부 RAG 보류 답: 대기 문구 말풍선에는 버튼이 없고(`speech` 없음), **최종 답이 표시되는 순간** 그 답에 버튼이 생긴다(대기 중 비활성 버튼을 미리 보여 주지 않는다 — AC-VO3-5).

### 버튼 상태

| 상태 | 텍스트(보이는 이름) | 접근 가능한 이름(`aria-label`) | 속성 |
|---|---|---|---|
| 읽기 가능 · 대기 | "듣기" | "이 답변 듣기" | 활성 |
| 이 응답 재생 중 | "멈추기" | "듣기 멈추기" | 같은 노드의 텍스트·`aria-label`만 변경(새 노드 0 — C-4) · `aria-pressed`는 쓰지 않는다(이름이 상태를 말한다) |
| 다른 응답 재생 중 | "듣기"(그대로) | "이 답변 듣기" | 누르면 진행 중인 것을 끊고 이것을 읽는다(한 번에 한 답 — FR-VO3-7). 끊긴 쪽 버튼은 "듣기"로 복귀 |
| 확인 중(기기 음성 판별 최대 2초) | "듣기" | 동일 | `aria-disabled` + 이유 "읽기 음성을 확인하고 있어요."(`aria-describedby` → 이유 줄) |
| 읽기 불가(기기에 한국어 음성 없음 · `speechSynthesis` 없음 · 온라인 음성뿐) | "듣기" | 동일 | `aria-disabled` + 이유 줄 연결(§4.4) · 누르면 아무 일도 없다(`speak()` 0) |
| 녹음 중 | "듣기" | 동일 | `aria-disabled` · 이유 줄에 "녹음 중에는 답변을 들을 수 없어요." |
| 읽기 오류(`error` 이벤트) | "듣기"로 복귀 | 동일 | 상태 줄이 아닌 `#cb-status`로 "지금은 소리로 들려드릴 수 없어요." 1회 + 답변 글자 유지 · 재시도 자동 0 |

- 보이는 글자 "듣기"/"멈추기"가 접근 가능한 이름에 포함된다(레이블-이름 일치).
- 재생 시작·끝은 **라이브 영역으로 낭독하지 않는다**(소리가 곧 피드백이고, 낭독이 스크린리더·기기 음성과 겹친다 — R-8). 오류만 1회 낭독한다.
- 비활성 버튼이 모든 답변에 반복되어 소음이 될 수 있다 — 요구사항(FR-VO3-2 "비활성 + 이유")을 따르되 이유는 **한 줄을 공유**한다(§4.4). 개선 제안은 §12 F-9.

### 재생 규칙(UI에 보이는 부분)

- 말투는 `speech.tone` → 공유 대응표 → `rate`·`pitch`·`volume`, 속도는 `config.voice.rate` 배율. **화면에 말투 이름·숫자를 표시하지 않는다**(위젯은 종류를 모르고, 숫자는 방문자에게 의미가 없다).
- 긴 글은 문장 단위로 나눠 차례로 읽고, 서버가 2,000자 상한에서 자른 답은 "…나머지는 화면에서 확인해 주세요."로 끝난다(서버 보장 — 위젯은 추가 UI 없음).
- 멈춤 계기: 멈추기 · 말하기 시작 · **입력창에 글자 입력 시작(첫 `input` 이벤트)** · 패널 닫기 · 탭 숨김 · 새 답 읽기 시작. 전부 `cancel()` 후 버튼 상태 복귀.

## 4.4 VO-W3 — 답변 소리로 듣기 토글 · 읽기 불가 이유

### 배치

`panel.root`의 **헤더 바로 아래 별도 행**(헤더 안이 아님 — C-2). `voice.tts = true`일 때만 이 행(또는 이유 줄)이 존재한다.

```
┌────────────────────────────────────────────────────┐
│ 챗봇 이름                                  [✕ 닫기]   │  ← 헤더
├────────────────────────────────────────────────────┤
│ 답변 소리로 듣기   [ 꺼짐 ○──  ]                      │  ← 토글 행(autoReadToggle = true일 때)
│ 새 답변이 오면 자동으로 읽어 줘요. 스크린리더를 쓰면    │
│ 소리가 겹칠 수 있어요. 안내 문구는 읽지 않아요.        │
│ 이 기기에는 한국어 읽기 음성이 없어 소리로 들려드릴 수  │  ← 이유 줄(읽기 불가일 때만)
│ 없어요.                                              │
├────────────────────────────────────────────────────┤
```

### 요소

| 요소 | 규칙 |
|---|---|
| 토글 | `<button role="switch" aria-checked>` · 보이는 레이블 "답변 소리로 듣기" · 상태 글자 "꺼짐"/"켜짐"을 **항상 표시**(색·위치만으로 구분 금지) · 44×44px 이상 · **기본 꺼짐 · 사용자 조작으로만 켜짐**(NFR-VOA2) · 탭 세션 동안 기억(`sessionStorage cb.vo.ar.{slug}`) · 새 탭·새 세션은 꺼짐 |
| 설명 | 토글에 `aria-describedby`로 연결되는 상시 보이는 문구: "새 답변이 오면 자동으로 읽어 줘요. 스크린리더를 쓰면 소리가 겹칠 수 있어요. 안내 문구는 읽지 않아요."(NFR-VOA4 · H-3 · 마지막 문장은 시스템 안내 침묵이 의도임을 알려 혼란을 줄인다 — K-16) |
| 이유 줄 `#cb-voice-reason` | **한 곳**에 두고 토글·모든 듣기 버튼이 `aria-describedby`로 공유한다. 내용 우선순위: ① 기기 음성 없음/`speechSynthesis` 없음/온라인 음성뿐 → "이 기기에는 한국어 읽기 음성이 없어 소리로 들려드릴 수 없어요." ② 확인 중 → "읽기 음성을 확인하고 있어요." ③ 녹음 중 → "녹음 중에는 답변을 들을 수 없어요." ④ 그 외 → 비움(숨김). **라이브 영역이 아니다**(조용히 갱신 — 정적 안내) |
| 읽기 불가일 때 토글 | `aria-disabled="true"` · 이유 줄 연결 · 눌러도 켜지지 않음 · 저장된 "켜짐" 값이 있어도 **적용하지 않는다**(`speak()` 0) |
| 음성 늦게 생김(`voiceschanged`) | 2초 대기 후 불가로 판정했더라도 이후 음성이 생기면 **활성화만** 한다(이유 줄 비움 · 낭독 없음 — EX-VO-14) |
| 관리자가 토글을 숨김(`autoReadToggle=false`) | 토글 행은 없고, 읽기 불가·확인 중 이유 줄만 필요할 때 단독 표시 |

### 자동 읽기 동작 규칙 (UI가 보장할 것 — AC-VO3-10 · EX-VO-16 · EX-VO-25)

1. 토글이 켜져 있고 읽기 가능일 때만, **`speech` 키가 있는 새 응답이 도착하면** 자동 재생한다.
2. 재생 중 새 `speech` 응답이 오면 **진행 중인 것을 `cancel()`하고 최신 답을 읽는다**(대기열 없음 — 한 번에 한 답 · 오래된 답을 계속 읽지 않는다) — EX-VO-16에서 "또는 대기열 — ui-designer"로 넘긴 결정(§12 F-3).
3. **`speech` 키가 없는 응답(시스템 안내 3종 등)이 오면 아무것도 읽지 않고, 진행 중인 이전 답 읽기도 끊지 않는다**(`cancel()` 호출 0).
4. 외부 RAG 답은 대기 중 침묵하고 최종 답이 도착하면 그때 읽는다(최대 90초 침묵 — 알려진 한계 K-16).
5. **창이 닫혀 있거나 탭이 숨겨진 동안, 그리고 녹음(마이크 준비 포함) 중에 도착한 답은 읽지 않는다**(`cancel()` 후 대기열도 두지 않는다 — 닫은 뒤 갑자기 소리가 나지 않게). 창을 다시 열면 그 답에 "듣기" 버튼이 있다(§12 F-3).
6. 다음 중 하나가 생기면 즉시 멈춘다: 녹음 시작 · 입력창 글자 입력 시작 · 창 닫기 · 탭 숨김 · 토글 끄기.
7. 토글을 켜는 동작 자체로는 소리가 나지 않는다(재생 권한은 토글을 켜는 클릭 처리기 안에서 **볼륨 0의 공백 한 칸 발화 1회**로 확보한다 — 구현 확정 · EX-VO-22). 그래도 브라우저가 막으면 "지금은 소리로 들려드릴 수 없어요." 1회 · 수동 "듣기"는 정상.
8. 읽기 오류 시 연속 재시도 없음(안내 1회).

### 5.1 방문자 — 말로 묻기 (S-1)

```

**`SPEECH_UNAVAILABLE` 단일 응답 규약**: 서버가 이유를 구분해 주지 않으므로(존재 탐지 방지 — 설계 R-8·K-14) 위젯은 **이유를 추측해 달리 보이지 않고** 항상 같은 문구 하나만 보인다. 서버 상태 판단은 다음 설정 조회부터 마이크 숨김으로 반영된다(EX-VO-12) — **위젯은 설정을 페이지당 1회(첫 열기)만 조회하므로 실제로는 새로고침 뒤**다(§16.2 W-13). 그 전까지 `503`은 재시도 가능한 FAILED이고 마이크는 남는다. 서버는 네트워크 오류면 즉시, 시간 초과·5xx는 연속 3회(기본 · `SPEECH_FAILURE_THRESHOLD`)에 이르면 상태를 내린다(설계서 §5.1).

  → (며칠 뒤) 인식 숫자 확인
```

### 9.3 `UIUX_준수기준.md` 갱신 제안 (이 문서는 반영하지 않는다 — system-architect/오케스트레이터 승인 후 별도 편집)

`§8`(또는 새 절 "음성 입력·읽기") 아래에 다음 패턴 추가를 제안한다.

> **A. 음성 녹음 입력**: ① 녹음은 사용자가 누른 동안/눌러 시작한 뒤에만 열고 종료·취소·창 닫힘·탭 숨김 때 마이크를 즉시 닫는다 ② 녹음 중 상태는 아이콘·글자·버튼 형태 변화를 함께 쓰고 남은 시간은 글자로 보이되 **매초 낭독하지 않는다**(시작·종료·남은 시간 임계에서만 1회) ③ 취소 수단을 **키보드(Esc)와 화면 버튼 둘 다** 제공한다(터치 기기에는 Esc가 없다). 패널 같은 겹침 UI의 Esc 닫기와 충돌하면 **녹음 취소가 먼저**다 ④ 인식 결과는 자동 전송하지 않고 입력창에 채워 사용자가 확인·수정하게 한다(덮어쓰지 않고 이어 붙임) ⑤ 대기 시간에 상한을 두고 취소를 제공한다.
> **B. 상태 변화로 사라지는 컨트롤의 포커스**: 기능 불가 판정으로 컨트롤을 제거할 때 포커스가 그 컨트롤에 있었으면 가까운 입력 요소로 옮긴다(`body`로 떨어뜨리지 않는다).
> **C. 소리 읽기(음성 합성) 컨트롤**: ① **소리 자동 재생 금지** — 자동 읽기는 기본 꺼짐이고 사용자가 켠 경우에만, 언제든 끌 수 있다 ② 읽기·멈추기는 같은 버튼의 이름 변경으로 표현하고(새 노드 추가 금지) 재생 시작·끝은 라이브 영역으로 낭독하지 않는다(스크린리더와 겹침) ③ 읽기를 쓸 수 없는 환경에서는 컨트롤을 숨기지 않고 `aria-disabled` + 이유 글자로 알린다 ④ 소리가 나는 동작은 사용자 조작 직후에만 시작한다. **자동 재생 관련 정부 접근성 지침의 조항 번호는 원문 직접 대조 후 기재**(현재 미확인).

| W-15 | 명세 §4.2.1·§5.3: `503 SPEECH_UNAVAILABLE` → 마이크 제거 · 포커스 입력창 | `503`은 **FAILED**(재시도 가능 · 포커스 말하기 버튼 · 문구 "지금은 음성 입력을 쓸 수 없어요. 글자로 입력해 주세요.") · 마이크 제거는 `403`(분류 `DISABLED`)만 | 코드 리뷰 — 일시 장애 한 번에 마이크가 페이지 수명 동안 사라지는 것을 막는다(서버 숨김은 새로고침 뒤 설정 조회로 반영 — W-13). 명세 본문 §4.2.1·§5.3·§7·§12 F-8을 이에 맞게 고쳤다 |
| W-16 | 명세 §4.2.1: 1,000자 초과 시 남은 글자 음수 | 남은 글자 영역에 "{n}자 초과 · 줄여 주세요"(문구 제안) | 코드 리뷰 L-5 — 음수 숫자보다 행동이 분명하다. 위젯 공통 입력창 규칙(§8.1 `over(n)`) |
