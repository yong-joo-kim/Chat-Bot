# 버전관리

## 1. 저장소 초기화

현재 `D:\2. Team Source\Chat Bot`은 git 저장소가 아니다. 실제 코드 구현 착수 시점(첫 `backend-implementer`/`frontend-implementer` 호출 직전)에 `git init`하고 `.gitignore`(node_modules, .env, dist 등)를 구성한다.

## 2. 커밋 규칙 (Auto QA와 동일 컨벤션)

- Conventional Commits: `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`
- **사용자가 명시적으로 커밋을 요청했을 때만** 커밋한다(자동 커밋 금지). `git-manager` 서브에이전트만 커밋을 수행한다.
- `git add`는 관련 파일을 명시적으로 지정, `-A`/`.` 지양.
- 커밋 전 민감정보(.env, API 키, 실 대화 원문/PII) 포함 여부 확인.

## 3. 브랜치 전략 (제안)

| 브랜치 | 용도 |
|---|---|
| `main` | 배포 가능한 안정 버전 |
| `feature/<slug>` | 기능 단위 개발 (`new-feature` 하네스 1회 실행 = 1 feature 브랜치) |
| `fix/<slug>` | 버그 수정 |

머지 전략(PR 기반 vs 직접 머지)은 원격 저장소(GitHub 등) 확정 시 결정한다.

## 4. 챗봇 콘텐츠 버전관리와의 구분

`기능요구사항.md` 25번 "챗봇 복원/버전 이력관리"는 **챗봇 대화 콘텐츠(의도/키워드/대화그래프 등)의 버전 스냅샷/롤백** 기능이며, 애플리케이션 데이터(`ChatbotVersion` 엔터티, `개발명세서.md` §3)로 DB에 저장된다. 이 문서(§1~3)의 git 버전관리는 **소스코드**에 대한 것으로 서로 다른 계층이다.

## 5. 릴리즈 노트

기능 단위 개발 완료(사용자 승인 후 커밋) 시마다 `docs/changelog/`(구현 착수 시 생성)에 변경 요약을 append한다.
