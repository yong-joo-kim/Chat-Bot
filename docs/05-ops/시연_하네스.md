## 2. 시연 전 확인(진행자)

시연 PC에서 **고객이 오기 전**에 한다. 하네스는 사전 점검(P0)에서 아래를 점검해 `[주의]`·`[오류]`로 알려 주지만, 남의 프로그램을 끄거나 설정을 바꾸지는 않는다.

1. **Ollama — 플래그에 따라 규칙이 반대다**(PC-10)
   - **10분판 · `--with-local-llm` 없는 풀 투어 = 끄기**("GPU 없이 CPU로" 메시지와 RAM·CPU 경쟁을 피한다)
     1. 작업 표시줄 오른쪽 트레이(숨겨진 아이콘 `^`)에서 Ollama 아이콘을 우클릭 → **Quit Ollama(종료)**.
     2. 확인: PowerShell에서 `Get-Process ollama -ErrorAction SilentlyContinue` 가 비어 있고 `netstat -ano | findstr :11434` 가 비어 있어야 한다.
     3. 다시 `pnpm demo`(또는 `pnpm demo -- --dry-run` 이 아니라 점검이 도는 실행)를 해 PC-10이 `[통과] Ollama가 꺼져 있습니다`가 되는지 본다.
   - **`--with-local-llm` = 켜 두기**: Ollama가 실행 중이고 모델 `qwen3:4b-instruct-2507-q4_K_M`이 있어야 한다(`ollama list`로 확인). 하네스는 Ollama를 설치·기동·종료하지 않고 **그 모델 1개만** 올리고 내린다(공연 뒤 반드시 해제 — 서비스는 끄지 않는다). **다른 모델이 이미 올라가 있으면**(`ollama ps`) 그래픽 메모리를 나눠 쓰므로 먼저 `ollama stop <모델>`로 내린다(하네스는 남의 모델을 내리지 않는다). 하네스가 비정상 종료되면 모델이 남을 수 있다 — `ollama stop qwen3:4b-instruct-2507-q4_K_M`.
   - **스피커 켜기**(풀 투어 · 장면 8) — 합성 음성(음성 입력을 켠 경우)과 답변 읽기가 **현장 스피커로만** 들린다(영상에는 소리가 없다). 음소거가 아닌지 볼륨을 확인한다. 소리 점검 버튼은 없다.
   - **Windows 한국어 음성**(설정 → 시간 및 언어 → 음성)이 있어야 합성 음성을 만들 수 있다(없으면 음성 입력 장면이 생략된다). 듣기 버튼은 **브라우저의 기기 안 한국어 읽기 음성**이 있어야 활성이다(없으면 비활성 + 이유 글자를 보이고 정직성으로 통과).
   - **"GPU 없이 CPU로" 메시지가 중요한 고객**에게는 `--stt-device cpu`(또는 음성 입력을 켜지 않음) — 3050 + `auto`는 음성 인식이 GPU로 떠서 ①~⑨ 동안 "CPU 동작" 배지가 나오지 않고 `GPU 사용` 칩이 대신 보인다(정직성).
   - **다른 GPU 프로그램(게임·영상 편집 등)을 끈다**(풀 투어에서 GPU를 쓰는 계획) · **브라우저 창을 최소화·가리지 않는다**(장면 9 선제 안내의 체류 시간 계산이 멈춘다 — 말풍선이 안 뜨면 관리자 화면 대체로 넘어간다).
2. **메모리 확보**(PC-11b) — 가용 RAM이 2GiB 미만이면 모델 적재 직후 단건 지연이 평소의 3~10배로 늘 수 있다. 브라우저 탭·IDE 등을 닫는다(총 RAM 권장 16GB 이상 — 십진 16e9바이트 기준이라 16GB 노트북도 통과).
3. **네트워크 차단 권장**(PC-9) — 시연 PC의 Wi-Fi/랜을 끈다. 열려 있어도 진행되지만 "외부 송신 없음" 메시지의 증거가 약해진다. 강제하려면 `--require-offline`(열려 있으면 중단).
4. **화면 설정** — 배율 100% · 해상도 1920x1080(작은 노트북은 `--viewport 1600x900`) · 절전·알림(집중 지원) 끄기. **공연 중 브라우저 창을 최소화하거나 클릭하지 않는다**(상담 목록이 5초 폴링이라 최소화하면 30초로 느려진다).
5. **영상이 필요하면 ffmpeg 반입**(PC-6) — Playwright 전용 ffmpeg가 없으면 **영상만** 만들지 않고 나머지는 그대로 진행한다(없는 상태로 `recordVideo`를 넘기면 브라우저가 못 뜨므로 하네스가 아예 넘기지 않는다).
   - 인터넷이 되는 PC에서: `node node_modules/playwright-core/cli.js install ffmpeg`(약 2초)
   - 받은 폴더 **`%LOCALAPPDATA%\ms-playwright\ffmpeg-1011`(3.49MB) + `winldd-1007`(0.1MB)** 두 개를 시연 PC의 같은 위치에 복사(합계 약 3.7MB). `playwright-core`를 올리면 리비전 번호가 바뀌므로 다시 받는다.
6. **이전 실행이 남아 있으면 정리** — `pnpm demo -- --stop latest`(서버 유지 모드로 띄워 둔 실행 포함).
7. **계정 비밀번호 가리기** — 준비 완료 요약에 시연 계정 3개의 비밀번호가 **이 터미널에만 1회** 나온다(보고서·로그·캡처에는 남지 않는다). 화면 공유 전에 터미널을 가린다.

## 3. 명령 · 옵션 · 종료 코드

```
pnpm demo                         보이는 시연
pnpm demo:check                   무인 점검
pnpm demo -- --옵션               옵션(PowerShell에서 쉼표 값은 따옴표로: --only "s1,s5")
pnpm demo -- --help               전체 옵션
pnpm demo -- --dry-run            프로세스·브라우저 없이 계획 출력(단계표·예산·생략 순서·환경변수 공개표·선택자 문구)
```

**풀 투어(DT-2)**
```
pnpm demo -- --preset customer-onprem-full                          기본 투어(약 13분 50초 · 모델 0)
pnpm demo -- --preset customer-onprem-full --with-voice-input --with-local-llm --live-clustering
                                                                    플래그 전부(약 17분 15초 · 3050)
pnpm demo -- --preset customer-onprem-full --with-voice-input --stt-device cpu
                                                                    "GPU 없이" 메시지를 지켜야 하는 고객
pnpm demo:check -- --preset customer-onprem-full [플래그]           풀 투어 무인 점검
pnpm demo:check -- --preset customer-onprem-full --voice-mock-check STT 모델이 없는 PC의 파이프(위젯 → API) 점검 — 모의 인식(음성 인식 미검증)
```
- 플래그: `--with-voice-input`(장면 8에 말하기→글자→전송 · 합성 음성 + 가상 마이크 · 음성 인식 자식 8102) · `--stt-device auto|cuda|cpu`(기본 auto = GPU 조건이 되면 large-v3-turbo·GPU, 아니면 small·CPU) · `--with-local-llm`(장면 10 · 사내 소형 생성 · 생성 자식 8101 · Ollama) · `--live-clustering`(장면 7에서 지금 분석을 돌리고 완료까지 대기 · 사전 분석은 대체용) · `--voice-mock-check`(무인 점검 전용). **전부 풀 투어 전용**이며 `pnpm demo:check`(인자 없음)와 `pnpm demo`(인자 없음)는 항상 10분판이다.
- **불가 판정의 처리**: 보이는 시연 = 사전 점검에서 `[주의]` + **해당 장면만 생략**하고 이유를 로드맵 "이 PC 구성에서 생략한 장면" 띠·시작 카드·보고서에 표시(진행자가 `[확인]`에서 엔터로 계속) · 무인 점검 = 차단(종료 코드 2) · `--stt-device cuda|cpu`로 장치를 **명시**했는데 불가 = 양쪽 차단. 사전 점검(P0)에서 발견하므로 공연 중에 알게 되는 일은 없다.
- 구간 선택: `--only voice,proactive,edge` · 단계 ID는 글자 코드 `SV-`(음성) · `SP-`(선제) · `SE-`(생성) — 예 `--skip SV-06,SP-04`.

자주 쓰는 옵션: `--only s1,s5`(구간 선택: opening s1..s7 closing) · `--skip S1-06,S4-03`(생략 가능 단계만) · `--no-build`(빌드 생략) · `--port-offset 100`(포트 5개 일괄 이동) · `--browser chrome` · `--no-video` · `--no-gif` · `--customer-copy`(고객 전달판 `report/customer.html` 추가) · `--no-history-schedule`(준비 단축 — 아래 §4) · `--wait-live-schedule`(무인 점검에서도 라이브 예약 실행까지 대기, +최대 7분) · `--fail-fast` · `--prepare-only`/`--no-teardown`(서버 유지) · `--stop <실행ID|latest>`.

**종료 코드**(루트 `pnpm demo`·`pnpm demo:check`는 `pnpm -C` 형태라 코드가 그대로 전달된다): `0` 전부 통과(대체·생략은 통과로 보되 보고서에 표시) · `1` 단계 실패 1건 이상 · `2` 사전 점검/빌드/기동/데이터 준비 실패 · `130` 중단(Ctrl+C · 진행자 종료 · 창 닫힘).

**보이는 시연 진행 키**(터미널이 TTY일 때 — PowerShell·Windows Terminal. Git Bash mintty는 키를 바로 못 받아 **줄 명령**으로 동작하며 시작 때 안내한다):

| 키 | 줄 명령 | 동작 |
|---|---|---|
| Enter | (빈 줄) | "시연 준비 완료" 뒤 공연 시작(T0) |
| Space | `p` | 일시정지/재개(멈춘 시간은 예산 계산에서 제외 · 자막에 "잠시 멈춤") |
| `n` | `n` | 현재 단계 건너뛰기 — **생략 가능 단계만**(핵심이면 무시 + 터미널 안내) |
| `s` | `s` | 다음 장면으로(남은 단계는 "진행자 생략"으로 기록) |
| `q` | `q` | 종료 확인(`y`) → 정리 · 종료 코드 130. 공연이 끝난 뒤의 `q`는 확인 없이 정리하고 보고서 폴더를 연다 |

## 4. 실행 단계와 시간

```
P0 사전 점검 → P1 실행 폴더·격리 DB → P2 빌드(지문 캐시) → P3 기동(ml-worker ∥ API ∥ 정적 서버 3)
→ P4 데모 데이터 → P5 보정·예열 → 이력 예약 실행 대기 → [준비 완료 · 엔터 대기] → T0 → 공연 → 보고서 → 정리
```

- **준비 약 6분 이상**(캐시 있음): 이력용 예약(C-1)이 "생성 후 최소 5분 뒤" 실제로 실행되는 것을 기다리기 때문이다(제품 규칙). 그 사이 터미널에 15초마다 `[진행] 이력 예약 실행 대기: 남은 시간 …`이 나온다. 급하면 `--no-history-schedule`(약 1분) — 대신 장면 5의 예약 단계가 "대기 중 예약" 대체 화면으로 약해진다.
- **라이브 예약(C-2)** 은 진행자가 **엔터를 누른 순간(T0)** 에 걸고(`ceilMinute(T0+6분)`) 장면 5 끝에서 실행 결과를 보인다. 2인 승인이 켜진 챗봇의 예약은 작성자 요청 + 다른 관리자 승인이 있어야 실행되므로 **관리자 1 요청 → 관리자 2 승인을 API로 미리 처리**하며, 자막과 보고서 "정직성 표기"에 공개한다.
- 공연 600±30초(보이는 시연): 단계 예산은 상한이자 목표다. 빨리 끝나면 남은 시간만큼 자막과 함께 화면을 유지하고, 늦으면 **생략 가능 단계**를 구간별 생략 순서대로 건너뛴다(핵심 단계는 절대 생략하지 않는다). 핵심만의 합은 401초.

### 풀 투어(DT-2) 실행 단계 · 순차 적재 · 장면

```
P0 사전 점검(+PC-DX) → P1 → P2 → P3 기동(임베딩 ∥ API ∥ 정적 서버 3) → P4 데모 데이터(+챗봇 D·음성 설정·"기록만" 규칙)
 → [사내 생성] P4-L 생성 자식 기동(모델 적재) → 사전 생성 → Ollama 해제 → [음성] P4-V 음성 자식 기동(장치 결정·대체) → 합성 음성 확인(G-DX-1·2)
 → P5 보정(+G-DX-3 선제 규칙) → 이력 예약 대기 → 준비 완료(엔터) → 공연 → 보고서 → 정리(+하네스가 올린 Ollama 모델 해제)
```
- **3050(4GB) 순차 적재**: 음성 인식(GPU)과 Ollama는 **동시에 올리지 않는다.** 장면 8·9 동안 음성 인식이 상주하고, **장면 10 진입(SE-01)에서 음성 인식을 내린 뒤(VRAM 회수 확인) 생성 모델을 올린다**(GPU 전환 카드로 숨기지 않고 보인다). SE-04에서 모델을 내리고 생성 자식을 종료한다.
- 준비 시간은 음성 +약 1분 · 생성 +약 2분(미실측)이 더해지지만 이력 예약 대기(약 6분)와 겹쳐 진행되어 실제 증가는 더 작다.
- **장치 결정(`--with-voice-input`)**: auto = GPU·CUDA DLL(venv 폴더 또는 시스템 PATH)·그래픽 메모리 여유 1,300MiB 이상·turbo 모델이 모두 있으면 `large-v3-turbo`·GPU, 아니면 `small`·CPU(공개). **GPU로 시작하다 실패하면(자식 종료·60초 초과·장치가 cuda가 아님) CPU로 1회 다시 시작**하고 화면·보고서에 "장치 자동 대체"를 남긴다. 사전 점검의 DLL 확인은 힌트이고 **기동 시도 결과가 최종 판정**이다.

## 6. 정리 · 잔존 프로세스

- 정상·실패·Ctrl+C 모두 같은 정리를 한다(자식 트리 종료 → 정적 서버 닫기 → 포트 해제 확인 → 고아 표식 검사). 터미널 마지막에 `정리: 남은 프로세스 0개 / 포트 해제 / 개발 DB 변경 없음`이 나와야 정상이다.
- 서버를 일부러 유지한 실행(`--prepare-only` · `--no-teardown`)은 `pnpm demo -- --stop <실행ID|latest>` 로 끝낸다. 살아 있는 하네스에는 `stop.request` 파일로 스스로 정리하게 하고(15초 대기), 응답이 없으면 강제 종료한 뒤 표식 확인 후 정리한다.
- 하네스가 비정상 종료해도 **다음 실행**이 이전 실행의 `pids.json`을 보고 표식이 있는 프로세스만 정리한다(소유 하네스가 살아 있는 실행은 건드리지 않는다).
- `.demo-runs/`는 최근 5개만 보존(`--keep-runs`)하고 `.gitignore`로 커밋에서 빠진다 — **영상·DB·보고서를 커밋하지 않는다**.

## 7. 문제 해결

| 증상 | 원인 · 조치 |
|---|---|
| `[오류] 포트 3000을 다른 프로그램이 사용 중` | 출력된 PID·이름을 끄거나 `--port-offset 100`. 이전 하네스 실행이면 `--stop latest` |
| API 기동 실패 로그에 `Cannot find module 'multer'`(`MODULE_NOT_FOUND`) | **결함 후보 DHX-4**(제품 `apps/api/package.json`이 `multer`를 직접 의존성으로 선언하지 않음). 하네스는 `NODE_PATH`(pnpm 해석 경로)를 넘겨 기동하지만, 제품을 `node dist/main.js`로 직접 기동하는 구축형 설치는 실패할 수 있다 — 제품 쪽에서 별도로 고친다 |
| `[오류] 데이터 보정 게이트가 실패` | 의미 매칭 점수가 장면에 필요한 구간(꺼짐=폴백 · 켜짐=확정)에 들지 않음. 줄에 나온 문장·점수를 보고 `tools/demo-harness/src/data/dataset.ts`의 예문·질문 문구를 조정 |
| 단계 `[실패] … SELECTOR` | 제품 화면 문구가 바뀌어 접근성 이름을 못 찾음 — `tools/demo-harness/src/selectors/console.ts`를 갱신(단위 시험 H-T9가 제품 문구와 대조한다). 실패 순간 화면은 `shots/<단계 ID>-FAIL.png` |
| 단계 `TIMEOUT`/`VERIFY` | 조건 대기 상한 안에 기대한 변화가 없었음(서버 응답 지연 · 데이터 문구). 보고서 "실패 요약"의 기대값/실제값과 로그 꼬리 확인. 재개는 구간 단위: `pnpm demo -- --only s3`(같은 실행 폴더 재개 `--resume`은 아직 없음) |
| `[대체] S5-07` | 라이브 예약이 시간 안에 실행되지 않았거나(진행자가 오래 멈춘 경우) 만들지 못해 준비 단계의 이력 예약 화면으로 대신 보였다 — 자막과 보고서에 그대로 공개되며 종료 코드에는 영향이 없다 |
| 영상이 없다 | 보고서 "영상" 절에 사유가 적힌다 — 영상 인코더 없음(§2-5) · `--no-video` · 무인 점검 |
| 단건 지연이 크다(P95 > 200ms) | 모델 적재 직후 일시 현상일 수 있어 최대 3라운드 재측정하고 마지막 라운드로 `EMBEDDING_TIMEOUT_MS`를 정한다(모든 라운드를 보고서에 공개). 가용 RAM 확보(§2-2) |
| `pnpm demo \| head` 처럼 출력을 자르면 | 출력 오류를 삼켜 정리까지 끝까지 돈다(로그 파일에는 계속 남음) |
| 보고서 HTML 인쇄 | 항상 라이트 · A4 · 영상은 파일 위치 글자로 대체 · 접힌 상세는 인쇄되지 않음 |
| (풀 투어) 위젯에 말하기 버튼이 없다 | 마이크 버튼은 `voice.input`(서버 음성 인식 켬 ∧ 가용성) ∧ 보안 컨텍스트(`http://localhost`) ∧ `getUserMedia`·`MediaRecorder`일 때만 생긴다. 위젯은 설정을 **페이지당 1회(첫 열기)** 조회하고 가용성은 성공 30초·실패 10초 캐시한다 — 음성 자식이 늦게 떠 실패가 캐시됐다면 새 세션(SV-03이 새 세션으로 연다)으로 다시 확인. 모형은 반드시 `localhost` 출처(`127.0.0.1`로 열면 권한 프롬프트가 뜬다) |
| (풀 투어) `SPEECH_AUDIO_INVALID` / 녹음 오류 | 브라우저가 녹음한 webm/opus를 서버가 디코딩하지 못한 경우 — **제품 결함 후보**(2026-10-02 실측에서는 정상). 하네스는 우회하지 않는다: 보이는 시연은 같은 문장 타이핑 대체(FALLBACK) · 무인 점검은 실패 + `ml-speech.log` 확인 → `bug-triage` |
| (풀 투어) 음성 인식이 GPU로 안 뜬다 → CPU로 대체 | `[주의] 음성 인식을 GPU로 시작하지 못해 CPU(small)로 다시 시작했습니다` — `ml-speech.log`에 `cublas64_12.dll`·CUDA 오류가 있으면 CUDA DLL이 PATH에 없다(venv의 `nvidia\{cublas,cudnn,cuda_nvrtc}\bin` 또는 시스템 CUDA). 하네스는 venv 폴더가 있으면 자식 `PATH` 앞에 붙인다(운영 문서 절차 재현). 화면·보고서에 "장치 대체"가 그대로 공개된다 |
| (풀 투어) 선제 말풍선이 안 뜬다 | 창 최소화·다른 창 가림으로 체류 시간이 쌓이지 않았거나 모형 D 스니펫에 `data-proactive="on"`이 빠진 경우(하네스가 넣는다). 15초 안에 안 뜨면 관리자 화면(선제 안내 구역)으로 대체 — 무인 점검은 실패 |
| (풀 투어) 생성 모델이 안 내려간다 / 장면 10 대체 | SE-04 해제 실패는 경고만 하고 정리 단계가 한 번 더 시도한다. 계속 남으면 `ollama stop qwen3:4b-instruct-2507-q4_K_M`. SE-01에서 음성 인식 VRAM 회수·모델 적재가 실패하면 사전 생성 결과로 대체(FALLBACK + 자막) |

## 8. 유지보수 메모

- **선택자**는 `tools/demo-harness/src/selectors/*`가 단일 출처이고 접근성 이름·보이는 문구 기반이다(`data-testid` 추가 0 — 제품 코드 변경 0). 문구는 `apps/web/src/constants/*`에서 복사한 값이며 단위 시험이 원문과 대조한다.
- **시나리오 단계**는 `src/scenarios/{opening,s1..s7,closing}.ts`(선언형), 데모 데이터는 `src/data/dataset.ts`, 로드맵 문구는 `src/data/roadmap.ts`, 새 제품 환경변수(출구 키 등)는 `src/env/api-env.ts` 한 곳 — 제품에 새 출구(`EgressExitId`)가 생기면 단위 시험이 실패해 하네스 목록 갱신을 강제한다.
- **잠금 파일**: 하네스 의존성을 바꿀 때는 `pnpm-lock.yaml`의 하네스 임포터·새 패키지 항목만 손으로 병합하고 `pnpm install --frozen-lockfile`이 통과하는지, `git diff pnpm-lock.yaml`에 삭제 줄이 0인지 확인한다(일반 `pnpm install`은 제품 임포터의 `jsdom` 피어 해석을 바꾼다).
- **시험**: `pnpm -C tools/demo-harness run harness:test`(단위·정적 검사 · CI 미편입) · `npx eslint tools` 오류 0 · 통합은 `pnpm demo:check` 연속 실행.

## 10. 알려진 한계(보고서에도 고정 문구로 실린다)

브라우저 백그라운드 통신은 감시 범위 밖 · 화면 그리기는 GPU를 쓸 수 있음("GPU 없이"는 AI 추론에 한함) · API는 모든 인터페이스에 바인드(제품 동작 — 시연 PC 네트워크 차단 권고) · 스키마 밖 `process.env` 직접 읽기 비밀(이번 시연에서 쓰지 않는 기능)의 `.env` 잔존 가능성 · HF 캐시 잠금 파일 · 준비 단계 보정이 감사 로그 2행·임베딩 캐시를 남김 · 시간 수치는 이 노트북 기준 추정·실측이며 영업 수치 아님 · 하네스는 API를 `NODE_PATH`와 함께 기동(DHX-4 수정 전 직접 기동 시 실패 가능). **미구현**: 같은 실행 폴더 상태 재개(`--resume`) · LLM 동작 확인 부록(`--appendix-llm` — 풀 투어에서는 장면 10이 대신한다).
**풀 투어 추가 한계**: 합성 음성·가상 마이크(실제 사람 음성·실제 마이크 아님) · 영상·GIF에 소리 없음(현장 스피커로만) · 3050 결과는 **동작 확인 수준**(음성 인식 정확도·생성 품질·지연의 합격 판정 아님) · VRAM 수치는 관찰값 · 시연은 비운영(`NODE_ENV` 미설정)이라 운영 환경의 모의 인식 차단은 재현하지 않음 · 음성 원본 저장 0 확인은 파일 시그니처 휴리스틱 · 엑셀 행 수는 감사 기록 기준(파일 내부 시트 미파싱) · 가짜 마이크는 한 실행에 한 문장 · 풀 투어에서 음성 인식이 GPU로 뜨면 장면 1~9 동안 "CPU 동작" 배지가 나오지 않는다(`GPU 사용` 칩이 대신 — 정직성).
