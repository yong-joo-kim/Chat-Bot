### 5.10 AI 거버넌스·가드레일(No.36) 운영 요구 (2026-09-30 추가)

`ai-guardrails-설계.md` · ADR-0048. 위험 응답 규칙·RAG 답 개인정보 가림·운영 전환 2인 승인을 쓰는 설치의 **운영 책임**이다. 모델·GPU·새 외부 출구가 없다.

1. **마이그레이션**: `…_ai_guardrails`(`CREATE TABLE` 4 + 인덱스 + `ADD COLUMN` 5) 적용 전 생성 SQL에 `new_` 테이블·`DROP INDEX`가 없는지 확인하고, 적용 후 원시 부분 유니크 인덱스가 **4개 그대로**인지 `sqlite_master`로 확인한다. 데이터 이관·백필 없음.
2. **배포 즉시 바뀌는 것**: 외부 RAG 답에서 **주민등록번호·카드번호 형식이 기본으로 가려진다**(모든 챗봇 — 챗봇별로 끌 수 있음 · 거버넌스 모드 제외). 카드 형식은 14~16자리 연속 숫자(주문번호 등)도 가릴 수 있으므로, RAG를 쓰는 챗봇 담당자에게 "안전 가드레일 > 개인정보 가림" 설정 확인을 안내한다. 위험 응답 규칙은 0개로 시작한다(제품이 의료·법률 문구를 미리 넣지 않는다).
3. **규칙 운영**: 새 규칙은 "기록만"으로 시작해 현황의 적중 수와 이벤트(대화 마스킹본)를 확인한 뒤 "대체"로 강화한다. 다중 인스턴스에서는 규칙 변경이 다른 인스턴스에 `GUARDRAIL_CACHE_TTL_MS`(기본 60초) 뒤 반영된다. 긴급 시 `GUARDRAILS_ENABLED=false`로 규칙·가림을 전부 끌 수 있다(재기동 필요).
4. **2인 승인**: 환경 모드 챗봇에서 켤 수 있고, 활성 ADMIN(`chatbot:deploy`)이 **2명 이상**이어야 한다. 켜진 동안 운영 전환은 "승인 요청 → 다른 ADMIN 승인"이 되며 직전 운영 버전 롤백만 즉시 가능(기록됨)하다. 켜진 동안에는 환경 모드를 끌 수 없다(정책부터 끈다). 예약 전환은 예약 작성자가 승인 요청을 만들어야 실행된다(없으면 `승인 없음`으로 실패). 승인 정책 끄기를 서버 차원에서 막으려면 `ENV_APPROVAL_OFF_LOCKED=true`.
5. **알림**: 승인 대기는 콘솔 배지로만 알린다(메일·메신저 알림 없음 — No.41 2차). 승인자가 만료(기본 24시간) 전에 확인하도록 운영 절차에 넣는다.
6. **배포 후 확인**: 콘솔 "안전 가드레일" 탭 · 시험하기로 규칙 1개 판정 · 가짜/실제 RAG 답의 가림 표시(시뮬레이터 RAG 답 미리보기) · 2인 승인 켜기 → 요청 → 다른 계정 승인 → 전환 이력 "2인 승인" 표식 · 감사 로그 대상 "규칙"·"운영 전환 승인 요청" · 서버 로그에 질문·답·표현·사유 문장이 없는지.

> ⚠ §4의 헬스체크 기준(`redis`)은 초기안이다
