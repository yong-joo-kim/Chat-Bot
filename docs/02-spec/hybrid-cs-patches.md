# No.24 하이브리드 CS — 기존 문서 패치 목록

> 작성: system-architect · 2026-09-25 · 근거: `docs/02-spec/hybrid-cs-설계.md`, `docs/02-spec/decisions/ADR-0036-hybrid-cs-handoff-thread-short-polling-and-transient-raw-text.md`
> **적용 상태**: ✅ **적용 완료(2026-09-25)** — 오케스트레이터 세션이 104건 전부 "찾을 원문 정확히 1회" 확인 후 기계적으로 적용했다.
> **적용 방법**: 각 항목의 "찾을 원문"을 대상 파일에서 **정확히 1회** 찾아 "바꿀 내용"으로 교체한다. 모든 원문은 2026-09-25 시점 파일(No.27 패치 적용 후)에서 복사했고 문자열 검색(Grep `-o`)으로 대상 파일 안 유일성을 확인했다. "바꿀 내용"이 원문을 그대로 포함하는 항목은 append다(취소선 표기 항목은 원문을 `~~…~~`로 감싸 보존한다).
> **줄바꿈 주의**: 대상 파일은 CRLF일 수 있다. 모든 "찾을 원문"은 **한 줄 안의 부분 문자열**(줄바꿈 미포함)로 잡았다. "바꿀 내용"의 줄바꿈은 대상 파일의 줄바꿈으로 정규화한다.
> **순서 독립**: 어떤 "바꿀 내용"도 다른 항목의 "찾을 원문"을 새로 만들지 않는다. 같은 줄에 앵커가 여러 개인 항목(개발명세서 A-24~A-26 · A-28~A-30)은 서로 겹치지 않는 부분 문자열이다.
> 코드 변경은 이 파일의 범위가 아니다 — 설계서 §2.5 체크리스트와 §22.2(의도된 시험 기대값 변경 닫힌 목록)를 따른다.
> 항목 수: 개발명세서 47 · ADR 14 · 기능요구사항 2 · 하이브리드 CS 요구사항(PM 결정 기록 + P-9 반영) 38 · 선행 요구사항 3 = **104건**

````text
## 갱신 (2026-09-25 — No.24: 재검토 트리거 ① 발동 → 부분 갱신 · 상담 스레드는 봉투 밖)

하이브리드 CS(No.24, **ADR-0036 §1**)가 §4의 트리거 ①을 발동시켰다. 결론은 **Supersedes가 아니라 부분 갱신**이다 — 결정 1(봇 대화 상태 세션 테이블/Redis 미도입)·2(매 턴 재검증)·3(담지 않는 것)은 **불변**이다.

- **"상담 중"은 봉투에 없다**(§3 — 상태전이·권한 값). 개입 여부는 서버 스레드가 원천이며 공개 파이프라인이 엔진 호출 **전**에 판정한다(엔진·봉투 스키마·`CONVERSATION_STATE_VERSION` 불변).

- 개입이 전달되면 진행 중 컨텍스트 폼·설문·되묻기를 API 계층이 **비운다**(값을 줄이는 방향만 — 결정 2의 "매 턴 재검증"이 그대로 적용된다). 사용자가 봉투를 되돌려도 상담 중에는 엔진이 호출되지 않고, 종료 후에는 연결 시각 이전 진행 상태가 다시 비워진다.
- 감수 비용 ②(탭 복제 = 같은 `sessionId`)의 귀결: 두 탭이 같은 토큰으로 상담을 공유한다(콘솔은 한 사용자로 본다). 감수 비용 ③: 새로고침 시 **상담 구간**은 서버에서 복구되지만 봇 구간은 여전히 복원되지 않는다.
````

````text
## 갱신 (2026-09-25 — No.24 하이브리드 CS: 역할 3 → 4(`AGENT`) · 권한 15 → 17(`cs:read`·`cs:write`))
````

````text
하이브리드 CS(No.24, **ADR-0036 §5·§6**)가 도메인 무관 부품 `common/polling/PollingLoop`·`Clock`을 재사용한다. 이 ADR의 결정은 불변이다.

- **60초 상담 정리 루프**: 시간 기반 상담 종료 판정(조회 시점 판정과 같은 순수 함수)·만료 원문 필드 소거·`draining` 해제. 기동 즉시 `runOnce()` 1회.
- **선점(claim)을 쓰지 않는다** — 예약 실행과 달리 모든 연산이 조건부 갱신이라 멱등이다. 모든 인스턴스가 실행하며 같은 상담을 두 인스턴스가 동시에 종료해도 CAS가 1회만 통과시킨다. 임대·RUNNING 부분 유니크는 필요 없다.
- `CLOCK` 포트를 `HandoffModule`에서도 제공한다(같은 토큰 — 통합 시험의 `overrideProvider(CLOCK)`가 두 모듈에 함께 적용된다). tick 예외는 코드만 남긴 새 오류로 넘긴다(원문·메시지 인자를 `PollingLoop` 경고 로그에 흘리지 않는다).
````

````text
## 갱신 (2026-09-25 — No.24: 사전검사 대상 11 → 13종 · 상담 설정은 동반 삭제)

하이브리드 CS(No.24, **ADR-0036 §8**)에 따라 결정 3의 사전검사 목록에 **`handoffSessions`('상담')·`cannedResponses`('자주 쓰는 문장')**를 추가한다(11 → 13종). 결정 1~6은 불변이다.

- 상담 스레드는 상담 이력의 유일한 원천이고, 자주 쓰는 문장은 운영자가 작성한 대화 자산 성격이다 — 둘 다 **"하위 데이터 제거"(동반 삭제) 분류가 아니다**.
- **`ChatbotHandoffSetting`은 `ChatbotAnswerSetting`과 같은 설정 데이터**라 영구삭제 트랜잭션에서 **동반 삭제**한다(FK `Restrict`라 챗봇 삭제 전에 먼저 지운다).
- 자주 쓰는 문장 **단건 삭제는 허용**한다(대화 자산 편집 — 감사 `DELETE`). 상담 기록은 단건으로도 삭제할 수 없다.
````

````text
- **AC-CS8-1** ★ Given 담당 AGENT · 활성 상담 · 사용자 "제 번호 010-1234-5678", When `includeRaw=true`로 대화 보기, Then 해당 항목에 마스킹본과 원문이 함께 있고 `RAW_VIEW` 감사 1건이 남는다. 같은 요청 10회 반복에도 감사는 1건이다.
- **AC-CS8-2** Given 비담당 AGENT · EDITOR · `includeRaw` 없는 담당자, When 대화 보기, Then 원문 키가 없고 감사 0건이다. 비담당 ADMIN은 원문 ○ · 감사 1건(관리자)이다.
- **AC-CS8-3** ★ Given 상담원 종료, When DB를 직접 조회하면, Then 그 상담의 `rawText`가 전부 `NULL`이고(종료와 같은 트랜잭션) 대화 보기는 `rawVisible=false`다.
- **AC-CS8-4** ★ Given 사용자 무응답 11분 · 콘솔·위젯 요청 0건, When 정리 루프 1회 실행, Then 상담이 종료되고 원문이 소거된다(조회 없이도 파기).
- **AC-CS8-5** Given 적재 후 60분이 지난 원문, Then 읽기는 즉시 비노출이고 다음 정리 루프 후 `NULL`이다. 강제 인수 후 이전 담당자는 다음 조회에서 `rawVisible=false`다.
- **AC-CS8-6** ★ Given 고유 표식 원문을 상담 중 전송 후 종료·정리 루프, When 서버 로그·감사·오류 응답·이력·폴링·힌트 응답·`ConversationLog`·**SQLite DB 파일 바이트**를 전수 검사하면, Then 원문 문자열이 0건이다.
- **AC-CS8-7** Given 공개 폴링 `restore=true`, Then 사용자 메시지는 마스킹본이며 원문 키가 존재하지 않는다. PII가 없는 발화는 원문을 저장하지 않는다(`rawText=NULL`).
````
