# No.42 옴니채널 통합 인박스 — 기존 문서 패치 목록

> 작성: system-architect · 2026-09-26 · 근거: `docs/02-spec/omnichannel-inbox-설계.md`, `docs/02-spec/decisions/ADR-0042-omnichannel-inbox-signed-identity-customer-thread-and-record-channels.md`
> **적용 상태**: ✅ **적용 완료(2026-09-26, 84건)** — 오케스트레이터 세션이 항목마다 "찾을 원문 정확히 1회"를 확인한 뒤 기계적으로 적용한다.
> **적용 방법**: 각 항목의 "찾을 원문"을 대상 파일에서 **정확히 1회** 찾아 "바꿀 내용"으로 교체한다. 모든 원문은 2026-09-26 시점 파일(No.41 업무 자동화 패치 적용 후)에서 복사했고, 문자열 검색(Grep count)으로 대상 파일 안 유일성을 확인했다. "바꿀 내용"이 원문을 그대로 포함하는 항목은 append다(취소선 표기 항목은 원문을 `~~…~~`로 감싸 보존한다).
> **줄바꿈 주의**: 대상 파일은 CRLF일 수 있다. 모든 "찾을 원문"은 **한 줄 안의 부분 문자열**(줄바꿈 미포함)로 잡았다. "바꿀 내용"의 줄바꿈은 대상 파일의 줄바꿈으로 정규화한다.
> **순서 독립**: 어떤 "바꿀 내용"도 다른 항목의 "찾을 원문"을 새로 만들지 않는다. 같은 줄에 앵커가 둘인 항목은 없다.
> 코드 변경은 이 파일의 범위가 아니다 — 설계서 §2.5 체크리스트와 §21.3(의도된 시험 기대값 변경 닫힌 목록)을 따른다. `CLAUDE.md`는 이 패치의 대상이 아니다(작업 트리의 미커밋 수정 보존).
> 항목 수: 개발명세서 37 · ADR 9 · 기능요구사항 8 · 통합 인박스 요구사항(PM 결정 기록 + 설계 반영) 19 · 선행 요구사항 인계 정정 10 · 운영 문서 1 = **84건**

````text
## 갱신 (2026-09-26 — No.42: 봉투 `channel` 불변 · 원천 파일의 두 번째 포트 공존)

통합 인박스(No.42, **ADR-0042 §5**). 결정 1~9는 **불변**이다.

1. **봉투 `channel: z.enum(['WEB'])`·이벤트 7종 불변**: 인박스는 `WORKFLOW_EVENT_SINK`를 주입·발행하지 않는다. 수동 기록·시뮬레이션은 공개 파이프라인을 타지 않아 `TURN_LOGGED`·상담 이벤트를 만들지 않고, 식별 연결(고객 키·이름)은 봉투에 싣지 않는다(새 외부 전송 목적 — 2차 판단). 봉투 `channel`은 "대화가 들어온 배포 채널"의 의미를 유지한다.

3. **이 포트를 재사용하지 않은 이유**: 상담 이벤트에 `sessionId`가 없고(`sessionRef`만), 단일 제공자 토큰을 팬아웃으로 바꾸면 W-15 모듈 exports·배선이 바뀌며 인박스 처리 실패가 발송 적재 경로와 묶인다.
4. **2차 스레드 이벤트**(열림·배정·종료 알림) 착수 시: `WorkflowEventType` +3 · 봉투 `source.threadId`만(고객 키·표시 이름 0) · 기록 채널은 `channel`이 아니라 `data.recordChannel` — 봉투 v1 확장 규칙(선택 키) 안에서.
````

````text
데이터 지도 "업무 자동화 웹훅" 행 확인.

### 5.5 통합 인박스(No.42) 운영 요구 (2026-09-26 추가)

`omnichannel-inbox-설계.md` · ADR-0042. 챗봇을 통합 인박스에 참여시키는 설치의 **운영 책임**이다.

1. **고객 키 비밀**: 로그인 연동 식별을 쓰려면 `OMNI_CUSTOMER_KEY_SECRET`(32바이트 이상 — 예: `openssl rand -hex 32`)을 넣고 재기동한다. **이 값은 교체하지 않는다** — 바꾸면 기존 고객과 새 방문의 통합이 끊긴다(원 회원 번호를 저장하지 않아 재계산 불가). 백업 복원 시 같은 값을 함께 보존한다.
2. **식별 공간 비밀**: 고객사마다 `OMNI_IDENTITY_SECRET__<REF>`(32바이트 이상)를 넣고, ADMIN이 챗봇 설정에서 참조 `<REF>`를 지정한다. 같은 비밀을 고객사 로그인 서버와만 공유한다(메일·메신저 전달 금지). 고객사가 비밀을 교체할 때는 새 값을 `…__<REF>`에, 옛 값을 `…__<REF>__PREV`에 두고 재기동 → 고객사 전환 확인 → `__PREV` 제거.
3. **동의·고지**: 로그인 회원 정보를 챗봇 상담 이력과 연결한다는 사실의 고지·동의는 **고객사 책임**이다(연동 가이드·계약 명시). 토큰 권장 수명은 1시간(최대 24시간).
4. **거버넌스 모드 설치**: 인박스 메모·기록 본문과 고객 표시 이름은 암호화 대상이며, 보존기간 화면의 "인박스 메모·기록"·"고객 식별 정보"를 정책에 맞게 정한다(기본 무기한).
5. **배포 후 확인**: 마이그레이션 `20260926210000_omnichannel_inbox` 적용 뒤 원시 부분 유니크 인덱스 개수가 4 그대로인지 · 신규 테이블 8 · 외래 키 점검 0행 · 챗봇 설정 "통합 인박스" 화면의 비밀 상태(설정됨/없음/약함) 확인. 연동 가이드: `docs/05-ops/통합인박스_연동가이드.md`(deployment-engineer 작성 예정).
````
