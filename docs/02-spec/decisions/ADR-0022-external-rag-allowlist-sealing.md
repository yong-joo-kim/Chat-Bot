# ADR-0022 — 외부 RAG 서버 접촉면 봉인(allowlist 3 · `provider` 상수 · 문서 인입 분리)

- **상태**: 채택 (Accepted)
- **일자**: 2026-09-22
- **결정자**: system-architect (PM 확정사항 P-2·P-3·P-4 반영)
- **관련**: `docs/requirements/nlu-rag-answering.md` **J-5**, **J-6**, **J-8**, FR-0-41/42/47, FR-N2-5~16, NFR-S11~S15/S19, AC-N2-1~9, AC-N3-4/5 / **`docs/00-source/API_RAG.md` §0-2·§0-3·§2-2·§3·§4·§6-1·§6-4·§7·§8** / ADR-0011(공개 표면) / ADR-0013(PII 마스킹)
- **영향 범위**: `apps/api/src/rag/*`(신설), `packages/pii-mask`(승격), `apps/api/src/answer-settings/*`
- **세부 설계**: `docs/02-spec/nlu-rag-answering-설계.md` §9.1~§9.6·§11.4

## 맥락

2단계 답변은 **회사가 이미 운영 중인 외부 RAG 서버**(`API_RAG.md` 명세)에 위임한다. 자체 RAG 엔진을 만들지 않는다는 것은 PM 확정사항이다(P-2).

문제는 그 서버의 성격이다.

| 사실 | 출처 |
|---|---|
| **인증이 전혀 없다.** API 키·토큰·세션 어느 것도 요구하지 않는다 | §0-1 |
| `POST /api/documents/reset`이 **Neo4j의 RAG 데이터를 전부 지운다. 되돌릴 수 없다. 확인 절차도, 취소도, 복구도 없다** | §4 |
| `DELETE /api/documents`는 **`company`만 주면 그 회사 문서 전부**를 지우며 몇 건이 지워졌는지도 응답에 없다 | §3-1, §3-3 |
| `POST /api/rag/settings`는 **서버 전역 설정**이라 바꾸면 **다른 모든 이용자의 답변까지 바뀐다** | §7 |
| `/api/rag_prompts*` 14종은 **"인증 없는 관리자 API… 외부에 그대로 노출하지 말 것"** | §8 |
| `provider`를 `gpdf`/`opdf`로 주면 **요청 본문이 외부 서비스로 나가며 오류 없이 그대로 나간다** | §6-1 |
| HTTP 200이 성공을 뜻하지 않는다(무근거 `retrieval_success:0`, LLM 오류 접두어, `"실패."` 접미) | §0-3, §6-4, §6-5 |

즉 **연결 방식 자체가 이 기능의 최대 리스크**다. "우리는 그 API를 호출하지 않기로 한다"는 약속은 회귀에 약하다 — 6개월 뒤 누군가 "관리 화면에 문서 목록 좀 붙여주세요"라는 요청을 받으면 그 자리에 `reset`이 한 줄 옆에 있다.

## 결정

### 1. 외부로 나가는 출구는 **`RagHttpClient` 1개 클래스**뿐이다

- 모든 외부 HTTP가 이 클래스를 통과한다. 다른 어떤 서비스도 `fetch`/`axios`로 그 호스트를 직접 부르지 않는다(FR-0-41, AC-N4-6).
- 인증 헤더 주입 지점도 여기 1곳이다 — 외부 서버가 인증을 지원하게 되면 **한 파일만 바뀐다**(FR-N2-12).
- 외부 주소는 `RAG_BASE_URL` 환경변수이며 코드·DB·API 응답에 하드코딩하지 않는다. **미설정이면 2단계는 비활성**이다.

### 2. 경로 allowlist는 **3개**이고, 클라이언트는 **경로를 인자로 받지 않는다**

```ts
export const RAG_PATHS = Object.freeze({
  QUERY: '/api/rag/query',
  STATUS: '/api/status',
  DOCUMENT_METADATA: '/api/documents/metadata',
} as const);

class RagHttpClient {
  query(...)            // POST RAG_PATHS.QUERY
  status()              // GET  RAG_PATHS.STATUS
  documentMetadata()    // GET  RAG_PATHS.DOCUMENT_METADATA
  private send(key: RagPathKey, ...)   // ★ string이 아니라 키만 받는다
}
```

**"호출하지 않기로 한다"가 아니라 "호출할 수 없다"** 로 만든다. 임의 경로 호출 메서드가 없고, `send()`의 파라미터 타입이 `keyof typeof RAG_PATHS`라 문자열 조합으로도 우회할 수 없다.

| 외부 엔드포인트 | 취급 | 근거 |
|---|---|---|
| `POST /api/rag/query` | **허용** | 2단계 본체 |
| `GET /api/status` | **허용** | "연동 시작 전에 이 엔드포인트로 준비 상태를 먼저 보라"(§0-5) |
| `GET /api/documents/metadata` | **허용(관리자 연결 점검 전용, 읽기)** | `company` 오타를 침묵으로 넘기지 않기 위함(부록 B-6) |
| `POST /api/documents/ingest`, `/api/async_task*` | **미구현 — 분리(§4)** | 별도 상태기계·보안 검토 필요 |
| `DELETE /api/documents` · `POST /api/documents/reset` | **미구현 · 금지** | 복구 불가·확인 절차 없음 |
| `GET｜POST /api/rag/settings` | **미구현 · 금지** | 서버 전역 설정 |
| `/api/rag_prompts*` 14종 | **미구현 · 금지** | 무인증 관리자 API |
| `POST /api/summary` | **범위 밖** | No.24 영역 |

### 3. 금지 문자열 0건을 **테스트가 강제**한다

`rag/lib/rag-allowlist.spec.ts`가 `apps/**/src`·`packages/**/src`의 `.ts`를 읽어 금지 경로 문자열 4종의 출현이 **0건**임을 단언한다(`docs/**` 제외, AC-N2-1).

- **검사기 자신이 그 문자열을 포함하면 안 되므로** 탐지어를 조각으로 조립한다(예: `'/api/docum' + 'ents/reset'`). 이 트릭의 이유를 주석으로 남긴다.
- 같은 테스트에서 `RAG_BASE_URL`/`RAG_PATHS` 참조가 `RagHttpClient` 밖에 없음을 함께 단언한다.
- 코드리뷰 상시 점검 항목이기도 하다(둘 중 하나만으로는 회귀를 못 막는다).

### 4. `provider`는 **받는 필드 자체를 만들지 않는다**

클라이언트가 상수 `'pdf'`를 본문에 주입한다. 요청 DTO·설정 스키마·환경변수 어디에도 `provider`가 없다(AC-N2-2).

> 근거: `gpdf`/`opdf`는 **요청 본문을 외부로 보내고 오류 없이 그대로 나간다**(§6-1). **값을 받는 필드가 존재하면 언젠가 누군가 채운다.** 받지 않으면 사고가 원천 차단된다.

같은 원리로 `similarity_threshold`는 **설정에서 비워 두면 전송하지 않는다**(§6-1이 "특별한 이유가 없으면 이 필드를 아예 보내지 말 것"을 권고). 값이 있으면 `0 < v < 1`을 **우리가 먼저 검증**한다 — 외부 서버는 잘못된 값을 **조용히 무시**하기 때문에 검증하지 않으면 실수가 침묵한다.

### 5. 문서 인입(업로드)은 **이번 범위에서 분리**하고, 우리 쪽 아키텍처를 만들지 않는다 (P-3)

요구사항 문서는 인입을 신규 기능 No.48로 제안했으나, **PM이 최종 확정(2026-09-22)했다 — 문서 인입(업로드)도, 삭제·초기화도 우리 시스템(`apps/api`/`apps/web`)에 만들지 않는다.** 운영자가 외부 RAG 시스템에 직접 접근해 문서 생명주기(업로드·삭제·초기화) 전체를 처리한다. 우리 시스템은 이 문서들을 **읽기만**(`GET /api/rag/query`로 검색·`GET /api/documents/metadata`로 연결 점검) 한다. 따라서 **이번 설계 문서뿐 아니라 향후에도 문서 인입·삭제·task 폴링 아키텍처를 만들지 않는다** — No.48은 카탈로그에 신설하지 않고 종결한다.

분리의 기술적 근거(재검토 시 다시 마주칠 문제들)는 다음과 같다.

1. 인입은 기본 비동기 + `task_id` 폴링이고 **진행률이 항상 0**이라 진행 UI를 만들 수 없다(§5-1).
2. **서버 재시작 시 작업 기록이 소실**되어 `not_found`를 "실패"로 오판하지 않는 정책이 필요하다(§5-1).
3. `file_path`로 **서버의 임의 절대경로**를 읽을 수 있다(§1-1) — 별도 보안 검토 사안이다.
4. 파일명이 겹치면 **경고 없이 덮어쓴다**(§1-1).
5. `"삭제 실패"`가 "지울 게 없었다"와 **구분되지 않는다**(§3-3).
6. 재인입 시 청크 수가 줄면 **옛 청크가 남는다**(§1-5).

이번 범위에 넣지 않아도 **기능이 성립한다** — 외부 서버에 이미 문서가 적재돼 있고 2단계는 그 문서만으로 동작한다.

### 6. `GET /api/documents/metadata`는 **읽기 전용 + 스코프 숫자 1개만** 반환한다

- 응답은 JSON 객체가 아니라 **여러 줄 문자열**이다(§2-2) → 순수 파서(`parse-document-metadata.ts`)가 필요하다.
- **API 응답에는 현재 챗봇 스코프의 청크 수 1개만 담는다.** 파싱 결과 전체(= **다른 회사명 목록**)는 서비스 밖으로 나가지 않는다(테넌트 격리, AC-N3-5). PM 확정사항 P-3의 "타 회사명 노출 금지"를 코드 수준에서 보장하는 지점이다.
- `"Graph DB가 로드되지 않았습니다."` 는 HTTP 200이지만 실패다(§2-3) → `UPSTREAM_ERROR`.
- 대화 경로에서는 **절대 호출하지 않는다**(관리자 연결 점검 전용).

### 7. 테넌트 스코프와 PII

- `company`/`category`/`subcategory`는 **서버 보관 챗봇 설정에서만** 읽는다. **공개 대화 요청 본문에서 받지 않는다** — 위젯이 임의 `company`를 보내도 무시된다(AC-N2-3). 이것이 테넌트 경계의 유일한 방어선이다.
- 외부로 나가는 문장은 **PII 마스킹을 통과한다**(ADR-0013의 함수를 그대로 쓴다). 마스킹 지점이 2곳(저장·송신)이 되므로 `packages/pii-mask`로 승격한다. **복제 금지**(AC-N4-7).
- 관리자 시뮬레이션의 `useRag: true` 호출도 같은 경로를 지나므로 **마스킹이 적용된다**(NFR-S18).

### 8. 우리 API에 **RAG 프록시 엔드포인트를 만들지 않는다**

개발명세서 §4의 예고 `POST /rag/query`는 삭제한다. 프록시를 공개하면 **allowlist 봉인이 무의미해지고**(우리 서버가 우회 경로가 된다) 레이트리밋·비용·테넌트 경계가 전부 열린다.

### 9. 무인증·평문 리스크는 **수용하되 배포 전 전제조건으로 명시**한다 (P-4)

현 단계에서는 서버 측 보안 조치를 요구하지 않는다. 다만 **실제 고객 배포 전 ① 내부망 이전 ② 인증 도입 ③ 전송 구간 TLS 중 최소 1개 충족**을 전제 조건으로 건다. 미충족 시 2단계는 구축형 고객사에 제공하지 않는다.

## 결과

**좋아지는 것**
- 파괴적 무인증 엔드포인트가 **우리 코드에서 호출 불가능**하며, 그 사실이 테스트로 고정된다.
- 관리 화면에 위험 버튼이 없다는 것이 "정책"이 아니라 **구조**다(AC-N3-2).
- 외부 API가 바뀌어도 영향 범위가 `rag/` 모듈 안으로 한정된다.
- 우리가 자체 RAG를 만들지 않으므로 GPU 요구가 올라가지 않는다(No.30 GPU 8 → 자체 1).

**나빠지는 것 / 감수하는 것**
- **문서 적재 상태를 우리가 통제하지 못한다.** 문서가 바뀌어도 알 방법이 없고(웹훅 없음) 그래서 답변 캐싱도 할 수 없다.
- 답변 품질이 외부 서버의 프롬프트·검색 방식·모델에 종속되는데 **그 셋을 우리가 바꿀 수 없다**(전역 설정이라 건드리면 안 된다).
- 연결 점검이 "질의를 보내지 않는" 방식이라(FR-N3-7) **실제 답변 품질은 시뮬레이터에서 수동 확인**해야 한다.
- 외부 서버 장애 = 2단계 전면 중단. 회로차단기로 사용자 체감 지연만 막을 수 있을 뿐이다.

## 재검토 트리거

- 외부 서버에 **인증·테넌트 격리**가 도입될 때 → allowlist 확대와 프롬프트 관리 가능성을 재검토.
- 사용자가 **문서 인입을 우리 콘솔에서 하기로 마음을 바꿀 때**(2026-09-22 현재는 최종 종결됨, 재확정 필요) → §5의 6가지 선결 문제부터 푼다.
- RAG 서버가 **고객사 내부망으로 이전**될 때 → §9의 전제조건 해소, 구축형 △ → ○.
- 외부 API가 스트리밍·웹훅(문서 변경 통지)을 지원할 때 → 전달 방식(ADR-0023)과 캐싱 정책을 함께 재검토.
