# ADR-0053 — 시연 하네스 확장(DT-2): 풀 투어 별도 프리셋 · 계획 문맥 기반 조건부 단계 · 모델 장면 선택 플래그 · 고객 시연의 로컬 생성 모델 허용(DT-1 J-13 정책 변경)

- **상태**: 채택(Accepted) — PM 2026-10-02 결정(P-DX-1 = C · P-DX-2 = DT-1 3단계 완료 후 · P-DX-7 = 플래그를 켰을 때만 고객 시연 허용 · P-DX-3/10 = STT 장치 `auto` · 나머지 권고안)
- **일자**: 2026-10-02
- **결정자**: system-architect(방식) · PM(범위·정책)
- **대체하지 않음(정합)**: ADR-0051(DT-1 — 위치·제품 변경 0·Edge·격리·실제 시간·CI 0 전부 유지) · ADR-0046(엣지 추론 — 경량 구성 "동작 보장·품질 미보증"·백엔드 주소 통제) · ADR-0052(음성 AI — 전용 STT 프로세스·기기 안 읽기·음성 원본 저장 0) · ADR-0040(거버넌스 — 출구 허용 정확 일치)

- **관련**: 요구사항 `docs/requirements/demo-harness-expansion.md`(FR-0-349~353 · 접두 DX) · 세부 설계 `docs/02-spec/demo-harness-expansion-설계.md` · 상위 문서 패치 `docs/02-spec/demo-harness-expansion-patches.md`
- **번호**: `docs/02-spec/decisions/` 최대 0052 확인 · 저장소 전체에서 `ADR-0053` 사용은 요구사항 문서의 "예상" 언급 1건뿐(2026-10-02 grep)

## 맥락

DT-1(10분 · 7장면)은 PM 확정 범위이고 3단계 구현이 끝났다. 그 뒤 완료된 No.32(음성)·No.35(선제 안내)·No.37(엣지 추론)과 No.21·36의 미시연 부분을 보여 줄 수단이 없다. 설계 중 코드로 다음을 확인했다.

1. 증강 공급자는 **프로세스 전역 1종**(`AUGMENTATION_PROVIDER`)이라 챗봇·요청 단위로 고를 수 없다.
2. ml-worker 생성 역할은 기동 시 워밍업 요청으로 Ollama 모델을 적재하고, 이후 요청에 `keep_alive`를 보내지 않는다 — 모델은 Ollama 기본 보존 시간 동안 VRAM에 남는다.
3. 3050(4GB)에서 STT `large-v3-turbo` int8은 약 1GB, Ollama 4B 경량 구성은 관찰 약 2.3GB — 동시 적재는 미실측이며 위험하다.
4. Windows에서 STT의 GPU 적재는 pip `nvidia-*` DLL 폴더를 프로세스 `PATH` 앞에 넣어야 한다(제품은 자동 탐색하지 않음 — 운영 문서 절차).
5. 선제 안내 코드는 삽입 코드에 `data-proactive="on"`이 있을 때만 초기화된다. API 삽입 코드에는 없다.
6. DT-1 형식은 구간 9개·단계 ID `S0~S7·S9`·정적 예산 합으로 닫혀 있고, 결과 스키마는 `gpuUsedByHarness`를 `false` 리터럴로 고정한다.

## 결정

### 1. 프리셋 구조 — 별도 풀 투어 프리셋 + 계획 문맥

- 새 프리셋 `customer-onprem-full`. **10분 프리셋의 정의 파일·단계 객체·예산·검증·결과 키 집합은 바꾸지 않는다** — 풀 투어는 DT-1 단계 객체를 그대로 또는 얕은 복사로 재사용한다.
- 실행 전에 **계획 문맥**(`voiceInput: off｜real｜mock` · `sttDevice` · `localLlm` · `liveClustering` · 생략 사유)을 확정하고, 단계·구간은 `when(plan)` 술어로 활성 여부가 정해진다. 예산은 **활성 단계 합**이다. 정의 검사는 대표 계획 16개를 모두 해석해 검사하고, 기본·전부 계획의 총 예산을 선언값과 대조한다.
- 새 구간은 글자 코드 `SV`(음성)·`SP`(선제)·`SE`(엣지)를 쓰고 전역 순서 `opening, s1..s7, voice, proactive, edge, closing`의 부분열만 허용한다 — "⑩ 뒤 음성 장면 금지"가 순서 구조로 강제된다.

### 2. 모델 의존 장면은 선택 플래그로 격리

- `--with-voice-input`(STT 자식 · 가짜 마이크) · `--with-local-llm`(생성 자식 · Ollama · ⑩) · `--live-clustering`(⑦ 실시간 분석). 플래그 없는 실행은 GPU를 어떤 자식에도 노출하지 않는다(FR-0-350). 모든 플래그는 풀 투어 전용(10분판에 주면 시작 전 오류). `pnpm demo:check` 기본 범위는 10분판(P-DX-14).
- 장치·모델이 없을 때: **보이는 시연 = 사전 점검 경고 + 해당 장면 생략 + 이유 표시(P-DX-10)** · **무인 점검 = 차단** · 사용자가 장치를 명시했는데 불가 = 차단. 모의 인식은 무인 점검 전용 옵션(`--voice-mock-check`)으로만.
- 증강 공급자가 전역이므로 `--with-local-llm`이면 ④의 규칙 기반 예문 늘리기(S4-03)를 비활성으로 하고, 같은 기능을 ⑩에서 로컬 생성으로 보인다.

### 3. 자식 프로세스 확장과 GPU 노출 예외

- 자식은 최대 4개: API · 임베딩(CPU 고정 — DT-1 그대로) · 음성(`ML_WORKER_ROLE=speech` · 8102) · 생성(`augment` · 8101 · `CUDA_VISIBLE_DEVICES=-1`, 연산은 Ollama).
- GPU 노출은 **음성 자식이 `cuda`일 때만**. 이때만 `PATH` 앞에 `.venv` 안 `nvidia\{cublas,cudnn,cuda_nvrtc}\bin`을 넣는다 — 시스템 허용 키 값을 바꾸는 유일한 예외이며 코드 1파일로 한정한다. 이는 운영 문서의 Windows 절차를 재현하는 것이지 제품 결함 우회가 아니다(ADR-0051 §2의 `NODE_PATH` 논리와 같음).
- STT 장치 `auto`: GPU·DLL·VRAM 여유·turbo 캐시가 모두 있으면 `large-v3-turbo` int8 cuda, 아니면 `small` int8 cpu. cuda 기동 실패는 cpu로 1회 재기동하고 화면·보고서에 공개한다(조용한 대체 금지).
- API 환경은 계획별로 하네스가 명시한다(`SPEECH_*`·`ML_WORKER_SPEECH_URL`·`AUGMENTATION_*`·`DATA_EGRESS_ALLOWED_HOSTS` 정확 일치 · `PROACTIVE_ENABLED`). **`NODE_ENV`는 넘기지 않는다**(비운영 — 운영 mock 차단은 시연 대상 아님). DT-1 `.env` 4중 방어와 충돌하지 않는다.

### 4. 고객 시연에서 로컬 생성 모델 허용 — J-13 정책 변경(P-DX-7)

- **10분 프리셋**: 변경 없음 — 공연 중 Ollama 사용 0, "GPU 없이" 주장 유지(J-13·AC-DH7-2 그대로).
- **풀 투어 + `--with-local-llm`**: 공연 ⑩에서 사용자가 띄워 둔 Ollama의 경량 구성(4B·4비트)을 쓴다. 조건: ① 자막 "4B 소형 모델 · 이 노트북 GPU · 동작 확인 수준"·"문장 품질은 보증하지 않습니다" 필수 ② 후보는 사람이 고르는 연출(자동 반영 없음) ③ 준비 단계 사전 생성 결과를 대체 화면으로 확보 ④ 0건이면 G1 폴백 사실을 그대로 공개 ⑤ 이 구간 동안 "CPU 동작" 배지 미표시. 하네스는 Ollama를 설치·기동·종료하지 않는다(AC-DH7-2의 "Ollama 프로세스 기동 0"은 문자 그대로 계속 참).
- 3050 순차 적재: 생성 자식 기동(모델 적재) → 사전 생성 → **해제** → STT 기동 → ⑧⑨ → **⑩ 진입 시 STT 종료·VRAM 회수 확인 → 모델 적재** → 생성 → 해제·생성 자식 종료. 적재·해제·확인은 Ollama 공식 API(빈 프롬프트 적재 · `keep_alive: 0` · `/api/ps`)로, 하네스가 쓰는 모델 1개에만 한다. 저장소에 사용 선례가 없어 구현 첫 작업에서 이 PC 버전으로 확인한다.

### 5. 가짜 미디어로 음성 입력 시연

- 공연 브라우저(영속 컨텍스트 1개)를 `--use-fake-device-for-media-stream` + `--use-file-for-fake-audio-capture=<WAV>%noloop`로 띄우고, 마이크 권한은 고객사 모형 출처 1곳에만 부여한다(전역 자동 수락 인자 미사용).
- WAV는 실행마다 Windows SAPI 한국어 음성으로 합성(커밋 0 · `-EncodedCommand`로 인코딩·실행 정책 문제 회피). **한 실행 한 문장 · 공연 중 한 번만 녹음**(사전 점검은 별도 브라우저, 공식 인식 확인은 API 직접).
- 확인 범위는 정확도가 아니라 동작: 일치율 ≥ 0.8(제안) 또는 핵심어 전부 + 기대 의도 답. 자막에 "합성 음성 파일을 가상 마이크로 넣었습니다"를 필수로 띄운다. 관객용으로 같은 WAV를 무대에서 스피커로 재생한다(영상에는 소리 없음 — 공개).

### 6. 결과 스키마 v1 유지 + 최소 확장

- `result.json`은 v1 그대로 두고 선택 필드(`plan`·`models`·`vram`·`speech`·`localLlm`·`downloads`·`proactive`)와 정직성 종류 값을 더한다. **`machine.gpuUsedByHarness`만 `false` 리터럴에서 `boolean`으로 넓힌다**(10분판 값·키 집합 불변).
- 엑셀 내보내기 검증은 새 의존성 없이 파일 형식 + 제품 감사 로그의 행 수로 한다. 하네스 의존성 추가 0 · 루트 설정 변경 0.

## 결과

- **좋아지는 것**: 10분판을 그대로 둔 채 음성(듣기·말하기)·선제 안내·엣지 추론·실시간 분석·엑셀 내보내기·가드레일 현황을 한 명령으로 시연 · GPU 없는 노트북에서도 풀 투어 기본이 끝까지 돈다 · 위젯 마이크 → 서버 STT의 **첫 브라우저 종단 실행**이 무인 점검에 들어온다 · 3050 순차 적재 지점이 코드로 고정되어 공연 중 메모리 부족을 피한다.
- **치르는 것**: 하네스 형식 확장(계획 문맥·조건부 단계·정의 검사 16계획) · 자식 프로세스 +2 · 사용자 Ollama 모델의 일시 적재/해제 · 준비 시간 +1~2분(미실측) · 3050 `auto`에서는 ①~⑨ 동안 "CPU 동작" 배지가 사라진다 · 가짜 미디어·Ollama 해제·WDDM `nvidia-smi` 동작은 실기동 확인 전까지 가정이다.
- **하지 않는 것**: 제품 코드·마이그레이션·제품 의존성·`data-testid` 변경 · 실제 사람 음성·실제 마이크 · STT 정확도·생성 품질 판정 · 영상에 소리 넣기 · 문장 2개 이상 녹음 · 30분판·구독형 · CI.

## 재검토 트리거

- Ollama 해제/적재 API가 이 PC 버전에서 다르게 동작할 때 → ⑩ 사전 생성·대체 방식 재설계.
- Edge 업데이트로 가짜 미디어 인자가 동작하지 않을 때 → Chrome 채널 또는 음성 입력 API 전용 점검으로 축소.
- 제품이 ml-worker에 DLL 자동 탐색을 넣을 때 → `PATH` 주입 제거.
- 증강 공급자를 챗봇·요청 단위로 고르는 기능이 생길 때 → ④ S4-03을 플래그와 무관하게 유지.
- 운영 GPU 시연 서버(L40S)가 생길 때 → 순차 적재 대신 동시 적재 프리셋 검토.
- 리허설에서 풀 투어 상시 시간 생략이 관찰될 때 → 풀 투어 구간 예산만 조정(10분판 불변).
