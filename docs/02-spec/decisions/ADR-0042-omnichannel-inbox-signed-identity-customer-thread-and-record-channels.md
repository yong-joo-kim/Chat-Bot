## 맥락

카탈로그 No.42는 "여러 채널에 걸친 동일 고객 대화를 하나의 스레드로 통합하고, 채널이 바뀌어도 컨텍스트를 유지"하는 **상담원 관점 통합 뷰**다. 선행 그룹이 이 번호로 넘긴 것은 ADR-0009 트리거 ②(서버 대화 영속화 재검토), ADR-0036 트리거(스레드를 채널·챗봇 축으로 확장), No.24의 "여러 챗봇 동시 모니터링·채널 간 동일 고객 식별", No.29·No.14의 "방문자 식별자 없음"이다. 코드 확인 결과 결정할 것은 여덟 가지다.

1. **채널 현실**: 8개 `ChannelType` 중 WEB만 종단 구현이고 공개 파이프라인은 `'WEB'`을 6곳에 하드코딩한다. 외부 채널 실연동에는 계정·공개 HTTPS·심사·자격증명 저장 ADR이 전제인데 지금 하나도 없다. 무엇을 "여러 채널"로 삼나 — 그리고 ADR-0011의 "스텁 어댑터 파일 금지"와 어떻게 공존하나.
2. **같은 사람을 어떻게 아나**: `sessionId`는 탭·챗봇 단위 난수이고, `sessionRef`는 **일부러** 챗봇 사이를 못 잇게 만들어졌다. 최종 사용자 식별자는 시스템 어디에도 없다.
3. **무엇을 저장하나**: 식별자 도입은 새 개인정보 처리 목적이다(원 회원 번호·이름).
4. **같은 사람의 여러 기록을 어떻게 묶고 되돌리나**(오병합 복구).
5. **"볼 일이 생긴" 순간을 어디서 알리나** — 상담 시작은 봉인된 쓰기 파일(H-2)에서, 경고 도달은 fire-and-forget 로그 적재에서 생긴다. No.41이 이미 같은 원천에 포트를 달았다.
6. **로그·통계·학습 큐의 원천성**: 전화 기록·시험 대화가 섞이면 대시보드·질문 순위·학습현황이 오염된다.
7. **개인정보 통제**: 마스킹·암호화·보존·열람 감사를 처음부터.
8. **쓰지 않는 설치의 동작 불변**과 공개 표면(`@Public()` 8) 유지.

## 결정

### 1. 채널 = WEB 실연동 + 기록 채널 + 시뮬레이션 채널 — 외부 채널 실연동 0 (P-1 (b))

- 대화 **출처**를 3계열로 표현한다: `DEPLOY`(배포 채널 — 실제로는 WEB) · `RECORD`(`PHONE｜EMAIL｜VISIT｜OTHER` — 상담원이 적는 기록, **`ChannelType`이 아니다**) · `SIMULATED`(시험 고객 전용 가상 채널 — `ChannelType` 라벨 1개). 라벨·능력은 shared-types 상수 1곳.
- **기록·시뮬레이션은 `ConversationLog`·`UnansweredQuestion`·`MessageFeedback`·통계 원천·업무 자동화 발송함에 쓰지 않는다** — 인박스 모듈이 해당 서비스·포트를 주입하지 않아 **구조적으로** 불가능하다(정적 검사 O-10).
- **시뮬레이션은 어댑터가 아니다** — 콘솔 기능이며 `ChannelAdapterFactory`에 분기·파일을 더하지 않고 기존 `SimulationService.simulate()`를 호출해 결과를 인박스 항목에만 남긴다(모든 화면에 "시뮬레이션" 텍스트 라벨). ADR-0011 57행(빈 구현체가 "구현됐다"는 착시를 만든다)이 금지한 것은 **가짜 어댑터 파일**이며, 이 결정은 그 규약을 **지킨다**.
- **공개 경로의 `'WEB'` 하드코딩 6곳은 1차 무변경**이다 — 공개 파이프라인에 들어오는 채널이 WEB 하나뿐이라 매개변수화는 소비자 없는 추상화다. 2차 외부 채널 ADR의 교체 지점으로 목록화한다(재검토 트리거).
- **C-4**(`live-sessions.service.ts`의 `=== 'WEB'` 분기)는 `CHANNEL_IMPLEMENTATION`과 같은 **속성 표** `CHANNEL_CAPABILITIES`(+ `channelSupportsHandoff()`)로 옮긴다(동작 불변). 표를 읽는 것은 분기가 아니며, 리터럴 비교는 여전히 팩토리·`channel-config.ts` 밖에서 0건이다(O-18).

### 2. 식별 = 호스트 서명 JWT(HS256) · 기존 메시지 요청 헤더 · 상담원 수동 연결 (P-2 (a))

- 고객사 서버가 로그인 회원에 대해 **JWS Compact HS256** 토큰(`sub` 1~128 인쇄 가능 ASCII · `iat` · `exp` 필수 · `nbf`·`name`·`aud` 선택)을 만들고, 위젯이 `POST /public/chatbots/:slug/messages`의 **헤더 `x-cb-identity`**로 보낸다. **새 공개 경로 0**(`@Public()` 8 유지 — 상담 토큰 헤더 선례).
- 검증은 **라이브러리 없는 순수 함수**(`node:crypto`): 헤더 `alg === 'HS256'` 정확 일치(`none`·RS/HS 치환·`crit`·`jku`류 거부) → **페이로드 파싱 전에** HMAC 상수 시간 비교(`__PREV` 병행 비밀 1회 더) → 클레임 형식 → 시각(`exp + 300초`·미래 `iat`/`nbf` 300초·수명 ≤24시간). 실패 사유 7종.
- **실패 = 익명 처리 + 응답·지연·레이트리밋 불변** + 챗봇·사유별 인스턴스 로컬 계수(토큰·`sub` 기록 0). 공격자는 성공 여부를 알 수 없다.
- 비밀 = `OMNI_IDENTITY_SECRET__<REF>`(챗봇 설정의 참조 이름 → 환경변수 · ADMIN `security:write` · DB 값 0 · 32바이트 미만 = 사용 안 함) · **같은 참조 = 같은 식별 공간**(고객 공유). 읽기 1파일.
- 식별은 **참여 챗봇에서만**, **세션당 1회**(세션 식별 캐시) 수행하고 **상담원 보기 묶음에만** 쓴다 — 봇 응답·봉투·공개 응답·상담 게이트·레이트리밋에 영향 0.
- 적재는 **fire-and-forget**(응답 비차단 — 로그 적재 선례).
- 위젯: 임베드 속성 `data-identity-token` 또는 `window.__ChatBotWidget.identify(token|null)`(전역 심볼 1개 유지) → `sessionStorage` 별도 키 → 헤더. `sub`가 바뀌거나(A→B) 로그아웃(A→없음)하면 새 `sessionId`로 새 대화, 로그인(없음→A)은 세션 유지.
- 수동 연결·분리: 상담원(`cs:write`)이 세션(`sessionRef`)을 고객에 연결 · `MANUAL`만 분리. **`IDENTITY` 연결 분리는 ADMIN만**(토큰 재생·발급 실수의 유일한 복구 수단 — 분리 후 그 세션의 식별 토큰 무시).

### 3. 저장 = 식별 공간 솔트 HMAC 해시 + 선택 표시 이름(암호화) — 원 회원 번호 0 (P-5)

- 고객 키 = `HMAC-SHA256(OMNI_CUSTOMER_KEY_SECRET, "cb-omni-customer:v1\n<REF>\n<sub>")` — 서버 비밀(≥32바이트) · 식별 공간(테넌트) 솔트 · 도메인 구분 태그 · 모호성 없는 구분자. **챗봇 id는 솔트에 넣지 않는다**(넣으면 챗봇 간 통합이라는 목적이 사라진다 — `sessionRef`가 일부러 챗봇마다 다른 것과 반대 목적이며, `sessionRef`의 설계 의도는 그대로 남는다).
- 원 `sub`·토큰은 검증 함수 지역 변수로만 존재한다(DB·응답·감사·로그·지도 0 — 전수 grep 시험). 상담원 회원 번호 검색은 **POST 본문**의 번호를 같은 해시로 대조한다(URL·접근 로그 노출 0).
- 표시 이름(선택 `name` 클레임 · 상담원 입력) = 금지어 → PII 마스킹 → 거버넌스 암호화(`CUSTOMER_DISPLAY_NAME`). 고객 키 비밀 지문(8 hex)을 고객 행에 남겨 비밀 교체를 탐지한다(교체 = 통합 끊김 — 운영 금지).

### 4. 묶음 = 연결 행(복사 없음) · 고객 1:1 스레드 · 되돌릴 수 있는 병합 (P-3 · P-6 · P-7)

- **서버에 새로 두는 것은 고객·대화-고객 연결·스레드·기록/메모·태그·병합 기록뿐**이다. 대화 본문은 복사하지 않는다 — 타임라인은 연결된 `(chatbotId, sessionId)`로 기존 `ConversationLog`·`HandoffSession`·`HandoffMessage`를 **읽는다**(마스킹본만 · `rawText` 미선택).
- 연결 = `CustomerLink` **`(chatbotId, sessionId)` 전체 유일 1행**(출처 `IDENTITY｜MANUAL｜SYSTEM` · 재지정 시 이전 고객 기록 → 분리 = 원상 복구). 요구사항 초안의 부분 유니크(`unlinkedAt IS NULL`) 대신 재지정 모델을 택해 **원시 부분 유니크 인덱스 4종을 늘리지 않는다**.
- 스레드는 **"볼 일이 생긴" 순간** 만든다 — 상담 시작 · 경고 단계 도달(챗봇 설정 · 세션당 1회) · 수동 기록/메모 · 상담원이 직접 열기. 익명 세션이면 그때 **익명 고객**을 만든다. 식별 고객의 새 봇 대화만으로는 상태를 바꾸지 않는다(타임라인에만).
- 상태 `OPEN｜PENDING(snoozeUntil?)｜CLOSED` — 보류 해제는 **조회 시점 판정 + 다음 쓰기에서 확정**(새 루프 0). 담당 1명(가져가기 = 조건부 갱신 · 지정·놓기·상태·태그 = `version` CAS). 태그 = ADMIN 관리 전역 목록(≤100 · 스레드당 ≤10).
- 병합: **원본은 익명 고객만**(익명→식별 · 익명↔익명) — 식별↔식별·시험 고객·병합됨·식별 소거 고객은 금지. 병합은 연결·항목·태그를 **옮기고 옮긴 id를 기록**(`CustomerMerge`)하며, 되돌리기(ADMIN 또는 수행자 24시간)는 그 기록으로 원상 복구한다(그 사이 바뀐 연결은 건너뜀 · 역순 강제).
- **승격**: 로그인 전 익명으로 스레드가 열린 세션에 유효 토큰이 오면 익명 고객을 식별 고객으로 **자동 병합**(같은 트랜잭션 메서드 · 주체 system · 되돌리기 ADMIN).
- 스레드 담당 ≠ 상담 담당 — No.24 상담 잠금·토큰·원문 정책은 불변이며 상담 1건은 세션 기준 조인으로 스레드의 **항목**이 된다(`HandoffSession` 컬럼 추가 0).

### 5. 원천 신호 = No.41 포트와 분리한 순수 포트 · 커밋 후 fire-and-forget

- `common/inbox/inbox-signal.port.ts`(토큰 `INBOX_SIGNAL_SINK` · 판별 키 `signal` · `signal(): void`). 원천 2곳이 `@Optional()` 주입해 1줄씩 부른다: `handoff-thread.service.ts` `createHandoff` 트랜잭션 성공 뒤 `HANDOFF_OPENED` · `conversation-log.service.ts` `record` 적재 뒤 `TURN_RECORDED`. 원천 트랜잭션·쓰기 데이터·반환·예외 불변(H-2·H-3·H-7).
- **No.41 `WORKFLOW_EVENT_SINK`를 재사용하지 않는다**: 그 이벤트에는 `sessionId`가 없고(상담 이벤트는 `sessionRef`만), 토큰은 단일 제공자(`useExisting WorkflowTriggerService`)라 공유하려면 팬아웃 합성기로 No.41 DI 배선·봉인(W-15·W-16)을 바꿔야 하며, 인박스 처리 실패가 발송 적재와 한 경로에 묶인다.
- 경고 판정은 No.24 `evaluateSessionAlert()` 1벌(최근 30행 · 임계 = 챗봇 상담 설정)이며 `openOnWarning` 참여 챗봇의 미응답 턴에서만 DB를 읽는다. 비참여·응답 턴 = DB 0(참여 캐시 — 1쿼리/30초/인스턴스).

### 6. 개인정보 = 마스킹 → 암호화 → 보존 소거 · 열람 감사 +3 (P-10)

- **ADR-0013 여섯 번째 적용 지점 = 인박스 저장**(메모·수동 기록·시뮬레이션 입력/출력·표시 이름) — `maskPii()` 1벌 · `PII_MASK_MODE` 반영 · 원문 저장소 0 · 기록·메모에는 금지어 필터 비적용(내부 기록).
- **필드 암호화 +2**(`INBOX_ENTRY_TEXT`·`CUSTOMER_DISPLAY_NAME` — 봉인 = store 1파일 · 개봉 = 리더 1파일 · 영구 데이터라 **백필·재암호화 잡·기동 옛 키 검사 편입**). 고객 키 해시는 대상 아님(검색 키 · 비가역).
- **보존 종류 +2(전역만)**: `INBOX_TEXT`(항목 본문 소거 — 스레드 상태 무관) · `CUSTOMER_IDENTITY`(마지막 활동 기준 해시·표시 이름·지문 소거 — 행·연결·수치 유지, 같은 `sub`는 새 고객). 기존 No.45 파기 잡·writer 1파일에 편입(새 루프 0). 보존 저장 스키마의 새 키는 **선택**(기존 6키 요청 불변).
- **열람 감사(`VIEW`) +3**: 인박스 목록 · 스레드 상세(타임라인 페이지 포함) · 고객 검색(8 → 11). 쓰기 감사 대상 +3(`Customer`·`InboxThread`·`InboxTag`) — 연결·분리·병합·되돌리기·상태·담당·태그 목록·설정·시험 고객. 메모·기록·태그 부착·자동 열림·식별 연결은 비감사.
- 새 외부 출구 0 · 새 백그라운드 루프 0.

### 7. 권한 · 참여 · 환경 (P-8 · P-9)

- **신규 권한·역할 0**: 조회 `cs:read` · 처리 `cs:write` · 태그 목록·`IDENTITY` 분리·승격 되돌리기 = ADMIN 서비스 재검증(강제 인수 선례) · 시험 고객·시뮬레이션 = `simulation:write` AND `cs:read` · 참여 설정 = `chatbot:write` · 식별 비밀 참조 = `security:write`.
- 챗봇별 **참여 설정 1:1**(기본 꺼짐 · 환경 밖 — 저장 즉시 운영 반영 · 스냅샷·복사 대상 아님 · 영구삭제 동반 삭제). 연결은 영구삭제 사전검사 16종째. 전역 스위치 `OMNI_INBOX_ENABLED`(`false` = 인박스 API 404 · 식별 검증 0).

### 8. 쓰지 않는 설치는 바이트 단위로 같다 (FR-0-183)

헤더 없는 공개 턴 = 어댑터 `identity` 키 부재 → 분기 미진입 · 추가 조회 0. 헤더 있음 + 비참여 = 메모리 캐시 확인만. 신호 = 참여 캐시에 없으면 즉시 반환. 엔진·봉투·ml-worker·공개 응답 스키마 변경 0 · No.24 기존 응답 불변(고객 카드는 신규 조회 경로). 예외(의도된 변경): 보존 조회 `kinds` 6 → 8 · 열람 감사 목록 8 → 11 · 컨트롤러 40 → 45 · 영구삭제 사전검사 16종(설계서 §21.3 닫힌 목록).

## 근거

- **"세션 테이블"이 아니라 "고객 + 연결 + 스레드"**: ADR-0009 근거 61행이 예고한 대로 필요한 것은 순간 상태가 아니라 대화 스레드다. 모든 세션에 행을 만들지 않고 **볼 일이 생긴 세션과 식별된 세션만** 연결 행을 가지므로 만료 배치가 필요 없고, 봇 대화 상태는 계속 봉투라 엔진·시뮬레이터·TC·버전 결과가 바이트 단위로 지켜진다.
- **서명 토큰이 유일하게 안전한 자동 식별**: 서명 없는 외부 ID는 남의 ID를 넣어 남의 스레드에 끼어들 수 있고, 연락처 자동 병합은 폼 원문 처리 지점을 새로 만들며 오병합률이 높다. 호스트 서명은 위조 불가 + 동의·고지 책임이 호스트에 있다.
- **식별을 상담원 보기에만 쓰는 이유**: 식별이 봇 답·위젯 이력·권한에 쓰이는 순간 토큰 재생·탈취가 정보 유출이 된다. 보기 묶음에만 쓰면 재생 이득이 "상담원 화면 오염"으로 한정되고, ADMIN 분리로 복구된다 — `jti` 저장소 없이도 위험이 닫힌다.
- **라이브러리 없는 HS256 고정 검증**: 받는 알고리즘이 하나라 헤더 기반 알고리즘 선택 로직 자체가 없다(알고리즘 혼동 공격면 0). JWT 형식은 발급 측(고객사) 편의를 위해서만 따른다.
- **HMAC(서버 비밀) 해시**: 회원 번호는 공간이 작아(순번·전화번호) 단순 SHA-256은 DB 유출 시 사전 대입으로 되돌려진다. 서버 비밀이 있어야 해시를 만들 수 있다.
- **연결 행 + 이동 기록**: 복사 방식 통합은 되돌릴 수 없고 원천 봉인(로그·상담 쓰기 파일)을 깬다. 연결만 옮기면 분리·되돌리기가 원상 복구이고 원천 행은 한 번도 바뀌지 않는다.
- **로그 밖 기록**: 대시보드·질문 순위·학습 큐·만족도는 "실제 공개 대화"만의 원천이다(ADR-0033 봉인). 전화 기록·시험 대화를 같은 테이블에 넣으면 모든 통계가 필터를 기억해야 한다 — 다른 테이블에 두면 필터가 필요 없다.

## 감수하는 비용

1. **유효 기간 내 토큰 재생은 탐지하지 않는다** — 이득이 상담원 화면 오염뿐이고 ADMIN 분리로 복구한다. 짧은 수명(권장 1시간)을 연동 가이드에 명시한다.
2. **고객 키 비밀 교체 = 기존 고객과 통합 끊김**(원 `sub` 미저장이라 재해시 불가) — 교체 금지 운영 규칙 + 지문 경고.
3. **식별 실패 통계는 인스턴스 로컬**, 참여 설정 수렴은 다른 인스턴스에서 최대 30초.
4. **신호 발행 전 강제 종료 시 스레드 열림 유실**(커밋 후 fire-and-forget — 감사 기록과 같은 수용).
5. **이름 부분 일치 검색은 최근 활동 N명 범위**(암호문 `LIKE` 불가).
6. **식별은 로그인 회원만** — 익명 방문자는 수동 연결 전까지 세션 단위.
7. **공개 경로 `'WEB'` 하드코딩이 남는다** — 2차 외부 채널 착수 시 교체 지점 6곳을 한 ADR로 바꾼다.
8. **동의·고지는 기술로 강제할 수 없다** — 호스트(고객사) 책임을 연동 가이드·계약에 명시한다(EX-OC-21).
