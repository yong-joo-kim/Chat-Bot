## 맥락

카탈로그 No.35는 "이탈 징후/이벤트 트리거 기반 챗봇 선제 대화 시작"이다. 코드 확인 결과 지금 "봇이 먼저 말을 걸 수 있는" 곳은 **방문자가 보고 있는 웹 페이지 안(위젯)** 뿐이다 — 외부 채널 송수신 구현 0(`channel-adapter.factory.ts` 15~21행), 서버 → 위젯 상시 통로 0(ADR-0009), 입력 없이 봇 턴을 만드는 엔진 경로 0(`conversation.ts` 268~277행 · `turn.ts` 76~89행). 사용자는 2026-09-29에 **규모 A(웹 위젯 · 규칙 기반)**, **트리거는 "페이지 머묾" 1종만**, **닫음 기억은 탭 세션(`sessionStorage`)**, **측정은 숫자만**, **말풍선만(자동 열기 없음 · 휴대폰 기본 꺼짐)**, **이용 도움 안내로 한정(광고 아님 확인 감사)** 을 확정했다. 결정할 것은 열두 가지다.

1. **어디에 무엇을 저장하나** — 챗봇 스위치를 `strict`인 `WebChannelConfigSchema`에 넣을지(No.44 `feedbackEnabled` 선례), 별도 테이블로 둘지. 규칙·집계는?
2. **공개 표면** — 페이지마다 규칙을 받아야 한다. 새 공개 경로를 만들지, 기존 설정 조회를 늘릴지. 표시·클릭·닫기 수는 어떻게 받나. `@Public()`은 최대 +1.
3. **레이트 리밋** — 페이지 로드 조회가 대화 전송과 같은 `ip` 버킷(120/분)을 쓰면 같은 회사망(NAT) 뒤 대화가 429를 맞는다. 그런데 버킷 지정 데코레이터는 **핸들러 단위 고정**이다.
4. **개인정보** — 어떤 페이지를 얼마나 봤는지는 행동 정보다. 판정 위치와 서버로 가는 것.
5. **엔진** — 말풍선 클릭을 어떻게 대화로 잇나.
6. **노드 유효성** — 엔진은 없는(또는 꺼진) 노드로 가는 버튼을 폴백 응답으로 처리한다(`resolver.ts` 861~867행).
7. **바이트 동일** — 기능을 쓰지 않는 챗봇·사이트·구버전 위젯의 요청·응답이 변하면 안 된다.
8. **위젯 구조** — 상태 알림 영역(`#cb-status`)은 패널 **안**에 있다. 기능 선언은 상한 5 중 3 사용.
9. **캐시** — 조회 응답을 캐시할지.
10. **감사·거버넌스** — "광고 목적 아님" 확인의 기록 방식, 데이터 지도, 보존, 출구.
11. **확장 여지** — 보류된 트리거 2종(사이트 신호 · 대화 중 연속 미응답)을 나중에 붙일 자리.
12. **ADR 번호** — 보류 초안 두 건의 가번호와의 충돌.

## 결정

### 1. 저장 = 새 테이블 3개 · `WebChannelConfigSchema`는 건드리지 않는다

- 챗봇 스위치·세션 상한·최소 간격·대화 뒤 조용한 시간 = **1:1 `ChatbotProactiveSetting`**(행 없음 = 꺼짐 — `ChatbotHandoffSetting`·`ChatbotInboxSetting` 선례).
- 규칙 = **`ProactiveRule`**(챗봇 소속 · 이름 정규화 유일 · 순서 `position` · 트리거 JSON(판별 유니온) · 문구 · 버튼 JSON · 기기 · 게시 기간 · 표시 시간대 · 용도 확인 시각/확인자).
- 집계 = **`ProactiveDailyStat`**(`(ruleId, dayBucket)` 유일 · 규칙 이름 스냅샷 · 표시·클릭·닫기·끄기 정수 4개 · **세션·IP·주소·시각 원본 컬럼 없음** · `ruleId`는 FK 없음 — 규칙을 지워도 통계가 남는다).
- 마이그레이션 1개 = `CREATE TABLE` 3 + 인덱스뿐. 기존 테이블은 컬럼 0 변경(Chatbot은 Prisma 역참조 필드만 — DB 변화 0). 부분 유니크 인덱스 추가 0.
- **기각 — `WebChannelConfigSchema`에 선택 키 추가(No.44 방식)**: 이 스키마는 `.strict()`이고 서버는 저장값을 `parseChannelConfig()`로 읽는데, **파싱에 실패하면 기본값으로 폴백**한다(`channels/lib/channel-config.ts` 8~18행). 새 키가 저장된 뒤 구버전 서버로 되돌리면(롤백) 그 서버는 WEB 설정 전체를 기본값으로 읽는다 — 인사말·빠른 선택이 사라지고, **`allowedOrigins`가 빈 배열이 되어 Origin 가드가 모든 출처를 허용**한다(`origin-match.ts` 16행 · `public-origin.guard.ts` 44~50행). 롤백 한 번이 조용한 보안 완화가 된다. No.44는 이 위험을 한 번 감수했지만(ADR-0038 §5) 두 번째로 늘리지 않는다. 또 규칙은 여러 개이고 통계와 이어지므로 JSON 한 칸에 담기에도 맞지 않는다.
- 비용: 스위치 판정에 쿼리 1개가 더 든다 — 단 **선제 안내를 요청한 조회(§2)에서만**이고 대화 턴에서는 0이다(대화 경로는 이 테이블을 읽지 않는다).

### 2. 공개 표면 = 기존 설정 조회의 선택 확장(새 `@Public()` 0) + 수집 경로 1개(`@Public()` 8 → 9)

- **규칙 조회** = `GET /public/chatbots/:slug/config?proactive=1`. 쿼리 값이 정확히 `1`일 때만 응답 **맨 끝**에 선택 키 `proactive: { caps, rules[] }`를 붙인다. 쿼리가 없거나 다른 값이면 **핸들러·서비스 호출·쿼리 수·응답 바이트가 도입 전과 같다**(서비스는 기존 `getConfig(slug)` 그대로 호출된다). 구버전 서버는 모르는 쿼리를 무시하므로 신버전 위젯은 `proactive` 키가 없으면 아무것도 하지 않는다.
  - 새 조회 경로를 만들지 않는 이유: 말풍선은 챗봇 이름·스킨 색·런처 위치·런처 숨김(EX-PA-7)이 필요한데 이는 전부 이미 설정 조회 응답에 있다 — 한 번의 요청으로 끝난다. 새 경로를 만들면 수집 경로와 합쳐 `@Public()` +2가 되어 제약(최대 +1)을 넘는다.
- **수집** = `POST /public/chatbots/:slug/proactive-events` 본문 `{ sessionId, ruleId, kind: SHOWN｜CLICKED｜DISMISSED｜OPTED_OUT }`(`.strict()` — 주소·체류 시간·리퍼러를 담을 필드 자체가 없다) → **항상 `204`**(결합 검증 불일치·중복·서버 스위치 꺼짐도 같은 응답 — 규칙 존재 탐지 불가). 슬러그 판정(없음 404 · 비공개/채널 꺼짐 403)은 기존 공개 규약 그대로다(ADR-0011 §3).
  - 기각 — 수집을 대화 요청에 싣기: 클릭만 셀 수 있고(표시 수를 몰라 닫기율 계산 불가 — 측정 목적 상실) 엔진 경로에 새 필드가 생긴다. 기각 — 설정 조회(GET)에 사건을 싣기: GET 부수효과 금지 규약(개발명세서 §4.1).
- 새 핸들러는 `PublicConversationController`의 **맨 끝**에 둔다(기존 봉인 시험의 "핸들러 앞 N자" 창 검사를 건드리지 않는다). 공개 규약(Origin 가드·내부 필드 미노출)을 전부 상속한다.

### 3. 레이트 리밋 = 전용 버킷 2종 · 설정 조회는 "조건부" 전용 버킷

- `PublicRateBucketSpec`을 넓힌다(기존 값의 의미 불변): `kind` +`PROACTIVE_RULES`·`PROACTIVE_EVENT` · `key`를 **선택**으로(없으면 IP축만) · 키 출처 +`'body'` · 선택 필드 **`when: { query, equals }`** — 조건이 맞지 않으면 **데코레이터가 없는 것과 똑같이** 기존 `ip`·`session` 버킷을 소비한다.
- `getConfig`에 `@PublicRateBucket({ kind: 'PROACTIVE_RULES', when: { query: 'proactive', equals: '1' } })` → 선제 조회만 `pa-rules-ip`(기본 300/분)를 쓰고 **대화의 `ip` 버킷을 소비하지 않는다**. 선제 안내를 요청하지 않는 설정 조회(런처 클릭)는 현행대로 `ip` 버킷.
- 수집은 `pa-ev-ip`(기본 300/분) + `pa-ev-key:session:{본문 sessionId}`(기본 20/분). 가드는 파이프보다 먼저 돌지만 본문은 이미 파싱되어 있다(기존 `session` 버킷이 같은 방식으로 `req.body.sessionId`를 읽는다).
- 기각 — 선제 조회를 새 핸들러로 분리해 버킷을 고정: `@Public()` 제약 초과(§2). 기각 — 대화 `ip` 버킷 공유: 요구사항 C-11.

### 4. 개인정보 = 판정은 브라우저에서만 · 서버로 가는 것은 슬러그·규칙 id·사건 종류·세션 id뿐

- 경로 조건·체류 시간·탭 가시성·세션 상한·간격·닫음 억제·기기·표시 종료 시각 비교는 **위젯 안의 순수 함수**가 한다. 서버는 규칙 정의·켜짐·게시 기간·표시 시간대(KST)·노드 유효성·금지어만 판정한다(J-9 · FR-0-242).
- 위젯의 선제 요청 2종은 **`referrerPolicy: 'no-referrer'`** 로 보낸다 — 같은 출처 배포(구축형에서 흔함)에서 브라우저 기본값은 페이지 **전체 주소**를 `Referer`로 보내기 때문이다. 조회 URL에는 페이지 정보가 없고 수집 본문에는 주소 필드가 없다.
- 서버 저장 = 규칙(관리자 작성 텍스트) + 규칙·일별 정수. 중복 억제용 `(sessionId, ruleId, kind)`는 **해시로 메모리에만**(상한·TTL · 재시작 시 소멸) 둔다. 식별 토큰·고객 정보는 읽지도 쓰지도 않는다(ADR-0042 J-7 불변).
- 위젯 브라우저 저장 = `sessionStorage` 키 1개 `cb.pa.{slug}`(표시 수·마지막 표시 시각·닫은 규칙 id·끄기·마지막 사용자 전송 시각) — **localStorage·쿠키 0 원칙 유지**(`core/session.ts` 3~6행 · 정적 검사).

### 5. 엔진 변경 0 = 말풍선은 화면 표시일 뿐 · 클릭은 평범한 버튼 턴

- 말풍선 표시·닫기·끄기는 **대화 요청을 만들지 않는다** → `ConversationLog` 0행(방문·턴·미응답·질문 순위·학습 큐 불변).
- 버튼 동작은 기존 버튼 항목 형식 `{ label, action: NODE｜MESSAGE｜LINK, value }`(`ButtonItemSchema` 계열)을 그대로 쓴다. 위젯은 이를 `toOutputViews()`로 바꿔 **기존 `handleButtonAction()`에 넘긴다** — `NODE`는 창을 연 뒤 `buttonAction: { kind: 'NODE', nodeId, label }` 턴(엔진 `resolveByNodeId` — `resolver.ts` 817~819행), `MESSAGE`는 사용자 말풍선 + 문장 턴, `LINK`는 새 탭. 공개 메시지 요청·응답 스키마, `resolveTurn`, 대화 서비스의 `sendMessage` 경로 변경 0.
- "노드 id만 알면 바로 진입"은 기존 성질이며 넓히지 않는다(공개 경로가 받는 버튼 동작·검증 불변 — NFR-PAS4).
- **위젯 기능 선언은 추가하지 않는다**(3/5 유지). `proactive-v1`은 대화 **응답**에 선제 제안을 싣는 2차 트리거(연속 미응답)가 생길 때만 필요하며 그때 4/5가 된다 — 이번에는 메시지 요청 바이트까지 불변이다.

### 6. 노드 유효성 = 조회 시점에 "지금 서비스 중인 번들"로 판정 · 삭제는 막지 않고 경고

- 공개 조회에서 `NODE` 버튼이 가리키는 노드가 **서비스 중 번들에 켜진 상태로 없으면 그 규칙 전체를 내려보내지 않는다**(버튼 하나만 빼면 문구와 버튼의 의미가 어긋난다). 서비스 중 번들 = 공개 대화와 **같은 소스 선택 함수**(`public-conversation.service.ts`의 `loadServing()` — 초안 캐시 또는 운영 포인터 버전 · 비활성 토픽 제외)를 **클로저로 넘겨** 얻는다. 파일 안 소스 선택 지점 1곳(E-9 — `bundleSourceOf(`·`.getCached(`·`versionBundles.get(` 각 1회)은 그대로다. 버전 읽기 실패면 선제 규칙을 비운다(닫힌 쪽).
- **노드 삭제는 막지 않는다**(요구사항 EX-PA-4 · AC-PA9-1). 대신 ① 콘솔 규칙 목록에 "연결 대상 없음 — 표시되지 않음" ② 노드 삭제 확인 창에 "이 노드를 가리키는 선제 안내 N개"(콘솔이 기존 규칙 목록 API로 계산 — 대화 설계 API·`reference-check.service.ts` 변경 0) ③ 이미 떠 있던 말풍선이 눌리면 엔진 폴백(허용된 짧은 구간 — 캐시를 두지 않아(§9) 다음 페이지 로드부터 사라진다).
- 기각 — `409 NODE_IN_USE`로 삭제 차단(상담 종료 버튼 선례): 운영 전환·토픽 비활성·버전 복원처럼 삭제가 아닌 경로로도 노드가 사라지므로 차단만으로는 닫히지 않고, 규칙 때문에 대화 설계 작업이 막히는 것은 요구사항이 원하지 않았다.
- 규칙·스위치는 **환경 밖 · 스냅샷 밖**(인사말과 같은 채널 표시 설정 계열) — 복원·운영 전환·예약 실행이 바꾸지 않는다. 챗봇 복사·토픽 분리는 규칙을 복사하지 않는다.
- 금지어가 나중에 추가돼 기존 문구에 걸리면 조회에서 그 규칙을 뺀다(EX-PA-12). **허용 도메인 목록은 공개 경로에서 읽지 않는다**(ADR-0043 §7 · 봉인) — `LINK` 주소는 저장 시점에만 검사하고, 목록이 나중에 좁아지면 콘솔이 경고한다(알려진 제한).

### 7. 바이트 동일 보장 = "요청 표시가 없으면 새 코드가 실행되지 않는다"

| 대상 | 보장 방식 |
|---|---|
| `GET …/config`(쿼리 없음) | 컨트롤러가 `getConfig(slug)`를 현행 인자로 호출 · 서비스는 선제 분기 전에 기존 객체를 그대로 반환 · 가드 조건 불일치 = 현행 버킷. 도입 전 커밋에서 캡처한 **응답 본문 골든 문자열**과 쿼리 수로 시험 |
| 구버전 위젯 | 선제 조회·수집을 부르지 않고, 메시지 요청·응답 경로는 이 그룹이 바꾸지 않는다 |
| 신버전 위젯 + 삽입 속성 없음 | 선제 코드가 초기화되지 않는다 — 네트워크 요청·타이머·이벤트 리스너·`sessionStorage` 쓰기 0 · 기능 선언 배열 불변 |
| 스위치 꺼짐 · 규칙 0 | 설정 조회(쿼리 없음)·대화·보류 폴링·상담 폴링·평가·시뮬레이터·TC·로그·통계 불변. 데이터 지도는 규칙·켜진 스위치가 모두 0이면 선택 키를 생략 |

### 8. 위젯 = 패널 밖 말풍선 + 패널 밖 상태 알림 영역 · 타이머 1개 · 경로 폴링

- 선제 안내가 켜진 사이트에서만 패널 **밖**(런처 옆)에 말풍선 요소와 **별도 `role="status"` 알림 영역**을 만든다(패널 안 `#cb-status`는 불변). 등장 시 포커스·스크롤 이동 0 · 자동 열기 0 · 정중 알림 1회 · 자동 사라짐 없음 · `prefers-reduced-motion`이면 애니메이션 없음.
- 체류 판정은 **페이지당 타이머 1개**(1초 간격 · 탭이 숨으면 멈춤 · 경과 시간은 시계 차이로 누적). SPA 경로 변경은 같은 틱에서 `location.pathname`을 비교해 감지한다 — **호스트 페이지의 `history.pushState`를 가로채지 않는다**(호스트 코드 변조 금지). 조건·상한·억제 판정은 DOM 무의존 순수 함수 1벌(`@chat-bot/shared-types/proactive-eval` — zod 무의존 서브패스, ADR-0012 방식)을 위젯과 콘솔(경로 검사 도구·미리보기)이 같이 쓴다.
- 경로 패턴은 **정규식 없이** 세그먼트 단위 선형 비교(`*` = 한 단계 · `**` = 0개 이상 단계 · 부분 세그먼트 와일드카드 불허 · 패턴 ≤200자 · `**` ≤2개). 쿼리·해시는 비교하지 않는다.
- 번들 증가 추정 gzip +3.5~4.5KB(현재 15.76KB → 약 20KB · 권고 ≤5KB · 예산 100KB). vanilla·런타임 의존성 0 유지 — ADR-0012의 Preact 재검토 트리거는 **발동하지 않는다**.

### 9. 캐시 = `Cache-Control: no-store` 유지

- 요구사항 FR-PA5-8은 짧은 캐시를 허용했지만 **두지 않는다**. ① 규칙을 끄거나 노드를 지운 뒤 **다음 페이지 로드부터 즉시** 반영된다(EX-PA-4 구간 최소화) ② 핸들러의 `@Header('Cache-Control', 'no-store')`는 정적이라 쿼리별로 바꾸려면 응답 객체를 직접 다뤄야 하고, 그러면 쿼리 없는 조회의 헤더 동일성을 증명하기 어려워진다 ③ 부하는 전용 버킷과 조회 비용(추가 쿼리 1~2 · 번들·금지어는 기존 캐시)으로 통제한다.
- 재검토 트리거: 선제 조회가 공개 API 부하의 상위를 차지한다는 실측(규칙 결과 서버 메모이즈 → 그다음 HTTP 캐시 순).

### 10. 감사·거버넌스 = 감사 대상 +1 · 용도 확인은 행 + 감사 요약 · 출구·보존·암호화 추가 0

- `AuditTargetType` +`ProactiveRule`(34 → 35) — 생성·수정·삭제·켜기/끄기·순서 변경. 화이트리스트는 이름·켜짐·순서·트리거·기기·기간·시간대·용도 확인 시각이며 **문구·버튼 라벨/값은 감사 본문에 넣지 않는다**(바뀐 항목 **이름**만 요약에 — FR-PA7-5). 챗봇 스위치·상한 변경은 `UPDATE Chatbot`(전후 `proactive` 객체 — No.46 허용 도메인 선례) · 값이 같으면 감사 없음.
- "이 안내는 광고·판촉 목적이 아닌 이용 도움 안내입니다" = 요청 필드 `purposeConfirmed: true` **필수**(생성·수정 모두) → 행에 `purposeConfirmedAt`·`purposeConfirmedById` 저장 + 감사 요약 "광고·판촉 목적 아님 확인". 법적 판단이 아니라 운영자 확인의 기록이다(법무 확인 필요 — 요구사항 조사 한계 ①).
- 거버넌스 모드 ON에서도 동작 동일 — **외부 출구 0**(서버는 어디에도 송신하지 않는다 · `EgressExitId` 7 불변). 보존 종류 추가 0(집계는 개인정보 없는 숫자 — 챗봇 영구삭제 시 동반 삭제). 암호화 대상 추가 0. 데이터 지도 선택 키 `proactive?`(규칙·스위치 0이면 생략): 규칙 수·켜진 규칙 수·사용 챗봇 수·"집계 = 규칙·일별 숫자(개인 식별 정보 없음)"·"브라우저 저장 = `sessionStorage`(탭 종료 시 삭제)".
- 권한 신규 0 — 조회·통계 `channel:read` · 변경 `channel:write`(인사말과 같은 등급).

### 11. 확장 여지 = 판별 유니온 1분기 + 위젯 판정기 1개 (이번엔 만들지 않음)

- 트리거 스키마는 `kind` 판별 유니온이며 1차 분기는 `PAGE_DWELL` 하나다. 서버 공개 조회는 "위젯이 판정할 수 있는 종류" 닫힌 목록으로 거른다.
- **사이트 신호(`HOST_SIGNAL`)** 를 붙일 때: 유니온 분기 + 위젯 전역 `window.__ChatBotWidget.signal(name)`(이름만 · 인자 무시) + 판정기 1개 — 서버 공개 표면 변화 0.
- **대화 중 연속 미응답(`UNANSWERED_STREAK`)** 을 붙일 때: 서버 전용 규칙(공개 조회에서 제외) · 판정은 `handoff/lib/session-alert.ts`의 `evaluateSessionAlert` 1벌 재사용(No.24·No.41과 같은 수치) · 공개 메시지 응답 **선택 키 1개**(없으면 바이트 동일) · 위젯 기능 선언 `proactive-v1`(4/5). 이것은 대화 경로를 바꾸므로 **그때 이 ADR에 갱신 각주**를 단다.

### 12. ADR 번호 = 가번호는 예약이 아니다

- 요구사항 초안의 "ADR-00NN(가번호)"는 번호를 예약하지 않는다. **구현이 확정되어 설계 단계에 들어간 그룹이 그 시점의 다음 빈 번호를 쓴다.** 보류 초안 `plugin-marketplace.md`·`connector-hub.md`는 재개 시 다음 빈 번호(이 결정 이후라면 0046 이상)를 새로 잡고 본문 가번호 표기를 고친다.

## 결과

### 얻는 것

- 지금 기술적으로 가능한 유일한 곳(웹 위젯)에서, 엔진·대화 경로·채널 설정 스키마를 건드리지 않고 되돌리기 쉬운 형태로 시작한다(테이블 3개 DROP + 속성 제거 = 완전 철회).
- 방문자 행동 정보가 서버에 닿지 않는다 — 판정은 브라우저, 서버는 규칙과 일별 숫자.
- 기능을 쓰지 않는 모든 설치·사이트·구버전 위젯이 바이트 단위로 같다.
- 닫기율로 "성가신 안내"를 운영자가 볼 수 있다.

### 감수하는 것

- 공개 경로 +1(`@Public()` 9) — 누구나 가짜 수치를 보낼 수 있다(전용 버킷·결합 검증·세션당 1회·"참고치" 표기로 완화). 봉인 시험 6개 파일의 `@Public()` 개수 기대값이 바뀐다(닫힌 목록 — 설계서 §16.3).
- 설정 조회 핸들러에 조건부 버킷이라는 새 규칙이 생긴다(가드 1곳의 분기).
- 선제 안내를 켠 사이트는 **페이지를 열 때마다 요청 1건**이 늘고 캐시가 없다.
- 탭마다 상한이 따로 적용되고(여러 탭 = 여러 번), 재방문하면 다시 뜰 수 있다(P-3 (a)의 성질 — 버튼 문구로 정직하게 알린다).
- 해시 라우팅 SPA(`#/order`)는 경로 조건으로 구분할 수 없다(경로만 비교 — `/**`로만 걸 수 있음).
- 허용 도메인 목록이 나중에 좁아져도 기존 `LINK` 규칙은 공개 조회에서 걸러지지 않는다(콘솔 경고로만).
