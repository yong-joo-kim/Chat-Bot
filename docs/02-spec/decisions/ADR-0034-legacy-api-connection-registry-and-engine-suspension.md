## 맥락

카탈로그 No.26은 "대화상자 조건에 외부 API(GET/POST) 연결, 응답값 실시간 매핑·출력"이다. ADR-0008 §4는 "`UNSUPPORTED_OUTPUT_TYPES`에서 값을 빼는 것만으로 실행이 열린다"고 예고했으나 코드상 성립하지 않는다.

| 사실 | 근거 |
|---|---|
| 엔진은 DB·Nest 무의존 **동기 순수 함수**이고 예외를 던지지 않는다 — `await fetch`할 자리가 없다 | `packages/dialogue-engine/src/resolver.ts:115-126`, `outputs.ts:28-33` |
| `API_CONDITION`의 URL·**인증 헤더(평문)** 가 노드 JSON 안에 있어 번들·스냅샷·오버레이·노드 복사·노드 조회 응답으로 퍼진다 | `packages/shared-types/src/dialogue.ts:520-530`, `dialog-nodes.service.ts:311` |
| 노드 조회는 `dialogue:read`이고 **VIEWER가 이 권한을 가진다** — 지금도 VIEWER가 토큰을 평문으로 읽을 수 있다 | `dialog-nodes.controller.ts:35-36·57-58`, `security.ts:48` |
| 응답값 매핑·실패/불일치 분기가 없고 `bodyTemplate`은 자유 문자열(인젝션 여지)이다 | `dialogue.ts:524-530` |
| `conditions[].nextNodeId`가 참조 무결성 4곳에서 모두 빠져 있다(잠재 결함) | `design-validator.ts:5-18`, `dialog-nodes.service.ts:92-104`, `reference-check.service.ts:132-158`, `snapshot-integrity.ts:83-101` |
| 웹 미지원 배지는 공유 상수를 쓰지 않고 타입을 하드코딩한다 | `apps/web/src/pages/dialogue/components/DialogOutputEditor.tsx:126` |
| 개발명세서는 "연동 착수 시점에 암호화·시크릿 관리 방식을 먼저 결정한다"를 요구해 왔다 | 개발명세서 §5 보안 |
| 기존 외부 출구 선례(`RagHttpClient`)는 리다이렉트 제어·응답 크기 상한이 없다 — 고정 서버라 허용됐지만 관리자가 호스트를 정하는 레거시 호출에는 부족하다 | `rag-http.client.ts:72-79` |

즉 이 기능은 "상수에서 값 하나 빼기"가 아니라 **① 호출할 자리(엔진 계약) ② 시크릿의 거처 ③ 관리자가 정한 호스트로 나가는 출구의 방어 ④ 기존 데이터의 안전한 처리** 네 가지 결정을 요구한다.

## 결정

### 1. 엔진 통합 = 정지점 → 엔진 밖 실행 → 순수 재진입 (J-4)

- `executeOutputs`가 v2 `API_CONDITION`을 만나면 **실행을 멈추고** "호출 요청서"(`ApiCallSuspension` — 연결 id·메서드·경로 템플릿·바인딩 값·재개 상태)를 결과에 담아 반환한다. 뒤의 아웃풋은 실행하지 않는다(`API_CONDITION` = 노드의 종결자, `CONTEXT_FORM`과 같은 규약).
- API 계층이 1회 호출한 뒤 엔진의 **순수 함수 `resumeAfterApiCall(suspension, result, bundle, now)`** 로 매핑·조건 판정·분기 노드 실행·`{api.*}` 치환을 하고 다음 상태를 확정한다.
- `resolveTurn`은 정지 시 **"호출 실패" 가정의 폴백 결과를 본체로 동봉**한다 — `apiCall`을 처리하지 않는 소비자도 빈 응답을 받지 않는다.
- 엔진 수정은 **닫힌 목록**(executeOutputs 분기 · 재진입 함수 · 참조 편입 · 결과 타입 선택 필드 · 폼 완료 값 전달)으로 한정하고, 엔진에 I/O·타이머·`fetch`·`process.env`·Nest·Prisma 심볼이 **0건**임을 정적 검사가 단언한다(FR-0-78·88 "엔진 불가침"의 의도된 예외).
- 경로 추출·조건 판정·치환 순수 함수는 **`shared-types/api-mapping.ts`**(zod 무의존)에 두고 엔진·웹 편집기 미리보기·시뮬레이터가 같은 1벌을 쓴다(웹은 `shared-types`만 의존).
- 소비자 4곳(공개 대화·시뮬레이터·비교·TC)은 **실행기만 다르다**(실제/목) — 공개 대화는 실제, 시뮬레이터는 목 기본 + 조건부 실제, 비교·TC는 항상 목.

### 2. 전역 연결 레지스트리 — 노드는 `connectionId` + 상대 경로만 (J-2, P-2)

- `ApiConnection`(전역, ADMIN 관리): 이름 · 기준 URL · 허용 메서드(GET/POST) · 인증 방식 · `secretRef` · 타임아웃 · 레이트리밋 · `allowRawPersonalData` · `personalDataLookup` · 목 전용 샘플 응답 · 사용 여부.
- `API_CONDITION` v2 = `{ version: 2, connectionId, method, path, pathParams, query, body, responseMappings, conditions, defaultNodeId?, failureNodeId? }` — **헤더·URL·자유 본문 템플릿 필드가 없다.** 요청 구성은 **구조적 바인딩**(상수 / 같은 턴에 완료된 폼의 슬롯)이며 경로·쿼리는 퍼센트 인코딩, 본문은 객체 구성 후 `JSON.stringify`.
- "어디로 나갈 수 있는가"는 외부 송신 경계이므로 연결 관리는 `security:write`, 편집기는 **등록된 연결을 쓰기만** 한다(선택 목록 `dialogue:read` — URL·시크릿 참조 미포함).

### 3. 시크릿 = DB 미저장 · 환경변수 참조 (J-3, P-3 — 개발명세서 "연동 착수 시 결정"의 결정)

- 연결은 `secretRef`(이름)만 저장하고 값은 **`LEGACY_API_SECRET__<REF>` 환경변수**에서 `LegacyApiSecretResolver` **1파일**만 읽는다. 콘솔은 `NOT_REQUIRED｜CONFIGURED｜MISSING`만 본다.
- 시크릿 값은 DB·노드·번들·스냅샷·API 응답·감사·서버 로그·trace·`ApiCallLog` 어디에도 없다(정적 검사 + 가짜 시크릿 전수 grep 시험).
- 선례 2건(채널 자격증명 미저장 · 증강 API 키 = 환경변수만)과 일치하며, **암호화 키 관리·회전·백업 유출**이라는 새 문제를 들이지 않는다.

### 4. 레거시 호출의 유일한 출구 = `LegacyApiHttpClient` + SSRF 다층 방어 (J-11, P-9 — NFR-S4 재정의)

- 클라이언트는 **`build-request.ts`만 만들 수 있는 브랜드 타입 `ValidatedLegacyRequest`** 만 받는다 — 임의 URL 문자열을 받는 메서드가 없다(ADR-0022 "경로를 인자로 받지 않는다"의 계승 형태). 모듈은 클라이언트를 export하지 않는다.
- 방어 층: ① 등록된 연결만 ② `http`/`https` ③ WHATWG `URL` 정규화 후 조립·**재파싱 동일성 검증**(경로 이탈·호스트 변경·CRLF 차단, `.`/`..` 경로 값 거부) ④ **DNS 해석 1회 → 해석된 모든 주소 검사 → 검증된 주소로만 소켓 연결**(`node:https`의 `lookup` 고정 — 재바인딩 방지, TLS SNI는 호스트명 유지) ⑤ **절대 차단**(루프백·링크로컬·메타데이터·`0/8`·멀티캐스트·예약·클라우드 메타데이터 단일 주소 + IPv4 매핑/호환/NAT64/6to4 내장 주소) — allowlist로도 열 수 없음 ⑥ **사설 대역은 운영자 환경변수 allowlist로만**(기본 빈 목록) ⑦ 리다이렉트 불추종 ⑧ 응답 256KB 스트림 상한 ⑨ JSON만 ⑩ 단일 데드라인(DNS~본문 수신 합산).
- 사설 대역을 무조건 막으면 구축형 사내 레거시에 접근할 수 없다(기능의 존재 이유와 충돌). 그래서 **사설 대역은 네트워크 운영자가 열고, 루프백·메타데이터는 누구도 열 수 없다.** 루프백에는 ml-worker·임베딩 서버가 있다(ADR-0024).
- 신규 의존성 0 — `node:https`·`node:dns`·`net.BlockList`만 쓴다(`undici` 직접 의존 회피).

### 5. 동기 단발 호출 · 탄력성 (J-5/J-7, P-5/P-6)

- 같은 HTTP 응답 안에서 완결 · 연결별 타임아웃 기본 3초(1~10초) · **턴당 외부 호출 1회**(분기 노드의 두 번째 호출은 실행하지 않고 실패 처리) · **재시도 없음**(POST 비멱등, 예산 여유 없음) · GET/POST만.
- 연결 단위 회로차단(연속 **인프라** 실패 5회 → 60초, half-open 탐침 1건) · 분당 레이트리밋 · 동시성 상한(연결 10 · 전체 50, 대기 없음). **4xx는 실패로 세지 않는다** — 익명 사용자가 잘못된 입력을 반복해 회로를 열고 다른 사용자의 조회를 막는 것을 방지한다.
- 실패·불일치는 선택 분기 노드(`failureNodeId`·`defaultNodeId`)로, 미지정이면 고정 문구로 끝난다. 고정 문구 턴은 `isAnswered=false`이되 **미응답 큐에 적재하지 않고 RAG로 넘기지 않는다**(학습 공백이 아니라 외부 장애 — 문서 검색으로 덮으면 틀린 답이 된다).
- API 노드가 없는 턴의 공개 대화 예산(P95 500ms)은 **불변**이고, API 턴은 "기존 + 외부 응답 + 50ms"의 별도 예산을 갖는다.

### 6. `ApiCallLog` = 메타데이터 전용 (J-13, P-11 — ADR-0016 §5의 실체화)

- 연결 id·이름 스냅샷 · 챗봇 · 노드 · 대화로그 id · 출처(공개/시뮬레이터 실호출/연결 테스트) · 메서드 · **치환 전 경로 템플릿** · 결과 코드 · HTTP 상태 · 지연 · 응답 바이트 · 분기 · 마스킹 여부 · KST 일 버킷.
- **치환된 URL·쿼리·헤더·요청/응답 본문·바인딩 값·응답 값 컬럼이 존재하지 않는다.** ADR-0016 §5가 우려한 "Header에 토큰/PII 포함 가능·고용량"을 **담지 않는 것**으로 원천 해소한다 — 행이 작아 1차 자동 정리가 필요 없다(No.45).
- 목·TC·비교는 기록하지 않는다(ADR-0030 운영 지표 오염 방지). 호출 1건 1건은 감사로그가 아니다.

### 7. 기존 v1 데이터 — 읽기 호환 · 실행 안 함 · 쓰기 거부 · 응답 가림 · 자동 변환/삭제 없음 (J-16, P-4)

- 읽기 스키마 = v2 ∪ v1(판별 `version === 2`). v1은 **기존과 바이트 단위로 같은 미지원 처리**를 받는다.
- 노드 생성·수정 요청에 v1이 있으면 `400 API_OUTPUT_LEGACY_FORMAT`(서비스 가드). 복사는 v1을 제외한다(토큰 복제 차단).
- **노드 조회·버전 내용·버전 차이 응답**에서 v1의 헤더 값·본문 템플릿은 `[비공개]`로, URL은 origin까지로 가린다 — VIEWER의 평문 토큰 열람을 해소한다.
- 자동 변환(URL을 보고 연결을 임의 생성 = ADMIN 승인 없는 송신 경계 확장)과 자동 스크럽(`DialogNode` 쓰기 경로 추가 = 자산 쓰기 봉인 약화 + 스냅샷 해시 흔들림)을 하지 않는다. 스냅샷 스키마 버전을 올리지 않으며 업캐스터도 없다. 과거 스냅샷 속 토큰은 **해당 버전 삭제**(기존 기능)로 제거한다.

### 8. 응답값의 수명 = 같은 턴 · 텍스트 필드만 (J-9/J-10, P-8)

- `{api.이름}` 토큰만 치환(다른 `{...}`는 문자 그대로) · 대상은 텍스트 필드만(`TEXT`·`CARD` 제목/설명·`BUTTON` 문구/라벨) · **URL 필드 치환 금지**(피싱·오픈 리다이렉트) · 제어·서식 문자 제거 · 길이 절단.
- 응답값을 `ConversationState`·`ContextVariable`에 쓰지 않는다 — 대화 상태는 클라이언트 보관·무서명이라(ADR-0009) 넣는 순간 노출·조작된다. `CONVERSATION_STATE_VERSION` 1 유지.

### 9. PII 외부 송신 = 기본 마스킹 + 연결 단위 명시적 예외 (J-12, P-10)

- SLOT 바인딩 값은 기본적으로 `maskPii()`(1벌 재사용 — ADR-0013 **4번째 적용 지점**)를 거쳐 송신한다. `allowRawPersonalData=true` 연결(ADMIN · 연결 이름 재입력 확인 · 감사)만 원문을 보낸다. 관리자 작성 `CONST`는 비적용.
- 로그·trace·`ApiCallLog`에는 **항상** 원문이 없다(`personalDataMasked` 플래그만). 시뮬레이터 변수 표시도 마스킹 후 보여 준다.

### 10. 권한 신규 0종 · 시뮬레이션/TC는 목 기본 (J-14/J-15, P-12/P-13)

- `Permission` 15종 불변. 연결 관리 `security:*` · 선택 목록·샘플 `dialogue:read` · 호출 로그 `chatbot:read`.
- 시뮬레이터 실제 호출은 `simulation:write` + GET + **저장된 노드와 직렬화 동일한 아웃풋** + 단건일 때만, 불충족이면 거부가 아니라 목으로 격하한다(VIEWER발 SSRF·오버레이 우회 차단). 비교·TC는 **항상 목** — TC 실행 모듈은 외부 출구 모듈을 import하지 않고 읽기 전용 카탈로그만 쓴다(DI 그래프 부재로 실호출 불가).

### 11. 참조 무결성 편입 · 스냅샷 취급 (J-17/J-18 — architect 확정)

- `getOutgoingNodeRefs()`에 `apiTargets`(v1·v2 `conditions[].nextNodeId` + v2 `defaultNodeId`·`failureNodeId`)를 추가해 저장 검증·삭제 409·들어오는 참조/고아/흐름·스냅샷 무결성 경고 4곳에 편입한다(삭제 검사는 자체 JSON 탐색을 이 함수 재사용으로 교체 — 규칙 1벌).
- `ApiConnection`은 스냅샷 대상이 아니다(전역 설정). 노드의 `connectionId` 참조는 스냅샷에 포함되며, 복원 시 연결이 없거나 꺼져 있으면 **경고(차단 아님)** + 실행 시 실패 분기. 스냅샷에 시크릿이 들어갈 자리는 원천적으로 없다.

## 근거

- **정지점 방식은 엔진 계약을 지키는 유일한 선택지다.** 비동기 엔진(대안 B)은 ADR-0008/0010의 순수 함수 전제를 깨고 소비자 4곳과 엔진 테스트 전부를 async로 바꾸며, TC 대량 실행에 await 체인을 넣는다. 사전 호출(대안 C)은 어느 노드가 매칭될지 알아야 호출할 수 있어 엔진을 2회 돌리고 폼 완료 턴에서 세션 전이가 어긋난다. ADR-0020(의미 점수 주입)은 입력 문장만으로 사전 계산이 가능했지만 API 호출은 매칭 결과에 의존한다 — 그래서 "주입"이 아니라 "정지 후 재진입"이다.
- **PENDING(ADR-0023)을 재사용하지 않는 이유**: RAG는 다음 대화 상태가 PENDING 시점에 이미 확정된다. API 분기는 호출 결과에 따라 다음 노드가 달라지고 그 노드가 폼을 시작할 수 있어 상태를 미리 확정할 수 없다.
- **시크릿을 노드 밖으로 빼는 것이 암호화보다 강하다.** 노드 JSON은 복제·유출 경로(번들 캐시·스냅샷·오버레이·조회 응답·복사)가 5개다. 암호화해도 복호화 키를 가진 서버가 매 경로에서 다뤄야 하지만, 노드에 없으면 경로 자체가 없다.
- **등록된 연결이 SSRF 1차 방어선이다.** 호출 가능한 호스트를 ADMIN이 명시한 것으로 좁히면 EDITOR·오버레이·익명 입력이 대상 호스트를 정할 수 없다. 그 위에 네트워크 계층 검증(DNS 후 주소)을 얹어 "등록된 이름이 내부를 가리키는" 경우까지 막는다.
- **원문 없는 로그가 보존·마스킹 정책 논쟁을 끝낸다.** ADR-0016 §5가 분리를 요구한 이유(고용량·토큰/PII)는 원문을 저장한다는 전제였다. 원문을 저장하지 않으면 보존기간·마스킹 요건이 `RagCallLog`와 같아진다.
- **v1을 조용히 바꾸지 않는다.** 변환은 승인 없는 송신 경계 확장이고, 스크럽은 봉인된 자산 쓰기 경로를 늘린다. 대신 실행하지 않고(기존 동작) 응답에서 가리는 것만으로 실제 위험(평문 토큰 열람)을 닫는다.

## 대안과 트레이드오프

| 대안 | 기각 사유 |
|---|---|
| **B. 비동기 엔진 + 호출 포트 주입** | 엔진 순수성·동기성 붕괴, 소비자 4곳·엔진 테스트 전부 async 전환, TC 처리량 저하 |
| **C. 사전 호출 후 엔진 재실행** | 턴당 엔진 2회, 폼 완료 턴의 세션 전이 불일치 |
| **D. PENDING 재사용(비동기 전달)** | 분기 후 상태를 PENDING 시점에 확정 불가. 재검토 트리거 = 레거시 응답이 상시 5초 초과 |
| `UNSUPPORTED_OUTPUT_TYPES`에서 값만 빼기(ADR-0008 예고) | 호출 자리 없음 · v1 인라인 시크릿을 그대로 실행하게 됨 · 웹 배지가 상수를 쓰지 않음 |
| 시크릿 DB 암호화(마스터 키 = 환경변수) | 키 회전·백업 유출·암호화 구현이 새로 생긴다. 셀프서비스가 필요해지는 시점(No.45)에 재검토 |
| 외부 비밀 관리자(Vault 등) 연동 | 구축형 설치 전제조건 증가. 1차 과설계 |
| 노드에 URL 유지 + 사설 IP 차단만(NFR-S4 원안) | 구축형 사내 레거시(10.x) 접근 불가 — 기능의 존재 이유와 충돌. 토큰 노출도 그대로 |
| `fetch`(undici) + 사후 IP 검사 | 해석과 연결 사이 재바인딩을 막을 수 없다. 주소 고정에는 `undici` 직접 의존 필요 |
| 호출 1건마다 요청/응답 원문 로그(마스킹·단기 보존) | 마스킹 누락 시 토큰·PII 유출, 보존 정리 배치 필요. 재검토 트리거 = 연동 장애 분석 요구 반복 |
| v1 자동 변환 / 자동 스크럽 | 승인 없는 송신 경계 확장 / 자산 쓰기 봉인 약화·스냅샷 해시 변화 |
| 응답값을 다음 턴 상태로 이월 | 클라이언트 보관·무서명 상태에서 노출·조작 가능(ADR-0009) — 서버 세션 저장소와 함께 재검토 |
| 일반 텍스트 전체 `{...}` 치환 | 기존에 `{...}`를 문자 그대로 쓰던 답변이 깨진다(회귀) |
| 시뮬레이터 무조건 실제 호출 | VIEWER(`simulation:read`)가 오버레이로 만든 임의 호출이 사내망으로 나간다 |
| 연결 캐시(TTL ≤5초) | API 턴에서만 발생하는 PK 1회 조회를 아끼는 대가로 "사용 중지 즉시 반영"을 무효화 로직에 의존하게 된다 |

**감수하는 비용**
① **엔진을 수정한다** — 선행 6개 그룹이 지킨 "엔진 불가침"의 첫 예외다. 닫힌 목록 + 엔진 I/O 0건 정적 검사 + API 노드 없는 번들의 기존 스위트 무수정 통과로 통제한다.
② 시크릿 추가·교체에 운영자 작업(환경변수 + 재기동)이 필요하다 — 구독형 셀프서비스가 아니다.
③ 회로·레이트 카운터는 인스턴스 로컬이다(RAG 게이트와 같은 수용, 교체 지점 1곳).
④ TLS 연결 재사용이 없어 호출마다 핸드셰이크 비용이 붙는다.
⑤ 익명 사용자의 타인 정보 조회는 근본 차단할 수 없다 — 표시·경고·레이트리밋·레거시 2요소 대조 권고로 가시화한다(P-14).
⑥ 고정 문구 턴은 응답출처 통계에서 `FALLBACK`으로 잡힌다(통계 분류 무변경 우선) — 상세는 외부 연동 로그 탭이 담당한다.
⑦ 편집 경험이 "URL 직접 입력"에서 "연결 선택"으로 바뀐다(ROCHA 원본 화면과 다를 수 있다 — 요구사항 조사 한계).
