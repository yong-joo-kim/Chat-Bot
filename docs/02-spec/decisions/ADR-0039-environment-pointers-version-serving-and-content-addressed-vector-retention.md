# ADR-0039 — 환경 분리 = 한 챗봇 안의 버전 포인터 · 운영 번들 = 불변 스냅샷 역직렬화 + 라이브 운영 자산 · 의미 색인 = 문장 해시 주소 보존 저장소

- **상태**: 채택 (Accepted)
- **일자**: 2026-09-25
- **결정자**: system-architect (도입·1차 범위·정책 12건은 PM 확정 — 요구사항 §11 P-1~P-12 전부 추천안)
- **관련**: `docs/requirements/environment-separation.md` J-1~J-20, FR-0-149~160, FR-EN1-\*~FR-EN9-\*, NFR-ENP/ENS/ENA/ENM, AC-EN1~EN8, EX-EN-1~26, C-1~C-4 / ADR-0008(노드 동점 규칙 · K-1 번들 순서) · ADR-0009(클라이언트 대화 봉투) · ADR-0011(공개 = ACTIVE ∧ 채널 · 캐시 없음) · ADR-0015(권한) · ADR-0016(감사) · ADR-0019(학습 큐) · ADR-0024(임베딩 `textHash` 재사용) · ADR-0025(자산 쓰기 봉인) · ADR-0029(TC = 버전 축) · ADR-0030(TC 자원 격리) · ADR-0031(버전 스냅샷·ID 보존 복원) · ADR-0032(예약 배포) · ADR-0033(로그 봉인) · ADR-0037(토픽 필터·ID 재매핑 적재기)
- **Supersedes(부분)**: **ADR-0031 §8**의 "환경 개념·환경별 태깅·승격·트래픽 전환을 만들지 않는다" 부분 · **ADR-0032 §1**의 "draft/published 분리 기각 → No.40" 부분. 두 ADR의 나머지 결정(스냅샷 범위·해시·ID 보존 복원·단일 트랜잭션·라벨 무의미·타 챗봇 복원 없음 / 예약 엔진·엄격 바인딩·권한 재검증)은 **불변**이다.
- **영향 범위**: `apps/api/prisma/schema.prisma`(+ 마이그레이션 2) · `apps/api/src/{environment(신규 3모듈), versions, embedding, conversation, rag, simulation, validation, handoff, learning, dialogue-common, deploy-schedules, chatbots, audit-logs, config}` · `packages/shared-types/src/{bundle-target(신규), environment(신규), version, deploy-schedule, validation, conversation, learning, security, audit, common, index}.ts` · `apps/web`. **`packages/dialogue-engine`·`apps/widget`·`apps/ml-worker` 변경 0**
- **세부 설계**: `docs/02-spec/environment-separation-설계.md`

## 맥락

카탈로그 No.40은 "배포 전 별도 환경에서 대화 플로우를 테스트하고, 환경별로 버전을 태깅·트래픽 전환"이다(PM 도입 확정 2026-09-25). 지금 시스템에는 운영에 보이지 않는 준비 공간이 **구조적으로 없다** — 공개 대화는 `getCached(chatbotId)`로 자산 테이블(현재 상태)을 읽고, 편집은 무효화 즉시 운영에 반영된다. No.28은 이 부재 때문에 "준비 편집이 운영에 잠시 보인다"를 감수 비용으로 남겼고(ADR-0032 감수 비용 1), No.25는 환경·승격·전환을 명시적으로 비워 두었다(ADR-0031 §8).

결정해야 할 것은 여섯 가지다.

1. "환경"을 무엇으로 만드는가 — 자산 테이블 이중화, 복제 챗봇, 버전 포인터 중 무엇인가.
2. 운영 포인터를 어디에 두어야 공개 대화의 **추가 조회 0**과 모드 꺼진 챗봇의 **바이트 동일**을 동시에 지키는가.
3. 스냅샷을 서빙하면 **동점 승자**가 캡처 직전 라이브와 달라진다(C-1) — 엔진을 바꾸지 않고 어떻게 같게 하는가.
4. 임베딩 색인은 슬롯당 벡터 1개(초안 문장)뿐이다(C-2) — 초안 편집이 운영 의미 점수를 바꾸지 않게 하려면 무엇을 바꾸는가.
5. 한 캐시를 공유하는 번들 소비자 6곳(C-3)의 소스를 어떻게 드러내는가.
6. 기존 복원·예약 복원(No.25/28)의 의미가 모드를 켜는 순간 바뀐다(C-4) — 어떻게 처리하는가.

## 결정

### 1. 환경 = 한 챗봇 안의 버전 포인터 — 초안은 기존 테이블, 스테이징·운영은 `ChatbotVersion`을 가리킨다

- **초안(DEV)** = 지금의 자산 테이블 그대로(편집기·자산 서비스 6종·학습 반영·증강 승인·복원 경로 **수정 0**). **스테이징·운영** = 불변 `ChatbotVersion` 스냅샷을 가리키는 포인터. 3단 고정(P-2).
- **승격** = 초안 캡처(트리거 `PROMOTE` — 같은 상태면 재사용) → 스테이징 포인터 이동. **운영 전환** = 운영 포인터를 스테이징 버전(또는 운영 이력 버전 — 롤백)으로 이동. **자산 테이블 쓰기 0.**
- 같은 챗봇·ID 보존 버전이므로 운영 턴의 매칭 id·TC 기대값·평가 대상·학습 큐가 **추가 매핑 없이** 초안 자산 id와 이어진다(ADR-0031 §3의 4근거가 그대로 이점이 된다).
- 서버 간 이관(export/import)은 2차다 — 가져온 버전은 대상 서버의 **초안**에 들어가므로 이 모델 위에 쌓인다(ADR-0037 적재기 + 차이 적용 + 영속 ID 대응표가 부품).

### 2. 운영 포인터 = `Chatbot.prodVersionId` 컬럼(null = 모드 꺼짐) · 스테이징·게이트 = 1:1 `ChatbotEnvironment` · 이력 = append-only `EnvironmentSwitchLog`

- `PublicAccessService.resolve()`가 매 요청 이미 읽는 챗봇 행에 두어 **추가 조회 0**으로 얻고, 캐시하지 않으므로 전환 커밋 **다음 요청부터 전 인스턴스**가 새 버전을 쓴다(ADR-0011 "캐시 없음"과 같은 이유).
- null이면 현행 경로(`getCached` → `answerSettingsCache.get`)를 **같은 순서·같은 인자**로 탄다 — 모드 꺼진 챗봇의 응답 바이트·쿼리 수가 같다.
- 포인터·환경 행·이력의 쓰기 주체는 **1파일**(`environment-pointer.writer.ts` — export 0)이며 모든 갱신은 **기대값 조건부(CAS)**다(`updateMany where prodVersionId = expected` — ADR-0032 §2 방식, 원시 SQL 0).
- FK를 걸지 않는다(`Chatbot ↔ ChatbotVersion` 순환 · `chatbots` 테이블 재정의 회피). 보호는 앱 레벨 409(`VERSION_REFERENCED_BY_ENVIRONMENT`) + 보존 정리 보호 집합(운영·스테이징·운영 이력 최근 N·활성 전환 예약 대상)이다.
- 전환은 `Chatbot.updatedAt`을 갱신한다 — **수용**(운영 전환은 사용자가 보는 챗봇의 주 변경이며 빈도가 낮다. 빈번한 스테이징 승격·게이트 쓰기는 환경 행에 있다).

### 3. C-1 — 스냅샷 **해시 밖 최상위 보조 필드** `tiebreak.nodeUpdatedAt` + 서빙 역직렬화의 **생성순 재정렬**

- 봉투 최상위에 선택 필드 `tiebreak: { nodeUpdatedAt: { [nodeId]: ISO } }`를 둔다. `contentHash`는 `assets`·`answerSetting`·`profile`만 보므로 **기존·신규 해시 규칙이 같고** 영구 픽스처·골든 해시가 그대로다. `SNAPSHOT_SCHEMA_VERSION = 1` 유지(선택 필드 — `topicId` 선례). 봉투 검증 스키마(`z.object` strip)에 선언하지 않으면 파싱에서 사라지므로 **스키마에 선언**한다.
- 메타 `ChatbotVersion.tiebreakHash`(보조 필드의 sha256)를 둔다. 켜기·승격의 "같은 상태면 재사용"은 **`contentHash` ∧ `tiebreakHash`**가 같을 때만이다 — 편집 후 되돌리기로 해시는 같고 `updatedAt`만 다른 버전이 운영이 되는 것을 막는다.
- 서빙 역직렬화 `hydrateForServing()`은 ① 노드 `updatedAt`을 보조 필드 값으로 채우고 ② **6종 배열을 `(createdAt asc, id asc)`로 재정렬**한다. 스냅샷 본문은 `id asc`로 저장되지만 라이브 번들은 K-1 이후 `createdAt asc, id asc`이며, 의도·FAQ 매칭은 "동점이면 먼저 본 항목"이 이긴다(ADR-0008 갱신 각주 K-1) — `updatedAt`만으로는 C-1이 풀리지 않는다. `createdAt`은 스냅샷에 보존된다.
- 보조 필드가 없는 과거 스냅샷은 `capturedAt` 폴백(동점 = `id asc`)이며, 실제로 동점이 가능한 노드 쌍이 있을 때만 `LEGACY_TIEBREAK` 경고를 낸다.
- 결과: **엔진 변경 0**으로 "운영 서빙 = 같은 버전 시뮬레이터·TC = 캡처 시점 초안"이 성립한다.

### 4. C-2 — 슬롯 테이블·색인기 **무변경** + 문장 해시 주소 보존 저장소 `EmbeddingTextVector` + "보존 ∪ 같은 해시 초안 벡터" 조립

- `EmbeddingVector`(슬롯 테이블)·`IndexerService`·재색인 큐·ml-worker는 **바꾸지 않는다** — 모드 꺼진 챗봇의 색인 경로·벡터 수·임베딩 호출 수가 같다.
- 새 `EmbeddingTextVector`는 `(chatbotId, modelId, textHash)` 유일 · 원문 없음 · 모드 꺼진 챗봇 0행이다. 포인터·운영 이력·전환 예약이 참조하는 버전의 질문 측 문장 벡터를 **슬롯 테이블에서 복사**해 보존한다(pin). 버전은 항상 "그 순간의 초안"을 캡처해 만들어지고 초안 문장은 편집 시점에 이미 색인됐으므로 **추가 임베딩 호출 0**이다. 예외(캡처 직전 편집의 재색인과 재편집이 겹친 경합 · 모델 교체)만 기존 Provider 경로로 해당 문장을 임베딩한다.
- 버전 대상 점수는 버전 슬롯마다 "보존 저장소 → 없으면 같은 `textHash`의 초안 벡터"로 벡터를 모아 **기존 순수 함수 `assembleSemanticInput()`**에 넣는다. 같은 `textHash` = 같은 정규화 문장 = 색인기가 이미 같은 벡터로 취급하는 것이므로 대체가 안전하고, 초안이 문장을 바꾸거나 지워도 보존 쪽 벡터가 남는다 — **초안 편집·삭제·재색인이 운영 점수를 바꾸지 않는다**.
- GC = 보호 버전 슬롯 해시 합집합 밖 행 삭제(전환·승격 후 백그라운드) · 모드 끄기 = 챗봇 행 전부 삭제.

### 5. 전환·롤백 = 포인터 CAS + 이력 1행 · 게이트 = 순수 함수 1개(경고 기본 · 챗봇별 차단) · 예약 = No.28 동작 1개

- 운영 전환 대상은 **현재 스테이징 또는 운영 이력 버전**만. 롤백 = 직전 운영 버전(이력에서 파생)으로의 전환이며 **차단 게이트를 경고로 낮춘다**(긴급 복귀 우선). 자동 롤백 없음(ADR-0032 판단 유지).
- 게이트 `evaluateProdSwitchGate()`는 대상 버전을 **대상으로 한** 최근 성공 TC 실행(세트·합격률·유효 기간·임베딩 모델)을 본다 — TC 실행에 대상 차원(`targetKind`·`targetVersionId`)을 더해 "스냅샷 번들 TC 모드"(ADR-0032 대안표의 트리거)가 생겼기 때문에 가능해졌다. 미리보기·즉시·예약이 같은 함수를 쓴다.
- 예약 전환 = `DeployScheduleAction` `SWITCH_PROD_VERSION` 1개(실행기 1파일 + 레지스트리 1줄 + 권한 1분기). 바인딩 = "예약 시 운영 버전 id"(체인이면 선행 전환 예약의 대상) — 실행 시 다르면 `STATE_CHANGED`(엄격 바인딩). 게이트는 실행 시 재평가(차단 → `GATE_NOT_PASSED`, 영구). 실행기는 `deploy-schedules/**` 밖의 전환 서비스를 호출할 뿐 포인터를 직접 쓰지 않는다(예약 모듈 쓰기 대상 = `deploySchedule` 봉인 유지). 임대 만료 회수는 이력의 `deployScheduleId`로 판정한다(커밋의 증거).

### 6. C-3 — 소비자별 **명시 소스** · 2층 캐시(불변 코어 + 합성) · 무효화 지점은 기존 `invalidate()` 1곳

- 소스 = 판별 유니온 `{ DRAFT } | { VERSION, versionId }`. 공개 대화·상담 힌트 = 운영 포인터 · 시뮬레이터 대화·TC = 요청/실행의 대상(기본 초안) · 시뮬레이터 비교·답변 설정 미리보기 = 초안 고정. 공개 경로의 선택 지점은 1곳이며 초안 경로 코드는 바꾸지 않는다.
- L1 코어(키 `versionId`, 본문 불변이라 TTL 없음) + L2 합성(키 `chatbotId:versionId:토픽모드`, TTL 60초). L2는 **현재 설문·현재 토픽 활성**(스냅샷 밖 — 환경 밖 운영 자산)을 합성하므로 기존 `DialogueBundleService.invalidate()`가 함께 비운다(토픽 토글·설문 편집은 이미 그것을 부른다).
- 본문은 `VersionPayloadReader.loadStrict()`로만 읽는다(해시 재검증·업캐스트 · 본문 참조 파일 허용 목록 불변). 읽기 실패 시 공개 대화는 **초안으로 몰래 대체하지 않고** 엔진 미호출 폴백 턴으로 응답한다.

### 7. C-4 — 모드 켜기 시 활성 `RESTORE_VERSION` 예약은 `HELD(ENV_MODE_CHANGED)` · 복원 = 초안만 · 끄기 "운영 유지" = 기존 복원 API 선행

- 켜는 순간 복원의 효과 대상이 운영 → 초안으로 바뀐다. 예약자가 본 적 없는 의미로 실행하지 않도록 같은 트랜잭션에서 보류한다(엄격 바인딩의 취지). 끌 때 활성 전환 예약은 `CANCELLED`.
- 복원(`restore()`)의 코드·의미론·호출부 2곳은 불변이다. 모드 켜진 챗봇의 복원은 초안만 바꾸고 미리보기에 `ENV_DRAFT_ONLY` 경고가 붙는다(요청 계약 불변).
- 끄기 "운영 유지"는 콘솔이 **기존 복원 API로 초안을 운영 버전으로 되돌린 뒤**(백업·사후 검증 포함) 끈다. 서버는 초안 해시 = 운영 해시만 확인한다(아니면 `409 ENV_DRAFT_NOT_RESTORED`) — `restore()`의 세 번째 호출부를 만들지 않는다.

### 8. 권한 = 신규 `chatbot:deploy`(ADMIN) 1종 · 감사 = 신규 대상 `ChatbotEnvironment` 1종(액션 재사용) · 로그 = `servedVersionId`

- 운영 전환·롤백·전환 예약·모드 켜기/끄기·게이트 설정 = `chatbot:deploy`. 스테이징 승격 = 기존 `dialogue:write` AND `chatbot:write`(편집자). 긴급 차단 = 기존 WEB 채널 닫기(`channel:write`). 역할 추가 0.
- 감사: 켜기/끄기 `STATUS_CHANGE` · 승격·전환·롤백·게이트 `UPDATE` · 예약 실행은 예약자 명의 + `[예약 실행 #…]` 접두. `AuditAction` 추가 0. 사유 메모 본문은 감사·서버 로그에 남기지 않는다.
- `ConversationLog.servedVersionId` = 턴 처리 시점의 운영 포인터(엔진·BLOCK·상담 턴 공통 — 2차 비율 분할의 세션 귀속 분모) · `record()` 1곳 · 적재 후 불변 · 인덱스 없음(1차 적재만).
- 학습 큐의 "운영 미반영"·재유입 오표시는 **표시 단계 순수 함수**(전환 이력의 대상 캡처 시각)로 판정한다 — 수집기 봉인 불변.

## 근거

- **"두 벌"을 자산이 아니라 포인터로 만들면 선행 7개 그룹의 설계가 흔들리지 않는다.** ADR-0032가 draft/published를 기각한 이유(자산 서비스 6종·대화 경로·색인·학습 반영·TC·복원 동시 재설계)는 "자산 이중화"를 전제했다. 초안을 기존 테이블로 두면 편집·반영·복원·증강 경로는 **한 줄도 바뀌지 않고**, 남는 실제 비용은 서빙 경로·동점·색인·TC 대상 4건뿐이다.
- **불변 본문은 캐시의 이상형이다.** 버전 id가 곧 키이고 무효화할 일이 없다. 섞이는 라이브 부분(설문·토픽)만 기존 무효화 지점에 붙이면 된다.
- **동점 일치는 엔진 규칙이 아니라 입력의 문제다.** 엔진은 `updatedAt`과 배열 순서를 보고 결정론적으로 판정한다 — 라이브와 같은 값·같은 순서를 넣으면 같은 답이 나온다. 해시 밖에 두면 과거 스냅샷과 복원 검증이 흔들리지 않는다.
- **색인을 다시 짜지 않고 "같은 문장 = 같은 벡터"를 한 번 더 쓴다.** 재사용 키 `textHash`(ADR-0024)가 이미 그 등식이다. 주소만 문장 해시로 바꾼 작은 보존 저장소가 버전 차원을 해결하고, 모드 꺼진 챗봇에는 흔적을 남기지 않는다.
- **약속이 아니라 구조로 막는다**(ADR-0022 이래 여섯 번째 적용): 포인터 쓰기 1파일·미export · 서빙 모듈 export 1개(쓰기 경로가 소비자 DI 그래프에 없음) · 예약 모듈은 포인터를 쓸 수 없음(D-1) · `restore(` 호출 파일 2개 · 엔진 심볼 0 · `@Public()` 8 — 전부 정적 검사(`environment-sealing.spec.ts` E-1~E-17)가 단언한다.

## 대안과 트레이드오프

| 대안 | 기각 사유 |
|---|---|
| **자산 테이블 이중화(draft/published 컬럼·테이블)** | 자산 서비스 6종·편집기·학습 반영·복원·색인·TC를 동시에 재설계(ADR-0032 기각 사유 그대로) |
| **복제 챗봇 승격 체인(개발·스테이징·운영 챗봇)** | 영속 ID 대응표 + 차이 적용 적재기 필수 · 학습 큐가 운영 챗봇에 쌓이고 편집은 개발 챗봇에서 → 교차 반영 또는 드리프트 · 통계 분산(P-1 기각) |
| **포인터를 1:1 환경 테이블에만 둔다** | 공개 경로 조회 +1(매 턴) · 캐시하면 전환이 TTL만큼 늦고 인스턴스마다 다르다 |
| **`Chatbot.updatedAt`을 보존하는 원시 SQL 포인터 갱신** | 원시 SQL 봉인 비용(R-7·D-8) 대비 이득이 표시 정렬뿐 |
| **동점을 엔진 옵션으로 해결(`rankNodes` 규칙 변경·서빙 전용 인자)** | 엔진 변경 = FR-0-149 위반 · 기존 엔진 시험 전체의 전제 변경 |
| **항목별 `updatedAt`을 자산 본문(해시 범위)에 넣는다** | 모든 스냅샷 해시가 바뀐다 — "같은 상태 → 같은 해시"(편집 후 되돌리기)·복원 사후 검증·예약 바인딩이 깨진다 |
| **버전 번들을 `id asc` 그대로 서빙** | 의도·FAQ 동점 승자가 라이브와 달라진다(발견 제약) |
| **`EmbeddingVector` 유일 키를 문장 해시로 교체** | 모드 꺼진 챗봇의 색인·고아 정리·TC 벡터 로드가 전부 바뀐다(No.18 회귀 범위) |
| **버전별 벡터 테이블(버전 × 슬롯 전량 복제)** | 보호 버전 수 × 전체 슬롯 — 대부분 초안과 같은 문장의 중복 |
| **보존 저장소에 문장 원문 저장** | 원문 미저장 규약(EmbeddingVector) 위반 · 경합 예외는 메모리 인자로 충분 |
| **초안 번들 캐시 키를 `(chatbotId, source)`로 일반화** | 기존 6소비자 호출·시험 목 전체 변경 · 초안·운영 항목이 같은 LRU에서 서로 밀어낸다 |
| **끄기 "운영 유지"를 서버가 `restore()`로 직접 수행** | `restore()` 세 번째 호출부(D-3 봉인 개정) · 복원 미리보기의 사람 확인을 건너뛴다 |
| **모드 켜기 시 기존 복원 예약 자동 취소 / 그대로 둠** | 취소는 예약자의 의도를 지우고, 그대로 두면 의미가 조용히 바뀐다(P-8) |
| **2인 승인·신규 역할 "배포 관리자"** | 역할 매트릭스 전체 파급 · No.36/45 거버넌스와 함께(P-4 (3)(4) 기각) |
| **스테이징 외부 미리보기 링크** | 공개 표면 +1 · 토큰 발급·만료·유출 방어(P-2 (c) 기각) |
| **비율 분할(카나리·A/B) 1차 도입** | 세션 고정·버전별 통계·실험 종료 규칙이 함께 필요(P-3 (c) — 로그 귀속만 1차) |

## 감수하는 비용

1. **운영 전환이 `Chatbot.updatedAt`을 바꾼다** — 목록 "최근 변경" 정렬이 올라간다(의미상 맞다고 판단).
2. **보조 필드 없는 과거 스냅샷은 동점을 `id asc`로 가른다** — 경고로 드러내고, 커밋 ①(보조 필드 캡처)을 먼저 배포해 이후 스냅샷을 전부 보조 필드 보유로 만든다.
3. **초안 편집마다 운영 합성 캐시(L2)가 비워진다** — 다음 공개 요청이 합성 1회(쿼리 2 + 인덱스)를 치른다. 코어(L1)는 유지되어 본문 재파싱은 없다.
4. **보존 저장소라는 벡터 사본이 생긴다** — 크기 = 보호 버전 문장과 초안 문장의 차집합. 모드 꺼진 챗봇은 0행.
5. **끄기 "운영 유지"의 사후 라이브 동점은 복원 시각 기준이다** — 복원이 바꾼 행의 `updatedAt`은 복원 시각이다(ADR-0031 §3 불변 우선, 미리보기 경고).
6. **"반영 후 재발생" 숫자·필터는 운영 미반영 기간의 발생을 포함한다** — 배지 판정만 시간 기준이다(수집기 봉인 우선).
7. **망분리 구축형은 1차 동안 한 서버 안에서 초안/스테이징/운영을 운영한다** — 서버 간 이관은 2차.

## 재검토 트리거

- **비율 분할(카나리·A/B) 요구 확정** → 세션 고정 규칙·버전별 통계 비교·실험 종료를 새 ADR로. 로그 `servedVersionId`(1차 적재)에 인덱스 추가 검토.
- **망분리 구축형 고객의 서버 간 이관 요구 확정** → 버전 파일 내보내기/가져오기(서명·서버 버전 호환) + ADR-0037 §5 적재기에 "기존 대상과의 차이 적용" + 영속 ID 대응표. 가져온 버전은 대상 서버의 초안으로.
- **엔진이 노드 외 자산의 `updatedAt`을 순위에 쓰기 시작함** → `tiebreak`에 종류 추가(해시 밖 규칙 그대로).
- **초안 편집 빈도로 L2 재합성이 공개 지연에 드러남** → 설문·토픽 전용 무효화 지점 분리.
- **보존 저장소 행 수가 챗봇당 슬롯 수의 2배 초과가 상시화** → 보호 이력 N 축소 또는 GC 주기 재검토.
- **"운영 반영 후 재발생" 정확한 건수 요구** → 수집기에 반영 기준 시각 컬럼(ADR-0019 갱신) 검토.
- **2인 승인·전환 이력 보존 정책 요구**(No.36/45) → 전환 요청/승인 상태 기계 · 이력 보존 기간.
- **스테이징 외부 검수(UAT) 요구 확정** → 서명 토큰 미리보기 링크(공개 표면 +1)를 새 ADR로.
