## 맥락

카탈로그 No.43은 "사내 웹사이트·문서를 주기적으로 크롤링해 RAG용 지식베이스를 자동 최신화, 변경분만 재인덱싱"이다. 2단계 답변은 외부 RAG가 검색과 생성을 함께 하므로(ADR-0022), 우리가 색인을 따로 만들어도 외부 RAG는 그것을 쓰지 않는다. 그런데 2026-09-22 결정(ADR-0022 §5)은 "문서 인입도 삭제도 만들지 않는다"였다. 코드·외부 명세 확인 결과 결정할 것은 열 가지다.

1. **누가 무엇을 하나** — 우리가 수집·감지만 하고 외부 적재 API로 보낼지, 우리 쪽에 저장소·임베딩을 만들지, 외부 기능을 부를지(외부 명세에 크롤링 기능 없음), 목록만 보여 줄지.
2. **ADR-0022 봉인과의 관계** — 적재 경로를 열면 삭제·초기화·전역 설정·프롬프트 봉인은 어떻게 지키나. `file_path`(서버 임의 경로 읽기)는?
3. **외부 적재 API의 함정** — 파일 업로드만 · 3단 스코프 필수 · 비동기 · `progress` 항상 0 · 재시작 시 `not_found` · `completed`인데 "실패." · 같은 이름 덮어쓰기 · 직렬 권장 · HTML·TXT 지원 미확인 · 문서 1건 삭제 없음 · 재적재 시 옛 청크 잔존.
4. **새 외부 출구** — 크롤러는 관리자가 등록한 임의(사내) 주소로 나간다 — SSRF·리다이렉트·robots·속도.
5. **원문 저장** — 수집 문서를 우리 DB에 두면 보존·암호화·파기 대상이 커진다.
6. **실행 모델** — 크롤은 수십 분, 적재는 수 시간. `PollingLoop`는 tick이 끝나야 다음 tick을 잡는다. 다중 인스턴스.
7. **반영 시점** — 외부 문서에는 버전이 없어 적재 즉시 모든 챗봇·환경의 답변이 바뀐다.
8. **삭제·축소** — 외부에서 1건만 지울 수 없다.
9. **문서 해석** — PDF·OOXML 파서는 공격 면적(압축 폭탄·악성 PDF)이고 무겁다. 공개 대화와 같은 프로세스다.
10. **쓰지 않는 설치의 바이트 동일** — 데이터 지도·공개 대화·기존 시험.

## 결정

### 1. 역할 = 수집·변경 감지는 `apps/api` · 적재·청킹·임베딩·검색·답변은 외부 RAG (P-1 (a) · P-7)

- `apps/api`에 전역 자원 모듈 `kb-sync`(export 0)를 두고, 등록 소스를 주기적으로 방문해 **바뀐 것만** 외부 RAG `POST /api/documents/ingest`로 보내며, 작업을 `GET /api/async_task_status/{id}`로 **개별 조회**한다.
- `apps/ml-worker`·임베딩·자체 색인은 쓰지 않는다(ADR-0024 범위 불변 · GPU 4 → 1). 실행 위치는 api 서버다 — 출구 게이트·SSRF 부품·`PollingLoop`가 여기 있고 G-1은 `apps/api/src`만 검사한다.

### 2. ADR-0022 재결정 = 경로 3 → 5 · 파괴적 봉인 불변 (C-1 · J-2)

- `RAG_PATHS`에 `INGEST`·`TASK_STATUS` 2개를 더한다. 출구는 여전히 **`RagHttpClient` 1클래스**, 메서드는 경로를 받지 않으며, **`fetch(`는 `send()` 1곳**이다 — 멀티파트는 같은 `send()`의 본문 인코딩 선택(`JSON｜MULTIPART`)이다.
- `ingest()`의 `FormData`는 `file`·`company`·`category`·`subcategory` **4필드뿐**(동기 옵션 미전송 = 비동기). `taskStatus()`의 경로 뒤에는 UUID 검증 브랜드 값만 붙는다.
- 금지 목록: 기존 4종(초기화·문서 삭제·전역 설정·프롬프트) **불변** + **작업 목록·작업 취소** 추가. `file_path`·`force_sync`는 송신 조립 파일과 `kb-sync`에 0 — 저장소 전체 0은 불가능하다(질의 응답 파서 2파일이 `sources[].file_path`를 읽는다) → 보유 파일 2개 고정.
- **수동 업로드 화면(No.48)은 계속 만들지 않는다.** 들어가는 문서는 등록 소스에서 수집한 것뿐이고, 호출부는 `kb-ingest.runner.ts` 1파일이다.

### 3. 원문 비저장 · 적재 시점 재수집 (FR-0-210)

- DB에는 URL·해시·HTTP 검증자·길이·상태·외부 작업 id·코드만 둔다. 본문 텍스트·파일 바이트·HTML 원문 컬럼은 **존재하지 않는다**(정적 검사).
- 크롤 단계는 **감지만** 하고, 적재 단계가 그 URL을 **다시 받아** 변환해 보낸 뒤 메모리 참조를 버린다(디스크 임시 파일 0). 감지와 적재 사이에 바뀌었으면 새 내용이 들어간다.
- 검증자(ETag·Last-Modified)·해시는 "**마지막으로 외부에 성공 적재한 내용**"의 값이다 — 적재 성공 또는 해시 동일 확인 때만 갱신한다(304에 속아 영영 다시 보내지 않는 함정 방지).
- 보존 = 실행 이력·적재 작업의 종단 행은 `CALL_LOGS`(writer 1파일 행 삭제). 암호화 대상 추가 0.

### 4. 적재 계약 = 결정적 파일 이름 · DOCX 기본 변환 · 3중 성패 판정

- 파일 이름 `kb_<소스 id 8>_<URL 해시 16>.<ext>` — 같은 URL = 외부 덮어쓰기 = 갱신. 원 파일명·경로·한글을 넣지 않는다.
- HTML은 추출 본문을 **DOCX**(외부 지원 목록에 명시된 형식 — 최소 OOXML · 결정적 바이트)로 만든다. TXT·HTML 지원이 외부 담당자 확인으로 밝혀지면 `KB_HTML_INGEST_FORMAT`으로 바꾼다(첫 적재 전에 — 확장자가 이름의 일부).
- 성패 = HTTP 2xx ∧ `async_started` ∧ UUID `task_id`(접수) → `completed` ∧ 성공 접미(완료) · 실패 접미·`failed`·`cancelled` = 재시도(1·5·30분 · 3회) · 400 = 재시도 0 · **`not_found` = 실패가 아니라 1회 재전송** · 제출 후 3시간 = 시간 초과. 외부 `progress`는 쓰지 않는다(진행률 = 우리 작업 행).
- 적재는 질의 게이트·`RagCallLog`를 쓰지 않는다. 제출 전 응답 **최상위** `vllm_ready === true` 확인(60초 캐시 — `KbJobLease('INGEST_STATUS')` 행 · 구현 정정: 이전 구현이 읽던 `vllm.status`는 최상위에 없는 필드였다 — 설계서 §25 I-36). 작업 **조회**의 네트워크·5xx·429는 재전송이 아니라 재조회다(상태 불변 · 429는 조회 간격 ×2 이상) — 재전송은 `not_found` 1회(즉시)와 제출 단계 실패의 백오프뿐이다(설계서 §25 I-34).

### 5. 전송 전제 게이트 = `KB_INGEST_TRANSPORT_ACK` (P-5 · C-6)

`INTERNAL_NETWORK｜AUTHENTICATED｜TLS` 중 하나를 운영자가 선언해야 **적재가 가능**하다(없으면 등록·미리보기만). `TLS`는 `RAG_BASE_URL`이 https일 때만(기동 검사). 질의는 마스킹된 200자지만 적재는 **문서 전체**이므로 ADR-0022 §9의 "배포 전 전제"를 설정으로 강제한다.

### 6. 출구 = 7번째 클래스 `KB_CRAWL` · 적재는 RAG 클래스 그대로 · SSRF 부품 세 번째 공유 (J-11 · J-12 · C-7 · C-8)

- 레지스트리 7번째 클래스 `KB_CRAWL`(데이터 종류 `CRAWL_REQUEST` · 출구 파일 `kb-crawl-http.fetcher.ts` + 공유 전송·DNS). 요청마다 `checkEgress('KB_CRAWL', url)` → DNS 1회 → 모든 주소 판정(절대 차단 불가역 · 사설은 **별도** `KB_CRAWL_PRIVATE_ALLOWLIST`) → 검증 주소 고정 → 크기 상한. 데이터 지도 `exits[]`에서는 제외(DB 결정 출구 — 레거시·웹훅 선례).
- **리다이렉트는 크롤러가 한 단계씩 재검증하며 최대 3회** 따라간다 — 전송 포트에 선택 필드 `redirectMode: 'REPORT'`(3xx를 `Location`과 함께 돌려줌)·`captureHeaders`(ETag·Last-Modified·X-Robots-Tag 등)를 더한다. 기본값 = 현행이라 레거시·웹훅은 무변경. (구현 pass 5: 닫힌 목록 +`retry-after` · 다중 헤더 값은 `', '`로 합침 — 설계서 §25 I-59 · ADR-0034 갱신 각주)
- 적재는 **새 출구 클래스로 나누지 않는다** — 같은 호스트·파일·가드라 출구 판정이 같고, "문서 본문(소스별 마스킹·원본 파일은 비마스킹)"이라는 차이는 데이터 지도의 새 선택 절 `egress.kbSources`(데이터 종류 `DOCUMENT_BODY`)가 **소스 단위**로 보여 준다.
- robots.txt 항상 준수(4xx = 허용 · 5xx·도달 불가·범위 밖 리다이렉트 = 그 호스트 중단) · 호스트당 1연결 · 간격 = max(소스 간격, Crawl-delay) · 호스트가 겹치는 소스는 동시에 크롤하지 않는다(**판정 시점 = 크롤 시작** — QUEUED → CRAWLING 전이에서 겹치는 다른 소스의 CRAWLING 실행이나 더 먼저 만든 겹침 QUEUED 실행이 있으면 대기(FIFO) · 전이 CAS 뒤 사후 확인 · 예약·수동 실행·적재 승인·다중 인스턴스 공통 — 2026-09-28 pass 6 갱신, 설계서 §25.3 B안 · §25 I-68) · 식별 UA.
- ADR-0041의 재검토 트리거 "세 번째 출구가 같은 부품을 공유 → `common/outbound/`로 이동"이 **발동**했으나 **이동하지 않는다** — 동작 0 변경의 경로 이동이 무관한 spec 9개를 흔든다. 독립 리팩터로 분리한다(사용자 결정).

### 7. 실행 = `PollingLoop` 1개 · tick 조각 · 소스 행 CAS · 슬롯 임대 · 크롤 후 일괄 대기열 (J-13 · C-3 · C-12)

- 루프 1개(기본 10초 · tick 예산 30초 · 기본 꺼짐 · 시험 격리 `KB_SYNC_ENABLED=false`). 크롤은 **DB 프런티어**(문서 행)에서 URL 1개씩 조각 실행하고 임대가 끊기면 다른 인스턴스가 **이어서** 간다.
- **소스당 동시 실행 1** = 소스 행 `activeRunId` 조건부 갱신(CAS). **전역 직렬 적재** = 슬롯 임대 행 `INGEST_SLOT_0..N−1`(기본 N=1) CAS — 부분 유니크 인덱스를 새로 만들지 않는다(원시 부분 유니크 4개 보존). 잡 임대는 `governance/**` 밖의 동형 파일(G-10). (구현: 별도 `kb-job-lease.ts` 없이 `kb-sync/core/kb-run.store.ts`에 통합 — KB-9가 `kbJobLease` 쓰기 파일을 1개로 고정하므로. 소스 CAS와 선점·실행 생성 한 트랜잭션 `claimAndCreateRun()`은 `KbSourcesService` — 설계서 §25 I-4·I-5·I-39. 적재 슬롯은 제출 직후가 아니라 작업이 종단 상태가 되거나 백오프로 PENDING에 돌아갈 때까지 유지하고 조회마다 임대를 연장한다 — 설계서 §25 I-33)
- 적재 대기열은 **크롤 종결 후 일괄 등록**한다 — 새로 비율(>50%)·인증 벽(같은 해시 80%) 가드가 적재 전에 판정해 자동으로 미리보기로 강등한다. (구현 pass 8 — 적용 대상 확정: 새로 비율 = 모든 종류 강등 · 인증 벽 = SYNC·FULL_RESEND 강등 / PREVIEW는 실행 기록만 · 인증 벽 입력 = 실행 전체의 관측 해시 분포 `KbDocument.observedHash` — 설계서 §8.4 · §25 I-85 · 승인 뒤 새로 비율 재강등 루프는 설계서 §25.5 RG-23 — pass 10 해소: 승인으로 시작된 SYNC는 새로 비율만 면제 · 분모 = ACTIVE ∧ 적재됨 — 설계서 §25 I-94 · pass 9: 인증 벽 지문을 로그인 신호 기준으로 좁히고 분모 = 방문 HTML 전체 · 강등 판정을 삭제 감지보다 먼저 — 설계서 §8.4 · §25 I-89·I-90)
- 대량 첫 적재(수 시간)는 **BULK 레인**(증분 뒤) + 선택 시간창 + 예상 시간 표시로 운영한다. 작업은 DB 행이라 재시작·배포를 넘어 이어진다(SUBMITTED 작업은 같은 `task_id`를 다른 인스턴스가 계속 조회).

### 8. 반영 = 첫 회 미리보기 → 승인 → 이후 자동 · 환경 밖 (P-4 · J-15)

- 소스의 `configVersion`(범위·스코프·개인정보 옵션의 **값이 실제로** 바뀔 때마다 +1 — 목록은 집합 비교 · 구현 설계서 §25 I-38)에 승인을 묶는다. 승인 전·범위 변경 후·자동 강등 후에는 예약 실행도 **미리보기만** 한다. 승인하면 곧바로 동기화 1회(재크롤 후 적재).
- 지식베이스는 No.40 환경 밖 자원이다 — 외부 문서에는 버전이 없어 적재 즉시 그 스코프의 모든 챗봇·환경에 반영된다(챗봇 답변 설정 카드가 안내).

### 9. 삭제·축소 = 자동 삭제 없음 · "정리 필요" (P-3 · C-2)

404·410·재발견 실패가 **연속 2회**(동기화 실행 · 상한 미도달 · 중단 호스트 제외)면 "없어짐", 본문이 50% 미만으로 줄면 재적재 + "짧아짐", 스코프·형식 변경·robots 금지 전환도 "정리 필요"로 표시한다 — **외부에 적재된 적이 있는 문서만**. 외부 삭제 호출은 0이며, 관리자가 외부에서 정리한 뒤 "전체 다시 적재(정리 완료 확인)"로 표시를 해소한다.

### 10. 문서 해석 = 작업 스레드 샌드박스 · 검증된 라이브러리 3종 · 원본 파일은 사전 검사만 (P-6 · C-10)

- 모든 HTML·사이트맵·OOXML·PDF 해석과 해시·마스킹·변환은 **`worker_threads` 1개**(힙 192MB · 작업 30초 · 비정상 시 재생성)에서 한다 — 공개 대화의 이벤트 루프를 막지 않는다. 스크립트 실행 0 · DOCTYPE/엔티티 거부 · 압축 해제 상한(항목·총량·비율) · 매크로·암호 문서 제외.
- 라이브러리: `htmlparser2`(HTML·사이트맵 `xmlMode`) · `fflate`(OOXML 스트리밍 해제·DOCX 생성) · `pdfjs-dist` ≥ 4.2.67(`isEvalSupported: false`). 전부 순수 JS(네이티브 0). (구현 고정: `htmlparser2` ^9.1.0 — v12는 ESM 전용 · `pdfjs-dist` 4.2.67 — 순수 ESM이라 `common/lib/import-esm.ts` 경유 로드 · 선택 의존성 `canvas`는 `pnpm-workspace.yaml`에서 빌드 차단 — 설계서 §25 I-1~I-3)
- HTML 텍스트는 **마스킹 기본**(ADR-0013 7번째 적용 지점 — 거버넌스 ON이면 끌 수 없음 · 2026-09-28 PM 결정: 모드를 켜기 **전에** 저장된 마스킹 끔·서버 허용 없는 원본 파일 전달 소스는 실행 시작(PREVIEW 포함)·예약·적재 제출 직전에 차단 — 설계서 §10 · §25 I-86). 원본 파일은 기본 **보내지 않고**, 켜면 바이트 그대로 보내되 **PII 사전 검사 건수**를 보여 주고 거버넌스 ON이면 PII가 있는 파일(구현 pass 7: 쪽수·텍스트 상한으로 일부만 검사한 파일 포함 — 설계서 §25 I-82)을 제외한다. 금지어는 적재 문서에 적용하지 않는다(답변 출구 필터가 처리).

### 11. 권한·감사·표면

신규 권한·역할 0(관리 `security:write` · 조회 `security:read` · 챗봇 카드 `chatbot:read` — URL 미노출). `AuditTargetType` +`KbSource`(액션 추가 0). 관리 핸들러 13(컨트롤러 2) · `@Public()` 8 유지 · `ApiErrorCode` +3 · 기능 꺼짐 = KB 경로 `404`.

## 근거

- **가장 작은 재개**: 외부 RAG가 이미 가진 적재 기능을 그대로 쓰면 "자동 최신화"가 사람 손 없이 성립하고, 파괴적 경로는 한 글자도 열리지 않는다. 자체 색인안은 No.30·No.48 결정을 모두 뒤집고 GPU 4~7과 대량 원문 저장을 부른다.
- **"호출할 수 없게"의 유지**: 경로 인자 미수용 · `fetch` 1곳 · 필드 4개 고정 · 작업 id 브랜드 타입 · 금지어 조각 검사가 ADR-0022의 봉인 형식을 그대로 확장한다.
- **원문 비저장이 거버넌스 비용을 0으로 만든다**: 재수집 비용(바뀐 문서만 2번 GET)은 보존·암호화·파기·열람 감사 대상이 생기는 비용보다 훨씬 작다.
- **CAS가 부분 인덱스보다 이식성이 좋다**: SQLite·Postgres 공통 `updateMany` + 영향 행 수는 No.28·No.41·No.45에서 검증됐고, 원시 DDL을 늘리지 않는다.
- **작업 스레드**: 파서 취약점·압축 폭탄의 피해를 메모리·시간 상한 안에 가두고, 공개 대화 P95를 지킨다.

## 감수하는 비용

1. **외부에 옛 내용이 남는다**(사라짐·축소·스코프/형식 변경) — "정리 필요" 표시와 운영자 수동 정리로 드러낸다.
2. **답변 출처에 `kb_…` 파일 이름이 보인다**(공개 대화 경로 불변 우선) — 문서 첫 줄 제목·URL로 보완 · 매핑은 2차.
3. **바뀐 문서는 두 번 받는다**(감지 · 적재) — 원문 비저장의 대가.
4. **`INTERNAL_NETWORK`·`AUTHENTICATED`는 검증할 수 없는 운영자 선언**이다(TLS만 URL로 확인).
5. **호스트 속도 제한·robots 캐시는 인스턴스 메모리** — 다중 인스턴스에서 근사(호스트 겹치는 소스 동시 크롤 금지로 완화). pass 6부터 겹침 금지 판정이 크롤 시작 게이트(DB)라 인스턴스 수와 무관하다 — 남는 근사는 같은 실행이 인스턴스를 옮길 때 페이서 상태가 이어지지 않는 것(간격 1회 분량)뿐이다.
6. **첫 적재가 수 시간**이고 외부 vLLM을 점유한다 — 레인·시간창·ETA.
7. **`pdfjs-dist` 설치 크기**(수십 MB) — 원본 파일 사전 검사를 위한 것(빼면 PDF 사전 검사 없이 원본 전송 여부만 판단).
8. **공유 전송 부품의 위치(`legacy-api/`)와 쓰임(3출구)이 더 어긋난다** — 독립 리팩터 대기.

## 재검토 트리거

- **외부 RAG가 크롤링·동기화 API를 제공** → P-1 (c) 전환 검토(우리 크롤러를 예약·표시로 축소).
- **외부 RAG가 문서 1건 삭제 또는 삭제 결과 건수를 제공** → "정리 필요" 자동 처리(삭제 봉인 재설계 · 3필드 필수 · 호출 1곳).
- **"정리 필요" 누적이 운영 부담으로 실측** → 소스 전용 서브카테고리 재구축(범위 삭제) 2차 — 답변 공백 대응 포함.
- **외부 RAG에 인증·TLS 도입** → `RagHttpClient` 인증 헤더 주입(1파일) · ACK를 `AUTHENTICATED`/`TLS`로 검증 가능하게.
- **HTML·TXT 적재 지원 확인(Q-1)** → 기본 형식 전환(신규 설치부터).
- **SPA·로그인 사이트 비중이 높다는 실측** → 헤드리스 브라우저·비밀 저장 ADR(No.45 2차 KMS와 함께).
- **No.41 운영 이벤트 2차 착수** → "동기화 실패" 이벤트 추가(같은 발송 엔진).
- **네 번째 소비자(No.39 커넥터 허브) 또는 사용자 지시** → 공유 전송 부품 `common/outbound/` 이동.
- **답변 출처의 파일 이름 불만** → 공개 대화 출처 정제에 `kb_` 이름 → 제목 매핑(조회 1회 · 캐시) — 공개 경로 변경이므로 별도 설계.
- **처리량 부족(첫 적재가 하루를 넘김)** → `KB_INGEST_CONCURRENCY` 상향 협의 · 외부 RAG 증설.
