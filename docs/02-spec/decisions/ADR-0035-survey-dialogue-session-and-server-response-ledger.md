## 결정

### 1. 설문은 **챗봇별 자산**이다 (J-5, P-3)

`Survey(chatbotId FK Restrict, nameNormalized 챗봇 내 유일)` · 챗봇당 50개 · 경로 `/chatbots/:chatbotId/surveys/*`. 문항은 JSON(키 = 생성 후 불변 UUID). 설문 정의는 **대화 번들에 포함**(선택 필드)되어 엔진이 추가 조회 없이 판정하고, 교차 챗봇 방어가 번들 경계로 공짜가 된다(ADR-0009 근거). 전역 `/surveys` 예고는 정정한다.

### 2. 진행 방식 = **대화 내 멀티턴**, 상태 = **진행 포인터만 봉투** (J-2/J-3, P-2)

- 봉투(`CONVERSATION_STATE_VERSION` **1 유지** — `pendingClarify` 선례)에 선택 필드 2개: `surveySession`(설문 id · 구조 버전 · 시작 노드 id·아웃풋 위치 · 문항 순번 · 재시도 수 · 시작/마지막 시각) · `completedSurveyIds`(≤20). **응답 값·완료 판정·서버 발급 id는 담지 않는다.** 필드가 없으면 키를 생략해 기존 봉투와 바이트 동일하다.
- 봉투의 모든 값은 "사용자가 차례로 답하면 도달하는 값"이다(ADR-0009 §3 유지). 순번 조작 = 앞 문항 건너뛰기, 완료 목록 삭제 = 새 탭에서 재시작과 같은 결과이며 서버가 각각 `missingRequiredCount`·`isDuplicate`로 드러낸다.
- 위젯 전용 폼·새 `@Public` 경로를 만들지 않는다 — 응답은 기존 `POST /public/chatbots/:slug/messages` 한 경로로만 들어온다(`@Public()` 6개 불변). 문항은 기존 `TEXT` + `BUTTON`(5개 단위 분할)으로 표현하고 텍스트 입력(번호·라벨·숫자)을 항상 허용한다 — **위젯 변경 0**.

### 3. 엔진 통합 = **세션형 + 결과 동봉 + 사후 적재** — 정지점을 재사용하지 않는다 (J-4, architect)

- 순수 모듈 `survey-session.ts`(컨텍스트 세션의 **형제**)가 시작·전이(취소어 → 계속 가능 → 타임아웃 → 건너뛰기 → 판정·재시도 → 다음 문항·완료)를 맡고, 파이프라인에 **S0 설문 세션 단계**(S1과 상호 배타)를 둔다. 진행 중이면 모든 텍스트·`MESSAGE` 버튼 입력을 설문이 먼저 소비한다. 타임아웃·마감·구조 변경은 종료 안내 1줄 뒤 **이번 입력을 일반 대화로** 처리한다.
- 엔진은 응답을 **적재하지 않고** 결과의 선택 필드 `surveyEvents`(`EXPOSED｜ANSWERED｜SKIPPED｜COMPLETED｜ABANDONED`)와 `surveyTurn`(입력 소비 여부)만 낸다. 이 필드를 무시하는 소비자(시뮬레이터·비교·TC)는 **저장만 안 될 뿐 출력이 같다**.
- 엔진 수정은 **닫힌 목록 9항목**(executeOutputs 분기 · 세션 모듈 · S0/버튼 전환/완료 후 이동 · sanitize · **`resumeAfterApiCall` 설문 필드 이월** · `surveyTargets` · 결과 선택 필드 · **설계 점검 미지원 판정 교체** · **`mergeOverlay` 설문 이월**)이며, 엔진은 여전히 I/O·타이머·`Date.now()`·난수·Nest·Prisma 심볼 0건이다(정적 검사).

### 4. 응답 = **문항 단위 서버 적재 + 매 턴 재검증** (J-3/J-10/J-11, P-2·P-7·P-8)

- 공개 대화 파이프라인이 **엔진(및 API 완결) 뒤 · 출구 필터 앞**에서 `SurveyResponseService.apply()`를 await한다(설문 턴만). 쓰기 주체는 이 서비스 **1파일**(create·update)이다.
- **쓰기 키** = `(chatbotId, sessionId, surveyId, startedAt)` — 서버 발급 id를 봉투에 두지 않는다. **쓰기 가드**: 행 존재 · 상태 · 구조 버전 · 문항 키 일치 · **순서 증가**(조건부 `updateMany`로 원자 재확인) · 답 행 유일 · **값 재검증**(공용 순수 함수). 불충족은 조용히 무시(값 없는 경고 로그). 적재 실패는 대화 응답을 실패시키지 않는다.
- 선택 유형은 **선택지 1개당 1행**(대표 행 `isHead` 1개)이라 DB `groupBy`로 분포가 나온다. 라벨이 아니라 **키**만 저장한다(라벨 수정 허용의 근거).
- **중복**: 같은 `(chatbotId, sessionId, surveyId)`에 먼저 완료된 시도가 있으면 **노출·완료 시점에** `isDuplicate=true` — 통계 기본 제외. IP·쿠키·핑거프린트는 수집하지 않으며 여러 `sessionId`를 쓰는 부풀리기는 **근본 차단 불가로 수용**한다(레이트리밋이 상한).
- **자유 텍스트**는 `ConversationLogService.record()`와 **같은 함수·같은 순서**(금지어 → PII)로 마스킹한 값만 저장한다(ADR-0013 "저장" 지점의 두 번째 테이블 — 함수 1벌). 원문 컬럼 0. 서버 로그·trace·감사·오류 응답·시뮬레이터 응답에 응답 값 0.

### 5. 응답이 달린 정의 = **구조 잠금 + 문구 수정 허용 + 복제** (J-8, P-5)

첫 답 행(응답·건너뜀) 이후 문항 추가·삭제·순서·유형·선택지 추가/삭제/순서·척도 종류·필수·선택 수·최대 길이 변경은 `409 SURVEY_STRUCTURE_LOCKED`. 문구(문항·선택지 라벨·척도 라벨·소개·완료 문구·취소어·타임아웃·기간·상태)는 수정 가능(경고 배너). 응답 전 구조 변경은 `structureVersion+1`이고 진행 중 세션은 다음 턴 종료 안내. 구조를 바꾸려면 **복제**(키 재발급·DRAFT). 버전별 통계(리비전)는 만들지 않는다.

### 6. 참여 통계 = **노출일(KST) 코호트 + 조회 시점 이탈 판정** — 배치 없음 (J-13, P-10)

노출·시작·완료·중도 이탈·미시작 이탈·진행 중 + 참여율·완료율·중도 이탈률, 문항별 도달·분포·평균·NPS. 무응답 이탈은 행을 바꾸지 않고 `lastInteractedAt + 현재 타임아웃 < 조회 시각`으로 판정한다. DB `groupBy` + 설문 전용 순수 조립(ADR-0004) · 원시 SQL 0 · 기존 `summary-assembler.ts` 수정 0. **챗봇 스코프만** — 단 노출 당시 `groupId` 스냅샷은 지금 적재한다(ADR-0033 §4 — 후속 그룹 통합이 과거를 소급 변경하지 않게).

### 7. 대화 통계와의 관계 = **`ConversationLog.surveyTurn`** (J-14, P-11)

설문이 입력을 소비한 턴은 로그에 그대로 남기되 `surveyTurn=true`(파생 불가 → ADR-0004 통과, 기존 행 false = 사실, 백필 0). 질문 순위(**모든 스코프 — 대시보드 포함 5곳, 조건 상수 1벌**)·미응답 수집(사유 `SURVEY_TURN`)·RAG 판정(입력 `surveyTurn`)에서 제외한다. 턴 수·세션·응답률·출처는 불변. 설문이 입력을 소비할 턴은 의미 점수(임베딩) 계산도 생략한다.

### 8. 응답 데이터의 수명 = **삭제 경로 0 · 사전검사 대상** (J-12, P-9 — ADR-0033 확장)

`SurveyResponse`·`SurveyAnswer`의 `delete*`·원시 `DELETE` 0건, 쓰기 1파일, FK `Restrict`(Cascade/SetNull 없음)를 정적 검사가 단언한다. 응답(노출 포함)이 있는 설문은 삭제 불가(`409 SURVEY_HAS_RESPONSES`) → **마감**. 챗봇 영구삭제 사전검사에 `설문`·`설문 응답`을 추가하고 동반 삭제 목록에 넣지 않는다. 보존기간·파기는 No.45 — 그때 "단일 서비스 + 같은 트랜잭션의 수치 롤업 선적재"(텍스트·세션 ID 없음) 규약을 따른다.

### 9. 기존 v1 `SURVEY` = **읽기 호환 · 실행 안 함 · 쓰기 400 · 자동 연결/변환 없음** (J-18, P-15)

읽기 = v2(`{ version: 2, surveyId: uuid, onCompleteNodeId? }`) ∪ v1(자유 문자열), 판별 `version === 2`. v1은 기존과 바이트 동일한 미지원 처리. 새 v1 저장 `400 SURVEY_OUTPUT_LEGACY_FORMAT`, 노드 복사 시 v1 제외. 자유 키로 설문을 자동 연결하지 않는다 — 관리자가 나중에 같은 이름의 설문을 만드는 순간 과거 노드가 **조용히 실행되기 시작**하는 것을 막는다. `UNSUPPORTED_OUTPUT_TYPES = ['SCENARIO']`. AC-5-7의 기대값이 201 → 400으로 바뀐다(의도된 변경).

### 10. 품질 도구 = **저장 0 + 미리보기 판정** (J-17, P-14 — ADR-0030 형식)

시뮬레이터·비교·TC·버전·예약 모듈은 `SurveyResponseService`를 **주입할 수 없다**(DI 그래프 부재 + 정적 검사). 시뮬레이터는 실제 상태·기간이 기본이고 `설문 미리보기` 토글로 DRAFT·마감·기간 밖 설문을 진행한다(결과 패널 `설문 단계` — 판정 값 미표시). **TC·비교는 항상 미리보기 판정**(상태·기간 무시) — 실행 날짜에 따라 응답 해시가 달라지지 않는다(ADR-0029). 미리보기 여부는 재진입 상태에 실려 API 목 완결에서도 유지된다.

### 11. 버전·예약 = **설문은 스냅샷 밖, 참조만 스냅샷** (J-9/J-19, P-6·P-16)

스냅샷은 노드 `outputs`(설문 참조)만 담는다 — 봉투가 자산 6종을 명시 나열하므로 구조로 보장된다. 복원 미리보기 경고 3종(`SURVEY_MISSING`·`SURVEY_NOT_OPEN`·`SURVEY_LEGACY_FORMAT`, 차단 아님). 설문 삭제 409는 현재 노드 참조만 본다. 설문 운영 기간은 설문 자체 상태 + 선택 기간을 **대화 시점에 엔진이 판정**하며 No.28(예약 배포)은 변경 0이다.

### 12. 권한·감사 = **신규 권한 0 · `Survey` 감사 대상** (J-15, P-12·P-13)

정의 `dialogue:read｜write`, 결과·통계·CSV `chatbot:read`(VIEWER 포함 — 마스킹본). `AuditTargetType`에 `Survey`(정의 CRUD·상태·복제 — 문항 본문 미기록). 응답 1건·CSV 내보내기는 감사하지 않는다. CSV 2종은 기간 필수·최신 10,000행·BOM·수식 인젝션 방어·`sessionId` 미포함.

## 근거

- **정지점은 이 문제의 도구가 아니다.** 정지는 "다음 출력이 외부 결과에 달렸을 때"만 정당하다. 설문의 다음 출력(다음 문항·재질문·완료)은 입력과 정의로 결정되고, DB는 **기록만** 한다 — 기록 결과가 출력을 바꾸지 않는다. 정지를 쓰면 턴당 1회 규약 때문에 API 분기 노드의 설문이 실행 불가가 되고, 소비자 4곳에 설문용 완결 헬퍼가 붙는다.
- **값을 봉투에 두지 않는 것이 ADR-0009를 지키는 유일한 방법이다.** 봉투 누적(대안 B)은 완료 전 이탈자가 어디서 멈췄는지 알 수 없어 카탈로그의 "참여통계"가 노출/완료 2점으로 퇴화하고, 탭을 닫으면 부분 응답이 사라진다. 서버 세션 테이블(대안 C)의 이득(포인터 위변조 방지)은 서버 쓰기 가드가 대부분 얻는다.
- **순서 증가 가드 + 쓰기 키 + 값 재검증**이 무서명 봉투에서도 응답 데이터의 신뢰를 만든다. 조작 가능한 것은 "어디까지 왔나"뿐이고, 그 조작의 결과는 서버 데이터(누락 수·중복 표시)에 드러난다.
- **키 저장 + 구조 잠금**은 "문구는 고치고 싶다"와 "과거 응답이 흔들리면 안 된다"를 동시에 만족하는 최소 장치다. 리비전은 통계·CSV·집계 전부에 버전 축을 요구한다.
- **`surveyTurn`은 파생할 수 없는 사실**이다(어떤 턴을 설문이 소비했는지는 로그 행만으로 알 수 없다). 설문은 응답자 전원이 같은 값을 반복하므로 컨텍스트 폼과 달리 질문 순위를 실제로 오염시킨다.
- **삭제 봉인 확장**은 ADR-0033의 논리 그대로다 — 응답은 참여 통계의 유일한 원천이고, "아무도 안 지운다"는 우연을 정적 검사로 바꾼다.

## 대안과 트레이드오프

| 대안 | 기각 사유 |
|---|---|
| **B. 응답 전체를 봉투에 누적 → 완료 시 1회 제출** | 이탈 문항 불명(참여통계 퇴화) · 탭 닫으면 부분 응답 소실 · 값이 봉투에 있어 조작 가능 |
| **C. 서버 세션 테이블 + 봉투에 서버 발급 id** | 매 설문 턴 읽기 + 엔진 입력 주입 경로 신설 + ADR-0009 결정 1 대체. 재개 능력은 A와 같다(`sessionId`가 탭 저장소). 재검토 트리거 미발동 |
| **D. 위젯 별도 폼 + 신규 공개 제출 경로** | `@Public()` 7번째(레이트리밋·Origin 가드 재설계) · 위젯 신규 렌더러(번들 예산·접근성·채널 격하) · "대화 **중** 호출"과 거리 — No.46 |
| **정지점(ADR-0034) 재사용** | 정지 조건 불충족 · 턴당 1회 충돌 · 소비자 4곳 완결 헬퍼 |
| **자유 키 자동 연결 / v1 자동 변환** | 나중에 만든 같은 이름 설문이 과거 노드에서 조용히 실행 |
| **설문 리비전(버전별 통계)** | 통계·CSV·집계 전부에 버전 축 — 1차 과설계. 트리거 = 복제 반복 운영 부담 |
| **설문을 스냅샷에 포함** | 스키마 버전·업캐스터·차이·복원 적용기 확장 + **복원이 잠긴 구조를 되돌려** 응답과 정의가 어긋남 |
| **IP·쿠키로 중복 차단** | 개인정보 범위 확대(No.45) · 공용 IP 오탐 |
| **이탈 확정 배치(스케줄러)** | 조회 시점 판정으로 충분 — 배치는 멱등·misfire·다중 인스턴스 문제를 새로 만든다 |
| **대화로그의 설문 답을 `[설문 응답]`으로 가림** | "로그는 사용자가 실제로 보낸 것" 규약 위반 · 이득 없음(같은 마스킹 함수를 거친다) |
| **응답 삭제 허용(설문 삭제 시 동반)** | 참여 통계 원천 소실 — ADR-0033과 같은 판단(마감으로 대체) |
| **질문 순위를 조회 시점 조인으로 제외** | 로그 행만으로 설문 턴을 식별할 수 없다(파생 불가) |

**감수하는 비용**
① **엔진을 두 번째로 수정한다** — 닫힌 목록 + 엔진 I/O 0건 정적 검사 + 설문 없는 번들·봉투의 기존 스위트 무수정 통과로 통제한다.
② 이전 문항 버튼을 다시 누르면 현재 문항의 답으로 적재될 수 있다(위젯 변경 0의 대가 — No.46).
③ 여러 `sessionId`를 이용한 표 부풀리기를 막을 수 없다(익명 위젯의 구조적 한계).
④ 조회 시점 판정은 **현재** 타임아웃 값을 쓰므로 타임아웃을 바꾸면 과거 진행 중/이탈 분류가 소급해 바뀐다.
⑤ 봉투 키 집합 고정 검사(No.26 L-12)의 기대값이 바뀐다 — 목적은 설문 세션 키 집합 고정 검사로 더 정밀하게 유지된다.
⑥ 자유 텍스트의 이름·주소는 가려지지 않는다(고지).
⑦ 컨텍스트 폼의 버튼 6개 이상 미표시 결함은 이 결정의 범위 밖으로 남는다(별도 과제).
