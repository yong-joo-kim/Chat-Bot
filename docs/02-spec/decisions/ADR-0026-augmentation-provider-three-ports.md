# ADR-0026 — `AugmentationProvider` 3-포트 추상화(규칙 · Gemini · 로컬 생성모델)와 `packages/llm-provider` 배치

- **상태**: 채택 (Accepted)
- **일자**: 2026-09-22
- **결정자**: system-architect (PM 확정사항 3 반영 — G2 기본 제공자 = Google Gemini, G3 = 자체 GPU 보유 확인)
- **관련**: `docs/requirements/learning-augmentation.md` **J-3**, FR-0-53/54/55, FR-L1-5~9, NFR-LS1/LS3/LS5/LS7, NFR-LM6/LM7, AC-L1-14/15, AC-L4-1/12 / ADR-0024(ml-worker 범위·`packages/llm-provider` 미생성) / ADR-0022(외부 HTTP 출구 단일화) / ADR-0013(PII 마스킹 1벌) / ADR-0011(타입 분기는 팩토리 1곳)
- **영향 범위**: `apps/api/src/augmentation/providers/**`(신설), `apps/ml-worker/**`(선택적 생성 프로파일), 개발명세서 §1·§2·§2.1·§5.1·§6
- **세부 설계**: `docs/02-spec/learning-augmentation-설계.md` §4·§5

## 맥락

증강 후보 문장을 무엇으로 만드는가는 **배포형태(구축형/구독형)·데이터 거버넌스·GPU 보유 여부에 따라 답이 다르다.** 같은 코드가 세 상황을 모두 지원해야 한다(개발명세서 §5 "배포형태 중립").

PM 확정 사항이 선행 그룹 대비 두 가지 바뀌었다.

1. **G2(외부 LLM API)를 승인**했고 **기본 제공자는 Google Gemini**다. 단 **API 키는 나중에 환경변수로 공급**되므로 **지금은 키 없이도 앱이 기동**해야 한다.
2. **G3(로컬 생성모델)를 승인**했고 **데이터센터급 GPU(VRAM 24GB 이상)를 보유**한다. 따라서 소형 양자화 모델로 타협하지 않고 **실제 생성모델 후보를 실측 비교**한다.

## 결정

### 1. 포트 1개 + 구현체 3종. 교체 지점은 **팩토리 1곳**이다

```ts
export type AugmentationProviderId = 'rule' | 'gemini' | 'local';

export interface AugmentationProvider {
  readonly providerId: AugmentationProviderId;
  /** true면 PII 마스킹·금지어·타임아웃·회로차단 경로가 강제된다. */
  readonly requiresNetwork: boolean;
  /** 검증 전 원시 후보. 실패·타임아웃·스키마 불일치는 빈 배열로 수렴한다(예외 전파 금지). */
  generate(input: {
    seeds: readonly string[];   // 기존 예문 + 의도명
    targetCount: number;
    locale: 'ko';
  }): Promise<readonly string[]>;
  healthy(): Promise<boolean>;  // 예외를 던지지 않는다
}
```

| 구현체 | 방식 | 자체 GPU | 외부 호출 | 구축형 | 역할 |
|---|---|:---:|:---:|:---:|---|
| **G1 `RuleBasedAugmentationProvider`** (**기본값**) | 어미·종결형 변형, 조사 교체, **기존 `Keyword.synonyms`·`HomonymDictionary` 동의어 치환**, 띄어쓰기·어순 변형, 경어/구어 변환 | 0 | **없음** | ○ | **1차 필수 구현 · 모든 폴백의 종착점** |
| **G2 `GeminiAugmentationProvider`** | Google Gemini API에 패러프레이즈 요청 | 0 | 있음 | △ | PM 승인. **키 미설정 시 G1로 저하**하며 기동을 막지 않는다 |
| **G3 `LocalGenerativeAugmentationProvider`** | ml-worker의 생성 프로파일에 `POST /augment` | 6~7 | 없음(사내) | ○ | PM 승인. **구축형에서 외부 전송 0 + 고품질**을 동시에 만족하는 유일한 구성 |

**선택은 챗봇별 설정이 아니라 인스턴스 설정**(`AUGMENTATION_PROVIDER` 환경변수)이다. 챗봇마다 외부 전송 여부가 달라지면 데이터 거버넌스 판단이 챗봇 단위로 흩어지고, "어떤 챗봇의 문장이 외부로 나갔는가"를 운영자가 추적할 수 없게 된다(FR-L1-5).

### 2. **G1은 기능의 바닥이다** — 모든 실패는 G1으로 수렴한다

| 상황 | 동작 |
|---|---|
| 환경변수 미설정 | G1 |
| `AUGMENTATION_PROVIDER=gemini`인데 **API 키 없음** | **기동 성공** + 경고 로그 1회 + G1로 동작. 화면은 "고급 증강을 사용할 수 없어 기본 방식으로 생성했습니다"를 표시 |
| G2/G3 타임아웃(기본 30초)·4xx/5xx·스키마 불일치 | G1 폴백 + 동일 안내. **오류 화면이 아니다**(FR-L1-7) |
| 연속 5회 실패 | 회로 open 60초 → 그동안 G1 직행 |
| 테스트·CI | `MockAugmentationProvider`(결정론적 후보 N건). **외부 자원·GPU 없이 전 테스트 통과**(NFR-LM7) |

> `MockEmbeddingProvider`로 Python 없이 전 테스트가 통과하는 것과 같은 논리다(ADR-0024 §3-2). **개발·데모·CI가 외부 자원에 묶이지 않는 것**이 이 프로젝트의 확립된 규약이다.

### 3. 네트워크 Provider의 **강제 경로 5단계**

`requiresNetwork === true`인 구현체는 예외 없이 다음을 통과한다(FR-L1-6, NFR-LS1/LS3).

```
시드 문장 ─▶ ① PII 마스킹(packages/pii-mask, 같은 함수 1벌) ─▶ ② 금지어 검사
         ─▶ ③ 송신(타임아웃 30초 · 회로차단 5회/60초)
         ─▶ ④ zod 파싱(실패 = 호출 실패로 처리, 예외 아님)
         ─▶ ⑤ 길이·제어문자·한국어 판별 ─▶ [ADR-0025 §3의 의미 검증으로 인계]
```

- **PII 마스킹 적용 지점이 3곳**(대화로그 저장 · RAG 송신 · **증강 송신**)이 되지만 **함수는 여전히 1벌**이다(ADR-0013 갱신 — 정책 불변, 지점만 확대).
- **외부 HTTP 출구 규약 확장**: 외부로 나가는 HTTP는 RAG 1곳(`rag-http.client.ts`) + 임베딩 1곳(`http-embedding.provider.ts`) + **Gemini 1곳(`providers/gemini-augmentation.provider.ts`)** 뿐이다. 다른 어떤 서비스도 이 호스트들을 직접 부르지 않는다(개발명세서 §2.1).
- **자격증명은 코드·DB에 저장하지 않는다**(채널 자격증명 미저장 원칙과 동일). 환경변수로만 주입하며, 로그·응답·감사 어디에도 나타나지 않는다.
- **`AUGMENTATION_PROVIDER=rule` 구성에서 외부로 나가는 HTTP가 0건**임이 검증 가능해야 한다(AC-L1-14) — G2/G3 구현체는 **인스턴스화 자체가 일어나지 않는다**(팩토리가 선택된 1종만 생성한다).

### 4. **G2 = Google Gemini**. 지금은 설정 스키마 + 클라이언트 껍데기까지 구현한다

| 항목 | 확정 |
|---|---|
| 환경변수 | `AUGMENTATION_GEMINI_API_KEY`(없으면 G1 저하) · `AUGMENTATION_GEMINI_MODEL`(기본값 코드 상수) · `AUGMENTATION_GEMINI_BASE_URL`(기본 공식 엔드포인트, **사내 프록시·게이트웨이 주입용으로 열어 둔다** — 하드코딩 금지 원칙) |
| SDK | **공식 SDK를 의존성으로 추가하지 않고 `fetch` + zod로 REST를 직접 호출**한다. 근거 — 접촉면이 엔드포인트 1개이고, SDK는 전송·재시도·로깅을 자체 정책으로 수행해 §3의 강제 경로(마스킹·타임아웃·회로차단)를 우회할 여지를 만든다. RAG 클라이언트와 동일한 판단이다 |
| 프롬프트 | 코드 상수 1곳(`lib/gemini-prompt.ts`). **사용자·관리자 입력이 프롬프트 지시문 위치에 들어가지 않는다**(시드는 구조화된 JSON 배열 필드로만 전달) |
| 응답 신뢰 | zod 파싱 필수. 프롬프트 인젝션으로 유도된 이상 출력은 **의미 검증(ADR-0025 §3)에서 대부분 탈락**하며, 통과해도 금지어·한국어 판별이 남는다 |
| 키 없는 상태 | **정상 기동 + `GET .../augmentations/capability`가 `{ providerId:'rule', degradedFrom:'gemini', reason:'API_KEY_MISSING' }`을 보고** — 화면이 원인을 말할 수 있다 |

### 5. **G3 = 로컬 생성모델**. ml-worker의 선택적 생성 프로파일로 수용하고, 모델 선정은 실측으로 확정한다

- 계약: `POST /augment { seeds: string[], targetCount: number, locale: 'ko' } → { modelId, candidates: string[] }`.
- `apps/api`는 이것을 **`local` Provider 구현체 1개**로만 안다 — 모델·서빙 엔진·프롬프트 규칙을 알지 못한다(`/embed`의 `kind` 프리픽스 규칙을 API가 모르는 것과 같은 경계).
- **모델은 실측으로 고른다.** ml-engineer가 **후보 3종을 5지표로 비교한 표**를 남기고 확정한다 — 직전 그룹에서 임베딩 모델(KURE-v1)을 고른 절차와 동일하며, **이 표가 G3 착수 시 가장 먼저 나와야 하는 산출물**이다.

| 지표 | 측정 방법 |
|---|---|
| ① **의미 보존 통과율** | 생성 후보 중 `0.75 ≤ cos ≤ 0.97` 비율(높을수록 좋다) |
| ② **신규성 통과율** | 기존 예문과 `cos < 0.95`인 비율(①과 트레이드오프 — 둘의 곱이 실질 수율) |
| ③ **타 의도 충돌률** | 다른 의도 예문과 `cos ≥ τ_accept`인 비율(낮을수록 좋다) |
| ④ **생성 지연** | 시드 5건 → 후보 20건 배치 1회의 P95(관리자 대기 UX 성립 여부) |
| ⑤ **VRAM 점유 · 라이선스** | 임베딩 모델과 **동거 가능한가** · 상업적 이용 가능한가 |

> **VRAM 24GB 이상 보유가 전제다.** 소형 양자화 모델로 타협하지 않는다 — 데이터센터급 GPU에서 의미 있는 품질 차이를 낼 수 있는 한국어 생성모델(한국어 특화 8B급 / 다국어 14B급 / 32B 양자화급)을 실제로 비교한다. **라이선스가 상업적 이용을 막는 모델은 후보에서 제외**한다(구축형 고객사 납품 전제).

**⚠ 자원 경합 통제(이 ADR의 핵심 운영 제약)**: 생성모델과 임베딩 모델이 **같은 프로세스·같은 GPU를 공유하면 대화 경로의 `EMBEDDING_TIMEOUT_MS=300` 예산이 증강 생성에 밀린다.** 따라서 ml-worker에 **실행 프로파일**(`ML_WORKER_ROLE=embed|augment|both`, 기본 `embed`)을 도입하고 **운영 기본 구성은 프로세스 분리**(별도 포트)를 권고한다. `both`는 개발 편의용이며 **대화 성능 예산을 보장하지 않는다**고 문서에 명시한다. 이는 ADR-0024의 재검토 트리거 *"ml-worker의 역할이 임베딩 서비스를 넘어서면 내부 구조(단일 프로세스 vs 워커 분리)를 다시 정한다"* 의 조기 발동이다.

### 6. **`packages/llm-provider`는 이번에도 만들지 않는다**

| 판단 | 내용 |
|---|---|
| **원칙은 지킨다** | LLM 연동은 **Provider 추상화를 통해서만** 한다. 포트 1개 + 구현 3종(`rule` ≈ 의존성 0 · `gemini` ≈ cloud · `local` ≈ on-prem)이 개발명세서 §1의 `mock｜on-prem｜cloud` 요구를 그대로 충족한다 |
| **배치만 미룬다** | 포트와 구현체는 `apps/api/src/augmentation/providers/`에 둔다. **소비자가 `apps/api` 1곳**이기 때문이다 — `packages/pii-mask`를 소비자가 2곳이 된 시점에 승격한 것과 동일한 규약이다(ADR-0013 갱신, ADR-0024 §7) |
| **승격 트리거** | LLM 호출 소비자가 **2곳 이상**이 될 때(No.24 상담원 답변 제안 · No.34 생성형 요약 · No.19 대화검증 자동 채점 등). 그때 파일 이동만으로 승격되도록 **포트 파일은 Nest 데코레이터·Prisma 타입에 의존하지 않게** 유지한다 |

## 근거

- **"인터페이스 1곳 + 구현 교체"는 이 프로젝트의 확립된 패턴**이다(ADR-0007 스테이징 · ADR-0011 채널 팩토리 · ADR-0016 감사 단일 진입점 · ADR-0018 학습 인계 지점 · ADR-0024 `EmbeddingProvider`). 이번이 여섯 번째 적용이며, 새 개념을 도입하지 않는다.
- **G1이 바닥에 있어야 기능이 성립한다.** 증강이 외부 자원 없이는 아무것도 못 하는 기능이라면, 구축형 고객사와 CI 양쪽에서 "있으나 마나"가 된다. 한국어는 교착어라 **어미·조사 변형만으로도 표현 다양성이 실질적으로 늘고**, 사내 사전(`Keyword.synonyms`·`HomonymDictionary`)을 재활용하므로 도메인 적합도가 외부 LLM보다 높을 수 있다.
- **키 없이 기동해야 한다는 요구가 설계를 결정한다.** Provider 선택과 Provider 가용성을 분리하고(`선택 ≠ 사용 가능`), 가용성 판정 결과를 **API로 노출**(`/augmentations/capability`)해야 화면이 "왜 품질이 낮은가"를 말할 수 있다. 조용히 저하되면 운영자는 Gemini가 동작 중이라고 오해한다.
- **GPU 경합은 실측 전에 구조로 막아야 한다.** 임베딩 300ms 예산은 공개 대화 API 500ms(P95)의 전제이고, 그 예산이 관리자 편의 기능 때문에 깨지면 **사용자가 대가를 치른다.** 프로세스 분리는 되돌리기 쉬운 통제다.
- **SDK를 쓰지 않는 것은 통제 일관성 때문이다.** 마스킹·타임아웃·회로차단·zod 파싱이 **모든 외부 출구에서 동일하게** 적용되는 것이 이 프로젝트의 불변식이다(ADR-0022). SDK는 그 불변식을 조용히 우회한다.

## 대안과 트레이드오프

| 대안 | 기각 사유 |
|---|---|
| **G2만 구현(규칙 기반 생략)** | 키가 없으면 기능 전체가 죽는다. 구축형 고객사(외부 전송 금지)에 제공할 구성이 없어진다 |
| **외부 RAG 서버를 패러프레이즈에 재사용** | allowlist 3경로뿐이고 `/api/rag/query`는 **문서검색 + LLM 생성**이라 용도가 다르며 수 초~수십 초가 걸린다. 봉인을 뚫는 순간 ADR-0022가 무의미해진다 |
| **Provider를 챗봇별 설정으로 노출** | 데이터 거버넌스 판단이 챗봇 단위로 흩어지고, 구축형에서 "외부 전송 0건"을 인스턴스 차원에서 보증할 수 없게 된다(AC-L1-14 불가) |
| **G3를 `apps/api`(Node)에 임베드** | 한국어 생성모델의 1차 배포 형태가 PyTorch/HF다. Node에 넣으면 모델 선택 자유가 사라진다 — ADR-0024 §3이 이미 내린 결론과 동일 |
| **생성·임베딩을 ml-worker 한 프로세스에 항상 동거** | 같은 GPU·같은 요청 큐를 공유해 대화 경로 지연이 관리자 작업에 종속된다. 개발 편의용 `both` 프로파일로만 허용한다 |
| **`packages/llm-provider`를 지금 만든다** | 소비자가 1곳인 추상화를 패키지로 올리면 빌드 그래프·버전·export 표면만 늘고 얻는 것이 없다. 승격 조건(소비자 2곳)은 이미 문서화된 규약이다 |
| **Gemini 공식 SDK 사용** | 전송·재시도·로깅 정책이 우리 통제 밖으로 나가 마스킹·회로차단·타임아웃 불변식이 깨질 수 있다. 접촉면이 엔드포인트 1개라 직접 호출 비용이 작다 |

**감수하는 비용**

1. **G1의 제안 품질은 LLM보다 낮다** → 검증 5종이 품질 하한을 지키고, 화면이 "생성 N건 중 M건 통과"를 항상 보여 준다(FR-L1-14). 낮은 수율이 **조용히** 나타나지 않는다.
2. **G2는 문장을 외부로 내보낸다** → PII 마스킹·금지어 통과가 강제되고, 구축형은 `rule`/`local` 고정으로 회피한다. 리스크 수용 범위는 RAG(R-1)와 동일한 방식으로 관리한다.
3. **G3는 모델 파일·VRAM·기동 시간을 소비한다** → `ML_WORKER_ROLE` 기본값이 `embed`이므로 **아무것도 하지 않으면 현행과 동일**하다.
4. **Provider가 3종이라 테스트 조합이 늘어난다** → Mock + 모킹 fixture 5종(정상/빈 응답/의미 이탈/금지어 포함/스키마 불일치)으로 고정하고, **외부 LLM을 실제 호출하는 테스트는 CI에 넣지 않는다**.

## 갱신 (2026-09-25 — No.24: 승격 트리거 미발동)

하이브리드 CS(No.24, ADR-0036 §9)의 응답힌트는 **LLM 생성이 아니라 기존 자산 검색**(의미 매칭 상위 N · 문자 유사도 · 자주 쓰는 문장)이다. LLM 호출 소비자는 여전히 증강 1곳이므로 승격 트리거(§6 "No.24 상담원 답변 제안")는 **발동하지 않았다**. 생성형 답변 제안·상담 요약이 착수되면 그때 승격한다(ADR-0036 재검토 트리거).
- **G3 실측에서 ④ 생성 지연이 관리자 대기 UX를 깨뜨림**(예: 후보 20건 P95 > 60초) → 서빙 엔진·양자화·배치 전략 재검토, 그래도 미달이면 G2 기본 전환.
- **`both` 프로파일 운영 중 대화 P95 회귀 관측** → 프로세스 분리를 권고가 아닌 **강제**로 승격.
- **Gemini 외 제공자 요구**(Azure OpenAI·사내 vLLM 게이트웨이 등) → `AugmentationProviderId` 유니온 확장 1곳 + 구현체 추가로 흡수. 포트는 바뀌지 않는다.
