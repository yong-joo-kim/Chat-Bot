## 맥락

카탈로그 No.32는 "실시간 음성인식/합성, 감정 톤 반영 자연스러운 음성 응대"다. 지금 제품에는 음성 코드가 0건이다. PM은 2026-10-01에 **규모 A**(웹 위젯 · 눌러서 말하기 최대 30초 · 서버 사내 STT · 인식 글자를 입력창에 채워 사용자 확인 후 전송 · 봇 답변은 **브라우저 내장 음성** · 감정 톤 = 규칙 기반 rate·pitch·volume · 음성 원본 저장 0 · 3050은 "동작 확인", STT 합격은 L40S 실측)를 확정했다. 서버가 새로 지는 부담은 STT 하나다. 결정할 것은 열 가지다.

1. **ml-worker 구조** — ADR-0024의 트리거가 발동했다. STT는 인증 없는 공개 경로가 부르는 **요청당 GPU 추론**이다. 대화 임베딩(300ms 예산)과 어떻게 떼어 놓나.
2. **디스크 0** — 녹음은 가릴 수 없는 개인정보다. 업로드·디코딩 어디에서도 파일이 생기면 안 된다. 그런데 웹 프레임워크의 업로드 처리는 큰 본문을 임시 파일로 넘기는 것이 기본이다.
3. **공개 표면** — 공개 경로 +1이 불가피하다. 본문 형식·세션 결합·레이트·동시 처리·오류 응답은?
4. **읽기용 글자** — 위젯이 화면 출력을 직접 읽게 할지, 서버가 만들어 줄지. 어떤 키로 어디에? **어떤 응답까지 읽나?**
5. **말투(감정 톤)** — 누가 고르고 어떻게 전달하나. 노드별 지정은 어디에 저장하나.
6. **저장** — 음성 설정·일별 숫자의 위치. 대화 턴 쿼리 수 고정 시험(17)과의 관계.
7. **Provider 추상화** — 명세서가 그려 둔 "LLM/STT/TTS Provider(`packages/llm-provider`)"를 지금 만들지. **시험용 `mock` 공급자가 운영에서 켜지는 것을 어떻게 막나.**
8. **거버넌스** — 새 출구·데이터 종류 · 기본 설치 데이터 지도 바이트 동일.
9. **위젯** — 의존성 0 · 꺼짐이면 실행 0 · 기기 안 음성만.
10. **바이트 동일** — 음성을 안 쓰는 챗봇·구버전 위젯의 요청·응답이 바뀌면 안 된다.

## 결정

### 1. ml-worker에 **배타 역할 `ML_WORKER_ROLE=speech`** 를 둔다 — ADR-0024 음성 트리거 해소

- 역할 값은 `embed`(기본)·`augment`·`both`·**`speech`**. `speech`는 **STT 1종 + VAD만** 적재하고 `/speech/transcribe`·`/speech/health`를 등록한다. 다른 역할과 **결합하지 않는다**(`both`의 의미 불변 · 음성 포함 조합 값을 만들지 않는다). 다른 역할에서 `/speech/*`는 404이고, `speech` 역할에서 `/augment`·`/cluster-label`은 404다. `/embed`·`/health`는 역할 무관 계약 그대로(이 역할에서는 `loading`/503).
- 같은 패키지·같은 진입점(`ml_worker.app:app`)·같은 설정 로더를 쓴다 — 별도 앱 모듈은 기각(운영 명령·시험 장치 2벌). 실행 스크립트 `start:speech`는 `VAR=값 명령` 셸 문법이 Windows에서 돌지 않아 **래퍼 스크립트**(`scripts/start-speech.mjs`)로 둔다(구현 반영).
- ADR-0024 §갱신 1의 "모델 파인튜닝 없음 · DB 접근 0"과 §갱신 4의 "건드리지 않는 것" 전부를 지킨다. 추가로 `speech` 프로세스는 **외부 송신 0**(모델은 로컬 파일 — 기동 중 내려받기 0 `local_files_only` 고정)이다.
- 알 수 없는 역할 값은 기동 실패로 바꾼다(지금은 조용히 아무것도 적재하지 않는다 — 기존 3값 동작 불변).
- `GET /speech/health`는 전사기가 **실제로 적재한** `device`·`computeType`을 보고한다(설정값이 아니라 — No.37 교훈).
- **비전(No.33) 착수 시에도 같은 방식**(별도 배타 역할)을 기본안으로 한다 — ADR-0024의 트리거는 "비전"에 대해서만 남는다.

### 2. 오디오는 **원시 바이트 · 메모리 디코딩**으로만 다룬다 (디스크 0)

- API: 공개 경로 본문은 녹음 바이트 그대로(`audio/*`·`application/octet-stream`). API의 본문 파서는 JSON·urlencoded뿐이라 이 본문은 파싱되지 않은 채 남고, **가드(레이트·Origin)가 끝난 뒤** 핸들러가 바이트·시간 상한을 걸고 읽는다. multer·`FileInterceptor`를 쓰지 않는다.
- ml-worker: `Request.stream()`으로 상한 읽기 → **PyAV `av.open(io.BytesIO(...))`** → 16kHz 모노 float32 → VAD → STT(배열 입력). `UploadFile`(python-multipart는 1MB를 넘으면 임시 파일로 넘긴다)·Pydantic 본문 모델(422 응답이 입력을 되돌려 싣는다)·`tempfile`·ffmpeg 하위 프로세스를 금지한다(정적 검사).
- **[구현 반영 — 코드 리뷰 M-5] 공개 경로의 임의 바이트가 외부 참조 형식으로 해석되지 않게 한다**: `av.open`에 `protocol_whitelist="pipe"`(커스텀 IO 외 프로토콜 접근 0)와 `format_whitelist`(matroska·webm·mov·mp4·m4a·3gp·3g2·mj2·ogg·wav)를 걸고, 열린 뒤 `container.format.name`을 허용 목록과 다시 대조해 밖이면 `INVALID`로 끝낸다 — HLS·concat·data URI처럼 다른 자원을 끌어오는 형식이 탐지돼도 열리지 않는다.
- 디코딩은 프레임 루프에서 **길이(32초 — `STT_MAX_AUDIO_SECONDS`, 실수 허용)·시간(데드라인)** 을 검사해 압축 폭탄을 끊는다.
- 오류 본문은 코드 문자열만이다 — `INVALID` 400 · `TOO_LARGE` 413 · `TOO_LONG` 413 · `BUSY` 503 · `DEADLINE` 504 · `LOADING` 503 · `FAILED` 500.
- 로그·오류 본문·감사·메트릭에 오디오 바이트·인식 글자를 넣지 않는다(바이트 수·지속 시간·결과 코드만).

### 3. 공개 표면 = **인식 경로 1개**(`@Public()` 9 → 10)

- `POST /public/chatbots/:slug/speech/transcriptions` · 세션은 헤더 `x-cb-session-id`(No.24와 같은 헤더 — CORS 변경 0) · 응답 `{ text, durationMs, empty? }`(`durationMs` = 녹음 길이 · 모델·장치 정보 0). 핸들러는 컨트롤러 맨 끝.
- 전용 버킷 kind `SPEECH`(`sp-ip` 30/분 + `sp-key:session` 10/분 — 대화 버킷 비소비). 본문이 파싱되지 않으므로 세션 키는 헤더에서 꺼낸다.
- 처리 순서는 **싼 검사부터**: (공통 가드 — 레이트 · Origin) → 서버 스위치(음성 쪽 DB 0) → 헤더 형식 → `Content-Type`·`Content-Length`(본문 안 읽음) → 챗봇 판정 → 음성 입력 켜짐 → 공급자 가용(캐시) → 본문 상한 읽기(1MB·15초) → **API 비대기 세마포어(기본 2 — 초과 즉시 `503 SPEECH_BUSY`)** → 공급자 호출(10초) → 후처리 → 집계. **[구현 반영] 공통 `PublicOriginGuard`는 모든 공개 경로처럼 이 경로에서도 핸들러보다 먼저 슬러그로 챗봇·WEB 채널을 조회한다(최대 2쿼리)** — 서버 스위치가 꺼져 있어도 이 2건은 남으므로 "DB 0"은 **음성 쪽 조회 0**의 뜻이다.
- **본문을 먼저 다 받은 뒤 세마포어를 잡는다** — 느린 업로드가 동시 처리 슬롯을 잡지 않게 하려는 의도이며, 대가로 읽는 동안 **동시 수신 요청 수 × 최대 1MB**가 메모리에 있을 수 있다(레이트 버킷·15초 수신 상한이 간접 상한).
- 챗봇 없음·비공개·채널 꺼짐·음성 꺼짐·서버 꺼짐·공급자 불가는 **전부 같은 `503 SPEECH_UNAVAILABLE`**. 신규 오류 코드 5종(`UNAVAILABLE`·`BUSY`·`AUDIO_INVALID`·`AUDIO_TOO_LARGE`·`FAILED`). **단 핸들러 앞 공통 가드의 응답(Origin 불허 `403` · 요청 한도 `429`)은 이 통일 밖이다** — Origin이 허용 목록 밖이면 존재하는 슬러그는 `403`, 없는 슬러그는 `503`으로 갈릴 수 있다. 기존 공개 API 전체와 같은 동작이고 설정 조회로도 이미 드러나는 정보라 **가드 순서는 바꾸지 않는다**(설계서 R-8·K-14 한계).
- ml-worker도 비대기 세마포어(기본 2)로 2차 상한을 건다. 대기열은 어디에도 없다.
- **세션 결합은 검증하지 않는다** — 대화 세션은 클라이언트가 만든 UUID이고 서버 등록부가 없다(ADR-0009). 세션은 레이트 분산 키로만 쓰고(헤더 형식만 검사) 실질 통제는 IP 축·동시 상한·크기·길이·수신 시간·Origin이다. 서버 서명 토큰은 1차 범위 대비 비용이 커서 기각했고 **PM이 대체 통제를 수용했다**(H-1 — 2026-10-01). 남은 위험(여러 IP 분산 호출)은 요구사항 R-13에 기록하고, 남용이 관측되면 서명 토큰을 재검토한다.
- 인식 요청은 대화 로그·미응답·통계 대화 수에 아무것도 남기지 않는다. 남는 것은 챗봇·일별 숫자(성공·말소리 없음·형식 오류·실패·혼잡)뿐이다.

### 4. 읽기용 글자·말투는 **서버가 만들어 응답 선택 키 `speech`** 로 보낸다 — **봇 답변에만**

- 키: `speech?: { text, tone }` — **메시지(응답) 단위** · 메시지 응답은 `feedback` 뒤 **마지막 키** · 보류 답변 폴링 응답은 `sources` 뒤 마지막 키 · 조건부 전개로만 채운다(없으면 바이트 동일) · **저장 0**.
- 붙는 조건: 요청 `features`에 **`speech-v1`**(4/5) ∧ 챗봇 듣기 켜짐 ∧ **봇 답변 반환 지점**. 위젯은 공개 설정 `voice.tts`가 참일 때만 선언한다 → 구버전 위젯·직접 연동 클라이언트·음성 안 쓰는 챗봇의 요청·응답 바이트 불변, 대화 턴 추가 조회 0.
- **읽기 대상 경계(PM 결정 H-3 — 2026-10-01)**: **봇 답변만 읽는다.** 봇 답변 = 그 질문에 대해 챗봇 콘텐츠가 내놓은 답 — 정상 턴 출력(노드 출력·챗봇 폴백 · 엔진 기본 폴백 포함) · 외부 RAG 최종 답(`READY`)과 실패 시 챗봇 폴백 문구(`FAILED`) · **No.36 "안전 문구로 대체"(입구·출구)**. **제품 코드 상수로 박힌 시스템 안내 3종 — 입구 금지어 안내 · 일시 장애(버전 읽기 실패 고정 문구) · 외부 RAG 대기 문구 — 에는 붙이지 않는다**(듣기 켜짐 ∧ 선언이어도 응답 바이트 불변). 상담 게이트 `HANDLED`와 구버전 상담의 미전달 상담원 메시지(봇 출력 앞에 전치되는 G-8 출력)도 읽지 않는다 — 읽기 글자는 전치 개수만큼 잘라 낸 봇 출력에서만 만든다(금지어 마스킹은 길이 보존 map이라 위치가 어긋나지 않는다). 판정은 **문구가 아니라 반환 지점**으로 한다.
- **안전 문구 대체를 봇 답변으로 보는 근거**: ① 대체 문구는 관리자가 규칙마다 쓴 챗봇 콘텐츠다(1~300자 · 금지어 검사 통과) ② 엔진 답·RAG 답을 **대신해** 질문의 답 자리로 나가며 처리 상태를 알리는 안내가 아니다 ③ 대화 로그에 봇 응답(`isAnswered=false`)으로 폴백과 같은 층위에 적재된다 ④ 요구사항 FR-VO4-4·AC-VO3-8이 "안전 문구 대체 = 차분함 고정"으로 읽기 대상임을 전제한다 ⑤ 출구 대체는 폴링의 최종 답 자리로 나간다. 시스템 안내 3종은 반대로 "못 받았다/기다려라"는 상태 알림이다.
- 글자는 **같은 응답에서 화면에 보내는 최종 봇 출력**(출구 금지어·RAG 출구 가림 이후)으로 만든다 → 화면에서 가려진 것은 소리로도 가려진다. 위젯이 출력에서 직접 만들지 않는다(서버 규칙 1벌).
- 변환은 **강등 사다리 함수를 재사용하지 않는다** — 텍스트 단계가 `[카드]`·`[링크]` 접두와 LINK 주소를 싣기 때문이다. 같은 판별 유니온 전수 분기 구조의 API 순수 함수를 따로 둔다. 가림 표시 → "○○ 가림" · URL·이모지·장식 기호 제거 · 2,000자 상한 + 끝맺음.
- 보류 RAG는 폴링 요청에 기능 선언이 없으므로 **보류 시작 때 말투 계획을 `PendingAnswerStore`에 함께 둔다**(글자 아님 · 보류 시작 응답 자체에는 `speech` 없음). 출구 가드레일 "안전 문구로 대체"를 폴백과 구분하도록 `complete()`에 선택 표식 `safetyReplaced` 1개를 더한다.
- `@Public()`·공개 경로·`speech` 키가 붙을 수 있는 공개 응답(메시지·폴링 2종)은 H-3 개정과 무관하게 그대로다 — 붙는 반환 지점만 줄었다.

### 5. 말투 = **닫힌 4종 + 응답 종류 규칙 + 노드 꼬리표**, 매개변수는 **공유 대응표**

- 식별자 `CALM`·`BRIGHT`·`APOLOGETIC`·`INFORMATIVE`(화면 이름 차분함·밝게·사과·안내). **응답 종류 3종 `ANSWERED`·`UNANSWERED`·`SAFETY`**(H-3으로 초안의 `BLOCKED`·`ERROR`·`WAITING` 삭제). 우선순위: 안전 문구(`SAFETY`) `CALM` 고정 > 노드 꼬리표 > 종류 규칙(미응답 = 관리자 지정 또는 `APOLOGETIC`) > 기본 말투. 관리자의 종류별 지정은 미응답 1종뿐이다. 판정 모델 0 · 글자 변경 0 · 사용자 감정 판정 0. 요구사항의 "상담 연결 안내 = 차분함"은 봇 응답 경로에 대응 종류가 없어 두지 않는다(H-4 PM 수용).
- 서버는 말투 **이름만** 보낸다. 이름 → rate·pitch·volume 대응표·안전 구간·배율 계산·기기 안 한국어 음성 선택·문장 분할은 **zod 무의존 서브패스 `@chat-bot/shared-types/speech-voice`**(위젯·콘솔 들어보기 공용 1벌 — ADR-0012 서브패스 선례, 네 번째). **api는 서브패스를 직접 import하지 않고 루트 index 재수출만 쓴다**(서브패스는 위젯·콘솔 전용 — 구현 반영).
- **노드 꼬리표는 노드 출력이 아니라 음성 설정 행(`nodeTones`)** 에 둔다 — 응답 1건 = 말투 1개라 출력 단위 지정은 의미가 없고, 출력 스키마(14종)·스냅샷 해시 정규화·복원 적용기를 건드리지 않는다. 대가로 꼬리표는 환경·스냅샷 밖(저장 즉시 운영 반영)이다(H-2 PM 수용).
- 원문 "감정 톤 반영 자연스러운 음성"은 **일부만 충족**한다 — 기기 음성이 pitch·volume을 무시할 수 있고 목소리가 기기마다 다르다. 자동 시험은 "넘긴 매개변수"까지만 검증한다.

### 6. 저장 = **1:1 `ChatbotVoiceSetting` + `SpeechDailyStat`** · 조회 = **전역 색인 캐시**

- 음성 설정(행 없음 = 전부 꺼짐 · 입력·듣기·토글 노출(기본 노출 — H-7 PM 수용)·배율·기본 말투·종류별 말투 JSON(허용 키 `UNANSWERED`)·노드 꼬리표 JSON) · 일별 숫자(챗봇 × KST 일 · 정수 5칸 · 글자·세션·IP 0). `WebChannelConfigSchema`(strict)에 넣지 않는다(롤백 시 WEB 설정 전체 폴백 → Origin 가드 무력화 — ADR-0045 §1).
- 마이그레이션 = `CREATE TABLE` 2 + `CREATE UNIQUE INDEX` 1만(원시 부분 인덱스 4 보존 · `ALTER`·`DROP` 0). **구현은 Prisma 생성 SQL을 쓰지 않고 직접 작성했다**(`20261001120000_voice_ai` — 부분 인덱스 `DROP` 생성 위험 원천 배제). 환경·스냅샷·복사·토픽 분리·승격 밖. 영구삭제 동반 삭제 +2. 보존 종류·암호화 대상 추가 0.
- 런타임 조회는 No.36 가드레일과 같은 계열의 **전역 색인 캐시 · stale-on-error** — 음성을 안 쓰는 챗봇의 설정 조회·대화 턴 쿼리 수가 변하지 않는다(쿼리 수 고정 시험 17 무수정). **[구현 반영] 설계 원안의 "색인(켜진 챗봇 id 집합) + 챗봇별 캐시" 2단을 1단으로 줄였다** — 켜진 행만 적재해 색인이 설정 자체를 담는다(쿼리 1 · TTL 60초 · 저장 시 같은 인스턴스 즉시 무효화 · 적재 실패 시 직전 값).
- 공개 설정 응답에 선택 키 `voice?: { input, tts, autoReadToggle, rate }`(마지막 키 · 둘 다 거짓이면 키 없음). `input`은 공급자 상태 캐시(성공 30초·실패 10초 · 만료 시 직전 값 + 백그라운드 갱신 · 첫 조회만 최대 1초 대기)를 반영한다. **[구현 반영 — 코드 리뷰 M-3] 인식 실패가 가용성을 내리는 규칙**: 네트워크 실패는 즉시, 시간 초과·5xx는 **연속 `SPEECH_FAILURE_THRESHOLD`회(기본 3 · 1~20)** 에 이를 때만 캐시를 거짓으로 바꾸고(그 전에는 `healthy()` 재확인만), 성공은 계수를 0으로 되돌린다. 하락 시 세대 번호를 올려 진행 중이던 이전 갱신이 결과를 되돌리지 못하게 한다. 느린 한 건이 모든 챗봇의 마이크를 숨기지 않게 하려는 것이다. 하락 후 **다음 설정 조회부터** 마이크가 숨겨지는데, 위젯은 설정을 페이지당 1회만 조회하므로 실제 반영은 새로고침 뒤다. `tts`는 서버 스위치와 무관하다.

### 7. Provider = **API 안 포트 `SpeechRecognitionProvider`**(`mock`·`local`) · TTS Provider 없음 · `packages/llm-provider` 미승격 · **운영에서 `mock` 차단**

- 위치 `apps/api/src/speech/providers/`(Nest·Prisma 무의존 포트 — 파일 이동만으로 승격 가능 · ADR-0026 C-5 규약). 예외를 던지지 않고 결과 유니온(`OK`·`EMPTY`·`INVALID_AUDIO`·`TOO_LONG`·`BUSY`·`FAILED(원인)`)을 돌려준다. `cloud`는 유니온 주석의 예약 자리만(P-7).
- 이름은 채널·위젯과 무관하게 지어 No.33(멀티모달 음성 이해)이 그대로 재사용한다.
- 숫자 표기 정규화(한글 숫자열 → 아라비아 숫자)·반복 고리 축약·상투 문장 제거는 **API 후처리**(공급자 무관)다. ml-worker는 디코딩·VAD·STT만 한다. pii-mask는 바꾸지 않는다. **[구현 반영 — 코드 리뷰 M-1·M-2] 정규화 제안 규칙(3050 실측 후 확정 대기)**: 6자리 이상 숫자 음절 구간만 바꾸고, 낱글자를 공백으로만 끊어 읽은 구간은 이어 붙이며(`공 일 공 …` → `010…`), 묶음으로 읽은 구간은 하이픈으로 잇는다(`공일공 일이삼사 오육칠팔` → `010-1234-5678`). 아라비아 숫자와 맞닿은 구간·조사가 붙은 토큰은 바꾸지 않는다(알려진 한계). 반복 축약은 숫자·구분자만으로 된 반복 단위를 건드리지 않는다(실제 번호일 수 있다).
- STT는 LLM 소비자가 아니므로 `packages/llm-provider` 승격 트리거(LLM 소비자 2곳)와 무관하다. 명세서의 "LLM/STT/TTS Provider" 서술은 "STT 포트는 API 안 · TTS는 사용자 브라우저"로 정정한다.
- ml-worker 쪽 모델 선택은 `STT_BACKEND=mock｜faster-whisper` + `STT_MODEL_ID` + 교체 지점 `_load_transcriber()` 1곳(No.37 `_load_generator()` 선례). 기본 모델을 두지 않는다(빈 값 = 기동 실패).
- **설정 오류(PM 결정 H-8·H-10 — 2026-10-01)**: ① `SPEECH_PROVIDER`가 `mock｜local` 밖이면 기존 enum 규약대로 **API 기동 실패** ② **운영 환경 ∧ `SPEECH_ENABLED=true` ∧ `SPEECH_PROVIDER=mock`(명시·기본값 모두)이면 API 기동 실패** — `mock`은 고정 문장("모의 인식 결과입니다")을 돌려주므로 운영 사용자에게 가짜 인식 결과가 나가는 것을 원천 차단한다. 비운영은 기동 + 경고 ③ **운영 판별 = `NODE_ENV`(앞뒤 공백 제거) === `'production'`** — API에 기존 운영 판별 기준이 없어(저장소에서 `NODE_ENV` 사용 0건) Node 관례를 이 기능이 처음 읽는다. 정의는 순수 함수 1곳(`config/runtime-env.ts`)이고 환경변수 스키마 키는 늘리지 않는다 ④ 같은 위험의 다른 입구(API `local` ↔ ml-worker `STT_BACKEND=mock`)는 기동 시점에 알 수 없으므로, **운영이면 `local` 공급자가 ml-worker 상태의 `backend === 'mock'`을 사용 불가로 본다**(마이크 숨김 + 경고 — 런타임) ⑤ `local`의 주소 누락은 가짜 결과가 아니라 "사용 불가"로 안전하게 수렴하므로 운영에서도 경고만 한다 ⑥ ml-worker 쪽 설정 오류(역할·백엔드 오타·모델 없음·CUDA 적재 실패)는 **음성 인식 프로세스만** 기동 실패. **[구현 반영 — 코드 리뷰 L-6] `NODE_ENV=production`을 넣지 않은 운영 설치에서는 ②가 기동 경고로만 내려가므로(fail-open), 개통 전 체크리스트 OC-5와 배포 설정(Compose `api` 서비스 등)에 이 값을 명시하는 것을 확인 항목으로 둔다.**

### 8. 거버넌스 = 출구 **`SPEECH_LOCAL`**(7 → 8) · 데이터 종류 **`AUDIO_RAW`** · 켜졌을 때만 지도에 행

- 레지스트리 +1(출구 파일 1개 · `masked: 'NO'`) — 정적 검사 G-1·G-2가 자동 추종. 모드 ON이면 기동 시 `ML_WORKER_SPEECH_URL` 호스트를 허용 목록으로 검사하고 런타임은 `assertEgressAllowed`가 막는다.
- 데이터 지도 `exits[]`는 레지스트리 전부를 행으로 만들기 때문에, **`SPEECH_LOCAL` 행은 `SPEECH_ENABLED ∧ provider=local`일 때만** 넣는다(기본 설치 바이트 동일). 선택 키 `speech?`에 "음성 원본 저장 0·디스크 0·가림 불가 · 답변 읽기는 사용자 기기 안 · 서버 전송 0 · 온라인 음성 제외"를 표기한다. `speech?` 판정에는 음성 설정 count 쿼리 2건이 매 지도 조회마다 쓰인다(결과 0이면 키 없음 — 응답 바이트 불변).
- 답변 읽기는 서버 출구가 없으므로 출구 클래스를 더하지 않는다. 클라우드 STT가 생기면 별도 출구 클래스 + 모드 ON 기본 차단(음성 원본은 마스킹 조건 허용 경로가 없다).

### 9. 위젯 = 브라우저 기본 기능만 · 꺼짐이면 실행 0 · **기기 안 `ko` 음성만**

- `MediaRecorder`(32kbps · 30초 · 1MB) · `speechSynthesis`. 런타임 의존성 0 · **gzip 증가 ≤7KB**(**PM 2026-10-01 결정** — 원안 5KB였으나 실측 +6.17KB(19,760B → 26,075B)로 원안 추정 3~4KB가 낮았다 · 100KB 게이트 통과 · 빌드는 증가분을 기록하고 예산 초과는 경고만) · **Preact 트리거 미발동**(ADR-0012).
- 공개 설정에 `voice`가 없으면 음성 코드를 조립하지 않는다(권한 요청·`getVoices()`·리스너 0 · `features` 3개 그대로). HTTPS·녹음 지원이 없으면 마이크 버튼을 만들지 않는다.
- 읽기 음성은 `lang`이 `ko`로 시작하고 **`localService === true`** 인 것만(누락·거짓 제외 — 판별 불확실이면 쓰지 않는다). 없으면 듣기·자동 읽기를 비활성 + 이유 글자. 읽기 모듈은 네트워크 호출 0. 브라우저 내장 음성 **인식**(`SpeechRecognition`)은 쓰지 않는다.
- 녹음은 입력창에 채우기만 한다(자동 전송 0). 마이크 트랙은 녹음 중에만 열고 모든 종료 경로에서 닫는다. 첫 사용 고지는 녹음 시작 직전 **단일 호출 지점**만 두고 1차는 즉시 통과(법무 확인 전 미구현). 인식 요청 대기 상한은 **15초**(서버 10초 + 업로드 여유 — 초과 시 중단·실패 안내).
- **[구현 반영] 인식 오류 처리**: `503 SPEECH_UNAVAILABLE`은 마이크를 없애지 않고 **재시도 가능한 실패**로 둔다(일시 장애일 수 있다 · 포커스는 말하기 버튼 · 문구 "지금은 음성 입력을 쓸 수 없어요. 글자로 입력해 주세요."). 마이크 제거는 `403`(Origin 불허)뿐이다(포커스는 입력창). 취소·종료·실패 뒤 포커스는 말하기 버튼, 성공 뒤는 입력창이다.
- **[구현 반영] Esc 우선순위**: 준비·녹음·인식 중 Esc는 음성만 취소하고 패널은 닫지 않는다. 그 밖의 상태는 기존대로 패널을 닫는다. 기존 패널 `keydown` 핸들러에 가드(`setEscapeGuard`)를 두는 방식이며 마이크가 조립될 때만 설정된다(음성 꺼진 위젯의 Esc 동작 불변).
- 듣기 버튼은 **응답마다 1개**(H-6 PM 수용)이고 `speech` 키가 있는 응답에만 만든다 — 위젯은 응답 종류를 해석하지 않는다. 자동 읽기는 기본 꺼짐 · 사용자 조작으로만 켜짐(켜는 클릭 안에서 볼륨 0 공백 발화 1회로 재생 권한 확보) · **최신 답 우선**(읽는 중 새 답이면 취소 후 최신 답) · 창이 닫혀 있거나 탭이 숨겨진 동안·녹음 중에 도착한 답은 읽지 않는다 · 녹음·입력·창 닫기·탭 숨김·새 답에서 즉시 멈춤 · `speech` 없는 응답(시스템 안내)은 읽지도 끊지도 않는다.

### 10. 바이트 동일 보장

음성 설정이 없는 챗봇 + 서버 스위치 꺼짐: 공개 설정·메시지·폴링·평가·선제 응답, 요청 `features`, 대화 로그, 통계, 데이터 지도가 도입 전과 같다. 새 공개 경로는 존재하지만 음성 쪽 DB 조회 없이 503이다(공통 Origin 가드의 조회는 다른 공개 경로와 같이 남는다). **듣기가 켜진 챗봇에서도 시스템 안내 3종 응답은 바이트가 같다**(H-3). 운영 설치라도 `SPEECH_ENABLED`를 켜지 않으면 기동 동작이 같다(운영 mock 검사는 켜졌을 때만). 기존 시험 기대값 변경은 닫힌 목록 **12건**(`@Public()` 개수 7곳 · 출구 개수 4곳 · 동반 삭제 1곳 + 구현 중 추가된 공개 스키마 전수 목록 1곳(X-12 — `topic-sealing.spec.ts`에 `PublicSpeechReplySchema`) — 설계서 §15.3)이며 PM 환류 개정으로는 늘지 않았다.

## 결과

**좋아지는 것**
- 서버 쪽 음성 부담이 **STT 프로세스 1개 + 공개 경로 1개**로 고정되고, 대화 처리(엔진·로그·마스킹·금지어·가드레일·통계·상담)는 한 줄도 음성을 알지 않는다.
- 녹음은 어디에도 파일로 남지 않는다 — 정적 검사와 디스크 감시 시험으로 강제되고, 디코더는 허용된 컨테이너·`pipe` 프로토콜만 연다.
- 읽기는 서버 자원 0이고, 화면에서 가려진 내용은 소리로도 가려진다. 읽는 대상이 봇 답변으로 좁혀져 시스템 안내 응답의 바이트가 듣기 설정과 무관하게 고정된다.
- 공급자·모델 교체는 환경변수와 교체 지점 1곳으로 끝나고, 3050(경량)·L40S(운영)를 설정만으로 고른다. **운영 설치에서 시험용 `mock`이 사용자에게 나갈 수 없다**(기동 실패 + 런타임 사용 불가 — 단 `NODE_ENV=production` 설정 전제).
- 일시 장애 한 건으로 마이크가 사라지지 않는다(연속 실패 임계 · 위젯 재시도 가능 실패).

**나빠지는 것 / 감수하는 것**
- **공개 API에 GPU를 쓰는 경로가 처음 생긴다** — 세션 결합을 검증할 수 없어 IP 축·동시 상한이 실질 방어다(다중 인스턴스에서는 상한이 곱해진다 · 여러 IP 분산 남용은 혼잡 거절로만 버틴다 — 요구사항 R-13).
- 본문을 먼저 받은 뒤 세마포어를 잡으므로, 받는 동안 동시 수신 요청 수 × 최대 1MB가 API 메모리에 있을 수 있다.
- 공통 Origin 가드가 먼저 돌아 Origin 불허 시 존재·부재 슬러그의 응답이 다를 수 있다(기존 공개 API와 같은 한계).
- 읽기 품질·가능 여부가 사용자 기기에 달려 있다(한국어 기기 음성 없는 PC는 듣기 불가 · `localService` 신뢰성 미확인).
- **자동 읽기 사용자는 시스템 안내(금지어 안내·일시 장애)를 소리로 듣지 못하고 외부 RAG 대기 중(최대 90초)에는 침묵한다**(H-3 — 화면 글자·스크린리더 낭독은 그대로).
- **운영 판별이 `NODE_ENV=production` 설정에 의존한다** — 운영 설치가 이 값을 빠뜨리면 `mock` 차단이 경고로 내려간다(fail-open). 개통 전 체크리스트(OC-5 — 배포 설정 명시 확인)·기동 경고·데이터 지도 표시로 보완한다.
- **첫 사용 고지·음성 원본 법적 성격의 법무 확인은 개통 절차 게이트이며 코드로 강제하지 않는다**(H-5) — 체크리스트 없이 켜면 고지 없이 동작한다(콘솔 경고 글자로만 알림).
- 노드 말투 꼬리표가 환경·스냅샷 밖이다(운영에 즉시 반영 · 복원 대상 아님).
- 한글 숫자 정규화는 제안 규칙이며 3050 실측 후 확정 대기다 — 아라비아 숫자와 섞인 표기·조사가 붙은 토큰은 바뀌지 않아 기존 마스킹이 못 잡을 수 있다.
- 위젯 크기가 원안 예산보다 커졌다(+6.17KB — PM이 7KB로 상향 수용).
- ml-worker 설치 묶음·잠금 파일이 하나 늘고(`[speech]`·`requirements-speech-lock.txt`), 모델 반입 절차가 생긴다.
- 기능 선언이 4/5가 되어 다음 선언 1개 뒤에는 상한 상향이 필요하다.

## 재검토 트리거

- 기기별 목소리 편차·한국어 음성 없는 기기 문제가 고객에게서 실제로 제기되거나 감정 표현이 강한 음성이 요구됨 → 서버 사내 합성(TTS 모델 · 합성 공개 경로 · 결합 검증 · 출구 클래스)
- 공개 인식 경로 남용 관측(일별 혼잡·형식 오류 급증 · 다수 IP 분산) → 세션 서명 토큰(H-1 후속)
- 자동 읽기 사용자의 "무응답" 불만 → 시스템 안내 읽기 재결정(H-3 — 종류별 말투 JSON에 키 추가로 마이그레이션 0)
- 프로젝트 공통 운영 판별 기준 도입 → `isProductionRuntime()` 정의 교체(1곳)
- 위젯 증가분이 7KB를 넘거나 다음 기능이 위젯 크기를 더 늘림 → Preact 재검토 트리거(ADR-0012) 재판정
- 3050 실측 결과 → 한글 숫자 정규화 규칙·상투 문장 목록 확정(코드 상수 + 단위 시험 표)
- 실시간 스트리밍(규모 B) 확정 → 공개 API 첫 상시 연결 ADR
- 전화 채널(규모 C) 확정 → 새 채널 종류 `PHONE` · No.39 재개 판단
- 다중 인스턴스 전환 → 동시 상한·캐시 공유 저장소
- 기능 선언 6번째 필요 → `features` 상한 상향(서버 선배포)
- No.33(멀티모달) 착수 → STT 포트 재사용 · 비전은 별도 배타 역할
- 클라우드 STT 요구 → 새 출구 클래스 + 거버넌스 모드 기본 차단
