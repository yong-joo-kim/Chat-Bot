## 맥락

2026-10-01 결함 트리아지가 "PM 결정 필요"로 남긴 4건이다. 셋은 앞서 문서로 확정한 약속과 충돌한다 — ① ADR-0026 §2는 G2/G3 실패를 G1으로 채운다고 적었지만 구현은 0건으로 끝난다 ② 2인 승인 끄기 잠금은 "거버넌스 모드와 무관"(U-7)으로 확정됐지만 1인 우회가 가능하다 ③ 저장 마스킹의 날짜 오인은 "바이트 불변" 약속 때문에 출구에서만 고쳤다. PM은 ①은 구현, ②는 거버넌스 ON 기본 잠금, ③은 저장 경로까지 고치기로 했고, 롤백 토글(L-2)은 수용했다. 이어서 ③이 생년월일을 더는 우연히 가리지 않게 되는 문제(U-1)에 대해 **"생년월일·생일 같은 말이 앞에 있으면 예전처럼 가린다"**로, 거버넌스 ON 원본 파일 게이트 완화(U-4)는 **수용**으로 답했다. 구현 코드 리뷰가 한국어 양식에서 흔한 표기(`생년월일 - …`·`/`·`~`·곡선 따옴표·「」·`(양력)`·`Birth date`·제로폭 문자·구분 문자 4개)에서 날짜가 그대로 저장됨을 찾았고, PM은 **구분 문자와 키워드 목록을 넓히기로** 했다.

## 결정

### 1. 증강 폴백은 러너 1곳 · 원인은 반환값 · 표시는 기존 필드 우선

- G2/G3가 **사용 가능한 후보 0건**이면(원인 무관) 러너가 팩토리의 `getFallbackProvider()`(항상 G1)로 **같은 Job 안에서 1회** 다시 생성한다. G1도 0건이면 기존처럼 `PARTIAL`.
- Provider 포트에 **선택 메서드** `generateWithOutcome?()`를 더해 원인 코드(10종)를 **반환값으로** 보고한다. `generate()` 계약(C-1 예외 전파 금지)·서명 불변. 원인은 폴백 여부를 결정하지 않는다(표시·로그 전용 — C-6).
- **부분 성공은 보충하지 않는다**(G2/G3가 1건이라도 내면 G1 호출 0). **재시도 0**.
- 표시: 제안 행은 기존 `providerId='rule'`, 결과 요약은 기존 `degraded:true` + 선택 `fallbackFrom`·`fallbackCause`, 화면은 FR-L1-7 문구 1줄. 폴백이 없으면 결과 요약은 **지금과 같은 키만**(바이트 동일). 새 컬럼·감사·알림 0.

### 2. 끄기 잠금 = 명시값 우선, 미설정이면 거버넌스 모드 연동

- `ENV_APPROVAL_OFF_LOCKED`를 **3상태**(미설정/true/false)로 읽고, 순수 함수 1개가 `명시값 ?? (DATA_GOVERNANCE_MODE === 'ON')`로 판정한다. 거버넌스 ON + 명시 false는 허용하되 기동 경고 1줄.
- 잠금은 켜진 정책의 **끄기만** 막는다(켜기·만료 시간 변경 허용 · 꺼진 정책을 자동으로 켜지 않음).
- 현황 응답의 `offLocked`(실효 잠금) 재사용 + 잠금일 때만 선택 필드 `offLockedBy`(`SERVER_SETTING`｜`GOVERNANCE_MODE`). 오류 코드·사유 코드 불변.

### 3. L-2는 수용

직전 버전 단독 롤백의 A↔B 토글을 막지 않는다(감사·이력·현황 알림에 남음 · N40-1 수정으로 비직전 롤백은 이미 게이트 대상).

### 4. 저장 마스킹의 날짜 제외 = 출구 날짜 규칙 1벌 + **생년월일 문맥 예외** · `preserveDates` 기본값 반전 · v1 동결 골든

- `maskPii()` 기본 경로의 **계좌 치환 1곳**에서, 출구가 이미 쓰는 날짜 규칙(`YYYY-MM-DD` · 1900~2099 · 월 01~12 · 일 01~31 · 앞뒤가 숫자·ASCII 하이픈 아님)에 맞는 **독립 날짜**를 건너뛴다. 다른 4종 치환·모드·카운트 초기화 변경 0.
- **생년월일 문맥 예외(U-1 확정 · 2차 확장)**: 독립 날짜라도 **같은 줄에서 바로 앞 낱말이 닫힌 키워드로 시작**하고 그 사이가 **구분 문자 6개 이하**(+ 닫힌 주석 `(양력)`·`(음력)`·`[양력]`·`[음력]` 최대 1개)뿐이면 **건너뛰지 않는다** — 결과는 규칙 v1과 **바이트 동일한 `[계좌번호]`**(카운트 `account` +1). 별도 종류·표식은 만들지 않는다.
  - **키워드(닫힌 7)**: `생년`·`생일`·`출생`·`탄생일`·`birth`·`dob` + 두 낱말 `birth date`(사이 공백 1~2개).
  - **구분 문자**: 공백(줄바꿈 제외) · `:` `=` `,` `(` `[` `"` `'` · **`-` `/` `~`** · **하이픈 변형 U+2010~U+2015 · 빼기 U+2212 · 물결 U+301C** · **곡선 따옴표 “ ” ‘ ’** · **「 」 『 』** (전각 반각화는 NFKC).
  - **제로폭·보이지 않는 문자**는 판정 창에서 **제거한 뒤** 판정한다(N36-2 금지어 정규화와 같은 집합).
  - 판정은 날짜 앞 최대 **32글자** 고정 창의 선형 역방향 스캔이며 정규식 역추적이 없다. 세부는 설계 §5.2-B.
- **출구에도 같은 예외**를 적용한다(판정 함수 1벌 공유). 출구에서 날짜는 계좌 단계에서만 가려지므로, 예외 날짜는 챗봇 출구 설정에 **계좌번호 종류가 켜져 있을 때** `[계좌번호]`로 가려지고, 꺼져 있으면(기본 주민번호·카드) 지금처럼 그대로 나간다.
- **선택 경로(출구)의 날짜 자리표시 제거(구현 확정)**: 선택 경로는 날짜를 사설 영역 자리표시로 미리 바꾸던 방식을 버리고 기본 경로와 **같은 계좌 단계 콜백**으로 날짜를 판정한다 — 자리표시 때문에 뒤 단계(이메일) 정규식이 날짜 주변을 기본 경로와 다르게 보던 차이(퍼징으로 확인)를 없애기 위해서다. 부수 효과는 **더 많이 가리는 방향**이다: 날짜에 붙은 이메일 `1990-05-12x@y.co`가 예전 출력 `1990-05-12x***@y.co`에서 새 출력 `1***@y.co`가 된다.
- `preserveDates`는 제거하지 않고 **생략 = true**로 뒤집는다. `false`는 구 동작(v1과 바이트 동일 — 모든 날짜 가림)이며 가드레일 출구 설정의 "날짜 보호 끔"이 계속 쓴다. 문맥 예외는 `preserveDates`가 true일 때만 의미가 있고, 끄는 옵션은 두지 않는다. 선택 경로 진입 조건은 `kinds` 유무만.
- 골든: 현행 말뭉치를 `storage-corpus.v1.json`으로 **동결**하고 날짜 케이스만 갱신한다(306건 중 23건 — 말뭉치에 문맥 키워드 0건이라 확장 후에도 23건 그대로). 생년월일 문맥은 **손 작성 골든**(`birth-context-corpus.json`)으로 고정한다 — 2차 확장으로 기존 66건 중 **2건**의 기대값이 바뀌고(구분 문자 4개 케이스) 새 케이스를 덧붙인다. 전체 재생성은 계속 금지.
- **과거 저장분은 재마스킹·되돌림·백필하지 않는다.** KB 적재 변환 규칙 버전도 올리지 않는다.
- **규칙 버전**: `PII_MASK_RULES_VERSION = 2`를 **유지**한다(2 = 날짜 제외 + 생년월일 문맥 예외, 이 ADR의 최종 규칙). 버전은 "배포된 동작"을 식별하는 값인데 v2 구현은 확장 시점에 아직 커밋·배포되지 않았다 — 배포된 적 없는 중간 상태에 번호를 쓰면 폐쇄망 확인 로그가 오히려 혼란스럽다. **단 2차 확장 전 v2가 어느 환경(시연 서버 포함)에든 배포됐다면 3으로 올린다**(설계 §5.5-5). **확인됨(2026-10-01): v2 유지** — `git log`상 `packages/pii-mask/src/index.ts`에 이 상수를 도입한 커밋이 없고(HEAD에 없음, 작업 트리에만 존재·미커밋) 시연·운영 어디에도 배포되지 않았다(U-15). 기동 로그 문구·패키지 버전(`0.2.0`)은 유지. ⚠ **2026-10-01 후속(ADR-0050 §1 · T-5)**: v2가 커밋(`49284fb`)된 뒤 저장 결과를 바꾸는 긴 숫자열 카드 우선 분류를 더하므로 **규칙 v3**로 올린다(기동 로그 문구에 "긴 숫자열 카드 우선" 추가 · 패키지 버전은 유지).
- **U-4 수용**: 거버넌스 ON에서 원본 파일(PDF·Office) 전송 게이트의 PII 건수에서 독립 날짜가 빠져, 날짜만 든 파일이 `PII_IN_RAW_FILE`로 막히지 않는다. 생년월일 문맥 날짜는 계속 건수에 들어가므로 그런 파일은 여전히 막힌다.
- **설계 수용 사항(별도 PM 확인 대기 — U-14)**: 문맥이 날짜 **뒤에** 오는 표기(`1990-05-12 (생년월일)`)는 보호하지 않는다(날짜가 그대로 남는다). 판정이 "날짜 앞" 한 방향만 보는 설계의 결과이며 PM은 아직 결정하지 않았다.

## 근거

- **폴백**: 요구사항 FR-L1-7이 화면 안내까지 명시하고, 경량 G3(3050 4GB)는 타임아웃이 잦아 0건 종료의 체감 비용이 크다. 폴백을 Provider 안이 아니라 러너에 두면 Provider는 "실패 = 빈 결과" 단일 규약을 유지하고 G1 생성은 팩토리 1곳에서만 일어난다(교체 지점 1곳). 원인을 인스턴스 상태로 넘기지 않는 것은 싱글턴 재사용 시 동시 Job 간 오염을 막기 위해서다.
- **부분 성공 비보충**: 경량 G3는 1회 상한 20이라 보충 규칙이면 모든 Job이 G1 혼합이 되어 No.17의 G3 품질 실측을 오염시킨다.
- **잠금 기본값 연동 + 명시값 우선**: 거버넌스 설치는 이미 "완화는 환경변수 + 재기동"이 원칙이므로 2인 통제 해제도 같은 등급으로 올린다. 명시 false를 무시하면 승인자 부족 교착을 풀 수단이 모드 끄기뿐이 되어 더 위험하다.
- **날짜 제외 방식**: 새 날짜 규칙을 만들지 않고 출구 규칙을 재사용해야 저장본과 출구 결과가 같은 문자열을 같은 날짜로 본다. 기본 경로 변경을 계좌 치환 1곳으로 좁히면 "나머지 바이트 불변"을 차분 시험으로 기계적으로 증명할 수 있다.
- **문맥 예외의 모양**: 예외 결과를 v1과 같은 `[계좌번호]`로 두면 예외 문장은 "바뀌지 않은 것"이 되어 과거 저장분·마스킹 표식 제거(발화 분석 `mask-tokens`)·통계와 충돌하지 않는다. "낱말 시작" + "바로 다음 낱말" 조건은 `발생일`·`생일 선물 … 날짜` 같은 오탐을 막는다. 2차 확장은 낱말 조건을 그대로 두고 **사이에 올 수 있는 기호만** 넓혔으므로 일반 날짜 제외의 효과는 유지되고, 늘어나는 가림은 "키워드 낱말 + 기호들 + 날짜" 모양으로 한정된다.
- **ASCII 하이픈과 날짜 경계**: 날짜 바로 앞의 ASCII `-`는 날짜 경계 규칙에서 이미 "독립 날짜 아님"이 되어 v1처럼 가려진다(`생일-2026-09-30`). 따라서 `-`가 구분 문자로 쓰이는 것은 날짜와 다른 구분 문자(공백 등)로 떨어져 있을 때뿐이며, 날짜 자체의 하이픈과 섞이지 않는다.

## 감수하는 비용

1. 폴백 제안은 G1 품질이다 — 화면 안내 1줄과 "규칙 기반" 배지로 드러낸다.
2. 거버넌스 설치에서 켠 2인 승인을 끄려면 서버 설정 + 재기동이 필요하다(승인자 부족 교착 포함).
3. 저장 텍스트에 규칙 v1(날짜 가림)과 v2(날짜 원문) 행이 공존하고, 미응답 큐·질문 순위의 병합 단위가 날짜별로 갈라진다.
4. 생년월일 문맥 예외는 **같은 메시지 안의 바로 앞 낱말**만 본다 — 봇 질문에 날짜만 답한 경우·양식 슬롯 값·`고객생년월일`처럼 붙여 쓴 낱말·키워드와 날짜 사이에 다른 낱말이 낀 경우·**날짜 뒤에 문맥이 오는 경우(U-14)**의 생년월일은 가려지지 않는다.
5. **(U-4 수용)** 거버넌스 ON에서 날짜만 있던 원본 파일이 원본 그대로 외부 RAG로 나갈 수 있다.
6. 출구에서 생년월일은 계좌번호 종류를 켠 챗봇에서만 가려진다(기본 설정에서는 지금처럼 그대로 — 변화 없음).
7. (2차) `생일 - 2026-10-01 이벤트`처럼 키워드 낱말 뒤 기호를 사이에 두고 온 **생년월일이 아닌** 날짜도 가려진다(과탐 쪽 — fail-closed).
