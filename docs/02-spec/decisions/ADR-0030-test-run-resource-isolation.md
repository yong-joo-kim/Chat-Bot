# ADR-0030 — 대량 TC 실행의 운영 자원 격리 (임베딩 캐시 우회 · RAG 상한 · 로그/자산 봉인)

- **상태**: 채택 (2026-09-23)
- **관련**: 요구사항 `docs/requirements/validation-regression.md` **J-8**(최대 위험) · J-9 · J-10 · FR-V1-20/21 · FR-V2-13/20~23 · NFR-VP4 · AC-V4-3 · 설계 `validation-regression-설계.md` §7·§12
- **연관 ADR**: ADR-0020(의미 점수 주입) · ADR-0022(외부 RAG allowlist 봉인) · ADR-0023(비동기 보류 답변) · ADR-0024(ml-worker 범위) · ADR-0025(봉인 방식 — "약속" 대신 "불가능") · ADR-0027(in-process 큐·배치 간 양보)
- **Supersedes**: 없음

## 1. 맥락 — 테스트 도구가 운영 품질을 떨어뜨리는 사고

이 그룹은 **새 모델을 적재하지 않는다**(GPU 2 유지). 그러나 **호출량의 첨두**를 만든다. 세 가지 위험이 실재한다.

1. ⚠ **전역 질의 임베딩 캐시 축출**. `QueryEmbeddingService`의 질의 캐시는 **LRU 1,000건 · TTL 10분**이며 `storeInCache()`가 초과분을 **가장 오래된 것부터 축출**한다. TC 2,000건을 이 경로로 실행하면 **운영 대화가 데워 놓은 1,000건이 전부 밀려난다** — 실행 직후 실사용자의 캐시 적중률이 0으로 붕괴하고 모든 턴이 ml-worker를 다시 때린다. 증상이 "실행 중"이 아니라 "**실행 후**"에 나타나 원인 추적이 어렵다.
2. **로그·통계·미응답 큐 오염**. 2,000건 실행이 미응답 큐에 2,000건을 꽂으면 No.15가 즉시 무너진다.
3. **외부 RAG 독점**. 그 서버는 **인증이 없고**(ADR-0022) 다른 이용자와 공유된다. 2,000건 × 5초(P95)는 사실상 DoS이며, `RagGateService`의 동시 게이트를 대량 실행이 독점하면 **운영 대화의 2단계가 굶는다**.

## 2. 결정 — 임베딩: 운영 캐시를 **공유하지 않는다**(의존성 그래프로 봉인)

**TC 실행 경로는 `QueryEmbeddingService`를 주입하지 않는다.** 전역 LRU에 접근할 수단이 DI 그래프에 존재하지 않으므로, 오염 코드는 **작성돼도 컴파일되지 않는다**(ADR-0022/0025의 봉인 방식 — "안 하기로 약속" 대신 "할 수 없게").

| 대안 | 판정 |
|---|---|
| A. `QueryEmbeddingService.embed()`에 `skipCache?: boolean` 옵션 추가 | 기각 — **호출부가 플래그를 잊으면 그대로 사고**다. 대화 경로와 실행 경로가 같은 서비스를 공유하는 한, 회귀 한 줄로 봉인이 풀린다 |
| B. 실행 전용 두 번째 캐시 인스턴스 | 기각 — 캐시가 두 벌이면 TTL·크기·무효화 정책이 두 벌이 된다. 실행 로컬 맵이면 **정책이 아예 필요 없다**(실행 종료 = 소멸) |
| **C. Provider 직접 배치 호출 + 실행 로컬 맵(채택)** | `EmbeddingProviderFactory.getProvider()` → `provider.embed(texts, 'QUERY')`. **`ClassifierPredictService.predictBatch()`가 이미 쓰는 선례**이며 새 패턴이 아니다. 전역 상태 증가 0 |

**구현 규칙**
- 실행 로컬 `Map<normalizedText, Float32Array>` — 같은 문장이 여러 TC에 나와도 **1회만** 임베딩(NFR-VP3).
- 배치 크기 `TEST_RUN_EMBED_BATCH_SIZE` 기본 **64**(색인기·provider 상한과 동일). TC 2,000건 = 최대 **32회 호출**.
- **A/B 두 계열이 같은 질의 벡터를 공유**한다(같은 문장·같은 `modelId`). 비교 실행이 임베딩 호출을 2배로 늘리지 않는다 — 늘어나는 것은 코사인 계산(CPU)뿐이다.
- **벡터 맵·번들·인덱스는 실행당 각 1회** 로드(N+1 금지).
- 배치 실패는 **실행 실패가 아니다** — 저하 모드(규칙 매칭, `band: SKIPPED`)로 계속하고 `degradedMode: true`를 기록한다.
- **점수 조립 로직을 복제하지 않는다**: `SemanticMatchService.score()`의 조립부를 `embedding/lib/assemble-semantic-input.ts` **순수 함수로 추출**하고 양쪽이 호출한다(동작 변경 0, 기존 테스트 무수정 통과). 랭킹·타이브레이크가 두 벌이 되면 "시뮬레이터와 TC의 판정이 다르다"가 발생한다.
- **M2 오버레이 예문의 벡터**는 실행 시점 배치 임베딩(`PASSAGE`) 후 **실행 로컬 entries로만** 쓰고 `EmbeddingVector`에 저장하지 않는다 — 승인 전 자산이 색인에 들어가면 제안/자산 분리(ADR-0025)가 깨진다. 이 비용은 **제안 문장 수(수십 건)** 이며 TC 수와 무관하다. 하지 않으면 **증강의 효과가 B 계열에 반영되지 않아 M2가 무의미해진다**.

**검증 가능성**: 전역 캐시를 900건까지 채운 뒤 TC 2,000건을 실행하고 **원래 항목이 그대로 남아 있음**을 단언한다(AC-V4-3). 정적 검사는 `validation/**`에 `QueryEmbeddingService` 참조 **0건**을 단언한다.

## 3. 결정 — RAG: 기존 출구를 재사용하고 **실행당 상한**을 건다

**PM 확정: 옵션 허용 + 상한.** 요구사항 제안(기본 비활성)에서 "기본 비활성 + 명시적 옵션"은 유지하되, 옵션 경로를 실제로 연다.

| 규칙 | 내용 |
|---|---|
| **새 HTTP 출구를 만들지 않는다** | **`RagHttpClient`·`RagGateService`를 그대로 주입**한다. `apps/api`의 외부 HTTP 출구는 **여전히 3곳**이고 allowlist 3경로도 불변이다. 실행 전용 클라이언트를 만들면 ADR-0022의 봉인(경로를 인자로 받지 않음·금지 문자열 0건 정적 검사)이 **두 벌로 갈라진다** |
| **기본값 `useRag=false`** | 미지정 실행은 외부로 나가는 HTTP **0건**(AC-V3-10) |
| **실행당 상한 50건** | `TEST_RUN_RAG_MAX_CALLS` 기본 50. 초과분은 호출하지 않고 **`wouldUseRag: true`로 표시만** 한다(`ThresholdPreviewResponse.wouldUseRag` 선례) |
| **운영 대화 우선** | 실행기는 RAG를 **직렬(in-flight 1)** 로만 호출하고, `ragGate.tryAcquire()` 실패 시 **대기하지 않고 건너뛴다**. 대량 실행이 게이트·레이트리밋·회로차단을 독점하지 않는다 |
| **판정 제외** | RAG를 실제로 호출한 TC는 **`NOT_JUDGED`**. 비결정론 응답은 회귀 판정의 기준이 될 수 없다(NFR-VM6 — 결정론이 M1 비교의 전제다) |
| **관측 로그 없음** | `RagCallLog`·`ConversationLog` 미기록(시뮬레이션과 동일 — FR-N2-3/AC-N2-25 상속) |
| **PII** | 송신 직전 `maskPii()` **예외 없이** 통과. ADR-0013의 적용 지점은 **여전히 3곳**이다(새 지점이 아니라 기존 "RAG 송신" 지점의 재사용) |

## 4. 결정 — 로그·자산·제안: 쓰기 경로를 갖지 않는다

| 봉인 | 수단 |
|---|---|
| `ConversationLog`·`UnansweredQuestion` **0건 증가** | 실행 서비스가 **`ConversationLogService`를 주입하지 않는다**. 미응답 큐 적재 지점이 `record()` **내부**이므로(ADR-0019) 로그를 안 남기면 **큐·응답률·접속수·시간대 분포가 자동으로 안전**하다 |
| 대화 자산 **변경 0건** | 실행 모듈이 `IntentsModule`/`KeywordsModule`/`FaqModule`/`DialogNodesModule`을 **import하지 않는다** — 자산 변경 코드가 컴파일되지 않는다(ADR-0025 L1과 동일) |
| `AugmentationSuggestion` **쓰기 0건** | **`AugmentationModule`을 import하지 않고** Prisma로 읽기만 한다. import하면 승격 유일 지점(`AugmentationAcceptService`)이 이 모듈의 DI 그래프에 들어와 ADR-0025 봉인이 약해진다. `ClassifierTrainingService`가 `IntentsService`를 주입하지 않는 선례와 동일 |
| 운영 API 지연 | 배치 경계마다 **이벤트 루프 양보**, **챗봇당 동시 실행 1건**. 실행 중 다른 API P95 증가 **20% 미만**(ADR-0027과 같은 규약) |

## 5. 결과

- 실행은 **운영 대화의 캐시·게이트·로그·자산 어느 것도 훼손하지 않는다**. 이를 약속이 아니라 **import 그래프 + 정적 검사 7단언**으로 보장한다.
- 신규 외부 접촉면 **0건**. 외부로 나가는 호출은 여전히 ① ml-worker `/embed` ② 외부 RAG(옵션) 둘뿐이며 둘 다 기존 클라이언트를 통한다.
- 신규 전역 상태는 **실행 취소 레지스트리 1개**(프로세스 로컬, 인터페이스 1곳)뿐이며 다중 인스턴스 전환 시 교체 지점이 1곳이다.

## 6. 감수하는 비용

1. **실행 경로가 회로차단기의 보호를 받지 않는다** — `QueryEmbeddingService`의 연속 실패 회로차단을 공유하지 않으므로, ml-worker가 죽어 있으면 실행기가 배치마다 실패를 겪는다. 완화: 배치 **연속 2회 실패 시 그 실행을 저하 모드로 고정**하고 이후 임베딩을 시도하지 않는다.
2. **실행 중 임베딩한 문장이 운영 캐시를 데워 주지 않는다** — 의도된 결과다. 두 캐시가 섞이는 순간 축출 문제가 되돌아온다.
3. **RAG 옵션은 여전히 외부 서버에 부하를 준다** — 상한 50건 + 직렬 호출 + 게이트 양보로 통제하지만 0은 아니다. 재검토 트리거는 **외부 서버 운영자의 부하 보고**이며, 그때는 기본값을 "옵션 자체 비활성"으로 되돌린다.
