## 맥락

2026-10-01 PM 결정 묶음(ADR-0049)의 리뷰·회귀에서 결함 후보 3건과 관찰 1건이 남았다.

1. **T-5**: v2 주민번호 정규식에 경계가 없어 공백·하이픈 없는 16자리 카드의 앞 13자리를 주민번호로 가져가고 끝 3자리를 남긴다(`[주민등록번호]111`). AMEX 공백형은 어떤 규칙에도 걸리지 않는다.
2. **K-1c**: 증강 러너가 Job마다 Provider를 새로 만들어 Gemini 회로차단 상태가 버려진다. local에는 회로가 없다.
3. **L-6**: 이메일 정규식이 `@` 없는 긴 영숫자 연속에서 O(n²)이다.
4. **K-1d**: 폴백 G1 호출 예외가 Job 전체 실패로 번진다.

**개정 ① 맥락**: 1차 결정(연속형 주민번호에만 13자리 경계 + 카드 단계에 "14자리 이상 숫자 연속"·AMEX 대안)을 구현하자, 경계 없는 하이픈형 주민번호가 카드 단계보다 먼저 돌아 긴 숫자열의 마지막 6자리를 가로챘다 — `4111111111111111-1234567` → `4111111111[주민등록번호]`(v2는 3자리 노출). 퍼징 30만 건 중 약 1.2만 건에서 v2보다 원문 숫자가 더 남았다. 리뷰가 제시한 대안 (a) 하이픈형에도 앞 경계 (b) 긴 숫자열 단계를 주민번호 앞에 (c) 둘 다도 검토했으나 **셋 모두 v2보다 더 새는 입력이 있다**(`1900101-1234567` — (a)(c) · `1234567890123456789-1234567`·`12345678901234567 5678 9012 3456` — (a)(b)(c)). 앞 단계 일치를 바꾸면 v2에서 뒤 단계가 이어받아 가리던 숫자를 잃는다.

## 결정

### 1. 저장 마스킹 규칙 v3 = v2 다섯 단계 그대로 + 사후 카드 보강 (개정 ①)

- 주민번호 → 카드 → 전화 → 계좌 → 이메일 다섯 단계의 정규식·순서·치환·날짜 제외·생년월일 문맥 판정은 **v2와 같다**(이메일만 L-6의 결과 동일 스캔).
- 다섯 단계 **뒤에** 카드 보강 1단계(기본 호출, 그리고 `kinds`에 카드가 있을 때만):
  - ⓐ 주민번호·카드 표기와 숫자가 다른 글자 없이 맞붙은 덩어리(숫자 1개 이상) → `[카드번호]` 1개(`rrn`→`card` 카운트 이동 · 이번 호출이 만든 표기만 차감)
  - ⓑ 원문으로 남은 14자리 이상 숫자 연속 → `[카드번호]`
  - ⓒ 원문으로 남은 AMEX 공백형(4-6-5) → `[카드번호]`
- **불변식 F-1(구성상 증명)**: 보강은 앞 단계 결과에서 원문 숫자를 가리기만 하므로 **v2가 가린 숫자 위치는 v3도 모두 가린다** — 모든 입력·두 모드·모든 `kinds` 조합. "v3가 v2보다 더 새는 입력 0건".
- **Luhn·주민번호 체크섬 미사용**(오타 카드·2020-10 이후 주민번호 미탐 방지 — fail-closed).
- **바뀌는 입력의 닫힌 정의**(v2 출력 기준): 표기에 숫자가 맞붙은 덩어리 · 원문 14자리 이상 숫자 연속 · 원문 AMEX 공백형. 저장 골든 306건 중 **15건**(`[주민등록번호]<잔여>` → `[카드번호]`)이며 1차 구현의 기대값과 바이트 동일하다.
- AMEX 하이픈형은 v2대로 `[계좌번호]`(보강은 이미 가린 것을 다시 분류하지 않는다). "하이픈 뒤 7자리"처럼 v2가 남긴 숫자 묶음이 하이픈 너머에 있으면 v3도 남긴다 — 새 노출이 아니며 주민번호 형식(앞 정확히 6자리)이 아니다(강화는 Q-10).
- **Q-1 오탐 범위(리뷰 보통 2)**: 14자리 이상 숫자 연속(마이크로초·나노초 타임스탬프·송장·주문번호·순번·시리얼)과 주민번호·카드 표기에 숫자가 맞붙은 덩어리(예 `12900101-1234567`)는 `[카드번호]`로 가려진다 · 11~13자리 숫자·전화번호·사업자번호(`123-45-67890`)는 변화 없음 · 13자리 주문번호는 종전처럼 주민번호 모양이면 `[주민등록번호]`.
- **바이트 불변 원칙의 두 번째 의도적 예외**(1차 L-5). **과거 저장분 재마스킹·백필 없음.** 규칙 버전 **v3**(v2가 커밋 `49284fb`로 배포 가능 상태) — 기동 로그 `pii-mask 규칙 v3(저장 마스킹 날짜 제외 · 생년월일 문맥 예외 · 긴 숫자열 카드 우선) · 모드 …`.

### 2. 증강 회로차단 = 상태만 프로세스 공유, Provider는 Job마다

- 회로 상태를 팩토리(Nest 모듈 싱글턴)가 공급자별(`gemini`·`local`)로 지연 생성·소유하고 Job마다 만드는 Provider에 주입한다. Provider 인스턴스는 캐시하지 않는다(Gemini의 Job별 금지어가 낡지 않게).
- **계수 = 인프라 실패만**(타임아웃·네트워크·5xx·429). 그 밖의 4xx·형식 오류·출구 차단은 중립, 2xx+스키마 통과는 성공. 시드 금지어·키 없음·회로 거부는 회로를 건드리지 않는다(Gemini는 시드 검사를 회로 확인보다 먼저).
- 임계(기본 5) → 개방(기본 60초, 네트워크 없이 `CIRCUIT_OPEN` → G1 폴백). 개방 시간 경과 후 **첫 호출 1건만 탐침**: 성공 → 닫힘 · 인프라 실패 → 재개방 · **중립 → 탐침 임대만 풀고 상태 유지(다음 호출이 다시 탐침 — 개정 ①: 출구 차단은 서버에 닿지 않은 호출이고 4xx·형식 오류도 회복 근거가 아니다)**. 늦은 실패는 개방을 연장하지 않는다. 탐침 임대 `AUGMENTATION_TIMEOUT_MS + 5초`.
- local 포함 · 설정 `AUGMENTATION_CIRCUIT_FAILURE_THRESHOLD`(5)·`AUGMENTATION_CIRCUIT_OPEN_MS`(60000, 하한 1000) — 기본값은 `env.validation.ts`, 운영 안내는 `자동배포.md`(`apps/api/.env.example`은 없다). 시계 선택 주입. 다중 인스턴스 독립. `rule`·`mock` 구성은 회로 미생성(AC-L1-14).

### 3. 이메일 탐지는 결과를 바꾸지 않고 선형으로

- 시작 위치를 로컬 문자 연속의 처음 또는 직전 일치의 끝으로 제한하는 스캔 함수 1개를 기본·선택 경로가 공유한다. 되돌아보기만 더하는 안은 직전 이메일에 붙은 이메일(`x@y.com1@z.com`)을 놓쳐 결과가 바뀐다. 결과 동일은 논증 + 기존 골든 무수정 통과 + 구 정규식 오라클 차분 퍼징. 규칙 버전 불변.

### 4. (기록) 폴백 G1 예외 방어 — K-1d

폴백 조달·생성 예외 → 후보 0건 `PARTIAL` + 기존 폴백 키(`fallbackCause`는 1차 원인 유지). 새 필드 없음. 로그는 오류 이름만.

## 근거

- **T-5(개정 ①)**: 다섯 단계는 서로 이어받는다 — v2에서 주민번호가 13자리를 가져가면 남은 숫자를 공백 묶음 카드가, 하이픈형 주민번호가 연속형 뒤를 가져가는 식이다. 앞 단계의 일치를 바꾸는 어떤 정규식 변경도 이 연결을 끊어 일부 입력에서 v2보다 덜 가린다(설계 §2.5 반례). 보강을 맨 뒤에 두면 v2의 모든 일치가 그대로 일어난 뒤 남은 원문 숫자만 다루므로 "v2 이상으로 가림"이 정규식 분석 없이 구성으로 성립하고, 시험도 v2 오라클 출력에 보강 함수를 적용한 값과의 일치로 기계화된다. 표기를 카드로 둔 것은 출구 기본 설정(주민번호·카드)에서 계속 가려지기 때문이다.
- **K-1c**: 장애 상태는 엔드포인트의 속성이지 Job의 속성이 아니다. 계수·탐침 판정은 레거시 게이트(ADR-0034)의 ALIVE/INFRA/NEUTRAL 선례를 따르되, 탐침에서는 "서버가 정상 생성했다"만 회복으로 본다.
- **L-6**: 무상한 메인 스레드 경로(관리자 시뮬레이터 레거시 응답 변수)와 KB 추출(작업 스레드)이 길다 — 함수를 선형으로 만드는 것이 한 곳 수정이다.

## 감수하는 비용

1. 저장 텍스트에 v2(`[주민등록번호]111`)·v3(`[카드번호]`) 행 공존 · 미응답 큐 병합 키가 배포 전후로 갈린다.
2. 14자리 이상 업무 번호와 주민번호·카드 표기에 숫자가 붙은 덩어리가 `[카드번호]`로 표기된다(Q-1 오탐 범위 — §결정 1).
3. 거버넌스 ON 원본 파일 게이트에서 AMEX 공백형이 든 파일이 새로 제외될 수 있다.
4. v2부터 남던 노출은 그대로 남는다: 하이픈 너머 숫자 묶음(`4111111111111111-1234567`의 `1234567` · `9001011234567-1234567`) · 4자리 묶음 카드 뒤 묶음 · 출구 "카드만"·기본 설정의 AMEX 하이픈형 · 13자리 연속(7번째 0·9) · 4-4-4-4-3의 끝 3자리 · Diners 4-6-4 공백형 · 전각 숫자 · 제로폭 분할.
5. 증강 회로 개방 중 Gemini capability `UNHEALTHY`(배너) · 탐침이 중립으로 끝나는 동안은 회로가 닫히지 않아 매 호출이 탐침이 된다(출구 정책을 고치기 전까지 G1 폴백이 계속).
