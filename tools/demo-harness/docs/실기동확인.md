## 확인별 상세

### 1. HF 오프라인 로드와 단건 지연
- 자식 환경은 설계 §6.4 그대로: `ML_WORKER_HOST=127.0.0.1 · EMBEDDING_DEVICE=cpu · CUDA_VISIBLE_DEVICES=-1 · HF_HUB_OFFLINE=1 · TRANSFORMERS_OFFLINE=1 · HF_HUB_DISABLE_TELEMETRY=1`, 작업 폴더 = 빈 실행 폴더(개발자 `.env` 미적재).
- `refs/main` = `8b418a58414668e75532ed045c22d9ca018ae2b2`(캐시에 존재). `main`을 해시로 풀어 오프라인 로드에 성공했다.
- 지연(순차 단건, 앞 3건 제외 20건):

| 측정 | 상황 | P50 | P95 |
|---|---|---|---|
| 수동 1 | 모델 적재 직후 | 729ms | 1610ms |
| 수동 2 | 직후 | 955ms | 1666ms |
| 수동 3 | 직후 | 631ms | 1457ms |
| 수동 4~6 | 안정 | 133 / 124 / 119ms | 167 / 138 / 146ms |
| 하네스 1~3회차 | 안정(1회 측정) | 108 / 111 / 108ms | 119 / 117 / 111ms |

  앞의 느린 3회는 CPU 부하가 아니라(측정 시점 CPU 6.7%) **가용 RAM이 약 4.3GB로 낮은 상태에서 3GB 상주 모델의 페이지가 올라오는 구간**으로 추정된다(미검증). 하네스는 이를 위해 P95 > 200ms면 최대 3라운드까지 다시 재고 마지막 라운드로 결정하며 모든 라운드를 기록한다.
- 결정: P95 ≤ 200ms이므로 `EMBEDDING_TIMEOUT_MS=300` 유지(API 재기동 없음).

### 2. Playwright + Edge
- 설치된 Edge: `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` 154.0.4258.37. `chromium.launchPersistentContext(<프로필>, { channel:'msedge', … })` 및 `chromium.launch({ channel:'msedge' })` 모두 동작.
- UA에 `HeadlessChrome/154.0.0.0 … Edg/154.0.0.0`.
- 하네스 구현: `src/browser/launch.ts`의 `probeBrowser()`가 PC-5(기동 → `data:` 페이지 → 스크린샷 → 종료)로 매 실행 확인한다.

### 3. ffmpeg·pngjs·gifenc 반입 영향
- ffmpeg가 없으면 `launchPersistentContext(..., { recordVideo })`가 `Video rendering requires ffmpeg binary` 예외로 **컨텍스트 기동 자체를 실패**시킨다 → 하네스는 PC-6으로 존재를 먼저 확인하고 없으면 `recordVideo`를 넘기지 않는다.
- 반입 목록(자동배포.md §5.13-4에 반영 필요): `node_modules` · `%LOCALAPPDATA%\ms-playwright\ffmpeg-1011` · `…\winldd-1007`(함께 설치됨 — `winldd` 없이도 되는지는 미확인이라 같이 복사 권고).
- 설치 스크립트가 있는 새 의존성 0 → `pnpm-workspace.yaml` `allowBuilds` 불변.

### 4. 공백 경로
- 마이그레이션 54개 전부 적용(`prisma migrate deploy`). 환경은 `SystemRoot·PATH·TEMP·TMP·USERPROFILE·APPDATA·LOCALAPPDATA + DATABASE_URL + CHECKPOINT_DISABLE=1 + PRISMA_HIDE_UPDATE_MESSAGE=1`뿐.
- `.env` 차단 4중 실측: ① 자식 env 백지 ② `CHATBOT_API_IGNORE_ENV_FILE=1` ③ 선적재 스크립트(지운 키 이름 기록) ④ 출구 키 5개 빈 문자열. 이 PC의 `apps/api/.env`에는 `AUGMENTATION_GEMINI_API_KEY` 등 Gemini 설정이 있었지만 자식 env에는 빈 문자열이 들어갔다(점검: 선적재가 지운 키는 `AUGMENTATION_TIMEOUT_MS` 1개 — 나머지는 하네스가 명시한 값이 이김).
- API는 모든 인터페이스(`0.0.0.0:3000`)에 바인드한다(제품 `main.ts` — 알려진 한계). ml-worker·정적 서버 3개는 `127.0.0.1`.

### 5. 표식과 종료
- 실측한 트리: `하네스 → python.exe(venv 런처, -X 표식) → python.exe(base 인터프리터, 같은 -X 표식, 포트 8100 점유)`. 하네스 → `node.exe --title=…(API, 포트 3000 점유)`.
- `Supervisor.teardown()`: 자식 역순 트리 종료 → 정적 서버 close → 5포트 해제 폴링 → 표식 기반 고아 검사(전체 프로세스 CIM 1회) → `cleanedUp`. 실측 정리 시간 수 초 이내, 7회 실행 모두 고아 0·포트 해제·`dev.db` 변경 0.
- 시나리오: ① 정상 종료 ② SIGINT 주입(모델 적재 중) → 130·고아 0 ③ `--prepare-only` 후 `--stop` → 3.4초 정리 ④ 다음 실행의 잔존 정리가 이전 실행 자식 2개 종료 ⑤ 표식 없는 PID(무관한 node)를 가짜 이전 실행에 등록 → 건드리지 않고 기록 ⑥ 하네스가 살아 있는 실행은 보호(아래 정정 #7).
- 한계: 실제 콘솔 Ctrl+C(OS 신호 전달)는 자동화로 재현하지 못해 `process.emit('SIGINT')`로 핸들러 경로만 검증했다 — **수동 확인 1회 필요**(PowerShell·Windows Terminal).

### 6. `iframe` 쿠키와 계정 교체
- 재현 방법: 격리 DB에 ADMIN·AGENT 2명 직접 생성(확인용 스크립트 — 1단계 하네스에는 데이터 생성 코드 없음) → 콘솔 서버 경유 `POST /api/v1/auth/login` → 메모리의 쿠키 값을 `addCookies`로 주입 → 무대 페이지에서 `__stage.setFrameSrc('console', …)` → `iframe` 안 `fetch('/api/v1/auth/me')`.
- `SameSite=Lax`가 같은 사이트(`localhost`, 포트 다름) `iframe` 요청에 실렸다. 제품 콘솔 SPA는 `iframe`에서 정상 렌더링(제품이 `X-Frame-Options`를 내지 않음).
- 영상 녹화 중이었고(`recordVideo` 성공), 외부 요청 감시(`context.route`)가 Google Fonts 요청을 차단해 시스템 글꼴(맑은 고딕)로 표시됐다.

## 다음 단계가 알아야 할 제약

1. **자식 환경 키 목록은 설계 §6.2 + `NODE_PATH`·`NO_COLOR`·`CBDEMO_API_PACKAGE_JSON`**이다. 새 제품 환경변수가 필요하면 `src/env/api-env.ts` 한 곳만 고친다(단위 시험이 부모 상속 0을 검증).
2. 하네스 안 서버 3개는 하네스 프로세스가 죽으면 같이 죽는다 → 데이터 생성·시나리오 중 하네스가 예외로 죽어도 `finally`에서 `Supervisor.teardown()`이 반드시 돈다(오케스트레이터 구조). 새 단계는 반드시 그 `try` 안에 넣는다.
3. 로그인 쿠키·비밀번호는 `Redactor`에 등록해야 로그·터미널·`state.json`에서 지워진다(`orchestrator`가 `Redactor`를 `Terminal`·`ManagedProcess`·`writeStateFile`에 주입). 계정 비밀번호 생성기는 `src/util/password.ts`(시험 완료).
4. 무대 `iframe`은 `window.__stage.setFrameSrc/setLayout`(1단계 최소 골격). ui-spec §3~§7 전체(상단 바·자막 띠·카드)는 `assets/*.html`을 교체하는 작업이며 `servers/stage-server.ts`의 `{{NAME}}` 치환·`/site?bot=<slug>` 슬러그 검증을 그대로 쓴다.
5. DB 직접 쓰기 2종(ADMIN1·과거 로그)은 아직 없다. `@prisma/client`는 하네스에서 import하지 않는다(정적 시험 H-S 1단계 규칙) — H3에서 `src/data/db-direct.ts` 한 파일만 허용하도록 시험을 갱신한다. 확인용 스크립트가 `apps/api/node_modules/@prisma/client`를 `datasources.db.url` 지정으로 쓰는 방식이 동작함을 확인했다.
6. 영상 파일은 `page@<해시>.webm` → `video/show.webm` 이름 변경이 필요하고, 컨텍스트를 닫아야 파일이 확정된다.
7. 준비 단계 합계(캐시 있음, `--no-build`): 사전 점검 3초 + 격리 DB 2초 + 서버 기동·예열·측정 16초 = **약 23초**. 이력 예약 대기(약 6분)는 데이터 단계에서 추가된다.
8. `pnpm demo`는 매번 `tsc`(약 3초)를 먼저 돈다. 결과 폴더는 `.demo-runs/`(무시 목록).
